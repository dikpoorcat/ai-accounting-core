# 历史：税务事实与期间结算确定性整改验收记录

> 文档性质：过去的实现结果。旧迁移编号只代表当时时点，当前数据库仅使用 `0001_baseline`。本文列出的测试方法、环境和数量不是当前统一门禁或后续任务要求。
> 验收日期：2026-08-10
> 结论：通过，可解除“无形资产与借款利息”阶段的税务前置阻断
> 边界：仍为单企业私有模拟试用内核，不是税务申报、法定账簿或法定结账系统

## 1. 验收范围

本轮关闭以下跨模块确定性缺口：

- 税务五项事实和费用角色不得由默认值推断；
- 税期预览与确认分离，确认绑定规范 JSON、SHA-256、完整规则、组织配置、来源和计算快照；
- 相同/重叠税期、同键换载荷和双连接并发只返回稳定领域错误；
- 正式税期、来源集合、税则、事件事实、解释轨迹和唯一固定模板凭证受服务与 PostgreSQL 提交点共同保护；
- 企业申报周期、管辖区或城建税率变化不重解释历史税期，且历史税则引用不因当前配置变化而失去保护；
- 固定资产出售受已确认税期来源锁保护，零收入报废不被误判为应税来源；
- 线性迁移拒绝旧税期、孤立正式税务调整和重叠税则污染，并安全管理迁移创建或复用的 PostgreSQL 扩展。

## 2. 稳定公共契约

- `finance_calculate_tax_period` 是严格类型化只读预览；`finance_confirm_tax_period` 是严格类型化幂等写入。
- 确认先取得同企业事务锁，再用行锁重新加载组织配置并重算；预览后来源或配置先提交时返回 `TAX_PERIOD_CALCULATION_STALE`。
- 确认先取得锁时，并发应税来源稳定返回 `TAX_PERIOD_SOURCE_LOCKED`；相同/重叠确认稳定返回 `TAX_PERIOD_ALREADY_POSTED` 或 `TAX_PERIOD_OVERLAP`。
- 正式税期必须保存规范哈希原文、哈希、组织配置快照、双税则外键、完整计算和逐来源快照；数据库可独立重算并核对调整事件与凭证。
- 正式事实和凭证不可原地修改；税期更正必须先冲正税期调整，再更正来源并重新预览确认。
- 零调整确认返回 `TAX_PERIOD_NO_ADJUSTMENT`，数据库零副作用；它不创建封闭税期，也不是会计月结。

## 3. 独立负向验收

独立终审覆盖并关闭了三项仅在并发或配置漂移下出现的 P1：

1. 企业管辖区改变后，旧正式事件引用的税则仍禁止更新或删除；
2. 新应税来源与税期确认并发时，锁后重算得到陈旧哈希或来源锁，不在外层提交泄漏数据库异常；
3. 组织税务配置与确认并发时，锁后 `FOR UPDATE` 重载保证配置先提交则确认陈旧、确认先行则配置更新线性化到其后。

直接 SQL 负向矩阵覆盖哈希原文、计算、调整事件事实、规则轨迹、税则/来源快照、凭证角色、金额和额外分录行。任一伪造都在 PostgreSQL 提交点拒绝为 `TAX_PERIOD_SNAPSHOT_IMMUTABLE`。

## 5. 最终裁决

税务事实、税则和期间确认的确定性前置门禁已关闭；当前代码、迁移和验收未发现剩余 P0/P1。可以按已冻结的开发基线进入“无形资产与借款利息”第一期实现。

零调整期封闭、法定申报、税会差异和会计月结不在本轮范围内，后续不得以本记录宣称这些能力已经实现。
