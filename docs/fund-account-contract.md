# 受管资金账户与明细科目

本约定只覆盖进入内核管理的公司资金账户。公司已经确认排除的平台、现金或其他资金，不因支持这些账户类型而自动纳入管理或回放。

## 原子登记

先登记并核实来源证据，再使用 `register_entity` 的资金账户专用合同。根字段为 `kind="fund_account"`、明确的 `account_type`、`source` 及已登记的 `evidence_digest`；`data` 按账户类型提供核算身份资料：

| 类型 | 必填身份资料 | 父级汇总科目 |
| --- | --- | --- |
| `bank` | `bank_name`、`bank_account_number`、`account_holder_name` | `1002` |
| `platform` | `provider_name`、`account_identifier`、`account_holder_name` | `1012` |
| `cash` | 明确的受管现金账户名称 `display_name` | `1001` |

银行账号使用完整字符串，保留前导零；允许去除原件中的分组空白，拒绝数值输入、掩码及非完整标识，不套用银行卡固定长度。银行名称、开户名和平台归属来自开户资料、流水或负责人明确确认，不能从公司名、档案显示名或账号尾号推定。字段核算语义、允许精度及可复用来源由命令 Schema 声明。

内核在同一事务内校验资料及来源、检查实际账户身份、建立档案、分配明细科目并保存审计。银行按规范化银行名称及完整账号检查重复，平台按名称及实际账户标识检查重复；同一身份且归属一致时返回已有账户，归属冲突返回结构化 `needs_information`。显示名称相同不是合并依据。

明细编码由内核分配，例如 `1002.0001`，AI 不提交科目编码。账户实体、类型、父级和编码保持稳定，改名或停用不释放编码。登记及查找结果返回实际身份和明细定义，查找支持实际账号、身份名称及明细编码。

## 资料修改与纠错

银行、平台真实账号只保存在正式资金身份定义；展示、搜索和工作上下文直接读取该定义。管理档案不接收 `display_number` 或 `external_identifiers` 账号副本。`update_entity_profile` 维护显示名称、备注及停用资料；现金账户名称仅存管理档案，正式身份由实体 ID 确定。现金改名不追加资金身份版本，也不改变明细科目。

实际开户资料录入错误使用 `correct_fund_account_identity`，提交账户类型对应的完整 `data`、当前 `fund_account.digest` 对应的 `expected_identity_digest`、`recording_error_confirmed=true` 及明确来源和已登记证据。内核检查类型、并发版本及实际账户冲突，在同一事务追加不可改写的身份修订与审计。实体、账户类型和明细编码保留，原身份和来源保留。它不移动资金或改写已登记业务的账户归属；业务引用错误仍通过有来源的类型化身份纠错流程处理。

## 分录与关账

登记、核算预览及发布均核对资金账户完整身份与明细绑定，不能直接引用半成品账户。期初、收付款、账户互转、备用金及融资按确定性业务规则产生逐行正式归属，与正式发布同事务保存。内部转账借方归属转入账户，贷方归属转出账户，不根据金额匹配。

正式分录保留父级金额和现金流口径，另存不可改写的逐行明细。预览返回明细归属，凭证详情及读取结果显示明细科目；同名账户通过编码区分。开放期替换、删除和闭期冲正按原凭证版本、精确来源及审计处理明细，不重写原凭证版本。

新关账格式冻结当时账户身份定义、逐行归属、明细余额和核验摘要。后续开户资料纠错不改旧冻结；旧关账格式仍按原合同核验。明细与总账、正式账户余额保持一致，不改变报表或现金流金额。

## 回放与现库

未来空库重放重新保全来源、登记完整账户身份并取得内核明细科目绑定后，才登记相关期初及业务，不复制现库实体或科目编码，不扩大原回放月份及管理范围。缺项在原事实清单中结构化记录，阻断该账户相关登记。

本轮清理以新建合成空库验证代码、结构合同及回放文档，现库退出后续使用并保全，不为退出字段建立迁移或兼容入口。真实重放等待用户另行指定；不替换现库、不切换运行资料根、不自动启动重放。
