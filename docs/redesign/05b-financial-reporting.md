# 财务三表和统一取数

本文规定 ledger 的首交计算，不是已实现功能。机器合同为 [reporting.schema.json](contracts/reporting.schema.json)，独立数字例为 [reporting-cases.json](examples/reporting-cases.json)。适用小企业会计准则、人民币、按月或完整自然季度查询，适用2013年起报告；不把三张表等同完整法定报表及附注或报税系统。

准则依据为财政部 [小企业会计准则](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852319878.pdf) 第79—88条及 [科目和报表附录](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852734144.pdf) 第67—82页。表号沿用附录；本体系自设细目和营运款分类是本设计的明确应用。报表主项的业务范围不由前端或导出模板选择。

## 一次读取和期间

`ledger.public.financial_snapshot(scope, read_context)` 返回严格 FinancialSnapshot，使用同一个只读事务和head。scope为core.LedgerScope：整家公司，不接受object_ids；period_from/to为同年单月或完整自然季度，不能跨年。as_posted的as_of省略时取period_to，提供时也须相等；current不提供as_of。非法范围返回invalid_input，不偷偷补月。字段和金额不得以任意字典扩展。

| 数据 | 固定含义 |
| --- | --- |
| balance_sheet.*.ending | 报告末月末余额。 |
| balance_sheet.*.beginning | 报告年1月1日前余额，季度报告也不是季度初。 |
| profit_statement.*.current | 本次单月或完整季度的损益发生额。 |
| profit_statement.*.year_to_date | 该年1月至报告末月的损益累计。 |
| cash_flow_statement.1—20.current/year_to_date | 同样期间内的正式现金流贡献。 |
| cash_flow_statement.21.current | 当前月/季度开始前的现金余额。 |
| cash_flow_statement.21.year_to_date | 年初现金余额。 |
| cash_flow_statement.22两列 | 同一报告末月末现金余额，必须相同。 |

所有中间数和输出均为整数分；借方减贷方记为D，贷方减借方记为C。汇总先按分加总，不逐行换元后舍入。展示和XLSX只把分除100，保留两位小数；负号保留，不按绝对值掩盖损失或贷方余额。不支持的数值范围返回明确问题，不截断、溢出或转float。

## 正式采用的选择

- `current`：每个业务当前完整目标一次，按目标所属月计入，反映已知最终事实；不能再加旧冻结或冲正，否则重复。
- `as_posted`：关账月采用冻结目标，后续发现期采用正式补差；开放月只用该月当前完整补差，旧开放版本被替换。目标、受控分录、资金分类和报表明细同时选取同一代结果，不能金额用冻结、分类读当前事实。
- ledger自己的余额/发生额选择器产生BS和PL主项。query_report_contributions只补规定的PL细目；query_fund_movements及正式采用头产生现金流。三者不相互叠加同一金额。TaxSale供税务/申报取数，不能作为第二份财报收入。

对一个稳定资金身份m和分类c，先把真实方向转换成该报表行的有符号目标T(m,c)：正常收款/付款各在对应行取正，原业务退款或逆方向取负；内部划转为零。若本期已存在冻结基准及以前正式补差，其累计为B，则本次正式现金流补差为`T−B`。同一开放更正期反复修改，用新完整差额替换旧差额；更正期关账后，下一次只减已经采用的累计。仅用ledger保存的完整资金目标、类别、generation及冻结采用头计算，不扫描当前业务事实。

CashflowContribution是这一公开只读结果：business_id、movement_id、public_slot、adoption_period、source_result、baseline/supplement、category和signed_amount_fen。它不是新付款事实，也不增建可编辑现金流水表。冲正分录本身不能生成资金；真实发生查询仍是一笔稳定身份，实际退款另有真实事实和资金身份。

例如1月错登记收款100000并冻结，2月改90000：2月CF补差−10000。若2月尚开放又改80000，2月完整补差改为−20000；若2月已关账，3月再改80000，3月只补−10000。累计最终80000，不能再补−20000。纯未付费用更正没有现金补差。

## 现金流量表：只消费正式资金分类

义务用 cashflow_weights 表达已知性质及比例，实际资金用 cashflow_parts 表达已经分配的真实金额。二者分工明确，不能因应付更正为零而抹掉实际付款的性质。付款及继承先按类别归并，再使用同一累计分配规则；来源分别留在必要采用依据中，不以来源条数决定比例。

退款及费用退回继承原构成中相应累计区间的差额。同一原债的多次超付追偿统一计算：依每笔经济截止和稳定身份顺序，只从其截止前真实付款中尚未被更早追偿占用的部分，倒序取本次金额。付款增加时加入新的可用区间，已取部分不因退款而释放。一笔可以采用多个区间；按各段 `C(末点)−C(起点)` 合计分类，再生成本笔权重。计算只用最终事实，不保存另一张可编辑分配表。

A、B等权、名义1分、实际付2分时，首笔追偿1分取 `[1,2]`，退B1；以后真实新增抵销1分而再追偿1分，只能取剩余 `[0,1]`，不会改掉原退款的类别。严格更晚的业务不改变已有分配；同一截止的身份排序只是稳定分配规则，不声称实际日内先后。只有月份时按整月计算截止，不补造月末发生日。每笔不能超过当时真实超额，也不能提前使用未来付款；较早尚未发现的缺口允许后来补认，最终容量仍由账务统一检查。

合并报销按各来源本次实际转债金额形成构成，例如工资类100分和资产类1分形成100∶1，不把两个单类权重1直接相加。混合原债已部分清偿后再转债，尚未实现可证明的剩余分类接续时明确保留分类未知，不能从零重新分配而重复使用舍入分量。

每笔FundMovement的cashflow_parts在采用时确定。已知时各项为正分，同类别先合并，合计等于真实资金金额；报表根据方向变成行的有符号金额。分类来源缺失时省去parts，表示未知，不能填空数组或猜分类；有据记税/真实付款仍保存，相关报表部分未就绪并留下具体待补。补齐来源重算同一资金身份的分类。category固定如下，不能再读费用当前JSON决定它落哪行：

处置税的归属使用税务已采用的经营/处置税构成，不能把同一税款同时算5和10。已计算的各来源税负先扣其明确减免/退抵；实际总额的一次性舍入差，按已知净税负权重、稳定来源UUID顺序分摊：第i项=`round_half_up(total×累计权重/总权重)−前面已分`，最后一项收余数。实际税源明确指定构成时优先采用该来源；实际正税额而全部权重为零且无分量来源，相关现金流未知，不能编造处置税额。税总额和凭证不因报告分类缺口被手改。

混合义务的多次部分付款，以及费用分项的累计退回，使用共同的整数累计分配 `cumulative_shares`（Webster 最高平均数法）。类别按稳定顺序排列，每一分归入 `权重/(已分数量+0.5)` 最高的类别，同值取顺序靠前者；程序用等价的整数商和余数调整，不能逐分循环或用浮点数。本次分类额取付款后累计分量减付款前累计分量。累计增加时任何类别都不倒扣，全部付清恰好得到完整构成；例如三个相等类别，从一分到两分依次得到 `[1,0,0]`、`[1,1,0]`，不能出现 `[0,1,0]`→`[1,0,1]` 这种累计增加却倒扣第二类的结果。税务一次性分级舍入与资金的多次累计分配分别承担不同工作，不能混用。

现金流合计：7=1+2−3−4−5−6；13=8+9+10−11−12；19=14+15−16−17−18；20=7+13+19；22=21+20。真实流入方向在流入行取正、在流出行取负；真实流出相反。正式补差可以为负，不取绝对值。

## 年中接续

opening.package表示接账月初的明细，不等于年初报表。年中existing_ledger要完整年度取数时，reports.continuation明确年初BS53行、接账前YTD和接账当季已发生的PL32行/CF22行，逐行唯一，不得重复/缺行；与bookkeeping_start和opening_package_id一致。

程序核对：年初BS30=53；接续PL21/30/32公式；CF7/13/19/20/22公式；接续CF21YTD=年初BS1，CF22YTD=接账期初资金，既往季度CF22也等于该接账期初。本年净利润只能取接续利润表，不能拿期初累计留存收益硬代本年利润；留存收益还可能包含以前年度积累及既往利润分配，不反推一套历史业务或自动补差。

查询覆盖接账月及以后时，YTD加接账前YTD一次；当前季度包含接账月时，加该季度接账前金额一次。接账在季度首月，该季度prior流量必须为零；后来季度不再加前季度。current现金21使用当期开始前余额，YTD现金21始终年初数。接账当月的current即该月，不把既往季度金额塞进月报；首交不返回接账前单独月份的月报，缺逐月来源返回needs_information。

缺接续资料时，已明确的接账期初和后续业务仍可办理；相关年初、跨接账季度和YTD字段为unestablished，当月和期末已知项照常返回。不能用“接账后累计”冒充“本年累计”。newly_established且有据为该年接账月新设立时，设立前流量及年初余额为明确零，无需伪造continuation。

## 未知、核验和输出

FinancialSnapshot包括范围和head、固定三表全部行、pre_tax、当前采用摘要selection、checks和issues。每个金额是`{state:known,amount_fen}`或`{state:unestablished,issue_indexes}`，未知没有amount_fen，不用null或0。issue_indexes索引本响应issues并指到具体缺口；不能将缺项自动转成老板会计问卷。

有未知输入的合计和勾稽继续传播未知；已知的不受影响字段保留。映射未知且非零时不能装作没有该科目。完整known零与未知清楚区分。checks固定十项：BS年初/期末30−53；PL本期/累计32−(30−31)；CF本期/累计22−21−20；CF本期/累计22−BS1；CF本期/累计20−同期间正式现金科目变动。pass差为0，fail保留实际非零差，unknown不带差额。

status=ready要求所有表格字段known、十项check均pass且issues为空；否则partial。只有ready可以按原有模板交付完整三表；部分结果可查看但不能输出成全部有效的报表文件。导出固定消费同一FinancialSnapshot，不另开业务汇总；模板行名/版式转换不改变金额与期间。选择摘要可重建，不保存每次查看的审计记录。

## 开发验收

至少执行examples的21个独立数字场景，包含完整DTO、往来拆分、开发支出、短期基金、混合付款、内部划转、年中接续、缺项、连续闭期补差、EIT无循环、合作代收代付、同事件改分类、撤去、混合处置税逐分分摊、长期借款到期列报及税借余。再验证：未知项不被零覆盖、跨公司不串账、导出数等于公开DTO、修改operations内部写法但相同正式结果不改变三表；无需前端重算或全历史扫描。

旧可复用点为account_definitions的部分精确映射、reports的纯公式、reporting_fields的字段语义及financial_statement_template的模板写入。4301旧存货归类、从凭证标签临时猜现金流、旧审批/证明/历史兼容和旧发布状态不复用。实现不能直接调用旧Reports取得整包结果而跨越新模块边界。
