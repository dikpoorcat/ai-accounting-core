# 新体系需求与开发设计

本设计面向一位本地老板管理多家公司。老板借助会计 AI 准备资料、理解事项和办理日常会计工作；内核负责明确规则下的计算、可靠保存及内部协调；看板供老板核对，也供专业顾问只读审查。

设计交付的标准是：具备相关 Python、SQLite 或 Vue 基础、没有参加前期讨论的开发者，能够按模块说明独立实现、运行测试并提交成果；不同模块能按事先约定完成真实集成。业务规则、接口含义、数据库结构及验收预期不留给实现者临场决定。

本目录定义完整需求与开发设计，包含可检查的字段合同、数据库结构和预先定义的验收样例。实现放在独立的 `src/ai_accounting_modular/`，按 [开发与验收](07-delivery-acceptance.md) 接通真实模块并验证；设计文件存在不代表相应功能已经实现。开发使用合成公司和隔离资料，不自行改变现有公司库或服务。

讨论设计时先读 [产品需求](01-product-requirements.md)、[整体架构](02-architecture.md) 和 [AI 工作要求](08-ai-work-and-materials.md)。交付开发时，以本目录全部合同、规则、结构及任务包为一套依据；机器合同不需要老板逐字段阅读。

## 设计范围

先独立设计目标架构，再核对旧实现是否存在可复用能力或遗漏的业务情形。新体系采用模块化单体、每家公司独立业务库，保持现有看板主要显示内容、UI 样式、既有用法及读取优化。

第一轮交付覆盖原有有效业务能力。投资理财先承接现有货币基金及近期需要的合作项目投资；合作只是其中一种记账方式，与其他投资类型共用办理、保存和查询，不另建项目经营子系统或独立详情页。预设类别不等于已实现全部金融产品，不支持的类型明确说明范围。

## 已实现的程序基础

`contracts.public` 提供严格字段校验、整数金额与日期、生成类型及共用上下文。运行 Schema 从设计真源生成到包内，不依赖工作区中的文档目录。

`storage.public` 提供新合成目录和公司库、单公司读写事务、回滚式试算、维护事务、结构核验与数据库一致副本。试算复用真实核算和事务末核验，不保存结果或推进版本。维护文档、读取模型和文件任务不改变业务版本；已有目标不覆盖，创建中断可明确接续。

`files.public` 提供备份和报表的当前文件任务、防重、进程中断接续、实际文件核验和受控下载；由装配方注入内容生产者。任务接纳与完成均复核语义头，重复捕获可安全回收，回复丢失不释放已接纳输入。真实公司备份和报表文件生产者仍需接通。

`ledger.public` 提供完整候选资源、正式计划采用、凭证和义务读取、完整槽替换、保号更正、必要冻结基线和来源引用。完整责任由重算计划和精确保留引用共同覆盖，未变结果不重写、不退出，资源继续有效；来源更正时索引核对当前消费者，不能省算后留下失效依据。资源采用区分正式产生期、关联期及必要实际日；同月未知先后先用数量边界核验，确实影响结果才补日期。应用按资源使用、余额范围和集合发布安排计算，读取只等待实际影响该范围的结果。税销售及税前利润共用正式取数，未知财报细目保留未知，不阻止已确定的总额。共享三表支持当前最终事实和历史采用补差；版本只覆盖实际取数来源。关账覆盖截至指定月尚未关闭的整段，保存当时三表及映射版本，历史读取不受以后映射变化影响。大规模性能仍待验证。

`ledger.opening` 保存独立期初成员，公开余额、义务、基金成本及资产卡片，不造历史凭证或资金。资产模块统一生成卡片并接续建账后的摊折和处置。`ledger.reporting` 保存有源三表比较资料和独立所得税累计，显式接续优先；非零新设期初不会被当作全部历史为零。规范化的期初、银行及平台明细共用完整集合摘要核验，各 owner 可以独立导出正确正文。

`identity.public` 保存并检索当前对象档案；`records.public` 保存来源、当前说明和未解事项，增量发布最终标准文档，并为备份提供同一快照的资料捕获和读取租约。期间查询覆盖所有相关范围并完整分页；待办中的嵌套来源同样保全。完整标准集合可在没有源数据库的情况下核验和复制，仍须由后续重建入口重新办理业务。`application.public` 以一次原子办理接通各owner，支持保号更正、撤去恢复、防重、按槽连带重算、自然唯一性和文档失败接续；当前工作月份及最终文档随有效内容一起维护。当前业务检索在SQL内分页，正文只取实际需要的范围，游标不受无关业务版本变化影响。AI可查询实际装配的业务种类，按需取得自包含输入字段合同，不接收内部记账计划。

经营模块已接通费用、押金、代收代付及返还、垫付转债、预收预付、履约和退款、费用退回、多付追偿、多收退款及其他实际收入；税点、真实红字和未来税额释放按对应毛额范围衔接。薪酬模块支持人员在册、缴费政策和实际缴费、工资、奖金及劳务。资产模块支持项目成本、完工转资产、直接或垫付批量取得、启用、折旧摊销及处置。资金模块承接各领域真实收付身份、付款、划转、抵销、托管和工资组合代发，以及银行/平台原行和完整银行核对。

税费模块已接通小规模 VAT、附加、已用资产 VAT、实际申报和退抵，以及共享税前利润下的所得税暂计、实际累计采用及年度汇算。累计下降先抵尚未清偿的税额，实际退款权利有独立来源，不能重复生成。融资及投资模块已接通股东资金、贷款合同、真实放款、分段计息和货币基金购买赎回；还本或更正会连带更新受影响利息，实际收付仍由资金模块办理。

合作项目作为投资类型接通合同、真实出资、按份经营、代理收付、分回、风险分担及退出，使用共同业务和凭证入口。经营者劳动不估价，不另建项目运营系统。实际款项与利润确认分开，更正早期经营事实后仍保留真实款项；同样的最终事实可以在独立空库重新核算。月内先后仅在确实影响真实资金时要求补日期。月度结果接续前月正确累计、当月变化及仍未清项目，新增晚月事实不重算未受影响的早月；合同仍保留一次完整集合核验，大规模性能仍待验证。

义务的分类权重与真实收付金额分别保存，零额更正仍保留已知性质。多次超付追偿只使用各自截止前尚未占用的付款区间，经济截止更晚的新业务不会挪动早期退款分类。已用工资和混合报销的真实办理场景验证：只取最终标准业务文档及其原件，可以在独立新库得到相同最终事实和现金流结果；完整重建产品入口仍需实现。

供应商费用与直接资产取得可以沿同一业务更正分类，实际付款和原编号接续；已有启用、处置和成本依赖须在同单完整处理。冻结结果退出由账务模块统一形成必要冲正，开放错误正文不积累。

`reading.public`和`dashboard.public`已接通公司/期间上下文、季度三表预览及业务来源查阅。三表保持既有响应格式，热读复用组件，相关范围变更才更新；来源列表不读取原件正文，实际下载核对完整摘要和最终范围。其余页面、真实Excel导出及HTTP页面仍需接通。

`host.public.create_kernel`通过公开工厂装配业务组合、读取和看板适配，可以在隔离目录办理业务、归档文档并更新季度预览；目录及公司由明确的存储调用创建。应用已提供说明/待办办理、当前和精确历史读取、期间检查及关账，并在业务事务中通知相关读取范围。网页、MCP/CLI及后台自动调度仍需接通；生成模型使用显式worker，不把preparing称为已经更新。验证使用新建合成公司。

## 开发前如何核对

在仓库根目录运行：

```powershell
& '.tmp-kernel-venv/Scripts/python.exe' docs/redesign/verify_design.py
```

[检查脚本](verify_design.py) 只读取设计文件，核对 Schema 引用、合成输入输出、来源摘要、冻结看板合同、文档链接，并在内存 SQLite 验证结构和保护约束。它不会打开任何现有公司库。

本轮检查环境为仓库虚拟环境的 Python 3.12.13、jsonschema 4.26.0、referencing 0.37.0。重建检查环境时将这两个库安装到仓库虚拟环境，不使用系统默认 Python；这些是设计检查依赖，不是新增产品模块。

这些检查说明设计文件相互吻合，不能代替业务程序、真实模块集成、浏览器和性能验收。后续实现必须按 [开发与验收](07-delivery-acceptance.md) 逐项执行预定结果；性能数字是交付要求，本轮没有声称已经达到。

## 当前决定

- 采用协作信任。会计 AI 承担职责内的专业判断，也主动引导不熟悉财务的老板准备资料和继续工作。
- 老板提供现实信息、作经营决定并负责全部外部付款、申报等实际办理。专业顾问只读审查，不修改账务或批准处理。
- 公共业务入口只接受类型明确的事实，不向 AI 开放任意借贷分录。
- 金额使用整数分，核算金额不经过二进制浮点数；月份与实际日期分开，不补造日期或未知金额。
- 开放月份直接更正或按条件撤去误记，保留原凭证编号，排除旧错误正文和纠错过程档案。闭期保留必要冻结结果，并通过关联冲正更正。
- 原件、标准业务文档和数据库保存最终正确账务所需内容。标准业务文档在日常工作中归并为最终有效事实，真实收付、退款和损失不因归并消失。
- 文档重建建立简化新账；备份恢复保存时状态；读取重建只重建派生数据，三种行为分别定义和验收。
- 现有数据库保持内容不变，另行隔离存放，由老板以后删除；新体系从空库测试。原件如存在则整理，原重放文档整理成标准业务文档；现有备份后续清理，新体系仍建设自身备份恢复能力。
- 上述真实资料搬移、换库、重放、旧备份清理和服务切换在明确安排后执行；开发中的合成建库与验证不操作这些真实资料。负责人按通过复核的节点统一安排 Git 提交。

方向依据为 [架构重新设计纲要](../architecture-redesign-outline.md)。旧架构和旧约定仅作为当前实现的参考，不能覆盖用户在本轮已明确的新决定。
