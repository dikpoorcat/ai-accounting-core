# 公司说明只读查阅设计

本功能已在现有模块内实现并接入正式公司库和常驻后台，增加公司说明的排版和只读查阅，不改变五个业务页面的主要内容与样式。开发与验收沿用[既有交付要求](07-delivery-acceptance.md)，对应外包清单第14项。

## 1. 老板看到什么

老板能随时查看所选公司的业务背景、日常安排和已经明确的说明。它是**当前公司说明**，与查看哪个记账月份无关，也不承诺展示历史月份当时的说明。没有凭证、没有可选月份的公司同样可查看。

入口放在现有侧栏工具区、“负责人身份”之前，名称为“公司说明”；展开侧栏显示文字，折叠侧栏和手机显示有中文名称的图标。沿用五项业务导航，不把第六项挤入手机底部导航，也不把链接放入会覆盖点击区域的公司选择框内部。

独立路由为 `/company-note?company_id=…`，沿用登录、公司选择、主题和页面外壳。页头为公司名称、“公司说明”、“只读”和“刷新”；正文按文章阅读，使用清晰的标题、段落、列表和表格。长文自然向下滚动，桌面控制行宽，窄屏正常换行，宽表格仅在表格内部横向滚动。没有编辑、保存、批准、关账入口，不使用固定高度文本框、长文弹窗或默认折叠正文。

界面不增加JSON、说明序号、摘要、来源证明或数据库信息等技术字段，不据此删改正文。老板要补充或修改内容，仍通过会计AI办理。

## 2. 一份正文，分别负责保存与展示

当前实现已由 `records` 在各公司数据库的 `company_note` 表保存正文，`scope_key='company'` 表示公司说明。`accounting_apply.notes` 修改它，`accounting_context` 读取它；标准文档中的NotesShard由程序从数据库生成。JSON中的换行转义本身不妨碍排版，真正缺少的是明确的正文格式和阅读入口。

| 模块 | 本功能的责任 |
| --- | --- |
| application / agent | 继续使用现有说明提交和查询，引导AI按需要整理公司说明。修改说明不伪造业务凭证。 |
| records | 唯一维护正文、格式、来源、并发序号及最终文档；只保当前有效说明。 |
| storage | 执行说明格式列的明确前向结构接续，保全原库及身份。 |
| reading | 在一次只读快照内，通过公开元数据和 `records.current_notes(('company',), read)` 取得当前公司说明。 |
| dashboard | 校验公司参数，适配公开读取结果和原有登录会话，不访问资料私表、文件或AI应用服务。 |
| frontend | 负责安全排版、阅读状态及公司选择的关联，不保存另一份可编辑正文。 |

标准文档继续承担最终事实重建，数据库备份继续承担准确恢复。不增加说明专用数据库、段落表、HTML副本、单独维护的Markdown文件、全文索引或历史编辑日记。说明排版不参与会计计算。

## 3. 正文格式与已有内容接续

复用现有 `text` 正文，增加一个明确的 `text_format`：`plain_text` 或 `markdown`。缺省固定为 `plain_text`，不根据星号、换行或文件名猜格式。

| 内容 | 固定含义 |
| --- | --- |
| 旧公司说明 | 按纯文本显示，保留字符、段落和换行。不会把 `*`、`_`、`1.` 或 `<…>` 重新解释成格式。 |
| 新整理的公司说明 | AI按轻量Markdown提交，使用标题、段落、有序/无序列表、加粗、普通表格、引用和文字链接；正文仍只有一份。 |
| 月份经营说明 | 本轮保持原有纯文本及失效规则。`text_format`可省略或为`plain_text`，不能提交`markdown`；不顺带改造简报展示。 |

`NoteChange / CurrentNote / DocumentNote`共用同一格式定义。NoteChange省略格式与显式填写`plain_text`语义相同；原有 `expected_seq`、来源和同内容重试规则继续适用。CurrentNote、DocumentNote及摘要的规范内容省略默认的`plain_text`，仅Markdown包含`text_format='markdown'`。格式由records统一规范化，其他消费者不各自转换。

因此，增加格式列不改写旧纯文本、旧摘要或已有NotesShard，也不因省略/显式默认值的差异推进序号。相同文字从纯文本改为Markdown是实际呈现变化，推进说明序号、更新notes分片；会计结果不变。未知格式明确拒绝，不能悄悄当纯文本。

数据库仍用 `note_text` 保存原始正文，仅新增`note_format`列，默认plain_text，允许plain_text/markdown，并约束Markdown只能属于company范围。当前公司结构为2，由[结构1基线](schema/company.sql)和[明确增量DDL](schema/company-note-format.sql)生成；封存结构1合同保持原文。目录结构仍为1，只有records和storage模块合同升为2，并记录各自父合同。

records负责该列含义；storage负责按明确起止结构合同执行接续及完整指纹核验，不能只改版本号、补指纹或重建公司。结构接续失败全部回滚，已有公司、数据库和负责人身份、事实、凭证、冻结依据与原件保持。规范默认值使旧正文摘要不变，不代表SQLite结构指纹可以不变。

旧标准文档缺少格式可明确按纯文本导入；旧数据库ZIP另有结构合同，不能因此宣称自动兼容。这里的旧结构仅指本模块化体系增加格式列前的结构，不包含原内核的库或备份。结构1 ZIP先核对原字节、完整结构和公司身份，再仅在临时数据库副本升级并复用当前完整业务核验；恢复目标保留原结构和正式数据。恢复时只清理files/reading派生状态，采用与旧合同完全相同的仓储及受限维护事务，不开放旧业务读写。

原位接续使用显式离线`database-upgrade`命令，先验证同公司、同数据库、同账务版本的完整备份，再事务内升级；不启动服务、不重新记账、不清空仍有效的月页。完成重试不改写数据库。使用方法见[运行说明](09-runtime-and-ai.md#明确的公司结构升级)。正式资料接续不由普通打开或开发测试自动执行。

## 4. 唯一只读接口

完整字段见[公司说明合同](contracts/company-note.schema.json)。它已接通运行校验与前端生成类型，独立于原五页冻结响应，不改变它们的版本和字段。

| 交接 | 固定约定 |
| --- | --- |
| HTTP | `GET /api/dashboard/company-note?company_id=…`，必须指定公司；不接受月份、分页、历史视图或写入参数。 |
| 进程内 | `reading.detail('company_note', ContextScope, {})`，ContextScope必须含company_id；一次只读事务，不依赖已有月份或读取模型。 |
| 正常响应 | `company`包含company_id、database_id、credit_code、name；`description`为null或完整的 `{text_format, text}`。详情始终明确格式，正文不截断。 |
| 无说明 | 公司存在但没有当前正文，`description=null`；空白正文按无说明展示，不补造内容。 |
| 参数或读取失败 | 参数不合法返回400，公司不存在返回404，登录状态沿用现有会话规则；存储或格式损坏返回明确错误，不能返回200和null冒充未填写。 |

响应字段由同一Schema生成后端校验、TypeScript及Ajv，运行合同随安装包交付，不依赖工作区设计目录；前端核对请求和响应的公司身份。错误沿用现有错误合同，不增加说明专用错误平台。响应采用`Cache-Control: no-store`，不存HTML、专用持久缓存或预计算说明投影。

只读取当前公司元数据和`company`这一条说明；不读取所有月份说明、业务正文、凭证或标准文件，不调用全月准备、重算或后台整理。只有实际需要显示时才查询，原五页默认响应和刷新不携带公司说明全文。

## 5. 安全排版与页面状态

前端采用 `markdown-it` 的公开解析接口，显式关闭原始HTML、裸网址自动链接和排版替换，仅对本设计列明的文章语法与普通表格排版。使用解析令牌映射为允许的Vue节点，文字作为文本节点输出；不把正文交给`v-html`，不执行HTML、内联事件、脚本或自定义组件。不启用远程图片、视频、iframe、脚本插件或代码高亮平台。图片语法保留可读替代文字和原文字地址，不创建资源请求；文字链接仅允许http/https，由用户点击后打开，禁止危险协议，不自动获取链接预览。

节点固定为文章正文的`h2–h6、p、br、ul、ol、li、strong、blockquote、table、thead、tbody、tr、th、td、a`；源标题h1–h5依次下移一级，h6仍用h6，页头保留唯一主标题。不得动态采用令牌标签名或整体传入`token.attrs`。仅有序列表可采用合法的start值，表格对齐映射固定左/中/右样式，链接只写入校验后的href和固定的新窗口/`rel="noopener noreferrer"`属性；不接纳正文的任意样式或事件属性。裸网址不自动变链接，显式`<http(s)网址>`与Markdown文字链接使用同一安全规则。

斜体、代码块和其他未列排版不增加对应节点，文字及代码内容按可读原文回退，分隔线作为段落间隔；不丢弃正文。图片令牌永不生成img节点。以上规则覆盖整个解析结果，不能只关闭`linkify`便认为默认语法已全部受控。

依赖固定到经核查的项目锁文件版本，新增的是一个解析器，不引入编辑器或文章管理平台。解析选择与安全配置参考[官方安全说明](https://github.com/markdown-it/markdown-it/blob/master/docs/safety.md)及[公开解析API](https://markdown-it.github.io/markdown-it/interfaces/MarkdownIt.html)。排版不完整保留可读正文，不把Markdown写法变成记账阻断；未知存储格式属于损坏，不能掩盖。

| 状态 | 页面行为 |
| --- | --- |
| 未选公司 | 提示先选择公司，不发送缺少公司身份的请求。 |
| 首次读取 | 显示正在读取，不借用上一家公司的正文。 |
| 未填写 | 显示“这家公司还没有公司说明”。 |
| 首次失败 | 显示“公司说明暂时无法读取”和重试。 |
| 同公司刷新 | 可保留已经读到的正文并显示正在刷新；失败明确说明未取得新内容，不能把旧正文称为已更新。 |
| 切公司、离开页面 | 取消旧请求，清空旧公司正文和错误；公司身份及本次请求标识共同防止迟到响应写回，快速A→B→A也不例外。 |

外壳通过路由元数据统一区分页面是否依赖期间。公司说明页隐藏月份选择，不要求selectionReady中的月份，不因旧地址带period而读取历史说明。同公司临时阅读后返回原五页，原来选定的月份或季度保持；切公司时按既有规则选择该公司的有效期间，允许新公司尚无期间，不复用另一家公司不适用的期间。地址可保留期间作为返回导航状态，但说明GET仍仅提交company_id，不因期间变化重读。原五页的期间选择和切换行为保持，独立来源页保持自己的精确范围。阅读状态留在页面局部；不新增全局Store、轮询或说明专用后台任务。

## 6. 更新范围

公司说明更新只改变公司说明、必要来源引用，以及notes和实际受影响的sources文档目标；纯默认值重试不更新任何目标，内容未变的分片沿用原文件。它不依赖普通金额变化而失效，也不让月度经营说明、凭证、税费、财报或五页财务投影全量重建；若现有影响声明把company说明当成全部月份的变化，应在其所属边界收窄，不在前端忽略失效来掩盖。

只读GET、打开、滚动、刷新和关闭都不推进说明序号、会计采用头、读取目标或文档状态。说明更新成功而文档暂未生成时，老板和AI从同一数据库读到当前内容；文档继续沿现有后台机制接续。完整备份仍等待其明确的一致点，不把旧分片当作最新资料。

## 7. 交付归属

本文件、唯一响应Schema和[预定义样例](examples/company-note-cases.json)组成共同依据。负责人统一格式、结构接续、读写字段、路由位置、文章样式和预期；实现者只决定不影响约定的局部写法，不另定数据真源、格式含义或接口。

| 承接方 | 交付范围及依赖 |
| --- | --- |
| A包，records/AI接入 | 格式规范、摘要防重、来源、NoteChange/CurrentNote/DocumentNote及NotesShard接续；AI更新说明。依赖共同格式定义。 |
| F包，storage/文件基础 | 唯一结构接续及旧ZIP恢复路径，验证失败回滚和数据保全；不解释正文或渲染Markdown。 |
| R包，读取及看板 | 独立只读读取、HTTP适配、生成类型与校验、工具入口和阅读页；后端与前端可依固定合同并行，最终接真实records。 |
| H包，集成负责人 | 统一装配与结构发布顺序，真实页面、AI更新、文档重建及备份恢复联调，核对五页未受影响。 |

共同合同由唯一owner修改，后台和前端不能各维护一份字段形状；A/F先统一格式与结构，R可按严格样例并行。没有新增运行模块或说明平台。

## 8. 验收清单

1. 桌面、折叠侧栏和手机均能找到所选公司的只读入口；键盘可打开、刷新和阅读。原五页和五项业务导航保持。
2. 合成Markdown样例的标题、段落、列表、加粗、普通表格和文字链接按约定显示；长文与窄屏可完整读，表格不撑宽整页。
3. 旧纯文本中特殊字符及换行保持；缺省/显式plain_text重试不推进序号或重写文档；只有公司说明可以采用Markdown。
4. 无月份公司正常读取；接口拒绝月份，页面的公司说明不随月份变化冒充历史版本。未填写、无公司、未知公司和失败分别表达。
5. 切公司、刷新、离开和A→B→A乱序响应不会串内容；同公司刷新失败不会把旧内容称为最新。
6. HTML、脚本、内联事件、危险链接不执行，图片和其他嵌入资源不自动加载；原文不经不安全HTML插入。
7. AI更新后，刷新得到同一正文和格式；导出、空库重建、当前结构ZIP准确恢复，以及旧结构恢复再前向接续均保持内容与必要身份，失败回滚不伤原库。
8. 只读操作不写库、不推进序号；说明更新不重算账务或失效无关月页；原五页不增加正文请求。增加无关历史业务不增加说明读取工作量。

验收检查实际查询范围、渲染、状态与接续，不新增未经老板确认的秒数、字数或固定运行次数门槛。设计静态检查与样例校验只证明开工文档一致，不能称为该功能已经实现。
