# 疑似重复复核与材料处置版本

疑似重复候选不等于重复业务。同一银行原行可以明确分配给不同真实债务和收款人；完整原件及有效复核依据支持 `create_separate` 时，当前发布和关账检查采用该复核。

当前采用比较双方业务主体、业务修订、事实与证据内容，以及稳定原件的来源身份、证据摘要、位置和解析声明。材料处置采用的所属期、处理方式、原金额、归期及全部分配链接均参与比较；链接保存业务身份、类型、金额字段、金额、归期和事实内容摘要。比较完整分配，不仅比较疑似重复双方的小计。疑似重复信号也必须一致。

材料来源修订、处置修订、事实引用和计算引用仍作为不可变审计依据保存并验证。仅刷新解析或处置版本，或无影响发布后把链接改为同内容事实及新计算，不单独撤销已有复核。金额、业务身份、事实内容、原件定位、解析声明或真实分配变化使原复核失效，须核对当前候选；材料完整性检查仍独立拒绝失效结果、错误金额或缺少归期依据。业务登记先于首次材料处置时，原件定位复核仍可采用；已有处置快照则约束其完整分配。

持久化的 `business-duplicate/2` 候选摘要、配对摘要、记录摘要及 SQL 结构保持不变。当前采用过程重新验证保存的原文和复核依据，再匹配当前业务；不改写历史候选或记录。已冻结的重复检查 v1 解释及源合同继续按原算法校验，当前采用语义不回写冻结结果。

合成回归使用真实类型化费用、付款、银行流水和汇总对账入口，覆盖无影响发布后的连续材料链接刷新、分配变化失效和原定位替换原子失败，并核对保存的复核记录原文未变化。相关测试位于 `tests/kernel/test_duplicates.py`；冻结与材料验证仍由各自测试覆盖。
