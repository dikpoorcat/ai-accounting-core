两档结果均通过数据库完整性、外键和证据摘要校验。100 员工最终保留 300 个稳定凭证、603 个计算版本；500 员工保留 1,500 个稳定凭证、3,003 个计算版本。待更正项均为零，库文件分别约 10.3 MiB 和 47.7 MiB。

此次测量支持的优化顺序是先增加类型化来源批量提交，再减少单次预览内共享规则与依赖范围的重复读取。500 员工来源建立用了 37.7 秒，而整月发布为 1.2–2.6 秒；入口事务粒度比纯工资算术更值得优先处理。750 份工资的再次更正需要 1.9 秒预览和 4.4 秒确认，确认内仍有 2.5 秒持锁，不能宣称复杂更正均为亚秒。

单员工更正的读取 SQL 在 100 和 500 员工档都为 76 次，确认 SQL 都为 285 次；其余员工的计算 ID 保持不变。这证明本次数据与规则下更正范围没有随全公司人数扩大。它不等于证明任意历史深度或政策变更都具有同样成本。
