# 新内核的银行代发文件

代发文件是根据已确认应付款生成的付款指令。**生成、重试或下载文件均不代表已经付款**，不会创建银行流水、付款事实或资金凭证。实际银行扣款发生后，仍通过 `payment` 类型化事实及其核销分配入账。

## 选取金额和收款人

`Exports.preview` 接收归集月份、已经留存为证据的银行模板摘要，以及可选的业务来源 ID。不接收外部金额、自由分录或覆盖应付款的行数据。

省略 `source_ids` 时，选取该归集月份全部未付工资、奖金、劳务和明确归属员工的报销；指定来源 ID 时，预览明确标记为部分范围。供应商费用不会因为收款人名称或账户看似个人而变成员工报销。

金额来自当前正式计算所产生的应付款及其剩余余额，已核销的真实付款自动扣除。相同收款人与用途合并成一行；文件最多 2,000 行。工资、奖金、劳务、报销具有明确的默认用途，也可使用已保存的 `payment_category` 管理说明。

保存了 `payment_period` 的来源按这个管理月份归集；未设置时按来源的核算月份归集。归集月份和用途都不改变原业务归属期、金额或凭证。跨月归集时，预览检查请求月份和实际来源月份的资料完整性，并保留两种月份以便复核。

收款姓名、账号和其证据由 `Exports.save_payee` 独立追加版本。账号始终按文本保存，保留前导零。缺少收款资料时返回明确缺项；不产生空账号、默认账号或零金额付款。

## 预览、确认和文件任务

1. 预览在一致数据库快照中读取应付款、余额、收款资料和管理说明，复用关账的资料完整性检查器，并拒绝未发布业务、待更正结果和资料缺项。
2. 确认检查核算、材料、管理三个版本及预览摘要，在一个短事务中保存冻结计划和 `payment_export` 文件任务。确认阶段不读写任意外部文件，也不改变核算版本。
3. `run_export_jobs` 在事务外读取已留存模板并生成四列 XLSX：收款方名称、收款方账号、金额、附言／用途。姓名、账号、精确到分的金额和用途全部写为文本，并回读核验。
4. 输出目录同时保存 `银行批量代发.xlsx` 和 `代发核对.json`；后者记录任务、原预览摘要、来源计算版本、收款资料版本、文件校验值和生成语义。

同一请求 ID 重试返回同一任务。文件任务采用进程锁；数据库写事务只用于领取任务和记录完成结果。文件生成失败可以重试，崩溃遗留的 `running` 任务可以恢复。如果文件已经发布但完成状态尚未落库，重试会核对任务身份、摘要和实际单元格后复用文件。已有无关目录或内容不一致的文件不会被覆盖。

计划一经确认便保留原金额和收款资料。之后新增付款、更正业务或修改账号，不会改写历史任务；需要反映新状态时重新预览并生成新任务，核对当前版本后再用于银行操作。
