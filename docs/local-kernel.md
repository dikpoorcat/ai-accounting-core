# 本地会计系统总览与文档导航

本文说明本地系统的用途、基本工作流程和专项文档入口。具体请求字段与可用能力通过 `finance_local_schema` 查询；AI 会计的正式操作规则以其中的 `agent_operating_protocol` 为准。

## 系统定位

系统供一位本地负责人管理多家公司，每家公司使用独立的 SQLite 业务库。内核位于 `src/ai_accounting/kernel/`，根据已确认的类型化业务事实计算并发布账务；页面提供只读查询与核对。

金额以整数“分”保存，税率及税额计算使用 `Decimal`。正式凭证必须借贷平衡，发布保持原子性和幂等性；缺少影响核算的事实时返回 `needs_information`。公共入口不接受任意科目、借贷方向或自由分录。

系统用于本地核算和办理跟进，不宣称是法定账簿、纳税申报或报税系统。生成申报资料或代发文件不会自动完成外部申报、缴税或银行付款。

当前体系标识为 `ai-accounting-kernel/2`，目录库与公司库均为 `draft / 0`，公司备份格式为 2。
当前工作优先沿已有本体系库补齐并试用；同体系结构变化须有明确来源、备份和保留核验，具体能力以实现和验证为准。
现有 5173 服务、资料根、原件、负责人身份及备份保留，正式合同冻结、正式包交付和运行切换延期。
连接核对精确结构指纹，不自动升级或重建；当前结构与后续安排见[开发结构合同](development-database-upgrades.md)和[路线图](kernel-refactor-roadmap.md)。真实重放须另行明确目标与范围。

## 运行入口

日常通过本地启动器准备服务、完成负责人原生密码验证并打开工作台，步骤见[启动说明](local-kernel-startup.md)。
一个资料根目录对应一个常驻服务，`finance-local` CLI、MCP、页面及后台任务连接同一服务；密码不进入业务命令载荷。

MCP 提供 `finance_local_schema`、`finance_local_command` 和 `finance_local_security`。业务调用绑定明确的 `company_id`，不能用任意数据库路径或 SQL 选择公司。

活动数据库放在本地磁盘，不通过网络盘或同步目录运行；需要共享时使用已生成并验证的备份包。
新建公司、切换资料根、恢复和重放分别按明确范围执行，启动不自动创建或替换公司库。
常用操作见[Windows 运行速查](windows-local-operations.md)，运行时与打包工具见[独立运行包说明](local-kernel-packaging.md)。

## 一个业务如何入账

通常分为四步，具体入口由当前结构合同和业务类型确定：

1. 保全实际采用的原件，登记证据并取得内容摘要。
2. 通过该业务的类型化入口确认事实，引用证据和已有可复用来源。
3. 预览确定性核算结果，核对金额、所属期、实际入账期及缺失事实。
4. 使用同一预览及相关版本确认发布，保存回执；响应丢失时复用原请求查询或重试。

`save_fact` / `save_facts` 仅适用于允许通用登记的事实。资产、资料处置等声明专用登记命令的业务必须使用对应入口；保存事实不等于已发布账务。

核算所属月、实际收付日期、工资所属月、个税申报税期和社保所属期分别保存，归集月份不能替代核算期间。
业务事实与采用依据保留版本；已发布结果不会因新资料到达而静默改写。

## 工作清单、外部办理与恢复

`workflow` 是公司工作起点；指定月份的完整性与关账条件由 `period_readiness` 查询。
清单按“下一步要办什么”组织，银行、工资、普通业务、税务、资产、融资六类作为后台完整性检查维度。

以 10 月办理 9 月及第三季度事务为例：

| 顺序 | 事项 | 工作内容 |
|---|---|---|
| 1 | 流水与基础资料收集 | 收集 9 月初至今的完整流水、票据及业务资料，区分 9 月业务与后续收付，保留已对账结果并补齐未识别业务。 |
| 2 | 工资、劳务与个税办理 | 核对工资及适用劳务、实际扣税与申报依据，分别处理申报、缴款和代发表。 |
| 3 | 社保、公积金办理 | 核对所属期、人员及个人／单位承担额，取得实际申报明细和缴款依据。 |
| 4 | 账务补齐与报表准备 | 复核普通业务和月度资料，处理资产折旧摊销、融资及影响报表的税费计提，完成分类与三表检查。 |
| 5 | 财务报表报送 | 当期需要报送时，核对报表、生成文件并报送，保全实际提交版本、采用依据及回执。 |
| 6 | 企业所得税及其他申报 | 核对第三季度所得税依据及当期适用税费，分别办理申报和缴款；工商年报等按实际适用范围列出。 |
| 7 | 收尾核对与关账 | 补取申报后的扣款流水，复核银行覆盖、匹配、余额及账务差异，完成资料和凭证检查、负责人核对批准及关账。 |

账务随资料到达持续处理；第 4 步是集中补齐，第 7 步是最终收尾。流水不能代替未收付款业务的事实依据，影响财报金额的核算须在报送前完成。

缺资料或待确认只阻断受影响事项，保留具体缺项并继续条件满足的独立事项。七步是默认办理顺序，不新增外部办理或复核的强制关账门槛。

状态分别表达资料、核算、申报、缴款、复核和文件交付，例如“待提供个税申报明细”“已申报，待核对银行扣款”。
有依据的无业务结论不能代替外部义务适用性确认；明确不适用也须保留依据，未知金额不补零，未知实际日期不推定。

工资、劳务与个税资料核对完成后，自动发起代发表流程；预览后按运行协议完成同版本确认，创建文件任务，成功核验后交付。
生成仍须满足现有资料完整性、模板、收款资料和金额依据要求；缺项时保留代发待办，补齐后接续，不必另等生成请求或关账。无未付余额不生成空文件。

代发表明确选取工资与适用劳务，不混入无关报销，也不以缩小范围绕过完整性检查。
实际申报税额与计算税额不同且按申报额代发时，须有明确采用依据，保留未代发差额；文件生成不代表实际代扣、付款或结清。详见[银行代发文件](kernel-payment-exports.md)。

中断或切换公司后重新读取真实工作状态，复用仍有效的确认、任务和产物。响应丢失先查原请求结果，未知不等于失败；文件失败处理原因后重试原任务，不能另记一笔业务。具体推进与恢复规则以运行协议为准。

## 更正、关账与文件交付

开放期允许通过类型化修改入口替代核算结果，保留凭证身份、编号与审计；符合条件的误录业务可撤去。
闭期凭证与冻结依据不可变，后续更正通过开放期的关联冲正处理；核算无影响的复核追加新的采用依据，不增加凭证。详见[核算等价合同](accounting-equivalence.md)。

关账检查完整资料覆盖、未处理事实及业务模块声明的期间义务。负责人核对关账预览后，经原生密码窗口批准，再提交同版关账；相关版本变化使旧预览失效。
“先办完再关账”是默认顺序，关账后的未完外部事项继续提醒；页面汇总不能代替正式检查。

季度报表在开放期完成核算、分类及报表检查后即可冻结导出并记录实际报送。
预览与确认绑定同一数据版本，后台使用保存的不可变报表计划生成文件；账务变化使旧确认失效。
真实报送版本、采用依据及回执保留，后续账务变化触发复核，不抹去已报送事实，也不回写原提交内容。详见[季度三表与报送复核](local-kernel-reports.md)。

账务发布、关账、外部办理和文件任务成功分别判断。文件交付以 `jobs` 中成功且已验证的产物为准，不能把待运行任务或中间文件当作完成。
每家公司独立生成 `<统一社会信用代码>.finance-company.zip`；恢复先验证便携包，禁止合并或覆盖既有公司。详见[多公司运行与备份恢复](multi-company-operations.md)。

## 开发与验证

业务计算位于内核与领域模块，CLI、MCP、HTTP 是本地调用适配；计算器不读取文件、当前时间或随机源。
验证按当前改动风险选择，使用隔离的合成公司；本机 Python 使用仓库 `.tmp-kernel-venv`。测试、构建和结构合同工具的具体要求见对应专项文档与仓库约定。
