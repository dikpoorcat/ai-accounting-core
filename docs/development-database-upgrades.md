# 开发结构合同与历史升级机制

当前全局字段去重采用新建空库作为验证基线。生产合同不声明从此前开发结构到本次结构的升级路径，不接受退出字段或旧字段别名。现库、原件和备份继续保全，现有服务不切换；本轮不运行 `upgrade-development`，不执行真实重放。后续真实重放须另行明确指定，执行边界见[空库重建文档](empty-database-replay.md)。

当前公司与目录仍属于 `ai-accounting-kernel/2`、`draft / 0`。新公司保存当前完整 SQL 指纹；创建、打开、备份、恢复均验证包内合同、库内记录和 SQLite 实际 SQL。版本数字相同不表示结构兼容，旧库和旧包不能通过改指纹、补标识或重建表接入当前结构。

## 保留的隔离升级机制

代码保留显式合同升级的通用机制及隔离测试，用于验证已声明来源和目标之间的事务、历史及内容保留。它们不构成本次结构的迁移能力，也不构成运行现库升级的授权。普通服务、MCP连接和数据库打开只核验合同，不自动升级。

该机制要求可信代码同时声明精确源合同、目标合同及前向边；不接收外部 SQL，不猜测未知结构。DDL前独立保存目录快照并生成、核验每家公司便携ZIP。每家公司锁内重新核验来源，在独立事务中调整精确声明的结构，核对原行值、身份、不可变历史、外键及完整内容后提交；失败回滚。多公司操作记录已完成前缀和失败公司，不声称跨公司共同回滚。

原始 `schema_history` 记录保持原文；已声明的开发调整向不可变 `schema_draft_history` 追加来源、目标、历史摘要和安装时间。普通连接核验完整SQL与连续的已声明合同链。新公司原安装记录直接对应当前合同，追加链为空。已发布的released合同不可回写，正式升级与开发合同独立。

## 历史记录与恢复边界

此前增加看板读模型及资金明细结构的开发升级记录、私有回执和合成验证按原时点保留。本次生产包不再装载这些来源合同或升级边。历史指纹和旧开户输入不是当前执行模板，不从展示名称推定开户资料。

备份始终属于保存时的精确结构。当前普通恢复入口只接受当前支持的同结构包，不能静默跳过结构差异；隔离历史机制的测试不扩大普通恢复范围。原备份及其身份、事实、冻结采用和证据保持原样，不作为清理资源。

当前结构的验证使用独立新建合成公司贯通登记、发布、资料采用、关账、成功ZIP和独立恢复，并对比原生与物化读取。真实公司不会因合成验证通过而自动建立、替换或重放。
