# Windows 本地运行速查

本机使用 `finance-local` SQLite 服务。一个资料根目录对应一个常驻服务；目录库索引多家公司，每家公司有独立业务库。当前开发库属于 `ai-accounting-kernel/2` 的 `draft / 0` 合同，连接时核对类别、版本和完整结构指纹。旧 PostgreSQL、Alembic 及旧 SQLite 库不是本系统的启动或升级来源。

## 启动与登录

在本仓库会话说“启动”，会按 `$accounting-startup` 只准备本地服务、验证 MCP 与负责人登录并打开页面。开始处理真实资料需另说“开始记账”或明确交办业务。

手工启动仓库环境：

```powershell
.\deploy\windows\start_accounting.ps1 -DataRoot D:\会计资料
```

未传 `-DataRoot` 时先使用 `FINANCE_DATA_ROOT`，否则使用仓库 `data/kernel-released`。原开发目录和凭据不自动导入；目录名称不改变当前draft／0结构状态。本轮按用户决定保持现有5173、资料根和身份，不进行正式合同冻结、正式包交付或运行入口切换；已有released隔离测试不授权转换当前库。`-NoBrowser` 只连接服务并返回身份状态；默认打开页面。服务在本机回环地址自动选端口，重复启动复用同一资料根的现有服务。独立运行包可在包目录执行 `finance-local.ps1 --root D:\会计资料 serve`。入口细节见[本地会计工作台启动](local-kernel-startup.md)。

负责人在页面发起设置或登录，密码和恢复码只在本机安全窗口输入。MCP 使用 `finance_local_security` 请求、查询或取消窗口；成功发起窗口不等于完成登录。取消后结束该次尝试。不要把秘密放进业务命令、聊天或终端参数。

页面可打开只表示服务可用。操作前仍要确认 `finance_local_schema` 与 `finance_local_command` 可连接，以及负责人已登录。开发工作区的 Python 命令使用仓库 `.tmp-kernel-venv`，不使用系统 Python。

## 工作与请求恢复

第2步确认工资方案、适用劳务及个税并登记必要输入，第3步核对社保、公积金实际承担额及申报缴款，第4步统一办理银行代发。尚未办理第3步不阻止第2步确认；第4步复用仍有效的确认，不因阶段切换重复确认。进入第4步先核对本次工资、奖金、劳务、报销及代付款事项和已收资料，在本步补齐必要事实、核算净额并正式发布；随后用 `export_sources` 按归集月份完整读取全部候选分页，核对范围，主动接续 `preview_export`、同版本 `confirm_export`、`jobs` 成功核验及交付，跟踪实际银行代发，不自动银行付款。所有明确 `source_ids` 统一标示 `selected` 范围，核验所选业务、直接和传递采用依据及精确关联义务的余额处理，相关原件整份检查；无关联的整月资料、税费和普通账务不阻挡选定付款，省略来源的完整导出和关账保持整月检查。缺项在第四步处理，继续本步其他可办工作并等待补齐，后续事项与银行代发无关，不作为前置条件，不等待后续核算回补代发。已有产物须核对完整覆盖本次来源和金额，新来源或金额变化须生成新任务，保留历史；候选为空或旧任务成功不能代替本次交付核验。正式计算、发布门槛不变，无未付余额不生成空文件。具体条件见[银行代发文件](kernel-payment-exports.md)。

泛化“开始记账”先调用 `workflow(company_id, as_of)`；指定核算月份时传 `period`，`as_of` 使用实际日期，申报覆盖期单独核对。聊天开场说明公司、期间和当前事项，展示八步完整清单：流水与基础资料；工资劳务与个税；社保公积金；银行代发；账务补齐与报表准备；财报报送；所得税及其他当期适用申报；收尾核对关账。第5步包含其他普通业务、资产、融资和影响报表的税费计提；银行在开始收集识别，收尾再次核对完整覆盖、匹配与余额。六类资料与核算状态仍作为完整性检查维度，实际办理和文件交付分别说明。空公司没有可靠月份时不补造起点；有依据的无业务不推定外办不适用。完整步骤见[会计工作流程](local-kernel.md#工作清单外部办理与恢复)。

每个已展示事项完成后重读 `workflow`，展示结果、完整进度及当前阶段下一项工作；完整清单不作为整月资料问卷。当前缺资料、待确认或技术阻塞时，只继续本阶段条件满足的独立工作并等待；提前推进仅限已核实的真实后阶段结果依赖或用户明确插办。技术阻塞、等待答复和后阶段业务可独立办理都不是后阶段依赖。后阶段已有资料仅先保全、解析、归期和准备草稿，不提前追问、要求结果确认或正式发布。真实依赖记录所需结果、所属阶段和回补点，按八步顺序推进，不跳过中间阶段；进入对应阶段后正常办理，取得结果时说明回补及返回位置；明确插办结束后返回原阶段。已有确认及负责人主动提前提供的明确确认，核对适用范围后复用，不逐项增设允许继续审批。普通重算不一律重新询问，关键事实或范围变化才重新确认。财报核算与报表检查通过后可在开放期冻结导出并记录报送，默认最后关账；原报送快照、采用依据与回执保留，不新增外部事项的关账门槛。恢复时按当前接口及真实状态重核旧稿阻塞和接续点，保留仍有效的真实后阶段依赖及用户明确插办安排；旧能力阻塞已消除时重判实际缺项，按顺序及有效例外纠正不合规接续，接续最早应办的未完成阶段，后阶段问题保留 `deferred` 待办，保留未决问题和已有结果。详细安排见[会计工作流程](local-kernel.md#工作清单外部办理与恢复)。

每条写命令使用稳定 `request_id`。响应丢失后，能恢复原载荷就用原键重试；只有编号时调用 `request_result(company_id, submitted_request_id)`。`committed` 返回原动作和保存的结果，`unknown` 只说明当前公司库没有该请求与审计记录，不能据此断定业务失败或另记一笔。改变请求内容或预览失效时重新核对，并使用新键。

`needs_information` 的 `fact_issues` 指向字段、精度和可复用来源；按 `status`、`code`、`reusable_sources` 及 `resolution` 核对实际处理条件。提问前定位公司、实际业务期间、对象和字段，复用已读上下文、原件、已有记录和负责人此前答复。开始或恢复用 `work_context(include_work_draft=true)`，后续沿分页或精确来源查证，本页未出现不是缺资料；六类 `work_area` 均可跨原资料类别精确复用来源，不从工作月份推定业务期间。候选通过对应领域 `prepare`／`preview` 核验，不统一增设通用登记预检。得到唯一明确答案时采用并保留来源，仅真实剩余缺失、冲突、歧义或新必要决定、批准才问，每轮当前阶段同一事项最多3个独立问题，不以子项打包。工作稿问题的 `answered` 仅表示收到回答，`resolved` 仅表示问题已解决，均不代替正式事实或批准；省略状态的旧稿仍须查证。详细字段见[事项工作稿恢复](work-draft-recovery.md)。

结果未知先查 `request_result` 和实际状态；预览过期、待重算及文件失败先通过现有恢复、重算、预览或任务重试入口处理。包装问题须同时读取嵌套 `cause` 的字段语义、约束、来源与处置入口，结合外层 `blocking_scope` 解释实际阻塞范围；文件级发布阻塞不表示负责人确认失效。阶段切换、普通重算及文件失败不自行撤销负责人确认，仅关键事实或范围变化部分重新询问。技术阻塞不能变成重复业务追问；现有入口可处理的共性阻塞集中排查并处理，需要修改实现的缺陷保留技术待办，说明缺少能力、受阻事项和接续入口，只继续本阶段条件满足的独立业务，不转到后阶段追问、确认或发布。会计操作不修改仓库、不切换或请求切换开发模式。

## 数据库结构与故障

普通连接会核对目录库及公司库的系统标识、结构合同和实际 SQLite SQL 原文，只接受当前支持的精确结构，不自动升级、删除、重建或补标识。本轮字段清理使用新建合成公司验证，现库退出后续使用，现库、原件和备份继续保全，现有服务不切换；生产包不提供此前开发结构到本轮结构的迁移或兼容路径。保留的通用机制与历史验证见[开发结构合同](development-database-upgrades.md)。已有文件即使没有业务行也不是可覆盖的新建目标。遇到 `schema_fingerprint_mismatch` 或不支持的库，保留原文件并按诊断处理；真实空库重放须另行明确目标和范围。

`verify_integrity` 只读检查权威内容、发布链及派生数据。确认为派生数据差异后，显式使用 `rebuild` 或 `repair_read_indexes`；两个入口都先核对权威源，在同一事务内恢复所有必要派生目录、金额／冻结派生及已登记读取模型，再完整核验。实际变化才推进读取修复版本一次，失败全部回滚；不修原始源、不更改业务 epochs 或冻结源，普通只读连接不自动维修。不要用 SQL 手工改账或绕过合同检查。

后台备份和文件任务通过 `jobs(job_id=...)` 查询。代发、财报和个税确认的 `output_directory` 可省略，提供时是导出父目录；默认使用公司内部 `exports`，新任务成果目录由程序分配。旧任务保留原保存的精确路径，恢复或重试不改写原请求。任务成功并核验产物后，用会计 Skill 的桌面复制脚本交付支付、财报和个税成果；相同内容复用，不同内容自动另名保留。失败返回稳定 `error_code` 和安全说明，处理明确原因后可对失败任务调用 `retry_job`；自动尝试有上限。`last_error` 是本机诊断内容，不作为公开结果或负责人追问。目录中的公司创建与恢复由 `operations` 查询。

## 页面与安全窗口

页面保持经营简报、资金、员工、资产、财务报表五页。普通记账关账先预览，再由负责人在同版核对内容上通过原生密码窗口批准，最后执行 `close`；页面浏览与窗口批准都不代替正式提交。按已确认重建文档重放时默认使用[专用批量关账](replay-batch-close.md)，在显式启用的公司、数据库及月份范围内接续，不逐月请求密码。报表、申报或付款的文件生成也不代表已对外办理。

页面开发构建和本机运行步骤见[启动说明](local-kernel-startup.md)。旧 `restart_dashboard.ps1`、Docker 容器和 `company_cli check-schema` 不是当前入口。
