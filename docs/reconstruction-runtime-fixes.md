# 重建资料的业务来源与新库准备

## 当前边界

本轮全局字段去重直接更新代码、数据库结构和现有回放文档，使用新建合成公司验证。现库退出后续使用，现库、原件及备份继续保全；不迁移、不保留退出字段别名、不执行真实重放或运行切换。未来空库执行只采用最终清单明确索引的已保全原件和负责人确认。旧凭证、计算、余额、冻结状态和回执不能代替新目标事实或执行结果。

当前生产合同没有声明此前开发结构到去重结构的升级路径，旧包及未知结构按合同拒绝，不能通过修改指纹或生成空库覆盖现库。通用结构机制与历史隔离验证见[开发结构合同](development-database-upgrades.md)。目录、公司、实体、事实、计算和精确修订身份由未来新目标产生，稳定业务键在实际执行时绑定；真实重放须另行明确目标和范围。

## 来源身份与完整银行原行

业务来源沿用内核主体身份合同：非空字符串，最多200字符。实体、账户采用各自合同；含冒号的内核工资主体是合法业务来源，不能替换为修订ID或旧别名。

受管资金账户按真实身份独立登记并由内核原子绑定唯一明细科目。银行账户根字段为 `account_type="bank"`，`data` 提供有来源的 `bank_name`、`bank_account_number`、`account_holder_name`；平台账户提供 `provider_name`、`account_identifier`、`account_holder_name`；现金账户提供有来源的 `display_name`，身份使用实体 ID。真实账号只保存在资金身份定义，展示、搜索和工作上下文直接复用；管理档案不接收展示编号或同义账号副本。开户名不默认采用公司名，完整账号及开户银行不从显示名称猜测。新目标只登记原件或负责人明确确认支持的身份值；开户资料缺项沿现有单份最终清单记录并返回 `needs_information`。这一要求不扩大已确认的平台及现金排除范围。

本次资金账户修订取消现库修复，只完成代码和回放资料；原库、原件、凭证、计算及冻结原文保留，等待另行明确执行空库重放。新目标重新登记来源、完整账户身份和内核生成的明细科目，取得绑定后才登记期初及业务。旧科目和实体编号只用于历史解释，不作为新目标输入；整理文档不启动服务切换或重放。

一条银行原行可引用多个不同的完整已发布资金来源，要求全部来源只对应该原行、同账户、实际日及方向，完整金额之和精确一致。单一来源可覆盖同日同方向的多条完整原行。原行编号、日期及金额保留，不推断逐人逐行分摊，不允许模糊多对多匹配。资金页每条原行仅计数一次。

`payment_method="bank_batch"` 的付款没有单一交易方时，必须显式提交 `counterparty_id=null`；每项 allocation 仍提供真实 `recipient_id`，与采用义务核验身份及金额。单人付款必须具名。完整整批付款与完整银行原行匹配，不虚构汇总机构或把第一人当整批交易方；实际少付保留未清偿责任。本月发生按原采用类别展示混合付款分项，单类多人批次保留精确原批次主行，首次展开即显示逐人用途和个人金额，不按姓名或相同成员集合跨原批次合并。完整原凭证与银行原行继续保持原金额和内容；活动分项的增加不重复计数凭证或资金原行。

## 代收转付的最终权利人

`pass_through.beneficiary_id` 必须引用已登记且具名的真实最终权利人，不能提交 `null` 或无真实姓名／名称的对象。先复用身份一致的对象档案、收款人或个税身份来源；仍缺少时返回 `needs_information`，阻止新登记、修订、批量登记及核算。实际付款人、受托性质、转付责任及金额仍须有明确来源，`rights_and_obligation_confirmed=true` 才能核算。

此前已保存的未具名来源继续保留，按精确 `pass_through:<subject>:remittance` 来源义务单独列示、核验和备份。原责任与其实际清偿采用同一稳定键，不按空姓名合并，不跨来源抵销。后来实际收款人不会追认为原最终权利人；有依据的更正使用正式纠错流程，原来源和闭期采用保持不变。存储列保留可空类型仅用于读取这些已有来源，不构成新录入例外。

## 未来回放的支付平台与现金边界

未来回放依据每家公司负责人明确确认的长期边界，不将支付平台及现金账户纳入本内核资金或投资管理，不追问范围外的资金来源、余额、内部支出或内部对账细节。已确认属于备用金的公司银行实际转入通过 `managed_reserve_expense` 计管理费用，实际退回公司银行通过 `managed_reserve_refund` 冲减管理费用，采用真实银行账户、日期、整数分金额及完整银行原行；不把现金收付推定为备用金费用。平台内部消费、申赎、收益和退款只保全资料，不再确认公司费用、退款、投资或余额。

范围外的平台及现金原件作为支持资料保留完整内容、实际位置及明确支持用途；内部业务明细依该公司负责人确认的边界作有依据的不入账处置，不同时分配核算金额。未来回放不登记范围外的平台或现金账户、期初、内部收付款与划转，也不登记平台产品的货币基金持仓。公司银行实际收付仍完整处理，与平台对应行不重复核算。明确有独立来源的股东投资到账直接按实际公司银行 `funding` 登记；验证款、押金及其退回保留实际业务性质，同日同额的不同业务仍按原行独立匹配。具体公司身份及边界确认保存在私有最终事实清单和所索引的负责人确认中，说明重建按[当前内核空库重建](empty-database-replay.md)执行。

当前通用平台接口继续存在。`managed_reserve_internal_movement` 是现有的精确原行留证能力，要求平台账户、当前正式原行、同月同账户、唯一采用及明确边界确认；其结果没有公司凭证、余额、现金流、费用或税额。这个接口不作为上述未来回放的输入，原有合成验证记录保留其实际范围，不证明新回放口径已经执行。文档和最终事实清单的修订不改动现库、身份或运行服务。

## 重复复核与资料刷新

已保存的“分别登记”复核按双方业务修订、内容、信号及完整原件分配语义核验。业务和原行处置未变时，资料处置重新绑定生成的事实或计算编号不会单独撤销复核；真实金额、期间、类别、位置、成员或分配改变仍使其失效。持久 `business-duplicate/2` 摘要算法及冻结v1规则不重写。详见[资料处置与重复复核](duplicate-review-material-semantics.md)。

## 验证与恢复

跨月原件的完整处置版本可以包含未来月份链接。关闭本月时，资料变化目录仍保留所有链接的反向追踪键，但只核验核算所属月不晚于关闭月的历史采用；未来链接由其实际月份核对，不能因前月留证提前冻结，也不能借此跳过未来月份失效链接。检查规则修复不重写已保存的目录根、冻结内容或v1历史验证器。

新库备份和恢复核验当前完整结构合同，不在滚动入口兼容退出的开发结构。来源合同不匹配时拒绝并保留原 ZIP，不把旧包改写成当前包；同结构滚动、发布中断和幂等重试继续核对档案原字节及公司身份。

便携备份任务的完成证明来自完整格式2清单及内容验证结果，不能套用报表导出任务的顶层文件SHA字段。工作状态核对公司与数据库身份、结构、期末、证据数量、完整覆盖结果及非负计数；当前文件是否仍存在另记为尚未检查，不能将过去成功证明冒充当前文件检查。

验证使用隔离合成公司，覆盖类型化登记、采用与原子失败、完整银行原行、独立往来责任、资料复核、冻结、批量关闭、结构合同、便携备份及恢复、原生和物化读取、页面响应合同。字段来源见[字段清单](field-sources.md)；账户身份、业务备注、工资确认、资料关联和贷款合同均从唯一正式来源复用。SQL 草案与浏览器生成合同同步生成。回放模板离线核验稳定键、执行依赖、目标绑定、材料覆盖和原件摘要，不把旧“可执行”结论当作证明。

只有用户另行明确指定真实重放时，才按[空库重建流程](empty-database-replay.md)准备目标和范围，重新取得身份及同版预览。明确缺项在现有最终事实清单保留，不从旧展示值猜填，不因合成验证通过自行执行。
