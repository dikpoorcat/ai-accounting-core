## 1. 目标、现状与设计基线
面向一位负责人管理多家公司，让五页默认层先回答“本月赚亏、钱在哪里、待收待付、需要处理什么”，再进入业务与精确来源。沿用 Vue 3、现有五页路由、现有浅深色样式与组件。保留当前工作树全部前序未提交成果，T1—T5 验收继续有效。

已阅读 roadmap、共同协作约定、AGENTS、FRONTEND、T5 v1 结果、有界查询及看板对齐说明，并检查实际页面、共享组件、API 和 T5 桌面/手机截图。具体障碍：
- 五页均先展示大段 PeriodPreparation；报表重复三个月。T5 截图中简报首屏几乎全部是核算准备及重复问题，经营结论和金额被推后。
- 公司选择在侧栏，期间在侧栏日历和页头重复；侧栏收起和窄屏下使用路径不同。页内导航的浮动负边距与固定滚动偏移容易受区块高度变化影响。
- 简报新增的五组共同查询明细在经营概览前，且常用业务动作与通用技术展示并列；准备问题只有重复中文句子，缺就近的来源动作。
- 资金/员工/资产已支持后端全范围筛选，不应重写为客户端筛选。真正的问题是账户选项只来自已加载账户，选择后页账户刷新后可能丢失名称；页内账户关注项也不能冒充完整关注清单。员工列表列数会随续页出现奖金等字段变化。
- 资金和基金的凭证目前是文字；资金完整摘要挤占列表。员工付款、来源期未结和资产项目来源藏在多层展开中。分页失败常上升为整页错误，使已成功读取内容消失。
- 窄屏资金表要求约 980—1100px 局部横滑；现有证据未证明页面级溢出，但日常阅读成本高。T5 仅保存简报截图，不能视作五页视觉验收。

视觉默认：沿用绿色强调色、浅灰背景、现有深色模式；用文字层级、留白和轻边框区分内容，减少大面积装饰与重复状态卡。桌面保留侧栏，手机保留五项底部导航。金额右对齐、等宽数字；主要数值突出，红/黄只用于实际问题，正常未关账和正常往来使用中性色。

                  本页核心金额
                  经营或领域结论 | 需要核对的事项
                  业务列表与筛选 → 行内详情 → 来源/凭证 → 技术依据
手机：公司/期间控制 → 核心金额 → 结论与待办 → 单列业务卡片
      固定底部五页；详情在原位置展开，完整财务表保留局部横滑。

## 2. 五页职责与信息层级
| 页面 | 默认层与后续路径 |
| --- | --- |
| 经营简报 | 本月盈亏、月末账面资金、月末待收、月末待付四项完整指标；有效经营说明或正式汇总事实概览；需要处理的分组入口；随后是待收待付来源、业务/凭证、资金资产与用工构成、核算和资料依据。长期资产移入构成区。无分录业务保留独立可达入口，不能因不在凭证列表而消失。 |
| 资金 | 月末账面资金与银行/现金/平台分布、全月对外流入流出；账户余额卡片及账户选择；账面变动/银行流水两种明细；基金确认成本与实际收付款独立区段。账户互转、流水覆盖、对账和未匹配分别表达。 |
| 员工 | 本月人数及后端已给出的用工成本、应发/应付等领域汇总；员工固定结构摘要行/卡片；先展开付款概况和按来源期的工资/劳务款项，再看工资构成、实际扣税、申报、代发依据与档案来源。不新增由已加载来源累加的全员未付指标；“本月付款”与“本月来源义务清偿”保留独立标题。 |
| 资产 | 长期资产账面价值、在用/待启用/项目成本与本月变动；固定/无形/待启用等现有筛选；资产卡片和项目投入就近导航；取得、折旧/摊销、退出及来源结算依次展开。整批或项目付款保留批次范围说明，不展示推定单卡分摊。未知核对状态直接指向实际问题或候选依据，不再链接不存在的“差异项目”。 |
| 财务报表 | 季度与可预览/可导出状态、下一步和三表摘要；待核对事项与补充资料选择；三张完整报表；逐月历史封存与当前跟进、已完成检查和技术资料展开查看。保留预览资料与导出绑定、生成进度、失效解释及重新生成。 |

共用 PeriodPreparation 改为简短的“所选期间核算”和“全公司当前跟进”两区摘要，页面业务指标前只留必要状态提示。正常解释与完整依据展开；问题组默认显示名称、该组准确条数和首条具体问题，展开可见全部。报表按三个月折叠分组，当前问题仍显眼。
历史/月末和当前跟进绝不合并为单一完成状态；资料、核算、款项、外部办理、文件分别表达。不同组可能重叠，不相加为一个“总待办数”，义务总数也不称待办数。

## 3. 统一交互、上下文与来源
- 公司与期间控件集中到现有 DashboardModuleHeader，侧栏保留模块导航及负责人/文件入口，移除重复常驻日历；复用现有 Router 与 useDashboardContext，不加 Store。公司名称在侧栏收起和手机状态下仍可见且可切换。
- URL 的 company_id/period 继续是共享上下文。换公司优先保留新公司可查看的同月，否则采用其后端默认月份并明确提示；换公司清理旧页筛选、凭证焦点、补充资料和展开状态。进入报表使用所选月对应季度；切季度继续采用现有该季度最近可查看月份规则，返回月页时月份明确可见。切月清除旧明细与游标。刷新保留适用筛选，更新共享上下文和可选月份。
- 现有页内导航改为稳定文档流中的区段导航，去掉浮动负边距；按实际导航高度设置滚动留白。点击定位后焦点落到标题；加载后的 hash 定位也检查请求世代。保留已有数字凭证/精确版本深链及双 HTML 入口。
- 筛选继续由后端执行，只提供现有账户、员工和资产筛选能力，不新增伪全量搜索。显示“全公司/全领域汇总”“当前筛选共 N 项，已加载 M 项”；分页按钮置于列表底部，页头保留范围说明，不改默认 100 条或自动拉完全部页。
- 账户选择器就近提供“继续加载账户”，复用 accounts 独立集合。按精确 type+account_id 保留已选项名称供选择器显示，补位项不计入集合数量；切公司/月清空。筛选变化重新获取游标，不复用旧过滤范围游标；账户关注摘要引用完整计数，已展开问题明确为已加载账户范围。
- 为来源跳转及浏览器返回保留必要的本页筛选：资金使用现有账户筛选参数及 book/bank 视图查询，员工/资产使用现有 filter 枚举；路由只保存选择值，不保存页数据、游标、快照或新的业务状态。模块导航只携带共享公司/期间，定向来源链接显式带目标；不继续复制所有无关 query。
- 详情统一采用行内渐进展开：对象/业务、所属期间、后端金额与具体状态 → 业务组成及历史月末/当前相关清偿 → 来源文件、相关凭证、更正关系 → 内部编号、哈希、版本、JSON。复用 BusinessStatusDetails、DashboardSourceHistory、VoucherTrace、EvidenceList，不新建通用详情框架。未知金额显示“暂无法确定”及原因入口；确实未提供的管理资料标为“未提供”。局部未知、未证明候选与已有独立获证旧记录均保留。
- 待办动作仅用已声明精确身份：subject_id 打开“查看相关依据”（缺少工资时不能把档案叫工资记录）；明确 bank_account_id 定位资金账户/流水；报表 location 定位对应期间和凭证。缺少稳定定位的事项保留完整中文问题和来源详情，不能从 field、姓名、编号外观或金额猜关联，也不将错误码直接转换成业务追问。
- 资金摘要使用已返回的 list_summary，完整摘要展开。资金/基金 reference 已核对来自正式 j.number/e.number，使用公司+凭证入账月+正整数凭证号进入现有 brief focused_voucher；不使用付款日期或业务来源月，不从摘要解析。焦点凭证始终独立于当前分页集合。银行原始摘要保留原文；无真实原文时不伪造入口。

代表路径：
1. 选公司/月份 → 看盈亏与账面资金 → 打开月末待付来源 → 查看该业务月末未结与当前后来付款 → 查看付款/原业务依据；两个时点金额不混为一谈。
2. 资金 → 选后页账户 → 查看全月筛选明细 → 展开短摘要 → 精确凭证 → 浏览器返回恢复筛选后重新读取，不恢复旧游标。
3. 员工 → “本月有工资”筛选 → 某员工 → 来源期款项、实际扣税和申报分别查看 → 付款来源凭证；所有金额来自对应完整汇总。
4. 资产 → 待启用或项目投入 → 取得/投入与整批结算 → 精确来源；未知金额保留可核对候选。
5. 报表 → 查看季度摘要与阻碍 → 定位相关月份/凭证 → 返回刷新 → 生成文件 → 任务成功且下载验证通过才交付。

## 4. 实现边界、状态及分阶段落地
第一阶段：在现有 App、ModuleHeader、SectionNav、PeriodPreparation、Pagination 和 context 范围内完成导航、统一上下文、层级与恢复模式；适量调整 props/emits 和明确前端展示类型，不新增前端依赖。
第二阶段：逐页按上表重排，补资金精确链接、员工稳定列表列、来源展开与待办定位；默认摘要行和窄屏卡片共用同一份数据与详情状态，避免隐藏组件重复发请求。
第三阶段：集中完成五页协作、实际浏览器与收口证据，整理 T6 实际增量、效果、适用代码状态和遗留问题回传架构审核。

统一恢复规则：公司/期间切换立即清空旧内容并显示新上下文加载状态；初次失败在本页重试；续页/详情失败只在该集合或详情显示重试并保留同版本成功数据；独立集合各有 loading/error/controller，不以一个 loadingMore 阻塞另一展开。snapshot 或 file_jobs collection 版本变化时明确提示“资料已更新，正在重新读取”，使旧分页/详情失效并重读；恢复不再次拼接旧页。取消请求不显示错误，迟到 success/catch/finally/焦点操作都必须检查世代。登录失效沿用负责人登录入口。

空态区分没有可查看月份、本月确实无业务、筛选无结果、未提供资料、尚未加载、未知/不完整与读取失败；筛选无结果可清除筛选；不得显示错误的零值卡片。正常未关账不是警告。
布局断点沿用现有 900/720px：桌面保留侧栏、多列金额与列表；中间宽度重排两列；手机单列/两列小指标、44px 操作区和底部安全区。资金摘要行在窄屏重排为日期/对象/金额/状态，账户与依据展开；员工卡片/列表保留但固定列稳定。财务原表维持可访问的局部横滑并提供提示。长名称/摘要/文件名可换行，键盘、焦点可见与减少动画偏好有效。

公共 HTTP、核算、查询规则、数据库版本、权限均不变；只补齐前端已返回但尚未声明的展示字段类型和少量路由/组件接口。没有发现本设计必须新增的页面投影。若实施发现精确对象、当前清偿汇总或全量搜索能力确实不足，先回报用户需要、现有字段和最小补充，等待架构批准，不在前端推导替代。
不处理 T5 已接受 P3 断连日志，不部署、不访问真实资料、不生成正式备份、不打包交付、不提交覆盖前序成果、不创建后续任务。
