# 用工关系与月度名册

人员身份长期稳定，员工和劳务共用同一个人员对象。同一时点只有一种用工关系；工资、奖金和劳务核算保留各自事实、精确采用版本及所属月份。

## 登记和变更

`register_worker` 原子创建人员或复用明确身份，登记管理资料与第一项用工事实。`data.action` 必须是 `hire` 或 `start_labor`，`effective_date` 保存实际日期或明确月份。复用身份必须提供 `entity_id` 和当前 `expected_revision`，不能按姓名自动合并。`hire` 可以明确提交 `initial_unpaid_leave=true`，直接形成入职即停薪的关系。

`change_workforce_relationship` 提交人员、档案版本、来源、证据及幂等键，支持 `hire`、`start_labor`、`unpaid_leave`、`resume`、`depart`、`end_labor`、`to_employee`、`to_labor`。结束后可重新入职或开始劳务；互转使用一个原子事件。转换到员工也允许明确入职即停薪，不能从零工资推断停薪。

事件以产生它的档案版本编号为身份。更正通过 `replaces_event_id` 引用尚未被替代的本人员事件，提交完整替代事实，原版本继续保留。`after_event_id` 只证明业务先后，不补造日期，也不能指向其他人员。日期与先后关联冲突、同月顺序未明或状态转换不成立时，返回结构化 `fact_issues`，事务全部回滚。只接受已经发生的事项。

写入结果仍为 `status / entity_id / profile_id / revision` 四字段，沿用档案审计类别和管理版本。重复请求返回原结果；相同键不同载荷、版本冲突、来源问题及生产读取模型失败均不留下部分身份、事件或回执。

## 唯一来源与读取

`entity_profile_revision` 只保存管理资料和本次类型化 `workforce_event`；不重复保存派生状态、完整区间或旧基线。普通 `update_entity_profile` 是部分更新，省略字段保留，显式空值仅清除允许为空的资料。它不接受用工事件、状态或起止日期，改名不复制事件。

程序从有效事件推导 `regular`、`unpaid_leave`、`departed`、`labor`、`labor_ended`、`unknown` 及状态段。无事件只能表示未确认；报酬、对象启停或未来入职记录不能代替过去关系。实际日期表示新状态从该日生效，区间前含后不含。年月精度原样保留，月边界不足以确认状态实际持续时保留未明确，程序不自动填成月初或月末。负责人明确确认管理起始日为对应业务月份1号时，可以该实际日期登记，并保存确认原话及适用范围；原件中的服务日期和核算所属期仍各用自己的来源。

`workforce_relationship_history` 默认每页20条，返回事件、精度、来源、证据、更正关系和系统登记时间。游标绑定人员、事件版本和查询月份；普通改名不使游标失效，用工变化后重新读取首页。提供 `period` 时同时返回该月状态、月末状态、员工／劳务成员判断及带相关记录引用的结构化问题。

## 看板口径

员工与个人劳务两个模块固定保留，共用“筛选人员”和卡片／列表切换。`collections.employees` 是员工明细，`collections.labor_workers` 是按正式人员身份汇总的“劳务报酬记录”，不再另设劳务人员名册。主集合默认每页20人，服务端先筛完整范围再排序分页，完整人数、筛选人数及已加载人数分别表达。实际用工事件月没有报酬或其他会计业务时，也能在月份上下文读取。

“在职”对员工表示所选月内确认存在正常任职期间；整月停薪仍属于员工，进入停薪筛选。对劳务表示所选月内确认存在劳务期间；月内离职、劳务结束或转换关系仍可出现在当月在职筛选，未来开始和期间未确认者不纳入。同月先劳务后员工可以在两个模块出现，各自区间不重叠，同一模块按人员去重。月内状态和月末状态分别返回，不用今天的状态筛历史月。

“全部人员”的劳务结果包含截至所选月已有劳务关系或当月有正式报酬来源的人；“已离职／劳务结束”分别判断员工离职和月内或月末劳务结束，转换为员工也属于劳务结束；“未确认”保留关系不明确的人。停薪留职筛选的劳务结果为空，“已确认不在册”只包含所选月明确没有劳务期间的人。已有工资或劳务业务但缺关系的，保留业务与金额并标识未确认，不从金额反推关系。

劳务卡片展示所选月状态、劳务报酬、已扣个税与应付净额。`gross_fen`、`booked_tax_fen`、`net_fen`、`personal_labor_fen`、`capitalized_labor_fen` 使用整数分字符串，`source_count` 表示该人员本月记录笔数。服务端核验同一所选入账月份、同一快照的完整正式采用来源后汇总，多笔来源合并为一人一张卡；无当月来源时各金额显示真实的 ¥0.00，注明“本月暂无劳务报酬记录”且不提供付款入口。读取或完整性错误不能当作零值。

默认响应只读取员工和劳务人员集合。展开人员才使用 `section=labor_sources&employee_id=<人员身份>` 读取该人的逐笔报酬，各人独立分页；费用和资本化分类、各笔付款详情仍保留。收起取消未完成读取，重开复用有效缓存；公司、月份、刷新、快照或筛选变化时清除旧展开缓存并拒绝迟到响应。人员筛选并行更新两个主集合，各集合独立失败和重试，概览保持全公司口径。劳务人员游标绑定筛选，不跨筛选拼接。员工响应合同为13，读取模型内容版本为6，人员完整金额、精确来源及筛选目录共同认证。

闭期名册使用最新确认的业务历史，关账时的管理版本保留查证。后补或更正只改变管理读取，不触发工资重算，不改冻结金额、凭证、材料采用及关账内容。

## 验证和重放

开发使用当前合同新建合成公司，不迁移旧档案基线，不接受旧任职入口。重放文档分别列出身份、用工动作、生效时间与精度、来源、先后和替代关系、工资核算资料及劳务业务。入职前不自动归劳务。劳务开始时间采用原件或负责人明确确认；负责人已确认以对应业务月份1号作为管理起始日的，直接写入事件并移除该起始时间缺项，其余未确认事实继续列出。

真实空库重放另行执行，只使用整理后的重放文档重新绑定身份与版本。现库、原件及备份保全；代码和合成验证通过不执行换库、服务切换或真实登记。
