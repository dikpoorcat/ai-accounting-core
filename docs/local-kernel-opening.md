# 有依据的期初接续与来源发现

期初接续使用一个公司、一份总清单和一个建账月份。它记录已存在的资产、负债、权益及核算累计数，不重放或补造历史收入、支出、收付款。普通命令仍只接受类型化业务事实，没有自由科目、借贷方向或任意分录入口。

## 期初事实

| 类型 | 采用的事实 | 后续用途 |
|---|---|---|
| `opening_bank`、`opening_cash` | 明确账户身份和余额 | 资金余额、首月银行对账 |
| `opening_obligation` | 原业务编号、对方、往来性质、未清金额 | 实际收付款或既有抵销入口核销 |
| `opening_asset` | 原值、累计摊折、实际启用日、年限、已摊月份、残值、用途、取整规则 | 连续折旧／摊销、处置 |
| `opening_money_fund` | 明确短期分类的货币基金身份、产品、持有成本和计量依据 | 后续赎回成本结转，归入总清单资产数量 |
| `opening_loan` | 合同、贷款人、本金、已计未付利息、接续计息起点 | 还本付息及本金变动日分段计息 |
| `opening_tax` | 税种、税务机关、原税期、应付／可退金额 | 实际缴款或退税核销 |
| `opening_payroll_payable` | 人员、实际收款方、原工资月、工资／税／社保公积金组成、未付金额 | 实际发薪和缴款 |
| `opening_payroll_state` | 人员本年截至上月的完整个税累计，以及是否已使用奖金单独计税 | 后续工资及奖金计算 |
| `opening_equity` | 实收资本、资本公积、盈余公积、留存收益及其持有人或依据 | 期初资产负债表 |

每项事实必须有不可变证据。每项包含相同 `package_id` 和建账月份；建账月份是接续边界，不冒充历史实际付款日期。往来性质、税种和权益类别限定了内核映射，不能由调用者提供科目。资产卡片须与已声明直线法及取整规则的累计数一致；不匹配应先核对卡片，不能自动补计历史费用。当前卡片范围为已启用的固定资产、无形资产；货币基金另有类型，详见[投资处理](local-kernel-investments.md)。借款范围沿用人民币、持牌机构和既有计息规则。

`opening_package` 引用全部明细业务身份，并对银行、现金、往来、资产、借款、税费、薪酬未付、薪酬累计和权益分别填写数量。零项也必须明确确认。贷款清单项另外引用其明确合同。总清单会核对引用完整性、重复身份、期间、合同以及整体平衡；缺项或不平衡返回 `needs_information`，不自动生成平衡差额。

先保存全部明细和总清单，再把总清单及明细放入同一个 `preview`／`confirm`。计算按依赖顺序执行，整个确认保持原子性。未被正式总清单采用的明细不能被核销或用于摊折。明细核销复用已有 `Payment`、`CashPayment` 和 `Settlement`，`source_kind` 为相应 `opening_*`，`source_id` 为原明细身份；贷款义务名为 `principal`／`interest`，其他未清明细为 `primary`。

总清单输出独立期初账户行和辅助余额，不产生凭证编号，不进入当月发生额、收入、费用或现金流。投影可从不可变计算重建。零期初也保留正式接续标记。首次期初必须先于正式业务凭证和关账；已关账期初不得通过修改月份或再次发布原地改变。

## 接续报表

`continuation_report_profile` 指定公司名称、准则、建账月和总清单；旧 `report_profile` 继续表示有明确依据的新设企业零期初。

一月接账可以直接从总清单形成资产负债表年初数。年中接账时，期初余额不能说明此前利润和现金流，因此完整季度三表还需要 `report_carry_forward`：原年初资产负债表，以及接账前本年、本季累计利润和现金流的固定模板全部行。对原报表进行合计、平衡和现金勾稽检查，零值也须明确提供。它属于报表补充依据，不生成分录，仅更新管理版本。

缺少历史累计不会阻止核算关账，但会阻止完整三表导出。关账后的补充必须通过 `report`／`preview_report_export`／`confirm_report_export` 的 `carry_forward_fact_id` 显式选择不可变版本。系统不会静默采用最新版本；导出计划冻结所选事实 ID，原关账清单保持不变。当前账目的分类、当前会计来源及闭期版本保护继续有效。

## 跨会话发现

`company_context` 返回绑定公司的身份、公司业务说明及版本、可检索类型。说明是管理背景，不能替代核算事实。`update_company_note` 要求 `expected_revision` 和 `request_id`；并发修改返回当前版本，调用者合并后重试，不能直接覆盖另一会话的说明。内容与可选证据按版本只追加，只递增管理版本。

`find_facts` 可按 `kind`、`person_id`、起止月份及 `current`／`pending`／`published`／`history`／`deleted` 状态检索。人员筛选适用于明确声明 `employee_id` 或 `person_id` 的类型。结果包含事实内容、稳定业务身份、事实版本、证据和发布状态；`after_id` 游标每页最多 500 项。查询始终绑定一个公司数据库，不借用聊天记忆或另一公司的事实。

验收在隔离空库进行：`tests/kernel/test_opening_continuation.py` 覆盖期初平衡、收付接续、资产、贷款、工资累计、银行对账、闭期边界和补充报表；`tests/kernel/test_discovery.py` 覆盖说明 CAS、管理版本、证据保护、分页和跨公司隔离。
