# 凭证候选的期间范围：r29 同类排查

触发：请求明确一个月或已排除冻结月份，但 SQL 先按会计科目扫描历史，或先扫描整年再排除。返回条数不随历史增加，实际扫描却增长。此前 A 类排查已处理事实期间和引用目录，漏查了 `Journal._sql` 的科目候选与报表全年凭证候选。本组补齐该范围，保留所有后续正式发布选择、采用证明及内容检查。

| 位置／调用方 | 实际证据与处理决定 |
| --- | --- |
| `Journal._sql`，月度 `FundsRead` → 简报、资金汇总及默认／按需明细 | 固定 r28 主 12／48 月都只返回 504 个资金凭证，强制 `voucher_line_account` 后按月过滤分别需约 44,900／171,900 VM。私有原型先以 `voucher_period` 定位本月，再按凭证主键检查科目，两档均约 20,000 VM，候选完全相同。决定仅改明确月份路径。 |
| 同一个 `Journal`，未限定月的财务位置、融资明细、历史账户 | 全历史截止月是实际业务范围；按科目先定位可以排除大量非命中凭证。保留原路径，不把月度策略扩成全历史扫描。 |
| `Reports._report`，年度未被有效冻结 flow 覆盖的候选，两处分支 | 主 48 月返回 1,026 个开放凭证，但扫描本年全部历史后排除冻结月，约 149,800 VM。报表组核对先从最多 12 个实际候选月定位；历史往来回退的科目范围保留。修复与验证由报表范围组记录。 |
| `position_v1._V1SelectedJournal` → 固定 v1 历史独立核验 | 未限定单月，实际需要历史科目来源；保留独立规则，不引用当前页面快路。 |
| CLI/MCP、关账、完整核验、维修、备份恢复 | 看板 CLI/MCP 复用同一 `Journal`；正式关账、完整核验及修复仍以原权威来源独立验证，不借候选筛选省略内容。固定版本 verifier 未修改。本组功能回归尚未完成。 |

私有只读原型使用 r28 源、已独立核验的主 12 月 r28／主 48 月 r26 合成库，[三份合同逐字节核对](stage9-account-period-scope-r29-contracts.json.gz)一致。两档各 ABBAABBA，资金页完整业务响应摘要相同；[原始记录](stage9-account-period-scope-r29.json.gz)保留全部样本。当时同时运行建库与完整核验，线程和 CPU 诊断不能当整页计时：12 月原生 CPU 中位 281.25→265.625 ms，48 月 531.25→390.625 ms；实际收益须固定整组后在隔离浏览器验证。

`dashboard_reads._account_voucher_ids` 已在明确月份时改为期间索引，未限定月仍用原科目索引；`Journal` 后续选择和核验未改。新增 4 项真实 SQLite 工作量测试及 Ruff 通过：空集合、重复科目、多行同科目、截止月、月份空隙、冲正及未限定月结果均保持；固定 1／100／500 笔本月数据，无关同科目历史增至 12／48／120 月后实际 VM 只允许索引深度的微小变化。成组回归已随 r29 固定候选完成，25 文件 344 项通过，源码前后清单一致；默认六入口完整响应与 r28 相同，详见下段。仍不宣称 500 ms 达标。

r29 固定只读源码的默认六入口对照已完成，完整业务响应与 r28 相同，仅每档 8 个生成时间／读取版本字段差异；返回行与字节逐页不变。资金 VM 在主 12 月 1,155,700→1,111,200、主 48 月 1,586,300→1,287,800；简报也分别 3,295,100→3,127,100、4,314,300→4,019,300。两项与同版报表／context 选择变动同时进入请求，不能把全页差值全部归给 `Journal`。原始六入口记录和合同、证据限制见[报表上下文同组记录](grouped-report-coverage-range-r29.md)。该插桩诊断不是纯浏览器验收，r29 受影响组回归与主 12 月独立完整核验均已通过，证据见[同组记录](grouped-report-coverage-range-r29.md)；主 48 月独立完整核验亦已通过，见[同组记录](grouped-report-coverage-range-r29.md)；纯浏览器验收仍待结果。
