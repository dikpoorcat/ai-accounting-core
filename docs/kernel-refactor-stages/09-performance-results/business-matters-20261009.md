# 同对象且同事项：实现与验证（2026-10-09 至 10 日）

本月发生与应收应付按正式对象身份和具体事项归组。分类只用于导航，不作为事项身份；工资、奖金、个税、社保、公积金及各税种分别列项。按负责人确认，工资、奖金计提及完整税期确认仍保留整项和原公共金额口径，实际缴付与应付义务分别列项。日期、所属月、用途和银行／现金／平台渠道不同，不拆开同一事项；不能明确事项或对象的记录保留单项。

本月实际缴款对象来自精确采用的正式收款人；应付社保、公积金对象来自正式员工身份，各自跨工资月归组，详情各有个人、单位两项。相同姓名的不同身份、多对象集合及原多人付款批次边界保持。混合凭证按义务事项拆成成员，金额守恒，预览去重后展示完整原凭证；原用途、档案备注和管理备注保留，共用文字标为“整单说明”。未知金额不转为零，异常状态不被汇总掩盖；关账历史使用原精确采用来源。

## 读取和合同

小型共享事项解析函数统一两处组摘要、付款分项和名称。没有新增数据库结构、持久投影、跨请求证明缓存、Store 或通用分组框架。服务端先形成完整范围组摘要，再分页20组；首屏只读摘要，展开专用 `brief-group` 每页20笔成员和配对精确凭证，进展按需读取。完整金额与组／笔／去重凭证计数不依赖已加载页。

`detail_scope_key` 与精确凭证共同约束成员详情，替代 `detail_scope_category`；响应、游标、请求 URL 关联与缓存都核对范围。HTTP、CLI/MCP、生成 TypeScript 和 Ajv 同步升级为 brief18、brief-group3、business-status10，不保留双选择器。单凭证号定位完整原凭证，多事项成员通过身份定位；首屏以外直接定位，不逐页寻找。

两处根分页只继续当前分类尚缺的组，按完整分类 `group_count` 和已加载唯一组键判断，当前分类完整后停止，切到未读齐分类继续原全局游标。未选分类首次切入可能需要读取，当前分类的完整可见内容保持；隐藏分类续页退出当前刷新等待链。独立凭证分页未改。收起、切范围、重试、迟到响应和增量追加沿现有保护。
