# 精确编号查询的索引退化

本轮这一类缺陷已修正并完成对应验证。正式冻结、打包和整页 500 毫秒验收不在本轮执行范围。固定验证源码为 r37：`eee15731556fd7087541bf867eef166aa1006c59d5b3ad65e86a0313d40cb996`。

## 根因与范围

触发条件是新增 `fact_id_subject_cover`、`subject_id_kind_cover` 后，SQLite 重新安排了部分连接顺序。调用方已经给出精确的事实编号集合，但查询先扫描某类主体及其全部修订，再反复遍历编号集合。结果未变，工作量却随无关记录增长。

此前只验证了新索引直接服务的报表查询，没有充分检查索引对其他连接计划的影响。本轮按同一根因补查当前读取、固定 v1、五页、关账、完整核验、修复与备份恢复；不把所有代码相似的查询都改掉。

| 位置 | 调用范围与实际证据 | 修改决定 |
| --- | --- | --- |
| `frozen_material._frozen_versions` 的四类资料、两个 SQL 分支 | 关账存储解码、当前准备和核验；12／48 月新索引均先扫描业务种类，旧结构按精确 ID 查找 | 从给定 ID 集合驱动全部内连接，保留类型、封签和结果数量检查 |
| `frozen_material._changed_sources` 的冻结封签计数 | 当前资料与冻结资料比较；四类资料均已核对原查询与修正后的执行计划 | 仅调整该计数查询；当前资料的完整集合差异检查保留 |
| `close_storage_v1._v1_frozen_versions` | 固定 v1 冻结内容、完整核验、备份恢复；镜像查询已复现同样计划 | 独立修正 v1 查询，不转用当前领域规则 |
| `report_flow._refs_from_ids` 与 `report_flow_v1._refs_from_ids` | 当期和冻结现金流来源；两档新结构均先扫描同类事实，指定 ID 落到内层 | 保留分类事实、主体类别及精确采用检查，调整连接驱动范围 |
| `reports` 的历史分类备用读取 | 报表缺少当前分类时按精确冻结 ID 取依据，已确认相同计划变化 | 同组修正，并覆盖备用分支 |
| `content_v1`、`storage`、`integrity` 精确事实装载 | 12 月新旧计划仍按 ID 查找；部分 48 月连接遇到锁，未作通过结论 | 不改；48 月未测路径明确保留限制 |
| 五页共同结果装载、资金对账单、对象及任务引用 | 已测代表查询没有由索引引起的全类扫描；已有固定 ID 驱动或左连接 | 不按外观批量改。旧有先按类别扫描的税务档案查询另列，不混成本次新增退化 |

修正采用职责所在查询内的明确连接顺序，不撤回有实际收益的索引，不增加 `ANALYZE`、业务缓存或省略核验。

## 已取得证据

真实 12／48 月合成库的资料查询：48 月取一条处置版本，原查询约 1,248,000 SQLite VM 步，精确 ID 驱动少于 100 步；取 100 条时，原查询超过 3,000,000 步后由诊断上限中止，修正方案约 2,700 步并返回 100 条。处置、来源和分期资料分别测量；大样本没有组处置数据，该分支另由非空合成回归验证。补充对照使用保留的原结构合成源执行原 SQL，12 组全部返回结果与新方案一致；中止的坏查询本身不算结果一致证明。这里记录的是实际工作量，不是页面耗时。

r36 的 12 月复制、完整核验及当前预览已完成，整个流程约 373 秒；48 月逐表复制完成，但后续进程已结束且没有完整回执，仍属未验证。旧失败、暂存目录及原始记录保留。本轮不再重建这两档库，用只读诊断定位查询，再用新建的小型业务样本验证行为和无关数据增长。

## 验证结果与收口

最终修改为五个生产模块的八处 SQL，保留原投影列、连接谓词、参数、去重和排序。独立复核未发现语义变化。新索引及公司／目录结构合同保持原样；因固定 v1 读取代码改变，隔离候选的内容合同摘要相应更新，仓库正式合同没有冻结。

- 固定源码后统一运行 26 个受影响测试文件，**336 项通过，零失败、零跳过**，约 465 秒；验证前后源码一致。范围包括五页后端及合同、按需准备、当前与历史资料、关账、内容核验、投影修复、备份恢复和服务入口。没有重跑无关前端构建或整库大套回归。
- 新工作量回归使用本期真实结构合同的相关表及索引，覆盖全部四类资料、当前和固定 v1；增加 180 个无关主体及每主体两次修订后，精确查询的执行量保持在规定余量内。现金流来源另增加 360 个主体及双修订。空集合、重复输入、缺失编号、缺封签、错误类型，以及期间／凭证两种筛选路径均保留原结果或拒绝行为。
- 报表备用读取通过真实业务登记、发布和关账建立场景；保留完整报表结果，加入 48 条未来同类事实后，目标季度的结果不变，备用读取工作量不明显增长。测试以业务结果和 VM 步数断言，执行计划文本只作为诊断原件保留。
- 用同一固定代码对现有 **12 月、50 人、每月 1,000 笔**合成库执行登记版本的完整内容核验，并重新生成真实开放月关账预览，均通过；完整核验覆盖 30,225 个事实版本、12,413 个计算、12,309 个凭证版本和 11 次关账，无核验限制。完整核验约 97.5 秒为诊断记录，不能与包括复制的旧流程约 373 秒直接比较，也不作为页面性能结论。
- 本次文件的 Ruff 与差异检查通过。全仓库已有的前端文件末尾空行问题不属于此组，没有趁机改动。
