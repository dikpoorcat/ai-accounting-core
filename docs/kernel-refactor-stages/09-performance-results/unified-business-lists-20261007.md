# 三处业务清单统一样式与排序验证

## 展示与读取

资金按业务、本月发生按业务及待收待付共用行字号、间距、分隔线、悬停、金额及末尾展开箭头。1200px及以上将对象与事项分列，列顺序分别为日期／对象／事项／方向／金额、业务时间／对象／事项／状态／业务金额／凭证、对象／事项／状态／待收待付金额；较窄屏幕统一为对象在上、事项在下，时间、状态、金额和凭证重新排列。事项使用现有简明字段，完整说明中新增内容保留在展开区，去重只比较实际可见的完整文本。

原行继续绑定各自准确记录、带符号金额、业务身份及精确凭证版本。没有业务身份的行不提供展开提示。整行点击、Enter／空格、同一区域单行展开、内部操作隔离、按需加载、缓存及迟到响应保护保持；社保公积金四项归并与详情拆解保留，原行事项只写“社保与公积金”，不附月份。

资金和本月发生按实际日期升序，同日按完整显示对象固定字符升序；按月确认在当月实际日之后，缺日期最后，不补造日期。待收待付分类内按对象、事项及正式身份排序，不按未显示的工资月份排序；社保分项采用统一事项前缀及正式分组键。同名不同身份和多对象的完整范围保留。

服务端复用已核范围，批量读取类型化日期及正式对象身份标量，名称复用现有展示档案读取与核验，确定全范围顺序后再装载本页正文及分录。冻结待付保留目录的完整成员及历史摘要依据，排序只投影固定state中的来源、对象及分类；选中20条才装载和核验完整state，第21个目录键仅判断续页。非排序冻结消费者保持原读取行为。历史余额不由当前结果替换，真实库结构、身份、业务及资料保持。

排序标量属于展示定位信息，不充当金额或采用证明；非选中完整业务事实及state不额外展开或逐个计算payload哈希。选中正文仍执行原事实、分录、完整state哈希及精确采用来源核验，完整目录和汇总检查保留。候选排序成本仍随范围N增长，通常为O(N log N)；资金增加一次作用范围标量SQL，明确义务的窄关系查询仍可能随匹配祖先增长，名称档案读取也随候选对象数量增长。本轮验证正文页边界和现有库刷新，不声称所有查询扫描量固定。

默认及业务续页的配对凭证只进入精确版本预览索引。首次手动切入按凭证以现有`section=vouchers`、无游标请求凭证号顺序的前20张，失败可重试，同范围复用；独立列表分页和全部模式仅使用自身游标。点击已加载凭证本地精确定位，不初始化独立列表；仅显示选中凭证时说明范围。两种流采用不同内部排序模式，旧排序游标失效。切回按业务或离开本月发生取消凭证集合读取，重新进入人工选择的集合可继续，精确定位不自动读取全部。默认刷新不增加请求或等待，已展开详情按原规则允许后台续读。

接口地址和简报14、资金9、详情7合同及生成响应格式保持不变，没有新增依赖、数据库字段或业务写入入口。前端沿游标增量追加，不重排或克隆已加载的集合，金额继续使用整数分字符串和BigInt。
