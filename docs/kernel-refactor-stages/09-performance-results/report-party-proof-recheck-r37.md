# 报表往来来源的重复工作复核

**没有找到值得实施的重复核验修复，本组停止，不改生产代码。** 工作区保持 r37。此前 r38 合并查询的试验已因没有主路径提速而撤回，不能把它计入优化成果。

本次用主 48 月合成公司的真实 2019 年第 4 季度报表入口，在一个只读快照中记录实际 SQL、返回字节、来源 ID、解码和缓存命中。沿季度页、简报报表 worker、公开报表、导出及 CLI／MCP 的共同读取核对范围；关账、完整核验、修复、备份和固定 v1 仍保留独立核验责任。其他页面没有本次同型重复证据，不能写成已经排除全部读取问题。

| 路径 | 实际结果 | 判断 |
| --- | --- | --- |
| 前一年末与本期期末 | 不同截止点，前者返回约 377 KB，后者约 8.918 MB | 两份账面基线有各自用途，不能合并成同一口径 |
| 首次开放贡献 | 938 个精确 ID，解码 938 次 | 首次必要读取 |
| 后续贡献 | 请求 1,003 个 ID；937 个命中同快照，66 个首次读取 | 没有再解码共同来源 |
| 全请求贡献 | 1,004 个不同 ID，解码 1,004 次，共约 3.059 MB | 来源正文没有重复解码 |
| 月度 flow | 首次读取所需月份；相同 11 月后续调用均 0 SQL、0 返回字节 | 已复用成功核验 |
| 字节完全相同的再次返回 | 在本期末往来范围仅观察到 3,733 B，来自少量关账头 | 不能据此声称有足以解决整页耗时的优化 |

全请求为 635 条 SQL、26,961 行、10,953,779 B 返回值、约 1,235,700 SQLite VM 步。父子阶段计数互相包含，不能相加；VM 每 100 步采样。返回字节不是磁盘读取量，≥256 B 的同值检查也不能证明小字段和所有 Python 中间对象均无重复。

诊断中的计数、哈希、全局 profile 和内存记录会明显放大耗时，不能拿它与独占计时比较。此前原生接口中位约 725.6 毫秒也不是浏览器整页时间。原始脚本、结果和审查保存在[证据清单](report-party-proof-r37-manifest.json)。

结论只到这里：主要来源、依赖及月度 flow 没有被二次装载或解码。不能删掉首次核验，也不再增加缓存。后续排查转向已有 12／48 月数据中的扫描范围和装载范围增长，先找具体证据；没有新证据，不重跑本组。
