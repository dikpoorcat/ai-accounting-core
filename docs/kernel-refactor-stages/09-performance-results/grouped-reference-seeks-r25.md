# 精确目录查询仍扫描大量期间行：r25 范围与决定

固定 r25-final、已独立核验的主 48 月合成库。只读私有对照见 `grouped-reference-seeks-r25.json`。与后台构造并行，VM、返回多重集及执行计划用于判断工作量；CPU 的 Windows 量化结果不当作页面计时。

## 根因及此前遗漏

`BusinessQueries._selected_accounting_references` 必须读取精确凭证／关账月／路径的全部命中，包括被篡改的 `reference_type`，再交给原校验器拒绝。现有索引首列是类型；不限定类型时，SQL 按期间／路径读大量其它凭证后再筛 ID。此前的期间半连接解决了密集候选重复扫描，却漏掉了资产默认页的稀疏跨月分布；不应把这次当成无关的新优化。

真实资产页三次读取分别取 47／47／93 行，却各约 521k VM。私有候选先沿现有索引逐个定位数据库**实际存在的全部类型**，再按类型、ID、期间精确查找；不使用允许类型白名单，不漏掉未知错误类型，不增加结构或跨请求缓存。结果多重集及重复请求次数相同，三次约为 3.2k／3.2k／6.2k VM。

同月 1／100／500／1,000 个候选也做 ABBA：旧半连接约 11.1k／13.8k／24.6k／38.1k VM，新选择约 0.2k／6.6k／32.2k／64.2k。密集500、1000项固定工作更多，但仍随实际命中增长；稀疏查询不再随无关历史目录行增长。采用同一个选择规则，不新增猜测阈值或第二套业务口径。

## 同类位置与处理

| 位置及调用方 | 检查结论 | 决定 |

| `_selected_accounting_references` → 员工、资产、简报长期资产、资金及 CLI/MCP 业务详情的 `_selected_accounting` | 真实资产默认页复现；原合同明确保留错误类型命中 | 在这个共同选择点修改，全部调用方继续原来源／叶子核验 |
| `read_indexes.selected_voucher_references` → `QueryReads.verify_selected_voucher_adoptions`、`Journal.hydrate` | 前一组已改 ID 驱动；合同原本只选择 voucher 类型，没有本次缺首列问题 | 保留已修实现和原截止期、重复引用验证，不扩大类型语义 |
| `dashboard_funds`、`dashboard_reads`、`dashboard_metadata`、`selected_voucher_sql`、报告凭证选择 | SQL 明确限定类型与精确 ID；已知页面计量未发现同型期间全集扫描 | 保持；管理快照非空详情部分仍未动态验证，不写成全部排除 |
| `report_flow`、`report_projection` 及其 v1、`position_v1` | 按分类／凭证 ID 或有意完整范围核验；不能把目录定位替换成采用权威 | 保持现有逻辑。固定 v1 不调用本次共同函数；其独立完整核验不改 |

| `dashboard` 资料／分类缺行检查、`FrozenFactSet` 成员判断 | 涉及多种来源和负面证明，与本次精确凭证元组不是同一语义 | 不为统一代码合并；无新增收益证据，继续记录原有未验证成本 |

## 验证边界

计划同组验证空集合、重复元组、未知／空字符串类型、错误路径、跨期间、1／100／500项及增加无关历史后的 VM；调用真实生产选择函数，结果与原完整查询多重集一致。坏类型继续交给生产校验器拒绝。源正文、采用依据与冻结叶验证不变。随后固定全组代码，统一受影响回归与五页工作量／响应对照；本记录不是最终500毫秒验收。
