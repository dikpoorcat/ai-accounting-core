# 经营简报长期资产净值恢复

本轮恢复账面资金之后的金色“长期资产净值”卡片，包含固定／无形在用数量，点击进入同公司、同月份的资产概览。简报合同由 14 改为 15；首屏增加 `long_term_assets` 的净值和两个数量，集合续页省略摘要并保留前端已加载值，默认刷新仍为上下文和主响应两个请求。

净值复用同快照已核的 `1601 + 1701 + 1604 + 189901 + 4301 + 1602 + 1702`，保留 2.1 的待启用和项目成本口径。数量从有效取得、期初、整批取得、启用和处置来源中按资产身份去重聚合，统计所选月末仍在用的资产。采用、冻结身份、完整启用成员及精确事实来源核验保留，不组装资产卡片、折旧明细或项目详情，不新增缓存、投影表或读取框架。

## 排查与实现

| 触发条件／根因 | 位置及判断 | 处理结果与剩余成本 |
| --- | --- | --- |
| 只需两个数量却复用完整资产来源整理 | 原 `_long_term_assets` 会构造卡片来源及读取项目余额，且返回五个未消费字段 | 使用本地 `_active_asset_counts`，取得／生命周期按已核事实版本主键读取，最终 `GROUP BY asset_type`、`COUNT`；只返回三个字段 |
| 金额已有同快照余额 | 首屏资产负债摘要已读取 `snap.accounts` | 七科目整数加法，已核余额路径新增 SQL 为 0 |
| 批量启用没有独立发布，替换与冲正不能裸数成员表 | 复用现有启用成员采用及顺序折叠 | 必要启用所有者和成员核验保留；冻结目录发现仍会读取所选范围内的折旧所有者身份目录 |
| 卡片可能未完成而刷新终点已经结束 | 真实卡片金额、两类数量及全部可见默认内容 | 新增缺卡片、缺金额、缺数量和旧金额／数量拒绝就绪回归，继续使用连续两帧稳定终点 |

## 业务与读取量验证

`test_dashboard_long_term_assets.py` 的 8 项测试覆盖期初、跨月、七科目净值、固定／无形批量启用及撤回、整批取得与单卡去重、处置、更正、冻结月份，以及必要来源损坏时拒绝返回更低数量。数量与资产页全公司摘要一致。首屏合同、摘要省略与续页保留另由后端及真实 Vue 测试覆盖。

聚合每次只执行一条 SQL，返回至多两行。`EXPLAIN QUERY PLAN` 的六个类型化事实分支均按 `revision_id` 索引检索；生命周期先物化分组，再以 `AUTOMATIC COVERING INDEX (asset_id=?)` 连接。仍有六次所选来源 JSON 遍历及分组临时 B 树，没有逐资产扫描全部生命周期的路径。
