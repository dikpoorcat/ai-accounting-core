## 计数错误与恢复边界

四分布的复制及声明升级均实际exit0。原f078后处理门禁把verification中的凭证版本数61,413错比voucher编号主体数60,057；三独立样本两种计数恰相同，准备检查遗漏了压力样本的版本多于编号分布。压力升级的完整内容核验及两种表各自保留都通过，随后序列／marker失败，旧主v3控制器exit1；这不是浏览器500ms失败，也不是迁移失败。

新共享门禁只把`vouchers`对应表改成`voucher_version`，其余来源、三次四coverage核验、247原表、身份／历史／FK／TRUNCATE断言保留。定向实际noDB导入检查接受四组真实回执，并拒绝原错映射及损坏版本数；SQLite／process／thread／Win32尝试均0。发现恢复收尾只写failed却可能exit0后，另做窄修：收尾receipt写盘后controller_failed退出1；r2仅检查最终导入／绑定及两个正常状态exit0、失败状态exit1，没有再跑四组或数据库／浏览器。首次smoke及r2分别保留，不合并成新的业务验证。

恢复使用既有12个角色的真实只读HANDLE和原Q／preview，原失败字节冻结；获得新的root空闲声明后只释放原control/start，真实等待全部角色退出，再读取各runner的正常业务／session／source守卫。修共享元数据门禁没有放宽500ms。
