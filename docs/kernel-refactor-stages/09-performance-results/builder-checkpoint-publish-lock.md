# 合成样本断点发布的短暂权限冲突

`MixedBook` 和 `IndependentBook` 只在完整月构造、预览及月度统计写入后发布构造断点。两者原先先写同目录 `.new`，随后只执行一次 `os.replace`；Windows 若在该步返回 `PermissionError`（包括 WinError 5），已完成月份的数据库状态存在，但新断点未发布。占用该文件的进程及拒绝访问的具体原因尚未确定。

测试构造器现在共用 `stage9_checkpoint.publish_checkpoint`：对同一份已写完的 `.new` 最多尝试 20 次原子替换，相邻尝试间等待 0.1 秒。只重试 `PermissionError`；持续失败会抛出原异常，保留旧断点和新候选。普通 I/O 错误不会被吞掉。该函数不推断月份是否完整、不读取或修复公司数据库，也不负责恢复失败候选；调用点仍限于两个构造器原有的月末和关账完成后位置。

定向测试对两个构造器分别模拟首次共享冲突后成功，以及持续权限失败：成功时旧断点在失败瞬间保持原字节，最终新内容发布；持续失败时旧断点不变且 `.new` 内容保留。现有断点恢复测试保持原身份和数据库 epoch 校验。验证：`test_stage9_checkpoint_publish.py`、两个既有 checkpoint 测试共 11 项通过，所改测试构造器与 helper 的 Ruff 检查通过。未对真实主 120 月 `.new` 执行恢复或改写，也未改生产备份发布机制。
