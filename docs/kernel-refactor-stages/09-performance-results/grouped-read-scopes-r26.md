## 保留的必要成本和否决结果

- 工资当前归属仍核验全部有关历史事实；资料档案不能代替工资已发布证明。本组没有用对象目录先删掉待核验候选。
- 报表同一请求的 937 份开放贡献重合已经由原缓存复用，约 1,004 份不同来源仍需核验；23 次月流调用实际只有 12 月执行 SQL。没有再加缓存。
- SQL 构造事实 JSON、仅用原文 SHA 代替类型解码的原型没有稳定默认整页收益，且可接受原解码拒绝的非法年月，未采用。不能把别处有前置封签和物理字段检查的快路直接挪来。
- 名单和最近使用新增的是必要来源核验，可能增加读取；不把安全修正写成提速。负向缺行、完整历史损坏仍按既定完整核验边界处理。
- 当前和 v1 实现分别保留职责。本次 v1 源码在首个正式合同冻结前修改；新候选必须重新生成内容描述并独立核验非空历史样本。r25 的通过不能代替 r26。

## 固定后统一验证

代码收敛范围为八个生产文件及对应测试，没有 DDL 或前端修改。计划一次运行 46 个受影响测试文件，覆盖五页、身份、采用、查询、关账、完整核验、修复和备份／升级历史；同时记录源文件清单，结束时确认未变。前端 r25 的 134 项、合同、类型与构建结果保留；没有前端新修改，不重复同一轮构建。

随后用同一固定候选运行主 12／48 月完整核验、五页工作量和完整响应对照。工作量测量可与建库并行，仅作诊断；纯浏览器计时必须等这些工作结束并在完整月检查点停下建库。120 月样本未建成，整页验收未通过，不能收尾。

固定 r26 的主 12 月完整核验已通过；46 文件成组回归 **503 项全部通过**，无跳过、无失败，源码清单前后相同。48 月完整核验亦通过，来源、历史、投影和目录核验均保留。两个样本全验均与其他诊断并行，其耗时不作纯计时结论。原型结果、失败、慢样本和 r25 通过记录保留，不覆盖旧文件。

固定候选五页的完整准备读取已测工作量，主 48 月与 r25 全响应逐字段比较，仅生成／检查时间和构建读取版本不同。SQLite VM：简报 5,547,800→4,305,100，资产 4,613,700→3,066,500；资金 4,049,400→4,055,000，员工 4,061,700→4,070,100，报表 6,292,600 不变。前四页的来源核验使返回量各增加 321 行；员工少解旧行数另省约 18.8 KB，不能把这些额外校验说成零成本。
