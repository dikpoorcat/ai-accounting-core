# v1 公司与目录升级保留矩阵（工作树，待最终验收）

保留职责位于 `backup._RETAINED_HISTORY_ROWS` / `_retained_history_digest`；便携包恢复与离线公司升级共用同一源列摘要。列清单是**v1 原有列**，目标 v2 增列可存在；凡要合法改写这些旧列的未来迁移，必须另有显式源→目标映射和验证，不能让新 verifier/相同行数默许。离线目录库另用 `_CATALOG_RETAINED_ROWS`。以下依据 `schema.py` 及各领域 DDL 的触发器、来源/闭月职责区分，并非扫描所有物理表。

| 类别 | 源目标逐行保留的表及稳定列 | 其他核验 |
|---|---|---|
| 公司/证据/事实根 | `identity(id,company_id,taxpayer_id,database_id)`；`evidence(digest,media_type,name)`；`subject(id,kind)`；`fact_revision(id,subject_id,revision,period,digest)`；`fact_evidence(fact_id,evidence_digest)`；`fact_scope(fact_id,kind,scope_key)` | 证据正文由 digest→SHA-256 全核验；类型化事实根/子行由 `fact_revision.digest` 和 v1 解码核验；`fact_seal` 可由全核验与行身份证明。 |
| 计算/来源链/处置 | `calculation(id,subject_id,fact_id,kind,period,digest,program_version)`；`calculation_scope(calculation_id,kind,scope_key)`；`dependency_scope(calculation_id,source,kind,scope_key,before_period)`；`dependency_fact(calculation_id,fact_id)`；`dependency_calculation(calculation_id,upstream_id)`；`disposition(id,subject_id,cause_id,action,calculation_id,explanation)` | 计算 outcome 由保存的 digest 核验；`calculation_seal` 由全核验，来源边仍保留原值，避免重新用未来当前 selector 推导旧选择。 |
| 正式凭证/发布/关账 | `voucher(id,number)`；`voucher_version(id,voucher_id,calculation_id,period,reverses_id,total)`；`voucher_line(version_id,line_no,account,debit,credit,cashflow)`；`calculation_publication(id,sequence,subject_id,previous_publication_id,calculation_id,mode,posting_period,baseline_calculation_id,voucher_id)`；`period_close(period,digest)`；`material_close_rule(period,rule_digest)` | 关账逻辑 manifest、私有分块/目录及批准引用由完整 v1 核验；物理 `close_storage_*` 是绑定在逻辑 digest 的存储表示，不双重冻结其行布局。 |
| 开放管理/资料/对象 | `management_revision(id,subject_id,revision,note,payment_period,payment_category)`；`payee_revision(id,party_id,revision,name,account,evidence_digest)`；`material_revision(id,period,category,expected,received,no_business,evidence_digest)`；`material_item(inventory_id,evidence_digest)`；`company_note_revision(id,revision,text,digest,evidence_digest)`；`display_profile_revision(id,kind,entity_id,revision,display_name,display_number,purpose,note,counterparty_id,beneficiary_id,handler_id,source,evidence_digest,digest)`；`period_commentary_revision(id,period,revision,text,context_digest,close_digest,source,evidence_digest,digest)`；`period_commentary_basis(commentary_id,contract,basis,content_digest)`；`entity(id,kind,account_type)`；`entity_profile_revision(id,entity_id,revision,content,source,evidence_digest,digest)`；`entity_resolution(id,correction_id,source_entity_id,target_entity_id,digest)`；`identity_correction(id,plan,digest)`；`identity_correction_item(id,correction_id,subject_id,action,before_fact_id,after_fact_id,replacement_subject_id,calculation_id)` | 已闭月快照只绑定被引用版本；本组摘要还保全**未关账/旧未引用版本**，目标完整核验继续独立执行。资料没有被直接填入业务行；测试用 `Periods.inventory` 保存真实清单。 |
| 其他不可变决定/回执及迁移时任务状态 | `source_change(sequence,source,target_id,before_ref,after_ref)`；`business_duplicate_check` 全部原有 15 列；`asset_batch_member` 全部原有 10 列；`request(id,digest,result)`；`audit(id,request_id,action,payload,created_at)`；`jobs(id,kind,payload,status,attempts,last_error,error_code,result)`；`security_close_approval` 全部原有 15 列。 | `source_change_head` 是 journal 序列头，由 journal 全覆盖校验；`jobs` 的生命周期列在普通 worker/retry 时可变，**离线迁移及恢复升级事务里没有执行任务的职责**，必须保留源值，尤其成功交付回执和失败尝试次数。批准的 `consumed_at` 在升级期间同样保留。 |
| 目录库 | `catalog_identity(id,instance_id)`；`company(id,taxpayer_id,name,path,database_id)`；`company_operation(id,taxpayer_id,kind,payload,status,attempts,last_error)`；`company_setting(company_id,revision,backup_directory)`；`security_owner`、`security_session`、`security_recovery`、`security_audit`、`security_identity_import` 的 v1 全列。 | 目录公司路径/三身份、结构与 FK/SQLite 完整性另行核验；目录行包含可变安全/operation 状态，但离线事务不应偷偷改写。新列仍可增加。 |

**明确排除。** `schema_meta/schema_history` 是升级合同版本证据，本应变化且由结构指纹/父合同约束；`state` epochs、`fact_current/calculation_current/voucher_current/pending` 是当前可变指针，journal 行已保全且完整核验比较其头/事件；`source_change_head` 由事件重算验证。`fact_*` 类型化正文/子表由已保留 `fact_revision.digest` + 固定 v1 解码绑定。`close_storage_*`、`read_index_*`、`entity_reference_*`、discovery、monthly/balance/opening、period/settlement/report/duplicate/material freeze 与 watch 物理行是可重建投影或逻辑闭月的分块表示；目标端依旧完整核验，不能以“可重建”跳过校验。这个排除不意味着当前业务指针可随意改变：迁移不能伪造新的 source_change 事件，因为 event 本身在摘要里。

**组回归。** 此前“jobs 生命周期列可变所以无需保留”的判断错误：可变只适用于 worker/retry，而升级事务内没有合法状态变更。已补全 v1 jobs 列，并加入真实 worker 成功回执、成功状态、失败 attempts 的同数篡改回滚及便携恢复回归。最终命令：`.tmp-kernel-venv/Scripts/python.exe -m pytest -q tests/kernel/test_stage9_backup_upgrade_history.py tests/kernel/test_offline_upgrade_history_preservation.py tests/kernel/test_offline_upgrade.py tests/kernel/test_migration_contracts.py tests/kernel/test_runtime_backup.py tests/kernel/test_foundation_backup.py tests/kernel/test_takeover_boundaries.py tests/kernel/test_job_diagnostics.py --basetemp .tmp/stage9-release-history-jobs-final`；**140 passed / 130.90 s**，原始日志 `.tmp/stage9-release-history-jobs-final.log`。正常 `retry_job`/失败后交付及任务诊断均通过。本组未改历史 v1 语义、DDL、内容合同或生产版本状态；尚未测量 48/120 月大库摘要耗时。
