# r33 简报父请求与报表诊断

读取固定 r33 代码和已由 r32 完整核验的 48 月主合成书。三份合同正文相同，不能把旧书核验改称 r33 完整核验。简报实际使用常驻只读连接池及原三 worker，完整准备、默认 100 条；报表为串行原生 deferred 调用。两者均有 cProfile 插桩，允许其他诊断同时运行，**不是纯计时，不替代浏览器验收**。

原始脚本、完整日志和 pstats 的无损压缩及 SHA 见 [清单](parent-report-profile-r33-manifest.json)。累计时间有嵌套，不能相加为总耗时或预计收益。

| 问题类型与触发条件 | 观测 | 判断及处理 |
| --- | --- | --- |
| 精确 ID 查询仍有较大读取成本：报表来源计数 | `browser_report_details` 两条 SQL 插桩累计约 209 ms，函数约 212 ms；报表函数约 932 ms | 页上只要两个计数，仍要按完整计划与权威种类计数。现有结果不证明无关行全扫，也不能据此删除历史来源。独立副本对照覆盖索引，尚未确定采用。 |
| 循环中逐月查询：历史采用核验 | 简报 `close_accounting` 141 次，累计约 160 ms；下层 `read_accounting` 约 157 ms | 不是 141 次同一范围重复核验。每月及各业务范围确有不同来源；可研究把相同调用的多个月份批量取行，保留各月摘要、成员、发布高水位及凭证集合核验。当前仅私有研究，尚未修改。 |
| 只读身份但要证明实际采用：资产摘要 | `_asset_card_sources` 约 127 ms，四组结果选择约 115 ms，内含资产成员及历史采用核验 | 不能直接改成当前指针或跳过批次成员。上述批量读取若成立，应覆盖此入口；尚未证明全部读取都是可省工作。 |
| 完整准备父请求 | `collect_current_readiness` 约 182 ms；`prime_select/select_many` 总计约 130 ms，含其他调用 | 资料、查重、报告 worker 的独立事务仍各自核验；不合并成功证明。银行并入资料 worker 的原型已另记负面结果，不重试。 |

报表 `party_balance_rows` 约 481 ms，内含开放期贡献与冻结月 flow；两次开放贡献读取的来源交集已由同快照复用，不能再次把整个函数当作重复工作。报表资料读取、资产身份、冻结采用和完整核验是不同证明范围。本轮只追加可定位的工作量依据，没有删减任何证明或页面内容。
