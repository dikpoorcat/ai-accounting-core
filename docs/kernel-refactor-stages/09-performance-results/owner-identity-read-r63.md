# r63 员工与资产对象身份读取

本组只处理老板看板需要对象身份却提前装载未消费历史结果正文的根因。开发范围为 `dashboard_reads.py`、`dashboard.py` 员工和资产读取、对应合成测试。本体系仍为 draft / 0，未冻结正式 v1；不操作真实资料；本身份读取子组未运行规模、纯计时、构包或全套回归；后续父任务固定候选的主 12 月核验、实际常驻工作量及纯浏览器结果分别列明。

## 成组范围与实施决定

员工默认名单的全部工资头都影响人员范围，包括无行工资和身份纠错后被合并的头。逐头核对 calculation/fact/subject/kind、来源期、入账期、封签、正式发布和开放期 current-head；闭月额外绑定独立 adopted leaf 的 publication、subject、fact、期间与 result digest。原事实及明确 employee role 的完整 recorded/current 引用证明保留。本月行数和金额、命中详情、付款 fallback 使用正文时继续严格核验。完全未消费的旧正文不在身份读取职责内；只改正文可由身份读取接受，正文和 mutable digest 同改仍由冻结 leaf 拒绝。身份结果不得加入完整 source/outcome 证明集合。

资产来源的 acquisition、独立 lifecycle、project 只用于对象集合和事实标量时采用同一身份选择。资产批次成员的反向撤回和再采用继续使用现有 member event selector，不能把仅发布头代替成员选择。取得 balances、项目余额与 capitalized_fen、折旧金额和 zero_reason、命中处置结果继续严格读取。老板简报复用来源身份集合，但其账面及项目余额仍独立核验。未证明等价的处理不强行省正文。

默认 20、全范围汇总、CLI/MCP、完整核验、关账、维修、backup 和 historical-v1 proof 的独立职责保持。现有 r50–r62 负面记录继续有效；不恢复已失败的缓存或第 24 项方案，不使用跨请求缓存。

## 主 12 月实际常驻工作量

固定 r63 与文件名 r62、实际固定 r61 的同一主 12 月根对照已归档于[常驻读取工作量](owner-resident-work-r63.md)。员工结果正文 **650 行 / 3,594,010B → 100 行 / 553,340B**，解码仍 100 次；总返回字节 7,923,563 → 5,055,183，但 SQL **147 → 149**、返回行 **10,649 → 11,299**、VM **582,900 → 604,700**，没有隐藏身份与事实证明的增加。资产结果正文 **120 行 / 204,576B → 109 行 / 197,173B**，解码 120 → 109；SQL 415 → 401、返回行 4,641 → 4,585、返回字节 2,902,845 → 2,886,105、VM 331,600 → 325,500。仍保留实际消费的 109 个资产正文及批次成员严格 fallback，不能声称全部身份路径省正文。

此次 helper 实际使用 ResidentReadPool；与主 48 月完整核验并行，native/profile 时间仅定位，不是纯计时或速度 A/B，也不是 48／120 月或正式包验收。纯浏览器 passed 由独立回执认定，正文、采用和原件解析的完整计数及 16 份原件 gzip/SHA256 见工作量清单。本组归档未运行新测试或测量。
