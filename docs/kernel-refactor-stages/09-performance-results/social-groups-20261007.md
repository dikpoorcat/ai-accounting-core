# 待付社保、公积金按员工月份合并验证

## 实现范围

个人社保、公司社保、个人公积金和公司公积金按正式员工身份及工资所属月份合并展示。姓名与“社保与公积金”上下分开，原行不带月份；实发工资、个税及其他款项继续单列。同名员工、不同工资月份不混合，同月多来源及期初四个独立业务可归入同组。工资所属月不同于所选月份时在展开区注明，正式义务及历史金额保持各自身份。

简报合同从13更新为14，增加必填可空的分组键、四项分类和工资所属月；详情合同7、接口地址和数据库结构不变。服务端只复用本页已经批量读取的工资事实，不新增查询、预加载或默认等待。常规工资使用正式工资期间，期初余额使用工资所属月；无法明确分组时保留单行并提示核对。

原始集合仍每页20个余额分项，选中模块后自动续页。未读完时合并行显示“正在汇总”，失败显示“尚未读全”，不显示部分金额为完整合计。期间分类、清单摘要及概览数量仍标原始“余额分项”；读完后使用合并项数，分页进度仍按原始分项计数。前端只归并新追加记录，完整读取后统一计算金额与状态；同一集合及摘要复用结果，新集合或范围失效清理分组状态。

合并详情直接使用已读分项，固定列出四项的原应付、实际已付、抵销／代付和月末待付，不再请求整笔工资详情。月末清单未列的分项注明“该月末未列待付款项”，不补造原金额或已付金额；未知显示“待核对”。后续按义务身份检查每项实际变化，历史余额不被覆盖，即使净合计不变仍保留成员变化。未结清和部分支付用琥珀色，只有成员均明确结清才显示绿色；更正、撤回及超额单独表达，合计为零不作为结清依据。最后一条拆解和后续记录不画底线。

实施开始时基线为工作区`d3aed9b`及已有资金详情改动。期间已有资金事项被独立提交为`6909ab5`，本轮保留其内容；其他会话的文档改动也保留。本次按用户要求提交，不推送，没有改真实业务数据、身份、结构或另建压力库。验证沿原资料根运行，只读取真实公司；响应式场景和截图使用合成数据。
