# 第 9 阶段 C 类：闭月根与字段桶同次复读（固定 r24 静态审查）

本轮只读固定 r24 及当前同范围源码、既有 r21 预览 py-spy 与 r23/r24 六入口计量；未运行数据库、测试或新采样，未修改生产/封存源。旧 `stage9-main48-r21b-preview-profile.txt` 是 r21 预览**早期**采样，栈仍在 `_verify_close_integrity_snapshot→decode_close`，不能推断后来 `_check_closes` 或 owner review 的时间占比。r23/r24 的六入口 meter 是普通页面，不是完整核验；其中每页 47 个 accounting subroot、约 1.868MB 是普通读的基线，不应冒充关账路径重复量。

公共入口在 `service.py` 把 `preview_close` 交给 `Periods.preview_close`，`verify_integrity`/`repair_read_indexes`/`rebuild` 交给 `Maintenance`，备份交给持久任务/`backup.py`；CLI/MCP 不另有第二套闭月解码规则。

`close_storage.decode_close` 与 `close_storage_v1.decode_close` **自身**存在静态确定的同调用重复：二者完整读取 `adopted_results`、`vouchers`、`material_coverage`、`management_snapshot`、`readiness`、`owner_review`，随后又读取 accounting subroot 做 subject filter、四个 family subroot 列举目录、material subroot 做保存摘要对照。`read_section(vouchers)` 还会再次装载 `adopted_results` 桶来核 voucher bucket 归属。按源码正常路径，同一闭月 `_family(accounting/material/management/review)` 为 **4/3/3/2 次（合计 12 次，唯一 family 4 个）**；`_family` 每次 SELECT 完整 subroot、核 SHA 并 JSON 解码。这是读取/解析重复，**不是**可删除相应逻辑核验：subject filter、目录全覆盖、saved material summary 都须保留。`_buckets_rows` 批读取目录及块并在 `_bucket_rows` 做各字节摘要/计数；全目录扫描仍须发现多余/缺失块，不能用当前 manifest 或可修目录缺行代替权威源。缺独立的 r24 完整核验字段桶调用计数/字节与等价损坏回归，暂不决定改造。

下一次若需定量，应在一次正常完整核验/预览的**同一个**事务内按 `decode_close`、`_family`、`_buckets_rows` 和 `_check_closes/owner_review/verify_read_indexes` 分段记录每 period/family 的调用、实际返回字节及 CPU，区分首解码、同函数复读与跨独立验证边界；不能将 r23/r24 普通页 1.868MB subroot 或 r21 早期 py-spy 计作该路径的全部成本。审查 24 已回退的 close_rows 两段方案不重试；不建立跨请求缓存。
