# 移除文件进度面板与报表任务最小读取

## 实际改动

以 `421f046` 为起点，移除“文件与处理进度”按钮、面板、专用样式、开关、异步组件和列表请求。`/api/local/jobs`、`browser_job_results`、`browser_jobs` 合同及生成产物同步退出。CLI／MCP 的任务清单、后台执行、重试和中断恢复保留；数据库结构未变，目录库、公司库继续 `draft / 0`。

报表生成改用 `GET /api/local/report-export/<job_id>/status?company_id=…`，严格合同 `report_export_status / 1` 只返回公司、数据库、任务身份、状态、尝试次数和公开错误。负责人会话在读取前后检查，任务必须属于当前公司且是报表导出。前端采用生成校验器，核对请求公司和任务，保留取消请求、重试、会话失效及公司切换保护。状态成功只表示生成完成；下载仍检查公司和数据库、目录边界、manifest、摘要及文件内容。

## 按根因排查与处理

| 问题类型 | 排查范围与实际问题 | 处理与证据 |
| --- | --- | --- |
| 已退出展示仍拥有后端读取 | 五页外壳、面板、共享 API、报表轮询、HTTP 分派、响应模型和生成清单 | 删除整条列表链。原报表轮询借用列表组装，重复读取任务载荷、来源及成功文件；改为按任务主键读取四个状态列。 |
| 专用缓存或预加载残留 | 组件状态、异步挂载、API、`QueryReads._jobs`、工作清单及期间／关账调用方 | 未发现面板专用缓存、预加载或失效逻辑；面板只在打开时读取，默认刷新不请求它。共用快照任务缓存服务 AI 和期间检查，保留。 |
| 读取规模随无关资料增长 | 单任务状态的 SQL、执行计划、VM、来源装载和文件访问 | 加入 400 个无关任务及 24 个无关事实后，业务结果和实际工作量相同：一个连接、一个 SELECT、主键索引查找、VM 小于 50；不装载任务结果、事实来源或文件。 |
| 删除展示核验后必要检查遗漏 | 原报表来源测试、完整核验、发布／来源核验、备份共用路径 | 来源与计划损坏断言转到完整核验。补齐报表计划的精确引用和期间类型检查；同快照已存在事实版本但类型化正文缺失，统一归为内容损坏，不能提示老板补事实。状态轮询不承接这些完整检查。 |

正式代码不再包含旧列表入口与合同；测试保留旧接口应返回 404、默认刷新不得请求旧接口、页面无入口／面板的断言。已删的历史面板下载脚本退出，文件篡改、目录和身份断言保留在现行下载测试中。
