# r78：月度核对按需读取与真实库刷新对比

本轮按用户指定的“评估老板视角下的无用内容”对话落地：已关账月份退出整块独立月度核对；经营金额、实际收付、业务变化、老板待办和关账状态留在各自现有栏目。开放月只有有效预览时才显示一条确认待办，点击读取精确预览。5173 已加载新页面与后端，未提交 Git。第9阶段仍未完成，本轮不继续规模验收、正式合同冻结或最终运行包交付。

## 根因、排查范围与处理

问题类型是“展示职责已经退出，专用请求与验收等待仍然保留”。原简报每次刷新并行读取上下文、主数据和 close-review，即使已关账也重新读取独立核对摘要；其中经营金额和业务分类与现有栏目重复，资料处置及后续办理属于 AI 会计工作。只删界面会留下专用读取，旧浏览器脚本仍会等待已删除区块。

| 排查位置与调用方 | 处理与边界 |
| --- | --- |
| 五页默认读取、共享上下文、BriefView、CloseReviewPanel、closeReview API | 简报移除预加载状态、独立导航与常驻核对区块；其余四页没有默认核对请求。只有点击有效确认提示才挂载核对组件。 |
| 服务分派、Dashboard、dashboard_owner、CloseReview | 简报同一读取快照内返回月份状态和可为空的有效预览定位；已关账／被后续关账覆盖不解码核对正文、不重新生成历史老板待办。 |
| 活动预览、密码窗口、最终关账 | 定位仍核对签名、公司／数据库／月份、三类业务版本及读取修复版本；只接受 ready 的活动预览。损坏仍返回内容错误，不伪装成无预览。最终批准与关账事务复验保留。 |
| CLI/MCP、原只读核对入口、冻结读取、核验、修复与备份恢复 | 保留原职责和历史合同；不因默认页面退出而删除必要历史或改变冻结内容。本轮没有重跑完整备份恢复与固定版本历史全套验收。 |
| 首次导航、热刷新、公司切换、布局与冷态浏览器脚本 | 删除强制 close-review 的请求及等待；检查 brief 权威月份状态与确认提示，默认核对请求必须为零。继续检查新响应、公司／期间关联与两次渲染帧。 |
| 测试动态组件 harness | 清理退出的预加载状态引用；保留上下文失败、取消请求、主数据失败、切公司、旧摘要失效和不自动展开新内容的断言。 |

简报响应升为9，新增 `month_state` 与 `owner_review_request`；其他页面及 close-review 响应版本不变。关账存储、数据库合同与结构均不变。刷新、切公司、切月份即收起旧核对内容；失效后不会静默改用新预览。完整核对入口继续供 AI 会计读取，按需页面仅显示老板需要确认的经营金额和业务。

- 受影响后端八文件成组回归：**181 passed，211.95秒**。覆盖有效／无预览、closed／covered、三类版本及修复版本失效、损坏签名／身份、替换预览、同快照关联、空公司、原生／HTTP响应，以及原批准和冻结边界。

- 当前后端从隔离合成库生成40份响应，生成同步检查、消费者合同验证、类型检查、release构建和改动范围静态检查通过。补充合成开放月浏览器验证：默认零次核对请求，点击一次并绑定精确摘要，刷新后旧内容消失，不自动再次请求。
- 真实库五页在375px及320px共10个布局状态无横向溢出；320px展开核对也无横向溢出。截图在本机忽略目录保存，人工查看简报、报表和展开核对内容；其余截图未逐张人工审阅。
- 只读对比前后，公司库247张表及目录6张登记／身份／结构表的逐表行数与内容摘要完全相同；五页响应去除生成时间、版本关联和新增定位字段后的业务内容摘要一致。没有业务登记、结构调整、换库、重放或冻结改写。
