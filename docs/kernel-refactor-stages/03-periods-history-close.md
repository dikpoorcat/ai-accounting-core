## 期间与发布

公共参数统一为 `posting_period`，退出 `correction_period`。开放月份按业务所属月入账；所属月已关账的迟到业务及冻结结果更正，必须明确指定开放入账月。业务原有所属月份纠错规则继续适用，公共层不放开工资等身份约束。

普通发布与资产批次共用期间判定。预览逐项返回 `source_period`、`posting_period` 和 `mode`，正式事务内重新核对。指定月份约束显式选择的独立结果以及需要确定入账月的闭期更正；自动重算的开放期依赖保留各自月份，无影响结果沿用原月份，资产成员跟随批次。单独无影响复核不能借参数移期。开放更正继续替换原开放段，显式选择与指定月份冲突时拒绝。

自动依赖必须分开判定：1 月工资已冻结，2、3 月仍开放，在 4 月更正 1 月时，1 月差额记入 4 月，自动重算的 2、3 月工资仍记原月。把一个参数强加给全部自动依赖，会使多个月份的累计链无法更正；本阶段将这处冲突作为技术缺陷修正。

重构 `calculation_publication` 为唯一不可变发布链，保存发布身份、主体、前次发布、计算、动作、入账月、固定比较基准与凭证。每个主体无分叉；撤去留下计算和凭证为空的节点，成员不独立发布金额。

| 动作 | 期间贡献 |
| --- | --- |
| 首次发布 | 增加新结果贡献。 |
| 开放期替换 | 撤去前一开放段，再加入新段；合法所属月纠错处理旧、新月份。 |
| 闭期更正 | 保留冻结段，开放月记录新旧结果差额。 |
| 无影响复核 | 金额及凭证不变，记录新依据。 |
| 撤去 | 撤去可删除的开放段，保留历史；已闭期采用的主体仍禁止删除。 |

每段保留固定比较基准：1 月 100 元冻结，3 月改为 120 元记增加 20 元，再改为 130 元后 3 月合计增加 30 元。对象键变化逐键计算，不以总额抵消不同对象。

## 关账与历史

`period_close` 的不可变内容和摘要仍是唯一冻结权威，引用目录可重建。新合同明确记录直接采用的发布及计算、精确凭证版本及拥有者、采用依据、冲正关系、无凭证结果、独立期初和资产成员；同时保存资料清单、准备依据、管理快照、负责人确认、试算平衡、前次关账身份摘要和批准快照版本。

不逐月复制传递祖先和上游事实全集，沿不可变依赖按需读取。旧缺字段、倒推期初、猜测资产采用及有限核验分支退出；必需依据缺失是内容错误，不要求老板补造业务事实。

三种口径分开：当前有效结果是正式发布；历史账面按实际入账月还原；当时冻结只读该次关账的明确版本。资金页和报表采用实际入账期，业务详情分开账面、当前业务值和冻结采用。`source=open|closed` 分别表示当前账面还原和精确冻结。空月可被后续关账覆盖，但不能冒充独立批准；请求不存在的当月冻结返回 `frozen_snapshot_unavailable`。

## 投影、读取与消费者

新增按发布、入账月、类别和对象组织的余额贡献，期初单独标记；保留当前余额并核对贡献合计。看板与报表共用冻结基线、后续发生及独立期初汇总。

清偿贡献使用现有义务与清偿解析，保存来源、义务键、期间、金额和未知状态，只服务读取。简报 KPI 聚合完整范围，明细先分页再装载。未知金额不变成零。两类投影由正式发布及保存结果重建，写入、撤去与投影同事务；修复只改派生数据，实际变化推进读取修复版本。

投影按期间和类别记录行数与内容摘要。普通读取批量核对命中投影、发布身份及源摘要；关账、完整性检查、备份、修复从权威源独立核对语义。版本不代替内容核验。不增加跨请求缓存；同一只读快照中只复用相同来源、摘要、核验范围的成功核验。身份枚举不展开完整采用证明，关系按批装载。

落地结构如下，全部纳入公司开发合同：

| 结构 | 保存内容与约束 |
| --- | --- |
| `calculation_publication` | 全局顺序、主体、前次发布、计算、动作、入账月、固定比较基准、凭证；内容摘要作为发布身份，禁止改删，主体根及后继唯一。 |
| `period_balance` | 发布、入账月、余额类别、对象、期初／发生额、整数分及来源／比较基准摘要。 |
| `period_balance_seal` | 期间与类别的行数、摘要；期间总标记覆盖零余额发布，防止整组投影丢失却被当作空月。 |
| `settlement_change` | 发布、来源、义务键、入账月、科目、往来方、类别、清偿方式、整数分及明确／未知状态；科目用于保持报表重分类一致。 |
| `settlement_projection_seal` | 每期清偿贡献的行数、内容摘要和发布身份集合；空贡献也不能掩盖发布丢失或移期。 |
| `period_close.manifest` | `ai-accounting-kernel/2/period-close`、格式版本 1；直接采用、精确凭证、期初及资产成员、发布顺序边界、批准快照和前次关账摘要。 |

完整核验可以在同一快照内复用已经核对的计算内容解码，但当前余额、期间贡献和清偿贡献仍各自生成预期并核对实际表。修复前后分别重新核验，不跨越写入复用成功状态。

同阶段接通 CLI、MCP、普通发布、资产批次、关账、核验、修复、备份、报表及看板。context 版本保持 2；brief、funds、employees、assets 升为 3；业务详情、期间准备、季度报表升为 2。资金页更新生成合同，共同读取和采用类型同步；其余类型及版本检查当期修改，剩余全面生成化归第 7 阶段。保留整数分、HTTP 字符串金额、分页和公司切换保护，不增加五页口径切换按钮。

## 实际结果

### 业务与核验

发布、撤去、两类期间投影与当前余额在同一事务完成。预览记录完整期间决定和发布前驱，事务内再次比较；资产成员跟随批次拥有者。连续闭期更正、开放段移期、对象换键、归零和撤去均按固定比较基准处理。

新关账直接采用发布及计算，区分凭证产生依据和复核采用依据。单月冻结缺失明确失败，空月覆盖不补造批准。独立期初、无凭证结果及资产批次有明确采用；已有范围关账的内部合同仍可用，其显式范围字段单独核验，正式入口退出归第 7 阶段。

内容核验保留权威来源的独立核对。发布身份与期间封签同时覆盖零贡献；普通发布遇到既有投影损坏会拒绝，不顺手修复。完整维修只重建派生数据，源事实、计算、发布链和冻结内容不变。成功核验仅在同一只读快照内复用。

合并验证修正了以下实质问题：首月资金期初漏计；自动重算跨多月工资时错误强加同一入账月；无凭证发布及整组封签丢失漏检；主体关联但义务键错配的未决清偿漏显示；关账逐份读取资料清单与重复校验证据。旧测试同步改为直接采用和新响应合同，保留原金额、冻结、原子性和权限断言。
