### D．响应重复校验与可选前端代码提前加载

拆分生成模块后漏查了调用方：`localKernel` 静态带入任务校验器，业务详情校验器经四页组件带入，简报还提前带入独立准备接口校验器，报表提前带入导出回执校验器。已集中修改这四条可选 API 为调用时加载，主响应、context、安全状态和可见核对摘要仍即时校验。加载前固定请求公司／月份，保留取消及旧请求丢弃；导出校验器在写请求前加载，不能产生提交后加载失败的不明状态。真实 Vite 模块加载测试覆盖四条路径的未调用不加载、加载中切换取消、保留公司与错误响应拒绝。

派生封签不能单独证明自身正确，须绑定不可变关账根。页面不声称核验了全部未命中的源内容或发现了所有目录缺行；完整核验、备份及维修仍独立检查权威来源和目录完整性。同账户绕过约束直接改文件的风险按既定边界保留，不追加系统隔离工程。

资料规则使用关账事务保存的明确规则身份，规则变化时更新，不因无关程序构建变化而失效。该身份只选择可用证明，不能替代内容核验，也不保存“已处理所以跳过”的结论。

变化目录由数据库触发器随事实指针、正式结果、待重算状态、身份纠错、重复核对和资料清单写入同一事务，只追加，失败一起回滚。它不记录调用入口或聊天，不新增业务版本 lane，也不提供操作页面。关账私有根保存精确序号边界；读取检查区间连续性，完整核验核对全部历史与权威来源。变化历史是不可改的来源，资料依赖和强信号目录是可修复的投影，两者不能互相替代。这组机制已接入新合成库并通过完整核验；整页性能仍未通过。

### 同一快照复用与工作量

同一只读事务内复用成功核验的块、来源、采用关系、清偿汇总、报表月数据和资料解析；失败不缓存，事务退出清空。不增加跨请求业务结果缓存。常驻连接每次请求仍重新核对身份、结构和权限并开启新事务；最多四条连接各使用 64 MiB 的 SQLite 页缓存预算，页面一致性由 SQLite 事务维持。页缓存只减少底层重复读取，不把它算作业务工作量下降。

常驻服务的完整简报增加三进程读取：资料、查重、报表与财务位置分别在自己的只读事务中完成，父请求处理默认明细及其他状态。报表检查和财务位置在同一子进程快照内复用；没有核验缓存跨事务传递。专用无事务连接在整组读取前后检查提交变化，各进程核对同一数据库身份；有变化就丢弃整组内容，用原单快照路径重读。每个服务最多一组并行请求，忙时直接走原路径；超时、部分任务启动失败和进程故障会回收整组。关闭后不重启进程，客户端不能提交已校验内容。此路径仅用于显式开放月的完整简报，正式关账及其他业务写入保持原检查。

准备检查、报表和看板共用 `QueryReads`，资料检查复用同次事实装载。资料递归核对结束时解除闭包对本次读取对象的引用，报表的纯递归键函数移到模块级，避免让请求对象等待循环垃圾回收。常驻服务在首次读取任何资料根之前，一次性准备静态模型和文件解析依赖，再冻结这些长期对象；正常垃圾回收保持开启，不冻结业务快照。命令模型由服务直接复用，普通 CLI／MCP 路径不变。批量查重在开始写入之前复用精确候选的事实与资料位置；每项仍独立选择权威候选和应用查重规则，下一次批量重新读取。

类型化依赖选择分开处理精确业务类型和跨类型范围，按已有联合索引定位，避免为本月一种业务遍历其他类型。报表分类在同一快照复用已经通过的逐版本核验，但每次仍对完整请求集合检查冲突；未通过的范围不缓存。旧年度未用于本页凭证的分类可由精确事实 ID、摘要及关账绑定的报表月根覆盖，不再展开其凭证选择与子项；进入逐行读取并实际解码的分类须核验保存的事实正文和凭证行。页面完全使用已核验的冻结报表月贡献时不再读取旧分类正文，其损坏由完整核验、备份及修复检查拒绝。报表是否存在开放发布按实际入账月份逐个索引跳转，不逐笔扫描已关账历史，也不以较晚关账冒充早期月份的独立关账。个税映射检查复用同一快照已经装载的工资事实，正式文件检查仍独立执行。

资金分页先确定命中键，随后批量装载来源；清偿明细按冻结目录范围和开放尾部定位，批量核验本页状态。银行对账按原行引用建立复合索引，避免每个原行重复扫描全部匹配项。查重先从对应类型的当前主体读取，按必要匹配键分组找候选，不先枚举成对组合，不扫描该主体全部历史修订。

资料检查按共同业务归集竞争来源，行处置和金额竞争检查只在本次检查内复用成功的金额归一结果。处置、分组和分期表增加原件来源索引；排除已经核验的冻结原件后，按权威表的来源键定位当前修订。缺少或已撤去原件的处置仍参与检查，不能只从原件登记表枚举而漏掉它们。处置链接另按事实版本索引，避免为本月命中业务扫描全部历史处置。期间枚举按索引跳到下个实际月份，不推造空月。完整核验只在同一次调用内复用已完整解码的关账内容、成功重建的清偿和报表来源，各期来源及语义检查保留。

资料金额核对只提取其类型化链接允许的顶层金额字段，保留原 JSON 类型，不把布尔、浮点或未知金额转成整数。同一合成月的 1,006 个结果，查询返回的值由 501,504 字节降至 21,902 字节；这是读取量诊断，不是整页计时。简报凭证笔数、分类计数和借贷合计共用一次分组汇总，保留默认分页、零行凭证及冲正含义；该组统计在同一数据上由 259,700 降至 152,400 SQLite VM 步数。疑似重复的插桩确认 949 个核对记录各检查一次，未为提速省略必要检查。

变化记录的读取仍检查完整连续区间、来源类型和前后引用，内存行改用不可变元组，两个引用直接检查。7,606 行的交替诊断中，单次中位数从 20.7 降至 14.7 毫秒，逐字段一致；[原始结果](09-performance-results/journal-row-representation-diagnostic.json)仅作工作量定位，不作为整页验收。

记录 SQL、SQLite VM 步数、返回行和值字节、事实和结果解码、采用证明、资料解析及峰值内存。VM 使用明确采样间隔；返回字节不是磁盘物理读取量，Python 峰值分配不是进程 RSS。不能仅凭 SQL 次数减少宣称性能完成。

大型测试资料的生成与运行性能计时分开。测试生成器可显式延后每次关账前重复的历史完整核验，只允许仓库临时目录中的指定合成公司，并记录各月延后的次数；登记、发布、资料检查、清单构建及两次摘要比较仍执行。生产代码没有此选项。生成器退出后，必须由独立进程运行未修改的完整核验，核对全部来源、历史采用、投影与目录，成功后样本才可用于浏览器测量。生成耗时不代表正式关账耗时，这类样本也不替代正常逐月关账门禁回归。

### HTTP 和前端

看板只读响应完成授权和命令检查后，在服务边界校验一次并立即按同一模型序列化；CLI/MCP 保持原生整数分，HTTP 保持规范整数分字符串。客户端不能声明数据已校验，独立 HTTP 校验入口仍拒绝未经校验的数据。

Ajv 校验器按合同拆分，各页导入所需模块，后台任务面板按需加载。请求关联、金额精度、分页快照、公司与月份切换及旧请求失效机制保留。完整简报遇到合同或内容完整性错误时直接显示失败，不能用按需响应掩盖错误。响应字段、URL、版本及默认显示内容不变；不推迟主 KPI，不展示旧结果来满足计时。

简报刷新时并行读取主响应和关账核对摘要；上下文和主响应通过后才展示核对内容。同一次请求组使用相同取消信号，切公司、切月或请求失败时丢弃旧内容；核对详情仍绑定该摘要的精确预览版本。没有新增接口或减少默认内容。

浏览器验收默认读取与运行包一致的 `src/ai_accounting/static/dashboard` 发布静态产物，缺失时直接失败；普通 `frontend/dist` 只能通过显式选项用于诊断，不自动回退。结果保存实际产物目录和逐文件 SHA-256；相关脚本测试 14 项通过。

## 正式版本与升级

性能和结构收敛后，目录、公司分别冻结完整 `released / 1` 合同，体系仍为 `ai-accounting-kernel/2`，备份格式仍为 2。正式合同只创建不覆盖；生成候选、显式冻结、只读检查分开，构建不得暗中生成。v2 起保存父指纹约束的增量合同及明确迁移步骤。正式入口拒绝 draft、旧体系及未知结构。

`finance-local --root <目录> upgrade` 为显式离线入口，不构造服务客户端、不自动停服务。先按已知正式来源合同只读核对目录、登记公司、身份及内容；存在未完成目录操作时拒绝。取得服务独占锁后再次核对，逐公司迁移，最后迁移目录；每库内容核验在提交前执行。失败库回滚，已完成库保留，重试核验后跳过，不宣称跨库原子。服务启动检查全部登记公司的结构和身份，拒绝混合版本资料根；不把此检查放入每次页面读取。

v1 固定必要的事实存储解码、对象引用及历史内容核验规则。源版本核验按对应规则读取，不把历史 v1 永久指向未来当前模型，也不重新计算冻结历史。用非空 v1 历史和隔离合成后续版本验证同一升级命令、失败回滚、重试和升级后启动；生产不注册虚构 v2。备份恢复仍只发布到不存在的目标，与原位升级分开。
