# 第 7 阶段：老板核对与五页看板

## 状态与范围

已完成。基线为 `dee9be9`，代码、测试和文档随本阶段一起提交；准确提交身份以包含本记录的 Git 提交为准。第 7 阶段结束，不进入第 8 阶段。

处理共享响应合同、同版关账核对、实际采用依据展示、清偿状态遗漏及正式批量关账退出。保持信任链、整月统一批准、单公司逐月关账和五页布局。老板在页面只读核对，密码在本机安全窗口输入，正式业务由 AI 调用内核执行。

不增加调用入口记录和近期变更列表，保留现有审计与业务历史。未映射科目的本月问题和期末问题分别保留，金额沿用正负号和元格式。

只使用新建合成库，不操作真实资料。删除批量批准结构后，目录库与公司库均更新开发合同指纹，继续使用 `draft / 0`；不迁移旧开发库。

## 实施设计

### 响应合同与页面

复用 Python TypedDict／TypeAdapter、JSON Schema、TypeScript 和 Ajv 生成链。context 保持 2；brief、funds、employees、assets 升为 6；business-status 升为 4；quarterly-report 和 period-preparation 保持 3；新增 dashboard_close_review 为 1，关账内容升为 4。

浏览器任务列表、安全窗口公开状态采用明确的版本 1 合同。报表生成回执准确描述已有 status、job_id 和 preview_digest，不改变文件生成和下载行为。其余写命令不扩入本阶段。

分页集合只保留一份 items/page，完整汇总独立保存。金额、来源、问题和采用依据明确建模，不使用开放 JSON 绕过金额声明。页面使用生成校验器及请求关联检查；退出已替代的手写响应、类型断言、金额字段名猜测和重复分页别名。清偿事件统一展示 relation_state，未知金额不能成为零。

### 核对、批准与冻结

同一关账快照产生 owner_review，包含全月业务和金额、真实收付与内部转款、凭证及试算、资料覆盖、负责人确认、剩余事项和精确采用依据。它直接进入原有 preview_digest，不新增重复摘要身份。

经营简报现有月度核对区只读显示；AI 生成预览后，老板核对，再由 AI 请求本机密码批准及执行单月关账。密码窗口显示同份紧凑摘要，只签发批准。

核对读取区分已冻结、被后续关账覆盖、尚未准备、可以核对和已失效。公司每月只有一个活动预览；新预览替代旧预览，页面不能静默换版。原生 calculation_hash 参数统一为 preview_digest，无旧别名。密码批准及关账均在写事务内复验完整摘要，包括读取修复版本。

核对详情复用已有直接采用目录；固定分块记录数量和摘要，普通分页只装载命中块，完整核验再检查全集。展示合同版本明确保存，冻结依据不以当前档案补齐；内容缺失或摘要不符明确失败。

### 正式批量能力退出

删除 preview_close_range、close_range、approve_close_batches 及其 Schema、分派、缓存、批准、窗口、专用模块、两库批量表和触发器。测试准备使用 tests 内逐月调用真实单月流程的薄夹具；保留领域断言，仅删除退出能力自身的断言。

## 实施顺序

1. 写本记录，完善响应模型和生成清单。
2. 统一分页，接通五页和附属响应，修正状态展示。
3. 建立核对内容，接通只读页面、本机密码窗口和冻结核验。
4. 移除正式批量能力，更新两库开发合同和消费者。
5. 验证修正，更新架构、路线图和运行说明，提交 Git，停止。

## 验收要求

- 空目录、无月份、完整／按需读取、所有分页、筛选、公司切换和过期快照。
- 缺字段、多字段、错误版本，浮点、布尔、非规范编码及 int64 越界金额明确失败；使用当前后端合成响应验证消费者。
- 当前与冻结采用分别准确；后补事实、无凭证结果、独立期初、资产批次及无影响复核正确。
- 预览替换、业务版本、读取修复、服务重启、密码失败、取消、过期、单次消费、原子回滚和幂等。
- 摘要或来源损坏拒绝；明细只读取命中块，完整汇总不由页面明细拼成。
- 清偿状态、未知金额、本月非零累计为零、未映射提示均保留。
- 正式命令、安全类型、两库结构和运行包无批量关账能力。
- 12、48、120 个月合成样本记录核对生成、分页、核验与页面的耗时、SQL、解码量和冻结体积；整页 500 毫秒仍属阶段 9。
- 后端相关回归、数据库及响应合同检查、前端测试、类型检查、构建和独立包全流程通过。

## 实际结果与提交

改动前定向后端 46 项、前端 109 项通过，仅作为基线，不作为本阶段验收。

### 已接通的行为

- 十二类页面及附属响应统一由 Python 合同生成 HTTP Schema、TypeScript 和预编译校验器。原生金额保留整数分，HTTP 金额严格输出 int64 范围内的规范整数分字符串。核心 CLI／MCP 的任务和业务详情保留原职责，浏览器使用窄投影。
- 分页集合统一为 `items/page`；账户筛选、公司／月份关联、快照、员工历史按需装载和完整汇总继续工作。清偿事件显示关系是否确认，未映射科目同时保留本月及期末问题。
- 业务详情分别显示当前与冻结结果的金额、政策和工资确认。简报的采用依据明确属于当前凭证页；全月采用内容通过固定版本的关账核对读取，不能把已加载的一页说成全月。
- 关账 v4 保存必填 `owner_review`。核对页、密码窗口与正式关账使用同一个 `preview_digest`；原生参数没有旧别名。后补事实不改写冻结核对内容。
- 活动预览按公司、数据库和月份唯一保存。三个业务版本及读取修复版本变化会使其失效；关账成功后立即退役活动预览，锁内检查也拒绝晚到的旧预览。页面从准备态转到同摘要的冻结态时清除旧分页绑定，不混用两种快照。
- 正式批量能力及两库相关表、触发器已删除。测试中的连续月份逐月调用真实单月流程，保留原有领域金额、历史和原子性断言。

### 验证中修正的问题

- 保留核心业务查询的完整结果，只缩减页面投影，避免页面整理损坏其他内核消费者。
- 运行包中的真实工资闭期更正暴露了页面 closure 分支与严格模型不一致；页面按明确合同投影，核心接口不变。当前确认修订 2 和冻结确认修订 1 各自保留准确资料来源。
- 当前及冻结业务的金额从各自精确计算读取，不能用当前金额填冻结结果，也不能在缩减原始数据袋时丢掉金额。
- 冲正取原凭证拥有者的业务金额，真实收付不包含冲正或期初；不同往来对象的重分类不能相互净掉。
- 派生投影维修前仅绕过损坏的派生位置，冻结核对内容仍从不可变来源重建；维修后的完整核验重新核对财务位置。
- 明细分页复用本次请求已校验的目录，避免请求内重复校验；不增加跨请求缓存，也不复制一份新的冻结权威。
- 冻结批准回执严格限制字段与类型，完整核验逐项核对公司库中实际消费的密码批准、公司与数据库身份、月份、预览摘要、业务版本、负责人和凭据版本。修改回执后重算关账摘要仍不能冒充有效批准；本期已有消费批准时也不能把回执改成 null 绕过核验。
