# 原看板的老板视角优化

五页、主题、侧栏、公司与月份选择、卡片、表格、筛选、展开、追溯和下载继续保留。默认页面先回答“记了什么、钱在哪里、赚亏多少、还需处理什么”，业务细节按需展开，哈希、内部版本和 JSON 放入技术详情。

## 页面与金额口径

| 页面 | 默认阅读内容 |
| --- | --- |
| 经营简报 | 本月账面盈亏，包含银行、现金及公司资金性质平台账户的期末资金，长期资产和待收待付。没有有效经营说明时，直接用正式汇总生成事实概览，不推测原因。 |
| 资金 | 钱在哪、本月收款与付款、账户间调拨及基金确认成本。全公司全月汇总与所选账户明细明确区分，银行资料覆盖和流水核对另行展示。 |
| 员工 | 本月有工资记录的人数、公司薪酬成本、应发工资奖金和付款。登记状态不替代工资记录；扣税、申报、代发依据、公司付款及代付抵销在详情中分别说明。 |
| 资产 | 在用、待启用及项目形成成本的账面价值。规则与核对过程折叠；整批付款明确为批次信息，不变成逐资产分摊。 |
| 财务报表 | 能否生成下载、需核对的具体事项和来源选择。正常检查折叠，异常保留业务及凭证定位。文件进度优先显示实际文件名，失败与失效结果解释原因并可重新生成。 |

正常未关账、正常待收待付和非必需管理资料缺项不统一标为异常。收款不称为收入，账面资金不称为可用余额，基金成本不称为市值。

## 凭证与查询合同

- `list_summary` 是短摘要，`display_summary` 是带来源期间、明确对象及已保存用途说明的完整摘要。业务列表、凭证列表和资金明细共用后端规则；银行实际原文另行保留，没有原文时不提供虚假的原始摘要入口。
- 按业务看展示业务金额及含义，按凭证看明确为凭证合计。冲正说明对原业务的更正，追溯使用所选凭证版本；连续更正可沿当前组与后续组逐步导航，按原凭证号区分。实际资金发生、业务确认和借贷合计不混用。
- 分录对象来自正式义务身份、精确依赖和核算模块的确定顺序，绑定后核对科目、方向及金额。多个同科目同金额对象不能靠金额猜测配对。合并分录允许多个对象并列各自金额；银行行无对象可显示横线，无法逐行分摊的关系留在业务说明中。
- “业务事实、资金与核销”通用重复块已移除。只在跨月付款、多来源清偿、个人代付、抵销或整批业务时补充具体说明；完整原始事实在核算依据的技术详情中。
- 关联凭据查询只读元数据，以原文件名为主，同名文件依然以独立证据身份区分；不为列表读取文件正文。哈希只在校验详情中出现。旧记录没有名称或只保存了摘要作名称时，明确显示“原文件名未保存”，不编造名称或改写不可变证据；现库有两份此类历史操作记录。
- 资金查询接收 `movement_account_type`、`movement_account_id` 和 `statement_account_id`。账户类型与稳定 ID 配对筛选全月记录后分页，显示编号不承担身份职责。游标绑定公司、月份、全部筛选条件、数据版本及明细种类；切换条件重载，版本变化整体刷新。
- HTTP 使用整数分字符串，CLI/MCP 保持整数合同；新增摘要、关联、凭据名称及筛选语义由同一内核只读查询提供。公司库仍为 v8、目录库仍为 v3。

## 管理资料与重放

已有展示档案、收款人和个税人员资料按精确身份复用。本轮经授权核对两家公司保全原件，为有明确依据的名称、用途和说明追加类型化管理档案；冲突或不能确证的资料继续保留待核对，不根据名称相似、内部编号或金额相同推断关系。

真实资料、原件位置、证据摘要、类型化请求、回执及补齐前后的不可变记录核验保存在忽略目录 `data/reconstruction-sources/dashboard-display-20260912/`，不进入源码或软件包。管理补充不重算凭证，也不重写历史月结封存。

操作协议要求今后同步保存原件已经明确的名称、用途和说明。重录时按身份映射关联原文件、业务和展示档案；经营说明使用新库预览依据重新保存，按实际顺序区分关账前说明和后来补充。参见[空库重放手册](empty-database-replay.md)和[检查单模板](formal-empty-db-startup-checklist-template.md)。
