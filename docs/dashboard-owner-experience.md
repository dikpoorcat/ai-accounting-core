# 老板看板的阅读与核验边界

五页、主题、侧栏、公司与月份选择、卡片、表格、筛选和下载继续保留。默认页面回答“钱在哪里、赚亏多少、是否需要本人行动”，业务细节按需读取。核算依据、来源证明、候选记录、内部编号、哈希、版本、审计和 JSON 不进入老板看板，也不放入折叠区或技术详情；AI 会计通过服务端、CLI/MCP 和诊断能力核对。必要金额、业务状态和内容核验不因展示精简而省略。

## 页面与金额口径

| 页面 | 默认阅读内容 |
| --- | --- |
| 经营简报 | 按实际入账月表达收入、费用、赚亏，展示资金、月末资产负债、本月用工成本、待收待付和本人待办。资产负债及用工卡沿用 2.1 版业务展示和金额构成浮窗；未知金额分别说明，试算过程仍留在核心核验。经营说明只采用已保存内容，不推测原因。 |
| 资金 | 钱在哪、本月收款与付款、账户间调拨及基金确认成本。全公司全月汇总与所选账户明细明确区分；需老板处理的资金风险说明对象、影响和下一步。 |
| 员工 | 工资记录人数、公司薪酬成本、工资奖金及实际付款。登记状态不替代工资记录；业务详情保留所属月、收款对象、公司付款和代付抵销的区别。 |
| 资产 | 在用、待启用及项目形成成本的账面价值、生命周期和实际付款。整批付款明确为批次信息，不无依据地分摊到单卡；核算规则和来源核验由 AI 处理。 |
| 财务报表 | 三表业务金额、报表是否可用及需要本人处理的事项。来源选择和核验由 AI 完成；文件成功并验证后才提供下载，失败和失效显示可理解的处理状态。 |

正常未关账、正常待收待付和非必需管理资料缺项不统一标为异常。收款不称为收入，账面资金不称为可用余额，基金成本不称为市值。

## 业务摘要与查询合同

- `list_summary` 与 `display_summary` 分别提供短摘要和包含业务期间、明确对象及已保存用途的完整摘要，均由后端同一规则产生。银行实际原文可作为收付款用途备注，没有原文时不编造。
- 实际资金发生与业务确认分别说明。冲正表达为原业务更正，不能描述为重新付款。简报恢复会计凭证的公开编号、摘要、科目、往来对象、借贷金额及原有展开、分页／全部样式；业务金额与凭证借贷合计分别表达，逐层核算追溯仍不进入老板页面。
- 对象依据内核明确关系展示，允许一行多个对象或不适用往来对象，不能靠同金额猜配对或把整批关系复制成逐项分摊。跨月付款、多来源清偿、个人代付和抵销仅补充老板理解业务所需的说明。
- 只有老板需要识别、下载或补充原件时展示文件名；未保存名称时明确缺项，不编造或改写不可变证据。证据身份、摘要和采用关系留在 AI 查询中。
- 资金查询接收 `movement_account_type`、`movement_account_id` 和 `statement_account_id`。账户类型与稳定 ID 配对筛选全月记录后分页，显示编号不承担身份职责。游标绑定公司、月份、全部筛选条件、数据版本及明细种类；同期间切换条件仅更新对应明细，版本变化重新读取。资金展示方式、员工／资产筛选和报表模板切换不清空整页。
- 财务报表保留税务局模板格式、三表全部项目与行号、纳税人和所属期，沿用原生成下载；桌面版式保持模板布局，移动端按项目纵向排列。看板退出“文件与处理进度”和全公司任务列表，报表生成期间仅查询这一任务的状态，文件下载时完整核验；其他任务由 AI 会计跟进。
- 默认每集合 20 条，计数和汇总覆盖完整范围；精确业务直跳独立于首屏分页，不遍历所有页寻找对象。HTTP 使用整数分字符串，CLI/MCP 保持整数合同；未知、零值、失效和历史账面与当前业务口径分别保留。
- 已关账及被后续关账覆盖的月份不显示独立月度核对区块，状态在页头表达；经营金额、业务变化及真实待办留在对应栏目。开放月只有有效核对预览才显示一条老板确认提示，点击后按精确摘要读取与密码窗口同版的内容；刷新或切换选择立即收起旧内容，失效后不跳到新预览。老板看板默认不请求核对正文、不运行完整 readiness，AI workflow、period_readiness、核心业务查询及关账仍保留完整核验职责。

## 管理资料与重放

已有展示档案、收款人和个税人员资料由服务端及 AI 按精确身份复用。名称、用途和说明只有明确来源时才追加类型化管理档案；冲突或不能确证的资料继续保留待核对，不根据名称相似、内部编号或金额相同推断关系。

真实资料、原件位置、证据摘要、类型化请求、回执及补齐前后的不可变记录核验保存在忽略目录 `data/reconstruction-sources/dashboard-display-20260912/`，不进入源码或软件包。管理补充不重算凭证，也不重写历史月结封存。

操作协议要求同步保存原件已经明确的名称、用途和说明。只有用户明确指定时才建立空库重放目标，按身份映射关联原文件、业务和档案；经营说明按实际顺序区分关账前内容和后来补充。参见[空库重放手册](empty-database-replay.md)。当前体系仍为 draft／0，正式版延期；性能通过记录与本次恢复摘要后的验证分别记录在[第 9 阶段](kernel-refactor-stages/09-performance-and-release.md)，旧页面的通过结果不替代恢复后的验收。
