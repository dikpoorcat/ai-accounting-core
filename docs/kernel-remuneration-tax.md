# 报酬与确认税额

工资、奖金和劳务的记账内核不计算个税。报酬正文保存人员、所属期、毛额、费用归属及适用社保公积金事实；`remuneration_tax_basis` 按稳定的 `source_kind/source_id` 保存最终报酬表应扣或实际扣税依据。内核从毛额扣除明确的个人社保公积金和税额，形成净额及应付款。

## 登记与发布

税依据包含报酬所属期、税期、整数分税额、`final_statement`／`actual_withholding`、明确确认和不可变证据，并以 `source_fact_id` 绑定确认时采用的精确报酬版本。支持工资、奖金、`labor`、`labor_accrual` 和 `labor_project_cost`。人员或毛额变化须重新核对税依据；只修改社保来源而人员、毛额未变时，可复用原真实扣税。实际扣税日仅在原件明确时填写，不强制与税期同月。零税也须有本期依据，工资无变化不能沿用上月税额，未列入个税表不能推定零税。缺税允许保存报酬正文；工资、奖金和 `labor` 正式预览与发布返回结构化缺项。两类计提劳务无税依据仍可发布毛额应付，净额代发等待税依据；后补依据触发原业务复核，重新发布后按原来源拆出净额与应付个税，不重复确认成本。

每项报酬只能采用一份当前税依据。补充或更正税依据推进受影响报酬的复核，不改变工资正文修订或无故撤销工资方案确认。合并来源必须保存完整的个人报酬分配和控制总额，各项税额之和等于原总额；同一原位置不能采用相互冲突的分配或将整池重复用作个人税额。

身份纠错同时修订报酬人员时，税依据也须由负责人明确确认并作为同次修订提交。`IdentityChange.remuneration_source_revision` 指向同次报酬业务的精确下一修订；编译器将其绑定为实际生成的 `source_fact_id`，原提案与解析后的正文分别保留。该入口只允许保持原报酬身份、所属期、税期及税额的显式税依据修订；缺目标、错修订、改金额或未经声明改精确引用会原子失败。普通税额更正仍通过类型化税依据入口办理，不自动复制旧值。

实际申报独立保存；银行缴款通过真实收付事实分配并核销应付税款，不反推个人扣税。申报额与账面扣税额存在差额时，核对来源并明确处置，银行代发保留现有有据的暂留差额能力。工资计提、扣税依据、申报、代发文件和实际付款不是同一完成状态。

## 个税输入文件

原有工资 XLS 模板只输出身份、申报收入、免税收入、社保公积金、扣除和减免资料，不输出内核计算税额。导出引用已确认的精确工资修订及有源管理明细，可在取得税额及工资正式发布前生成。每列包括零额均须明确，申报范围不由历史扣缴起点推定。映射、人员、明细或模板能力缺项仅阻断文件；同阶段条件满足的核算继续办理，不据此转到后阶段追问、确认或发布。

通过 `preview_tax_import` 核对后，`confirm_tax_import` 保存冻结文件任务。其 `output_directory` 可省略，默认使用公司内部 `exports`；提供时是导出父目录，新任务成果目录由程序分配。旧任务恢复或重试仍使用原载荷和精确路径。只有 `jobs` 成功且内容核验通过后，才用会计 Skill 的桌面复制脚本交付 XLS 与核对报告；相同内容复用，不同内容自动另名保留。文件生成和交付不代表已申报或已付款。

## 历史与结构调整

业务类型、业务编号和凭证链保持稳定。变化的当前事实写入新的类型化正文表；原正文、摘要、依据、凭证和冻结记录保留。每个修订必须恰好存在一份合法正文。原计税事实及旧扣税记录退出新登记，只用于读取、核验和清偿；显式引用原个人扣税记录时核对其精确修订及人员、期间、金额和证据，不自动转换历史计算数。

重算旧业务前通过当前类型化入口补齐事实。开放期保留编号替换，闭期在指定开放月建立关联冲正。公司库的结构调整保持 `ai-accounting-kernel/2`、`draft / 0`，只接受已声明的完整源指纹，追加前向结构合同和调整历史并验证失败回滚；不修改目录结构，不用新计算覆盖冻结历史。

开发与隔离合成库验证不代表已调整真实公司库或更正真实账务。真实库调整前必须先完成并验证备份，按明确授权应用已验证的前向步骤。
