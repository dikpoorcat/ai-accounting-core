# 当前内核空库重建

空库重建只有用户明确指定时执行，全部从头，仅使用整理后的重放文档及其明确索引的原件和负责人确认作为业务输入。目录、负责人、公司、实体、事实和计算身份均重新创建；负责人登录名由本人在原生窗口重新填写，不从旧目录读取或预填。通过当前类型化入口登记正确事实，并默认使用重放专用批量入口按月关账，不复制旧凭证、余额、计算结果、关账状态或完成标记。引用重建文档、发现运行缺口、结构指纹变化或既有重放范围确认，都不构成执行空库重建的授权。普通记账保留逐月本机密码批准。当前系统仍为 `ai-accounting-kernel/2`，目录库和公司库均为严格核验的 `draft / 0`，公司备份格式为 2；执行真实业务不表示第 9 阶段验收完成或正式合同已经冻结。

[重放专用批量关账](replay-batch-close.md)已实现并通过139项相关合成验证，其中重放31项、启动与模式查询10项。第9阶段未完成；本机显式启动才启用重放范围。开发通过或普通服务启动不自动恢复真实操作；已有明确继续授权时，核对当前库、原范围、实际进度及同版预览，以显式重放服务沿原范围接续，不重复请求已获得的继续授权。真实执行状态及回执保存在私有记录。能力缺失时暂停受影响的业务写入并补齐开发修复，不改为逐月弹出密码窗口，也不自行建立空库。

开发验收与明确授权的真实重建分别记录。合成验证使用[新公司库隔离验证与恢复检查单](formal-empty-db-startup-checklist-template.md)，不能证明真实公司资料完整或已经关账。真实重建以用户当前明确的公司、建账月份、截止月份和排除事项为范围，实际计划、来源、进度及完整回执保存到忽略的私有目录。重建授权不包含删除旧资料或覆盖现有数据库。

## 当前库优先

默认先使用当前本体系库试用并补齐缺口，保留已经登记、发布和冻结的进度。实现修复与真实业务分别执行；修复后重新核对当前库合同、身份、服务版本和实际状态，沿原进度继续。未经用户明确指定，不安排空库重放、新公司身份或新的负责人设置。

结构变化前先完成当前库备份并验证产物，再准备显式、有来源的同体系前向结构调整。调整核对源合同、目标合同和完整指纹，保留目录、公司、数据库及负责人身份、原件、事实修订、正式计算和凭证、审计、关账冻结及采用依据。过程须有事务、失败回滚和数据保留核验，不能用改标识、覆盖文件或当前重新计算代替迁移。已发布的 `released` 合同不可回写，旧体系库或备份不能借此导入新体系。

已实现的 `upgrade-development` 及结构历史、事务回滚和数据保留验证见[开发库前向升级](development-database-upgrades.md)。入口只接受包内声明的精确来源和目标；没有对应路径时保留当前库和备份、记录阻断并补齐开发与隔离验证，不自动切换到空库重放。显式新建合成库只用于测试，真实执行状态记录在私有回执中。

## 资料保全与来源审查

原件与负责人补充确认保存在忽略的 `data/reconstruction-sources`。每家公司独立记录原始相对路径、原文件名、字节数、SHA-256、页码或原行位置、来源、允许的日期精度、稳定业务引用、依赖引用、明确核算事实和未决事项。具体公司身份、金额、身份证件、工资、账号、真实说明和完整响应不进入公共文档或源码。

按真实字节核验原件；相同内容的其他路径或别名记入索引，不为改名修改字节。来源清单只追加，旧负责人确认和历史回执继续保留。每家公司形成一份私有最终事实清单，按字段和适用月份明确后续确认对旧解释的替代关系。先查完整补充确认，再确定仍缺少的事实；旧计划中的待问事项不自动成为当前缺项。

旧记录中的业务输入、原始确认和不可变附件可以作为事实索引；旧凭证、税额、折旧、累计数、期末余额和完成标记只用于解释历史差异，不能替代原始事实。个人付款日期、管理日期、核算所属月和公司实际收付款日各按其来源保存；原件仅明确月份时保留月份，不补造具体日。规则计算税额、实际扣税、实际申报与实际缴款各有自己的依据。

最终事实清单是后续空库重建的唯一输入导读，包含实体、政策及生效区间、期初依据、类型化业务事实、资产启用与专用计算步骤、完整材料及最终处置、银行原行与匹配、必要报告分类和未决事项。每项保留稳定来源业务键、原件摘要与定位、真实日期及允许精度、依赖键；目标库的实体、事实、计算、凭证版本、修订号及预览摘要在执行时重新绑定。清单不提供新的执行器，也不保存可跨库重发的请求包。

已查清的录入错误、来源误解、补齐事实及关联版本修复，合并到首次正确输入。旧草案、生成脚本、冲正重记及无影响复核回执列为历史查证资料，退出重建执行入口。真实后续付款、退款、备用金退回、债务抵销及业务变化按实际时间独立保留。核算金额与报税金额分别采用各自依据；最终扣款只减少一次核算工资，实际付款沿原金额登记，原工资资料按其真实金额维度关联。

整理后的验收以最终事实、原件及当前规则为依据。原回放产生的修订次数、凭证数量、后续纠错月份和冻结余额只解释历史；首次采用正确输入会改变这些结果。材料成员、合计、方向、归期及重复选择完整核对，保留未知事实及排除月份的边界。

## 目标与建账边界

1. 验证当前服务、实际 MCP 连接及负责人本机登录，读取 `finance_local_schema` 的运行协议、事实、命令及数据库合同。启动方法见[本地会计工作台启动](local-kernel-startup.md)。页面可打开不代替身份或 MCP 检查。
2. 先核对用户已明确指定空库重放，再明确目标资料根、各公司建账月份、截止月份及排除事项。每家公司独立业务库；新建目标文件必须不存在，已有文件即使没有业务行也不能覆盖。目标结构必须匹配当前完整指纹，不自动补标识或借重放替换当前库。按已登记的负责人范围确认原件制作私有范围文件，由本机显式启动 `daemon --replay-scope <private.json>`，限定公司、数据库、月份和该确认的 SHA-256；不能复用普通常驻服务或隐式继承重放权限，负责人仍须有效登录。范围文件不授权新建负责人身份。
3. 在本次全新目录和负责人下，依据重放文档重新创建目标公司，查询实际目录与上下文。依据文档来源确定建账前资产、负债、权益和必要累计数；零期初必须有明确依据，不能从空表推断。期初须在正式业务凭证和关账前完成，使用当前类型化入口，见[期初接续](local-kernel-opening.md)。
4. 建立来源稳定引用到新目标实体、业务及事实编号的映射。来源键不是数据库 UUID；旧公司 ID、实体 ID、事实版本、计算 ID、凭证版本、预览摘要和批准均不能跨库套用。新身份及依赖只能采用目标库实际返回。

完整公司包恢复保留包内身份与记录，只接收当前支持的同结构格式 2 公司包；空库重建重新形成事实与计算；投影维修只重建已保存正式内容对应的派生结果。三者互不替代。旧公司 v1–v13、目录 v1–v3 和旧备份不作为当前升级或恢复来源。

重放范围文件严格使用 `format: "ai-accounting-kernel/2/replay-close-scope/1"`、`catalog_instance_id` 和 `targets`；每个目标只含 `company_id`、`database_id`、`first_period`、`last_period`、`owner_confirmation`，最后一项是已登记范围确认原件摘要。启动时校验格式、精确目录/公司/数据库身份、1至120个连续月份及公司不重复。仅开发 `draft` 公司库允许显式测试范围，`released` 正式公司库拒绝；不另设manifest或会话token字段。文件只在显式启动时读取并固定，`ensure`及自动启动默认普通服务，不继承范围；更新文件后必须显式重新启动。

## 逐项登记与核算

使用 `workflow(company_id, as_of, period?)` 或指定月份的 `period_readiness` 核对银行、工资、普通业务、税务、资产、融资六类资料和核算状态，另列关账、实际办理和文件交付。这是工作状态，不是固定执行顺序；缺项保留待办，继续可独立处理的事项。

人员、机构、资金账户、资产等先用 `find_entities` 查找，再复用或登记。按当前 Schema 及专用入口登记证据、资料与类型化事实，金额使用整数分，不提供任意科目或借贷分录。[业务来源主体标识](business-source-identities.md)原样复用当前登记结果，含冒号的内核生成工资身份仍是合法来源；实体与业务来源分别采用自己的身份合同。CSV/XLS/XLSX 检查明细、隐藏行列、控制合计、金额和期间；PDF、图片、文本保留实际定位。逐项归期和处置、事实登记、正式发布分别完成，文件引用或旧完整标记不能绕过未处理行。

银行对账保留原行的完整日期、金额和编号。单一来源可对应同账户、同日、同方向的多条原行；一条原行也可通过多个 `matches` 引用不同的完整资金来源，但这些组合来源只对应该原行，完整合计须精确一致。不提供推断性分摊或模糊多对多匹配；资金页每条原行仅计数一次。修复及验证范围见[来源引用与组合银行对账](reconstruction-runtime-fixes.md)。

跨月原件保全其完整内容，逐项确定真实期间；排除月份的业务不提前登记或清偿历史应付。遇到 `needs_information`，先将结构化 `fact_issues` 与已保全来源核对。重建文档缺失的来源和处理规则统一记录，再查Git历史及保全旧库中的原业务输入、负责人确认和证据；查清后直接改写文档和候选。旧自动计算、凭证、余额或完成标记不能补造事实。只追问会改变处理且查证后仍无依据的缺项，管理缺项和技术故障不能直接变成负责人核算问题。

按最终清单先准备实体、完整政策、人员档案及有源税务事实，再按核算月份保存并发布工资和其他业务；真实收付款引用已经发布的义务，随后完成银行核对及材料最终关联。跨月原件的联合组或关联需要后月事实时，先完成拟关范围内的依赖，再逐月关账，不能先关闭来源登记月再补改关联。关账资料证明保留重复关系和同业务竞争来源的全部递归依赖、原件摘要及归期和处置版本；读取未来原件不提前冻结未来核算。旧资料规则证明保持原样，规则变化后的当前核验使用完整检查。各项使用当前入口的同版 `preview` 和 `confirm`，处理强重复候选和实际依赖；政策和首次工资处理的生效区间保持准确，后月规则不向前延伸。实际外部办理与账务核对分别保存；申报、扣税、缴款、文件生成互不推定，未知实际办理日期不填成确认日或月末。

公司说明通过 `company_context` / `update_company_note` 保存版本。原时点事实与说明、后来核实的录入修订、后来发生的新业务、关账后补充的管理资料分别记录。后补名称、用途或经营解读不能冒充旧关账前已知内容；经营说明重新绑定目标库预览依据，不复制旧摘要。

## 中断与重放批量关账

每次写入保存原请求键、载荷、公司及实际回执。响应丢失时重发原载荷与原请求键；只知道请求编号时使用 `request_result`。`unknown` 仅表示尚未观察到提交，不是失败，不能据此另记一笔。原载荷无法可靠恢复时先查真实业务状态；预览过期重新核对，内容改变使用新请求键。中断或切公司后重读上下文与工作状态，不沿用另一公司的对象、回答范围或批准。

按公司完成拟关月份的资料检查与核算，再调用 `preview_replay_close_range`，使用扁平 `company_id`、`first_period`、`last_period`、`owner_confirmation` 核对同一限定范围、已关账前缀及当前预览内容。使用 `confirm_replay_close_range`，携带相同四项字段，将返回的 `digest` 传为 `preview_digest`，另带同一 `epochs` 和稳定 `request_id`。无关账前缀时从范围首月开始，已有前缀时从其下一月继续。后续月份在前月实际关闭后由内核重新准备完整月度核对，逐月执行全部资料、核算、报表、内容完整性和冻结检查，并各自创建备份任务；范围确认不能豁免任何月份的业务事实或资料门槛。

批量确认不逐月请求 `approve_period_close`，冻结内容的 `approval` 为 `null`；重放范围、负责人及稳定批量/逐月请求身份进入审计。范围文件及其审计不冒充密码批准。普通常驻服务拒绝批量命令；普通记账继续使用 `preview_close`、同版页面核对、本机密码批准和 `close`。密码、恢复码和会话令牌只走本机安全渠道。

中间月份阻断时返回部分完成状态，保留已关月份，停在首个阻断月，不跳月、不重建已关前缀。同一请求的原样重试先核对已提交子请求与实际冻结链，再接续剩余月份。事实、资料、管理版本、读取修复版本或会话改变后停止旧批量，重新 `preview_replay_close_range` 核对剩余范围，使用新预览及新请求键。不能把已有范围确认当成可无限复用的预览或登录权限。

完成后读取实际关账结果、冻结报表、待办和后台任务。已关账凭证与采用依据保持冻结，后续会计更正走关联冲正，不能用当前计算覆盖历史。账已关、外部办理待核对和文件未完成可以同时成立，不概括为全部完成。

## 备份与交付记录

每家公司在已配置的关账备份目录中独立生成 `<统一社会信用代码>.finance-company.zip`，经过当前便携包核验后交付。`backup` 返回持久任务，通过 `jobs(job_id=...)` 查询；只有成功结果指向已验证 ZIP 才算完成，pending 或中间 SQLite 文件不算交付。首次备份只有当前 ZIP，后续滚动才产生 `.previous.finance-company.zip`。

失败时按安全错误码和说明处理原因，再重试原任务，不无限创建新尝试。需要恢复验证时使用独立且不存在的目标文件，核对格式、身份、证据、事实、凭证及关账；不覆盖现库，不把外部文件生成解释为已付款或已提交。

私有进度记录逐公司、逐月保存采用来源、新编号映射、请求回执、正式发布、关账结果、未决事项、排除范围及验证后 ZIP。旧重录脚本、`finance-replay`、`finance-backup`、`ai_accounting.replay_cli`、`finance_record_event` 和组合回放执行器均不作为当前执行入口。旧资料只用于查证，实际业务通过当前 `finance-local` 的 MCP 适配执行。
