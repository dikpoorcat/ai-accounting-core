# 老板看板与内核边界

老板看板沿用现有五页：经营简报、资金、员工、资产和财务报表。此次对齐只调整这五页的信息取舍和读取方式，不增加趋势页、其他页面或业务写入功能。看板回答经营资金状况、重要变化及其影响、风险和需要本人采取的行动。

页面呈现经营资金业务对象、金额、时间、影响、风险和明确待办，并保留老板要求查看的会计凭证及税务局模板报表。凭证公开编号、科目、往来对象、借贷分录和金额可在简报查看；试算过程、来源引用或采用证明、原始 JSON、内部编号及其他技术详情不进入看板，也不放入折叠区。核算来源、完整依赖追踪和诊断仍由 AI 会计通过服务端、CLI/MCP 读取；展示取舍不得改变正式业务事实或检查结果。

“AI 会计核对中”表示暂不需要老板介入的核对工作，不是老板待办。正常未付款、未申报或未关账状态本身不生成老板付款／办理待办。只有需要本人确认、补充资料、付款或作出决定时，才列为待办，并写清对象、金额、期限、影响和下一步。待收待付按真实业务义务表达，不以账户互转重复计入对外收支。

五页概览、资产与用工构成沿用原字号、字重、卡片和交互。资金余额和品牌导航保留原绿色；实际收款及资金增加使用高饱和鲜绿，浅／深主题为 `#008A32 / #4BEF7D`，浅底色为 `#E2F5E6 / #153A22`。长期资产、固定资产、无形资产及净值使用低饱和灰青绿，与现金流绿拉开色相和饱和度，浅／深主题为 `#657C76 / #9CADA7`，浅底色为 `#EDF1EF / #293530`。待收保留原蓝色，待付保留原橙红色（`warning`）；实际付款、资金减少、累计及本月折旧摊销、亏损使用原红色（`danger`）。取得成本、项目成本、工资及劳务成本、公司承担社保公积金统一使用柔和紫色，浅／深主题为 `#76558C / #C6A8DF`，浅底色为 `#F1ECF5 / #32283B`。实际收付按金额符号保留退款与更正的方向判断；已结清等完成状态保持绿色。报表的普通正文和税务局模板保持原版式。

## 页面口径

| 页面 | 面向老板的信息 |
| --- | --- |
| 经营简报 | 本期经营与资金摘要、重要变化、会计凭证、风险和本人待办。恢复按业务／按凭证、凭证展开、分页／全部及原有卡片样式；业务金额、凭证合计与实际资金影响分别展示。 |
| 资金 | 账户余额、真实资金变动、待收待付和资金相关风险。汇总覆盖全范围；资金明细只列真实账户，未指定时由后端在同一次请求内选择第一个，筛选应用于完整记录后再分页。 |
| 员工 | 本月薪酬成本、实际支付、截至月末未付，人员清单与本月薪酬保留，劳务单列。员工默认筛选“已确认在册”，员工和劳务共用员工明细标题旁的一处员工筛选及卡片／列表切换，默认卡片。员工不展开历月工资及逐笔付款，劳务保留相关收付记录；展开内容只补充当前布局未展示的信息。AI 核对中与确需本人处理的事项分开表达。 |
| 资产 | 在用、待启用资产和项目成本的对象、金额、时间及状态；默认筛选当前在用，资产明细标题旁的现有筛选后设置唯一的卡片／列表切换，默认卡片。卡片保留全部现有信息，项目投入保持原样；列表展开只补充主行未展示的信息。保留付款金额摘要，不展示逐笔付款或业务记录入口，不把整批或项目来源款项推定为逐卡分摊。 |
| 财务报表 | 季度关键金额、三张报表、税务局模板格式切换和生成下载。模板保留行号、全部项目、纳税人及期间，移动端纵向展示；切换格式不重新读取报表。 |

简报的经营金额按实际入账月份表达，收入、费用、赚亏的完整性只针对这些返回金额。月末资产负债和本月用工成本保留 2.1 版业务展示，使用同快照已核金额及窄摘要；往来按明确对象归类，不把不同对象抵消，资本化劳务另列且不计入用工费用。待收待付和资产负债的未知单独提示，不能把已确定的经营金额也变成未知。服务端仍核对全月入账来源、采用关系、凭证金额和月度投影；本月非零未映射金额与期末非零未映射余额分别提示，期初采用未建立不显示完整结论。快速通路不适用时精确读取必要来源，不把可确认金额降为未知。

简报资金摘要只读取账户金额与真实收付，不为银行匹配笔数生成另一份核对汇总。资金金额未知时明确提示 AI 会计核对中；确实缺少已约定的银行资料时，仍通过老板待办说明需要补什么。逐账户银行核对留在资金页，完整对账及其阻断继续由 AI 会计和内核处理，不把普通未匹配笔数重复列为经营风险。

五页共享公司与期间上下文。默认每个明细集合返回前 20 条，同时给出完整范围汇总和全量数量；筛选先在后端完整集合上执行，再对筛选结果分页。选中简报、资金、员工或资产的对应模块后，沿当前筛选和快照自动逐页读取剩余记录，每页仍为20条；页面先显示已读内容，续页不加入默认刷新等待链路。取消“加载更多”，失败保留当前范围已读内容并提供重试；切走模块取消正在读取的续页，切回从未完成游标继续，已读完不重发。公司、月份、筛选或快照变化时取消旧请求并拒绝迟到响应。业务详情仍在展开时才读取，展开后相关收付自动续页，收起即停止。凭证“分页／全部”切换及精确定位继续保留；报表没有续页集合。精确业务直跳按稳定业务身份查询，不通过遍历分页寻找目标。页面明确区分全量汇总和当前筛选／已读范围。

三处业务清单共用行文字、间距、分隔线、悬停、金额及展开箭头样式。所有普通列表参照简报“按业务”保留外侧留白：桌面左右 20px，手机 12px；表头、记录分隔线沿同一内缩轨道，首末列再留出 4px，不让横线直接连接外框。员工、劳务、资产、按凭证、资金按流水、基金与普通报表采用同一规则；展开主行与补充区之间不额外画横线，资金按业务不固定铺展开底色，沿用共享悬停与焦点反馈。报表的税务局模板保留原始版式。1200px及以上将业务对象与事项分列；较窄屏幕统一为对象在上、事项在下，时间、状态、金额和凭证重新排列，无横向滚动。对象用主文字，事项用现有简明字段，完整说明中新增内容留在展开区，不拆解中文摘要推测事实。

| 清单 | 桌面列顺序 | 全范围顺序 |
| --- | --- | --- |
| 资金明细·按业务 | 日期、对象、事项、方向、金额、展开箭头 | 实际日期升序，同日按对象；当月按月确认在实际日期后，缺日期最后 |
| 本月发生·按业务 | 业务时间、对象、事项、状态、业务金额、凭证、展开箭头 | 实际日期升序，同日按对象；当月按月确认在实际日期后，缺日期最后 |
| 待收与待付 | 对象、事项、状态、待收／待付金额、展开箭头 | 分类内按对象，再按事项及稳定身份，不用未显示月份排序 |

对象以完整显示名称固定字符升序排列，同名对象按正式身份区分，多对象保留完整范围。服务端先在已核范围批量读取日期、对象与身份的窄元数据，确定全范围顺序，再读取命中页的正文及分录；开放月和冻结月沿各自历史依据，不以当前数据改写历史。前端沿游标追加，不对已读局部页重排。社保公积金四项采用统一事项排序前缀和正式分组键，原行只写“社保与公积金”，月份只用于正确分组及必要详情说明。

三处清单的原功能、读取边界及同库前后验证见[统一清单验证](kernel-refactor-stages/09-performance-results/unified-business-lists-20261007.md)。后续审查修复同快照凭证刷新及待到达页恢复，限定排序祖先读取并消除资料依赖闭包重复遍历，实际结果见[看板审查与集中优化](kernel-refactor-stages/09-performance-results/dashboard-review-20261007.md)；本次未做整页计时，不继承历史大型样本的性能结论。

看板不展示“文件与处理进度”，也不提供全公司后台任务列表。报表页生成时通过 `report_export_status` 版本 1 按精确任务读取状态和公开错误，不读取来源或工作簿；下载继续核验完整文件。后台任务清单、恢复、诊断和期间检查仍供 AI／CLI／MCP 使用。

HTTP 金额继续使用十进制整数分字符串，浏览器按整数精确处理。精准请求关联、公司／期间／筛选／快照校验、响应结构校验及失效处理继续保留在 wire 合同；它们保障读取正确性，不作为老板可见内容。切换公司或期间时清除旧页面数据，过期响应不得覆盖新上下文。数据版本变化后旧分页和精确定位结果失效并重新读取。

## 版本与读取合同

看板响应版本：`context` 为 3；`brief` 为 14；`funds`、`employees` 为 9；`assets` 为 10；`business-status` 为 7；`quarterly-report` 为 5；`close-review` 为 2。简报默认返回 `financial_position` 和 `workforce_cost` 两份完整金额摘要；集合续页省略它们，前端保留主响应摘要。保留 `collections.vouchers`、全月 `voucher_count` 和精确 `focused_voucher`，不组装旧诊断图。业务续页同时返回命中页对应的精确凭证及保存分录，两集合按业务页顺序配对；页面将其加入凭证索引，不拼入独立的凭证分页集合或替换其游标。`month_state` 和可为空的 `owner_review_request` 保留，内部定位信息不展示给老板。待收待付主清单不设业务月份列；跨月清偿仍按原业务与入账期间核验，两处统一整行按需展开，原行保留对象、事项、时间／所选月余额和状态，展开只补充新增用途、必要关联对象与收付进度；待收待付不重复月末剩余金额，本月发生不重复本次事项卡。整笔款项逐项展示月末进度，后续仅列变化，相关收付显示紧凑读取进度与失败重试，读完后省略重复完成提示，最后一条记录不画底线；颜色区分正常未结清、结清、更正与纯历史。按需详情义务补传正式方向与款项分类，未知分类不默认应付。分页集合保留单一 `items/page` 表达；凭证全部显示沿同一快照的游标读取，精确直跳不依赖首屏分页。

按凭证主行完整显示保存摘要、冲正说明和准确业务金额；独立业务进展入口与分录展开互不触发。详情与摘要对齐，分录采用科目、往来对象、业务来源、借方、贷方五列三线表，不再显示会计分录标题；逐行资产链接与业务来源合并，必要的未逐行映射资产仍保留。收起箭头统一向右，展开向下。桌面进展通过 Teleport 在入口左侧显示，右箭头指向入口；最大宽680px并适应可用空间，视口四边保留12px，共用凭证及流水批次预览样式。款项名称独立成列，历史及后续分别按准确应收、应付、预付等语义分组，共用原金额、已收付、可选其他处理、剩余和状态表头。支持 WebKit 的浏览器使用3px滚动条，其他浏览器采用 thin 回退，状态与滚动条保留12px间距。手机保留原标签式分录和款项卡片，进展点击打开底部浮层，关闭回到入口焦点。进展只补充整笔业务所选月末收付、按义务身份确认的真实后续变化、未出现过的用途／备注和必要对象，不把分录当作实际收付。用途按完整可见文本去重，对象按正式身份去重，不同角色及同名不同身份保留。事件没有精确对应某版凭证时不按金额、月份或名称删除。简报必需布尔字段 `has_business_progress` 准确决定进展入口；无进展显示“—”，没有悬停、聚焦或详情请求。字段来自当前有界页元数据及窄关系查询，不逐行调用完整业务详情，不预加载进展。首次桌面悬停／聚焦或手机点击才按详情7合同读取，每页20条，相关收付自动续页。成功内容、游标及续页失败状态按公司、月份、快照、业务身份和收付口径保存在工作台局部缓存，重开及同版本刷新后可复用。刷新收起浮窗；范围变化清空缓存，关闭、切换或卸载取消未完成请求，迟到响应不能保存或追加。不新增原业务余额查询，不加入默认刷新等待链路。实现与历史计时边界见[凭证业务进展验证](kernel-refactor-stages/09-performance-results/voucher-progress-20261007.md)。

待付个人社保、公司社保、个人公积金和公司公积金按正式员工身份与工资所属月份合并一行，对象与“社保与公积金”分开，原行不附月份；实发工资、个税及其他款项保持单列。同名员工、不同工资月份不混合，常规工资使用正式工资期间，期初余额使用工资所属月；缺少明确身份或月份时保留单行并提示核对。清单未读完时合并行显示“正在汇总”，续页失败显示“尚未读全”，不把已读部分称为完整合计；分类和摘要此时仍标原始“余额分项”，全部读取后改为合并项数。分页进度始终按原始分项计数。展开直接使用已读分项，固定列出四项的原应付、实际已付、抵销／代付与月末待付，不重复标题或合计，不额外请求工资详情；工资所属月不同于所选月时在拆解中注明；月末清单没有的项注明“该月末未列待付款项”，不补造原金额或已付金额。后续进展按义务身份只列变化，未知与超额单独提示，合计为零不作为结清依据。分组随现有集合增量追加，全部读完后统一精确汇总，不参与默认刷新等待；身份字段复用本页已有工资事实，不改变正式义务。实现与同库验证见[社保公积金合并验证](kernel-refactor-stages/09-performance-results/social-groups-20261007.md)。

资金页未指定账户时使用 `movement_account_selection=first`，服务端返回明确的 `selected_movement_account` 和该账户全月分页；不先取得全账户明细再重读整页。自动页游标与随后明确账户的分页使用相同筛选，空账户和没有收付的账户仍分别表达。“按业务”按资金行身份整行点击或Enter／空格展开，同一区域一次展开一行；原行保留日期、事项、对象、方向与准确金额，更正用中性色说明“更正原业务”，金额不再重复更正文案。详情占满行下方，仅补充不同于原行的完整说明、用途、备注和按角色区分的关联对象；按账户身份排除侧栏当前账户，其他同名账户与不同角色仍保留。本业务自身款项进度逐项保留历史与实际变化，付款没有返回原业务余额时省略进度，不据此判断结清，不追加原业务查询。相关款项处理自动续页，保留用途、方式、月份、准确金额与失败重试。切账户、公司、月份、快照或按流水时收起，同范围重开复用；普通同快照刷新不重发详情，已展开详情可在其他页面模块继续后台续读。“按流水”完整显示日期、账户、银行摘要、对方、方向与金额，长摘要和名称自然换行；普通流水没有明细入口。“明细”为独立一列，位于收支金额左侧，列头与各行固定对齐；批量付款及组合收付款显示“N项”，没有明细的流水显示“—”。桌面细指针悬停或聚焦显示带指向箭头的浮窗，清单可移入滚动，移出入口及浮窗150ms后收起；点击入口或“查看完整明细”在原流水下展开全部清单，再次点击收起，同一区域仅展开一条。手机及不支持hover的设备在独立明细区域直接点击展开。浮窗与展开均保留收款人、逐项金额、批次合计及多条流水不能逐项归属的提示，不重复列表字段；支持键盘聚焦、Tab进入清单和Escape关闭。浮窗挂到页面顶层并适配视口边缘；页面滚动或窗口尺寸变化时关闭，浮窗内部滚动保持打开；刷新、筛选、切公司、月份、快照、查看方式或页面模块时清除浮窗及展开状态。所有明细复用已加载的同一份数据，没有额外请求或专用缓存。CLI/MCP 不指定账户时仍可查询全账户记录。全公司金额、数量和银行核验不属于被删除的“全部账户”选项，继续保留。按业务详情实现与同库验证见[资金行详情验证](kernel-refactor-stages/09-performance-results/funds-details-20261007.md)。
