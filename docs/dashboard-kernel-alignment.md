# 老板看板与内核边界

老板看板沿用现有五页：经营简报、资金、员工、资产和财务报表。此次对齐只调整这五页的信息取舍和读取方式，不增加趋势页、其他页面或业务写入功能。看板回答经营资金状况、重要变化及其影响、风险和需要本人采取的行动。

页面呈现经营资金业务对象、金额、时间、影响、风险和明确待办，并保留老板要求查看的会计凭证及税务局模板报表。凭证公开编号、科目、往来对象、借贷分录和金额可在简报查看；试算过程、来源引用或采用证明、原始 JSON、内部编号及其他技术详情不进入看板，也不放入折叠区。核算来源、完整依赖追踪和诊断仍由 AI 会计通过服务端、CLI/MCP 读取；展示取舍不得改变正式业务事实或检查结果。

“AI 会计核对中”表示暂不需要老板介入的核对工作，不是老板待办。正常未付款、未申报或未关账状态本身不生成老板付款／办理待办。只有需要本人确认、补充资料、付款或作出决定时，才列为待办，并写清对象、金额、期限、影响和下一步。待收待付按真实业务义务表达，不以账户互转重复计入对外收支。

## 页面口径

| 页面 | 面向老板的信息 |
| --- | --- |
| 经营简报 | 本期经营与资金摘要、重要变化、会计凭证、风险和本人待办。恢复按业务／按凭证、凭证展开、分页／全部及原有卡片样式；业务金额、凭证合计与实际资金影响分别展示。 |
| 资金 | 账户余额、真实资金变动、待收待付和资金相关风险。汇总覆盖全范围；资金明细只列真实账户，未指定时由后端在同一次请求内选择第一个，筛选应用于完整记录后再分页。 |
| 员工 | 本月薪酬成本、实际支付、截至月末未付，人员清单与本月薪酬；劳务仍单列。移除“各月份工资与付款”，不展开历月工资及逐笔付款。AI 核对中与确需本人处理的事项分开表达。 |
| 资产 | 在用、待启用资产和项目成本的对象、金额、时间及状态；保留付款金额摘要，不展示逐笔付款、处置等业务记录入口，不把整批付款推定为逐卡分摊。 |
| 财务报表 | 季度关键金额、三张报表、税务局模板格式切换和生成下载。模板保留行号、全部项目、纳税人及期间，移动端纵向展示；切换格式不重新读取报表。 |

简报的经营金额按实际入账月份表达，收入、费用、赚亏的完整性只针对这些返回金额。月末资产负债和本月用工成本保留 2.1 版业务展示，使用同快照已核金额及窄摘要；往来按明确对象归类，不把不同对象抵消，资本化劳务另列且不计入用工费用。待收待付和资产负债的未知单独提示，不能把已确定的经营金额也变成未知。服务端仍核对全月入账来源、采用关系、凭证金额和月度投影；本月非零未映射金额与期末非零未映射余额分别提示，期初采用未建立不显示完整结论。快速通路不适用时精确读取必要来源，不把可确认金额降为未知。

简报资金摘要只读取账户金额与真实收付，不为银行匹配笔数生成另一份核对汇总。资金金额未知时明确提示 AI 会计核对中；确实缺少已约定的银行资料时，仍通过老板待办说明需要补什么。逐账户银行核对留在资金页，完整对账及其阻断继续由 AI 会计和内核处理，不把普通未匹配笔数重复列为经营风险。

五页共享公司与期间上下文。默认每个明细集合返回前 20 条，同时给出完整范围汇总和全量数量；筛选先在后端完整集合上执行，再对筛选结果分页。选中简报、资金、员工或资产的对应模块后，沿当前筛选和快照自动逐页读取剩余记录，每页仍为20条；页面先显示已读内容，续页不加入默认刷新等待链路。取消“加载更多”，失败保留当前范围已读内容并提供重试；切走模块取消正在读取的续页，切回从未完成游标继续，已读完不重发。公司、月份、筛选或快照变化时取消旧请求并拒绝迟到响应。业务详情仍在展开时才读取，展开后相关收付自动续页，收起即停止。凭证“分页／全部”切换及精确定位继续保留；报表没有续页集合。精确业务直跳按稳定业务身份查询，不通过遍历分页寻找目标。页面明确区分全量汇总和当前筛选／已读范围。

看板不展示“文件与处理进度”，也不提供全公司后台任务列表。报表页生成时通过 `report_export_status` 版本 1 按精确任务读取状态和公开错误，不读取来源或工作簿；下载继续核验完整文件。后台任务清单、恢复、诊断和期间检查仍供 AI／CLI／MCP 使用。

HTTP 金额继续使用十进制整数分字符串，浏览器按整数精确处理。精准请求关联、公司／期间／筛选／快照校验、响应结构校验及失效处理继续保留在 wire 合同；它们保障读取正确性，不作为老板可见内容。切换公司或期间时清除旧页面数据，过期响应不得覆盖新上下文。数据版本变化后旧分页和精确定位结果失效并重新读取。

## 版本与读取合同

看板响应版本：`context` 为 3；`brief` 为 13；`funds`、`employees` 为 9；`assets` 为 10；`business-status` 为 7；`quarterly-report` 为 5；`close-review` 为 2。简报默认返回 `financial_position` 和 `workforce_cost` 两份完整金额摘要；集合续页省略它们，前端保留主响应摘要。保留 `collections.vouchers`、全月 `voucher_count` 和精确 `focused_voucher`，不组装旧诊断图。业务续页同时返回命中页对应的精确凭证及保存分录，两集合按业务页顺序配对；页面将其加入凭证索引，不拼入独立的凭证分页集合或替换其游标。`month_state` 和可为空的 `owner_review_request` 保留，内部定位信息不展示给老板。待收待付主清单不设业务月份列；跨月清偿仍按原业务与入账期间核验，两处统一整行按需展开，原行保留对象、事项、时间／所选月余额和状态，展开只补充新增用途、必要关联对象与收付进度；待收待付不重复月末剩余金额，本月发生不重复本次事项卡。整笔款项逐项展示月末进度，后续仅列变化，相关收付显示紧凑读取进度与失败重试，读完后省略重复完成提示，最后一条记录不画底线；颜色区分正常未结清、结清、更正与纯历史。按需详情义务补传正式方向与款项分类，未知分类不默认应付。分页集合保留单一 `items/page` 表达；凭证全部显示沿同一快照的游标读取，精确直跳不依赖首屏分页。

资金页未指定账户时使用 `movement_account_selection=first`，服务端返回明确的 `selected_movement_account` 和该账户全月分页；不先取得全账户明细再重读整页。自动页游标与随后明确账户的分页使用相同筛选，空账户和没有收付的账户仍分别表达。“按业务”按资金行身份整行点击或Enter／空格展开，同一区域一次展开一行；原行保留日期、事项、对象、方向与准确金额，更正用中性色说明“更正原业务”，金额不再重复更正文案。详情占满行下方，仅补充不同于原行的完整说明、用途、备注和按角色区分的关联对象；按账户身份排除侧栏当前账户，其他同名账户与不同角色仍保留。本业务自身款项进度逐项保留历史与实际变化，付款没有返回原业务余额时省略进度，不据此判断结清，不追加原业务查询。相关款项处理自动续页，保留用途、方式、月份、准确金额与失败重试。切账户、公司、月份、快照或按流水时收起，同范围重开复用；普通同快照刷新不重发详情，已展开详情可在其他页面模块继续后台续读。CLI/MCP 不指定账户时仍可查询全账户记录。全公司金额、数量和银行核验不属于被删除的“全部账户”选项，继续保留。实现与本次同库验证见[资金行详情验证](kernel-refactor-stages/09-performance-results/funds-details-20261007.md)。

同公司、同期间的资金按业务／按流水切换、简报业务／凭证模式、报表格式与三表切换只更新本地显示。资金账户、员工和资产筛选需要后端读取时，仅替换对应集合首屏，并绑定原快照；全公司汇总及无关集合保持可见。局部加载或失败不显示旧筛选结果及计数，重试仍读取该集合首屏；公司、月份或快照真正变化才重新读取相应范围。业务行点击展开详情，凭证号悬停或聚焦显示单个浮窗，点击已加载凭证直接在当前区域展开，不发请求；页面直跳仍由首次请求精确定位。凭证索引按保存的版本身份查找，刷新、切公司、月份或快照时清空，不缓存跨请求核验结论。

资产卡片只返回 `payment_summary`，保留准确来源范围、去重汇总、未知金额和核对状态。项目、处置和退役的逐笔付款字段及专用查询退出；资产看板不再提供 `settlement_events`。卡片不再预加载这些详情或历史笔数，也不再写入人员／资产详情缓存；必要付款摘要按来源范围在同一快照内复用。前端不再累加整套付款明细。

员工不再提供 `payroll_sources`、`settlement_events` 集合，退出工资历史分页、来源定位及逐笔付款组装；前端删除展开后的请求、按人员保存的历史页缓存及其追加、重试和失效代码。精确员工定位与默认列表使用相同的名单范围，只有身份或汇总范围无法证明时才回退完整读取。员工本月薪酬和截至月末未付仍保留必要历史汇总、身份与来源核验，同快照的精确范围汇总缓存继续使用；劳务详情与 AI 业务查询保留各自清偿能力和缓存。默认列表原已按需加载历史明细，本次减少的是展开或精确定位的额外读取，c063三主及独立分布整页热刷新已完成并达标；整组结果不单独归因这一员工读取改动。

月份清理组已沿五页和共享详情核对：交易日期、跨月工资分组、项目期间与报表季度各有业务用途，保留；清偿及冻结查询也不因简报删列而退出。没有月份专用 SQL 或刷新请求需要删除，默认刷新仍为上下文和主数据两个请求。后端定向4项、前端定向8项、生成同步、类型和构建检查通过；当时资料根只读确认简报版本10及字段退出，当前生成合同已为版本11；旧定向验证不冒充当前整组结果。后续c063规定主／独立热刷新及主120按需功能已成组验证，来源见阶段9。

老板看板默认不运行完整 readiness。页面可以显示明确的业务状态和待办摘要；AI workflow、完整 `period_readiness` 与 corebusiness trace 保持完整查询能力，仍服务于 AI 会计工作流和核算核对。普通未付、未申报、正常往来及非必需管理资料缺项不自动成为异常或老板待办。

关账核对存储合同保持版本 4，`OwnerReview` 保持版本 1。已关账及被后续关账覆盖的月份不显示独立核对区块，不默认读取核对正文，也不重新生成老板待办；关账状态留在页头，经营金额和业务变化留在现有栏目。开放月份仅当存在有效、可以核对的活动预览时，在老板待办显示一条提示，点击后按精确 `preview_digest` 读取与原生密码窗口相同的业务摘要。刷新及切换公司、月份时收起旧内容；预览失效后不能静默切换到新版本。存储合同及 CLI/MCP 核对能力继续保留正式事实与完整历史依据，展示裁剪不改变冻结内容、校验和批准边界。

AI 会计仍通过类型化入口准备、核对和执行关账，页面不增加准备、批准、关账或其他业务写入功能。实际付款、申报及其他外部办理各自遵循其正式事实和回执；看板不从“未完成”状态推断应由老板行动。

## 现有规则中需清理的偏差

会计凭证及税务局模板已按用户要求保留，技术追溯、试算过程、来源证明与内部编号不进入老板页面。默认20条及完整清单按需读取保持；c063主／独立450热刷新分别全部<500ms，主120按需37操作／75响应／159 HTTP功能组也已通过。1de新开发包161 CLI／19 MCP已完成，压力仅诊断；240／1536资源诊断与独立只读补证已完成；本轮开发范围完成，代码、测试与文档随本阶段提交。全部失败、未覆盖分支及源码窗口边界见[阶段9](kernel-refactor-stages/09-performance-and-release.md)，不将单项定向通过或正常功能补验扩大为整阶段、真人窗口、强制崩溃或整轮AI GUI验收。
