# 看板与内核对齐说明

本轮保留原五页界面，以现有 SQLite 内核和数据库已有资料调整展示。修复的是查询、关联和页面口径，不重新记账，不修改已冻结的核算结果，也不新增数据库版本或迁移。下文保留首轮对接验收；后续老板视角优化和经授权的现库管理资料补齐见[老板视角优化](dashboard-owner-experience.md)。

## 已有资料直接复用

历史页面缺少姓名或人员编号时，按同一身份复用已有展示档案、收款人资料及个税导入身份，提供实际采用的资料来源；存在冲突则提示核对。负责人不必为了让页面显示名称重新录入已经存在的资料。

实际申报可以发生在工资所属期之后，页面按工资来源关联，分别列出税期和登记月份，后来补充的资料有明确提示。期初薪酬分别展示工资来源期、启账月及正式应付组成；奖金和期初接续不会被提示补充常规工资申报。入离职日期优先用于判断所选月份的在册情况，当前停用状态不能倒推过去已经离职。上述管理信息不会改变工资、税额或历史凭证。

只有确实没有依据的资料才显示“未提供”。按月确认的取得月份、扣缴起点等保留月份精度，不补造日期。居民身份、购价拆分、付款到期日等原来恒空且不符合当前事实结构的栏目已移除或替换。

## 五页采用的展示口径

| 页面 | 本轮调整 |
| --- | --- |
| 经营简报 | 业务确认金额、凭证合计和实际资金分别展示；交易方按对应业务关系关联，批次人员不复制到每条分录；冲正和更正各自指向其核算依据。用工成本包含独立奖金拆分，资本化劳务另列。 |
| 资金 | 对外流入流出剔除账户互转，账户明细仍保留转入转出；银行流水区分未提供、部分覆盖、完整覆盖及待复核。货币基金按确认成本列示，申赎确认和真实收付款分别展示。 |
| 员工 | 工资、奖金、社保公积金、规则计算税额、实际扣税及申报分别查看。按工资来源期展示公司付款、代付转债、非现金抵销、尚未清偿及代发保留差额；劳务区分费用化与资本化，不按付款比例推算毛额或税额。 |
| 资产 | 在用资产、待启用固定及无形资产、尚未转出的项目成本一并展示并核对。多笔收付款和核销按来源展开；整批验收展示批次债权人及结算，项目形成资产展示成本来源，不推定逐卡付款分摊。处置确认与款项收回分开。 |
| 财务报表 | 已有月份不等于已关账；准备事项保留业务和凭证定位。预览采用的补充资料沿用到导出；任务完成且文件校验通过后才能下载，失效结果明确提示并支持重新生成。 |

## 刷新、分页与金额

T4 的页面版本、独立集合、游标、未知候选及当前跟进口径见 [有界看板查询](bounded-dashboard-queries.md)。下文的既有验证记录保留其原适用状态；T4 新增验证单独记录，不累加通过数量。

五页使用同一公司和月份选择。切换时取消旧请求、清空旧数据；刷新同时更新可选月份，等待中的旧响应不能覆盖新选择。

汇总由后端完整计算，长明细按页加载。继续加载时校验数据版本；期间数据变化则重新加载，避免旧页和新页混在一起。页面说明已加载范围，局部筛选不会冒充全量筛选。

浏览器接口传输整数分字符串，前端使用 `BigInt` 精确显示。CLI/MCP 继续保持原有类型合同；页面不重新计算会计结果，也不将缺少的银行资料当作零流水。

## 首轮内核对接验收结果（老板视角优化前）

2026-09-12 最终定向回归 **112 项通过**，覆盖上表六组看板测试，以及审计、性能、管理资料和迁移；前端 **19 项通过**，类型检查、`npm run build`、`npm run build:release`、相关 Python Ruff 与差异格式检查通过。

首轮 `pytest tests -q` 为 1,083 项通过、2 项失败。两项均已定位并处理：关账竞态测试仍挂在已不再调用的预览函数上，现改为真实事务开始前注入；无经营说明的快照无谓扫描全部历史凭证，现跳过未被使用的摘要计算。与原版本对照，无说明、有效说明、过期说明三种完整快照及摘要相同。最终 112 项复跑包含这两个失败案例及其相关回归，均通过；收尾没有再次重跑全部目录，不将不同批次计数相加为全量通过数。

两家现有公司的 **60 个可选月份、21 个季度**已用最终代码只读查询：四页月度查询共 240 次，季度报表 21 次，无查询错误。未打开可写业务连接，未修改真实公司资料。

浏览器以真实同源接口及合成公司核对五页和两个 HTML 入口、直接刷新、桌面及 390 像素手机布局、主题和侧栏偏好、公司切换竞态、登录失效、重复显示编号筛选、分页版本失效后整体刷新、完整明细、原凭证—冲正—替换依据导航，以及失效报表文件的解释和重新生成。待启用无形资产计入顶部净值，账户资料缺项明确显示，未出现页面横向溢出或未处理的 Vue 异常。

独立软件包已实际解压到其他目录，完成文件摘要核验、原生负责人登录、CLI/MCP、五页入口与六个鉴权查询、后台自动备份及恢复、仓库和包内启动器验证。最终包的计算构建、19 份发布资源与当前仓库逐项一致，软件包不含业务数据库。
