## 1. 当前裁决

内核已能在隔离临时 PostgreSQL 17 上使用完全虚构数据演练“从过去月份开始，逐月录入、生成期间和关账”的流程，但这只是工程验证，不是正式试用授权。

用户已完成 `DEC-001` 至 `DEC-031` 的正式选择。产品定位已固定为“单一小企业负责人 + AI/确定性内核”：负责人使用本地账户密码登录，只提供原始凭据并说清业务事实；AI 与内核负责分类、计算、记账、校验和追问，但不得推测缺失事实。一期不设业务角色或第二人复核，本阶段只做本地 Windows 单机部署；正式试用入口保留一次离线专业校准，不给专业人士创建系统账户，不介入日常工作。备份采用停服快照和独立本地数据库账户；依赖扫描器报告任何已知漏洞都无豁免阻断；本地登录与 MCP 之间通过 Windows Credential Manager 交付不透明 session token。

## 2. 已通过的虚构数据演练

新增单一 PostgreSQL 演练用例 `tests/test_private_pilot_simulation_postgres.py`，且只连接由 Testcontainers 临时启动的 `postgres:17-alpine@sha256:742f40ea20b9ff2ff31db5458d127452988a2164df9e17441e191f3b72252193`。演练使用虚构企业、客户事实、员工、资产、贷款人、证据和银行行，未读取默认 Compose 数据库或真实文件。

演练已验证：

1. 从 2026 年 3 月开始，按顺序生成并关闭 3 至 7 月五个自然月；
2. 3 月正式事实包含服务现销、工资计提、固定资产取得/启用、无形资产取得/摊销、金融机构借款放款/计息及税期确认；
3. 4 至 7 月逐月完成固定资产折旧、无形资产摊销和借款计息后关账；
4. 8 月开放期中，税期来源锁先阻止直接冲正 3 月销售；按顺序先冲正税期调整、再冲正销售后，3 月关闭 JSON 和 SHA-256 快照逐字节不变；
5. 全部凭证由既有固定模板生成并借贷平衡，未新增自由分录入口。

精确执行结果：`1 passed in 12.31s`。演练完成后 Testcontainers 已自动清理，当前仅保留原有默认 `ai-accounting-core-postgres-1`，且本阶段没有写入它。

本文件所在候选提交的完整门禁为 `461 passed`：非 PostgreSQL 集合 `341 passed`，固定 digest 的临时 PostgreSQL 17 集合 `120 passed`。Ruff、`pip check`、`compileall`、Alembic 单 head、依赖锁校验和 `git diff --check` 同步通过；测试没有连接默认 Compose 数据库或真实数据。

## 4. 历史账接入的硬边界

已决定的 `DEC-003` 允许企业从过去的真实开始记账月份起，逐月生成期间并录入截至当前的业务，但前提是能从该月起完整重建所有业务事实、证据和义务链。

若开始月之前已存在银行余额、应收应付、预收、固定/无形资产、借款、工资累计或税务累计状态，当前内核不得用自由分录、推断默认或伪造业务事件吸收这些期初量。这类企业必须停止接入，等待独立的期初余额/历史迁移项目和专业复核。
