- 目录：`396c26ab12876f416d0c5daea8ad75379929c20a0a8bd623f1c876260a79bf90`。
- 公司：`cf2cd67b54042f7f775a3f1c4972a89cf04898a84b476bc3160b78c70dc3cbbb`。

目录 v1—v3、公司 v1—v7 的结构合同保存在 `kernel/migrations`，已发布文件不回写。版本、`user_version`、身份、`schema_history` 和完整结构指纹共同核验；同版本缺表或封存触发器也拒绝写入。已知版本通过前向事务升级，失败包括提交失败都回滚，不以重新建表掩盖损坏或未知结构。

两个已正式关账的 v6 公司备份均已在独立目录升级到 v7：除身份版本和结构历史外，旧表内容逐项相同，新增实际扣税表初始为空；故障注入后原结构和数据均恢复。实际服务随后使用同一构建完成升级。

公共 Schema 与执行共用严格类型模型，所有入口检查字段、类型、公司身份及版本。业务只提交类型化事实，不接受任意分录或调用方编制的计算结果。预览返回完整计算结果及摘要；相关结果在一次预览中按依赖顺序核对，正式确认通过统一发布器原子提交。

计算在一致快照上执行，写事务外完成；正式提交再检查负责人权限、相关状态版本、预览摘要及幂等请求。数据库保护整数金额、引用、封存、借贷平衡、闭期和历史不可变。开放期更正保留凭证号，闭期更正直接反向原凭证并关联开放期新处理。

## 资料与业务

- 原件保留内容摘要与位置。表格全量核对原行、隐藏数据、金额、期间、控制合计及拆分；PDF、图片和文本保留页码或位置。公共分页不截断内部完整性判断。
- 来源归期和逐项处置版本只追加；联合来源组核对完整成员及联合结果容量，不编造逐行分摊。事实和结果中的同一金额别名共享使用额度，失效结果不继续证明资料已处理。
- 公司说明防覆盖更新，按业务类型、人员、期间和状态查询事实及来源。旧回放补充说明、修正版和负责人确认作为有依据的事实来源；旧凭证、余额和计算结果不导入新账。
- 工资方案复用须有明确本期确认。未知扣除保持空值；没有实际扣税确认时，仅在同一计算器证明税额必为零的范围内允许上界计算入账。
- **实际扣税与规则计算分开保存。** 有依据的 `payroll_withholding_actual` 决定本次工资扣税，保留规则计算值、差异、原申报累计减除及证据。后续累计抵扣采用实际已扣额，不更改规则或入职事实来凑平税务结果。
- 实际申报、实际扣税、外部缴款和银行付款分别追溯。实际扣税已确认时，相应差异不再形成暂扣；工资、代发依据和相关外部办理结果统一更正。重算不改写真实银行付款。
- 期初接续明细核验完整性和借贷平衡；无依据缺项不能用零或权益差额配平。期初不计入本期收入、费用或现金流。备用金和平台处理遵循明确确认范围，不推断资金性质。
- 关账与完整代发共用逐项完整性检查。核算缺项、漏项及对账不平阻断关账；外部申报缴款进度单列待办。已关账月份始终读取冻结版本。

## 身份、服务与真实恢复

独立负责人已从明确旧目录一次性接续到新 SQLite 目录，旧会话和关账批准没有转入。原密码可在原生 Tcl/Tk 窗口登录，Windows 凭据管理器保存当前会话；密码不进入聊天、命令行或业务 MCP。一次性接续桥及专属测试已删除。

每个资料根目录一个常驻服务，统一提供鉴权、命令、页面和后台任务。公司创建及恢复保存持久操作记录，启动恢复中断操作；导出及备份自动执行、有界重试，失败保留状态。不能将排队响应当作文件生成成功。

两家公司历史关账共用一次原生密码批准。批准绑定每家公司的数据库身份、明确起止月、摘要及状态版本，每家公司在一个事务中消费批准、关闭整段月份。后续 8 月更正没有再次要求关账密码。

18 份本轮历史季度三表文件已生成并核验。关账后的备份及 8 月实际扣税更正后的最终备份，均由 Online Backup API 生成每家公司独立 ZIP，再在独立目录恢复。全部证据摘要、冻结报表、月度金额和正式回执与实际 MCP 快照一致；四类汇总清空重建后相同，再次备份和独立恢复后的全部表相同。

保全目录保留 7 份旧备份中的原件及事实确认提取、完整回放补充索引。7 个旧结果 ZIP、3 个旧中间备份目录和相应临时旧结果回退 ZIP 已清理。删除只涉及审查过的具体路径及 Compose 项目标识匹配的容器和卷，没有执行全局清理。当前及 previous 新版公司备份保留。
