# 关账前资料覆盖核对

本页说明当前 `ai-accounting-kernel/2` 的资料入口。资料核对保存原件覆盖、真实期间、金额与处理依据；正式核算仍由类型化业务完成，不接收自由分录。运行时的 `finance_local_schema` 是请求字段和当前能力的发现入口。

## 操作顺序

1. 读取 `company_context`，核对公司、当前业务说明和实际进度。
2. 用 `evidence` 登记完整原件，保留原文件名、字节和摘要，再用 `inspect_material` 核对解析范围；`receive_material` 独立保存资料来源及解析说明。
3. 跨月原件通过 `preview_material_allocation`／`confirm_material_allocation` 明确逐项真实期间，未知期间保留未知。归期不表示业务已处理。
4. 登记并发布有明确依据的业务，再用 `resolve_material` 保存逐项处置。只有完整核准池、没有逐行分配依据时，使用 `resolve_material_group`。
5. 六类月度清单通过 `inventory` 追加原件范围和负责人完整性确认；无业务必须有该公司、该月、该类别的明确依据。
6. 用 `material_completeness` 检查拟关月份。关账和完整代发共用该检查器；文件引用、空表、旧完成标记不能代替真实覆盖。

普通记账按同版预览及本机批准关账；已明确授权的重放范围使用[批量关账](replay-batch-close.md)，不逐月请求密码。当前库补齐缺口默认保留已有进度，[空库重建](empty-database-replay.md)只有用户明确指定时执行。

## 原件、金额与方向

CSV、XLS、XLSX读取隐藏行列和工作表。当前 `specification` 使用 `columns`、`sheet_columns`、`header_rows`、`total_rows` 和 `controls`；列角色为 `amount`、`context` 或 `recognition_period`。未映射数据、真实金额缺失、公式无缓存、精度问题及控制合计差异均保留，金额不自动补零。

XLSX 预填模板只有在整行没有实际输入、所有公式均为同排空输入范围的 `SUM` 且原缓存为精确零时，才不生成该行原本不存在的金额字段；原公式缓存及位置仍进入覆盖记录。共享公式须有已知种子、明确适用范围和正确的位置平移。实际姓名、日期、文本、数值（包括手填零）、异常缓存、跨行或外部引用、声明的合计行或控制位置均不享受此豁免。只有模板的文件仍不能证明该公司当月无业务；CSV、XLS 和已冻结的旧解析依据保持原语义。

已登记 `evidence` 的完整原件还须通过 `receive_material` 进入资料池；仅保全文件不会让其业务行进入完整性检查。同一原表同时含模板和真实业务时，完整接收原表，对实际业务逐项归期和处置。

`controls` 明确每个合计的原位置和完整成员范围；只覆盖实际声明的成员。无法直接读取的金额可以在有明确来源时通过处置确认整数分，原值与诊断保留；确认后的明细和控制合计仍须一致。不能裁掉问题列、隐藏数据或把业务行伪称控制合计。

金额列的 `funds_direction` 仅依据原表头或明确来源声明：`inflow`／`outflow` 表示非负收入／支出列，`signed_net` 表示原正负净额。省略时沿用净额符号语义，不能从展示标签猜方向，也不能改原数的符号以绕过核对。

PDF、图片和文本以 `passages` 保存完整阅读后的原位置、页码和摘录，并明确 `all_pages_reviewed`。摘录和文件诊断本身不证明业务已处理；没有通用OCR能自动保证自由文本完整性。

## 正式结果与完整核准池

`MaterialLink` 明确业务身份、事实类型、事实版本、计算版本、金额字段、整数分金额和核算月。结果必须是当前正式采用的有效结果；允许无凭证业务结果，但其领域约束仍须满足。相同数值不建立金额字段的别名；只有领域声明的别名共享确认容量。

逐项 `recognize` 或 `other_period` 的链接金额之和等于原行金额。多个原行可分配到同一业务，但合计不能超过其原确认容量。后续清偿不减少原确认容量，也不使失效结果重新有效。

联合组保留原 `members`、`group_amount_fen`、完整 `links`、明确 `joint_basis_confirmed` 及已登记依据的位置。原成员合计、组总额和结果分配合计必须相等且方向一致，不建立缺少依据的逐行到逐人矩阵。一个原行不能同时属于逐项处置和联合组，多个组也不能重叠。

## 重复资料

`duplicate` 必须引用 `duplicate_source_id`、`duplicate_location` 并说明依据，不新增业务或再次消耗原业务容量。

- `links` 为空：重复原行与目标原行必须同额、同期间，目标处置完整有效。
- `links` 非空：目标原位置必须属于唯一当前联合组；链接只选择该组已有的一个或多个**完整分配**。七个字段逐一相同，不能裁切某项金额，不能重复选择。所选金额之和等于重复原行，且核算月与重复原行已明确的期间一致。
- 新引用仍校验重复原件自己的金额和收支方向，以及目标完整组的全部成员和结果。未选中的组分配失效同样阻断；来源、组、事实、计算或选择改变继续参与资料依赖和冻结核验。

例如一条银行原行属于核准合计3000分、正式分配为费用1000分和另一项业务2000分，另一份原件明确重复后者。可以在 `duplicate.links` 中精确引用目标组的完整2000分分配；不能把2000分原件声称重复整条3000分银行原行，也不能自行截取某个较大分配。

## 其他处置与期间

`supporting` 仅用于无核算金额且来源明确为支持用途的资料。实际业务必须有业务处置。`no_accounting` 保存明确理由及枚举性质，如预测、余额控制、非本公司业务、确认前取消或实际零金额；非零业务不能按零金额跳过。实际已入账业务不能因资料重复而再次确认。

本期应确认的业务尚未正式处理仍会阻断本期。跨月文件中的未来行只在其真实所属期成为门槛；`file_status` 仅是完整文件诊断。闭期资料的新问题由后续开放月持续承接，不重写原冻结，也不挪到无依据的远期。排除月份只保全来源，不能提前登记实际收付款或冒称已完成。

## 说明、历史与备份

公司业务说明通过 `company_context` 读取、`update_company_note` 携带 `expected_revision` 追加管理版本。原始业务说明文件仍保全为来源；管理说明不替代正式事实和不可变证据。

月度清单、来源、归期和处置均保留版本及稳定请求键；响应丢失沿用原载荷和请求键，未知状态先查回执。关账在公司事务锁内重新核验，预览后出现的变化不能由旧摘要覆盖。冻结证明保留当时采用的完整版本；后续资料依赖由不可变来源和变化目录定位。

当前读取仅在资料覆盖规则摘要相同时复用已验证的闭期证明。解析、归期或处置语义改变后，旧摘要回退到完整检查；不回写原冻结、清单或原件。模板解析修复后的覆盖规则为版本2，旧版本1证明仍按其历史依据保存。

公司备份由持久任务生成，只有成功并完整核验的独立便携ZIP可交付。普通运行不清库或修补来源，结构调整采用[显式开发库升级](development-database-upgrades.md)。旧体系接口、迁移编号和旧回放脚本只保留在Git历史，不作为当前操作指令。
