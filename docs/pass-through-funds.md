# 代收代付的类型化处理

当前内核用 `pass_through` 事实记录有依据的代收债权和转付义务。事实明确付款方 `payer_id`、整数分金额 `amount_fen` 和权利义务确认。最终权利人已经具名时，`beneficiary_id` 引用真实对象；受托性质和转付责任已有明确依据、最终权利人尚未具名时，显式填 `null`。未知姓名不改变等额应收和应付，也不生成虚构人员。财报按精确的来源义务分别核对未具名责任及其实际清偿，不跨匿名来源相互抵销。未确认义务不得推断成收入、预收或可支付余额。登记前查已有对象、事实与证据，字段精度和所需来源以 `finance_local_schema` 为准。

用 `save_fact` 登记业务事实，`preview` 核对计算、期间和依赖后再 `confirm` 正式发布。实际收款、向受益人支付及其核销按各自发生日期和来源另行登记，资金方向、账户、银行原行、金额及未结义务逐项核对。看板本月发生按原采用类别拆分混合收付款；收入与代收分别列示，代收与代付各有分类，分项只展示本类别的对象、用途、金额及相关收付，原完整凭证仍可独立查看。资料接收与处置、事实登记、正式发布、真实资金收付和外部办理是不同状态，不能由其中一项推定其他项已完成。

实际付款仍须有真实收款人依据。`payment_method=individual` 要求非空 `counterparty_id`；没有单一交易方的银行汇总代付使用 `bank_batch` 并显式将顶层 `counterparty_id` 设为 `null`，每项分配仍引用真实 `recipient_id` 和精确来源义务。已具名权利人的核销必须匹配其身份；尚未具名的责任按明确的实际支付事实清偿，不以事后收款人改写原采用的来源。一个完整批次可以匹配同账户、同日、同方向且合计准确的多条原银行行，不据此猜测银行子行对应哪名收款人。

开放期事实错误通过类型化更正或符合依赖条件的删除入口处理；闭期不改原凭证，在开放月使用关联冲正和替代。缺少会改变会计处理的受托性质、付款方、金额、期间、实际收款人或证据时返回 `needs_information`，不把未知余款默认归为预收或收入。完整命令和当前能力见[类型化业务事实](business-components.md)及运行时 Schema。
