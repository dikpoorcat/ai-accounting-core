# 代码收口

## 口令

```text
代码收口
代码收口：最近3个提交
代码收口：b4e59b8
代码收口：只审查
```

## 提示词

以指定提交引入或触发的问题为起点，按当前代码沿相关调用链收口。未指定范围时优先本对话刚完成的工作及其原提交，否则采用最近一次提交；本轮相关未提交修正一并纳入。扩展修改须有直接关联，后续提交和并行改动作为当前基线，只修改能归属本轮的部分。先区分运行代码、测试、生成物、必要冻结依据、临时工具和文档，不能只凭新增行数判断好坏。

检查重复实现、无用代码、职责混杂、一次性工具进入运行层、历史适配扩散、生成物重复、测试依赖临时环境，以及重复读取、核验、装载和缓存处理。发现一处问题，沿相关调用链排查同类问题，说明实际问题、依据和修改范围，再集中修复。

清理必须贯通受影响的字段、查询、调用方、缓存、依赖、测试、生成器和文档，不能只删表面内容。生成物从定义或生成器解决；必要冻结依据保留精确来源和完整内容核验。仅集中职责、约束和变化原因相同的重复实现；语义或合同不同的实现保留独立，不为减少行数硬造框架。

技术缺陷自行处理；涉及业务用法、功能删减或体验变化，提出具体影响和建议交给我决定。保留信任链、业务能力、金额精度、历史语义及必要核验，不操作真实资料或现有服务，不覆盖其他任务的改动。

修改收敛后，按实际影响覆盖相关入口和合同，成组验证；保留业务断言、损坏拒绝和必要的工作量检查。涉及对话行为变化时，补做对应的实际对话。分别报告本轮执行、仍适用的历史结果及未验证项，不把此前构建的结果算成本轮新验证。没有新变化、失败或风险，不扩大或重复大套测试。不能靠删除断言、降低门槛或减少功能宣称优化完成。

执行“代码收口”即授权本轮技术修正及合并所需的本地 Git 历史改写。修复完成并通过必要验证后，直接将本轮代码、测试和必要文档合并至对应原提交，无须再次确认；多个目标提交按修复归属分别合并。保留后续提交的内容和顺序，以及其他任务的暂存和工作区改动。没有可合并的原提交或无法确定修复归属时，保留修改并说明原因，不自行新建提交；没有修改或未通过必要验证时不改写提交。带“只审查”时仅交付审查结果，不修改文件或 Git 历史。不自动推送。

最后简明报告：清理了什么、为什么、验证结果、仍未解决什么，以及原提交和合并后的新哈希。更新必要文档，不堆过程说明。
