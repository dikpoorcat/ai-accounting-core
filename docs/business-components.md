# 类型化业务事实与组合处理

当前 SQLite 内核的公共入口只接收注册的类型化事实、证据和明确来源，不接受任意科目、借贷方向或自由分录行。`finance_local_schema` 列出实际可用的事实、字段、专用登记命令和精度；`finance_local_command` 使用同一合同。金额以整数分提交，税率和税额计算使用十进制数。

旧 `finance_record_event` 的 `components`／`funds` 请求、`finance_preview_event` 和 `finance_configure_account` 已退出运行接口。需要同次保存多项事实时使用当前 `save_facts` 合同；每种事实仍按自己的来源、日期、证据和身份规则计算。批量登记不等于所有事实已经正式发布，更不允许提交自由分录。

## 登记、发布与更正

先用 `find_entities` 和 `find_facts` 查已登记对象与来源，再登记原件 `evidence`。普通事实用 `save_fact`，已登记事实的开放期更正用 `amend_fact`；带 `x-registration-command` 的事实走 Schema 指定的专用入口。登记只保存事实。需要核算的业务先 `preview`，核对结果摘要、依赖、期间与版本，再 `confirm` 发布。正式凭证由内核计算并保证借贷平衡。

同次保存时，每项事实保留自己的业务身份、实际日期或允许的月份精度、证据和引用。已知真实收付要提供实际日期；按月确认的业务可在其模型允许时使用确认月份。外部申报日期、用途、名称等管理资料不能填充核算日期。核算缺项用 `needs_information.fact_issues` 指明字段、精度及可复用来源；核查已有资料后再问负责人，不从错误码编造问题。

`save_fact`、`amend_fact` 和 `save_facts` 会检查强重复候选。先核对原件与事实身份，必要时保留有依据的复用或另建选择。预览版本过期后重新预览；内容改变使用新请求键。请求响应丢失可用原键重试，或用 `request_result` 查保存的提交结果，`unknown` 不代表失败。

未关账月份可以通过类型化修改原子重算，保留原凭证编号和完整审计；无后续依赖的误记业务可用删除入口撤去。已关账凭证不原地改写，更正在开放月创建关联冲正。来源依赖和清偿余额仍须逐项核对；不能为凑平衡猜测金额或从当前值覆盖冻结历史。

## 资金、工资、税务及资产

收入、费用、往来与收付款使用各自注册的事实模型。真实银行流水可通过受控导入作为核对依据；账户、方向、日期和金额必须匹配。资料文件的接收、逐项处置、归属期间、事实登记和正式发布是不同状态，文件引用不能证明清单已处理。

工资先核对所属月、人员范围、实际扣税与来源；工资确认依据和发布使用专用准备与统一预览确认。工资付款、社保缴纳、实际申报、扣税和缴款各自保存依据，不互相推定。资产启用和逐月折旧／摊销使用批次准备及发布，保持逐项计算和合并凭证来源。

外部办理用 `external_completion` 保存真实事件、已知的实际日期或明确未建立的日期状态、不可变凭据及义务精确版本；`external_basis_review` 另存办理与正式账务的核对。办理可以先于账务完成；后续账务变化只使核对过期，不撤销真实办理。季度税务办理和季度财务报表报送分别处理，生成文件不表示已经对外申报。

期初、跨月清偿、无影响复核、无凭证结果、开放期替换和闭期冲正均属正常能力。具体模型与约束始终以运行时 Schema 为准；本说明不提供固定字段默认值或旧接口兼容方式。
