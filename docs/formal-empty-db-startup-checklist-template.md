# SQLite 空库重录与完整恢复检查单

配合 [SQLite 空库重录、完整恢复与结果核对](empty-database-replay.md) 使用。
复制一份到已忽略的私有目录，逐公司填写实际证据、目标身份、结果及未完成事项。
这里是操作模板，不表示任何真实公司已经重录、关账或恢复。

## 本次范围

- [ ] 已明确选择完整公司包恢复、按原件空库重记或仅重建已有汇总，并记录原因。
- [ ] 已明确本次目标公司、来源范围和独立目标根目录；全部 CLI 显式使用该 `--root`，MCP 绑定同一目录。
- [ ] 原库、原件和可恢复依据已保全；本次操作不自动清理原资源。
- [ ] 已从 `schema` / `finance_local_schema` 取得当前命令和事实合同。
- [ ] 当前环境为 SQLite 目录库 v3、公司库 v11；不使用已退役 PostgreSQL / Alembic / `finance-replay` 命令。
- [ ] 已通过本机安全窗口设置或登录目标负责人；没有复制身份密钥、会话或旧批准记录。

## 原始资料空库重记

完整公司包恢复不逐条执行本节，也不在恢复前先创建同一公司。

- [ ] 私有来源索引逐项保存原路径、原文件名、字节数、SHA-256、明确事实、日期精度及未决事项。
- [ ] `create_company` 返回身份与 `companies`、`company_context` 一致，持久操作状态已核对。
- [ ] 每个稳定业务引用和人员、往来、资金、资产引用都映射到本目标的新 ID；未直接沿用旧版本或计算 ID。
- [ ] 原件首次 `evidence` 登记传原文件名及完整原字节；相同内容的别名保存在私有索引，未篡改字节改名。
- [ ] 多行/跨月资料按当前资料接收、逐项处置和月份归属合同完成核对；登记文件不被误算为业务已处理。
- [ ] 使用 `save_fact` / `save_facts` 保存类型化事实，缺核算事实明确保留 `needs_information`，未补造日期或零额。
- [ ] 依赖来源先发布，再处理付款、核销、折旧等后续事实；工资计算税额、实际扣税、申报和付款分别核对。
- [ ] 每次正式 `confirm` 前保存原始完整请求：公司、subjects、预览 digest、epochs、稳定 request_id。
- [ ] 中断后以原 payload、原 request_id 查询/重试，确认结果丢失没有造成新凭证或新事实。
- [ ] 新内容、新目标或已失效的预览重新核对；没有把旧摘要换公司后直接套用。

## 名称、说明与历史顺序

- [ ] `update_company_note` 保存已提供的公司业务说明；保留原来源文件，说明不代替正式事实。
- [ ] 已有姓名、账户名和业务用途先复用内核来源；需要补充的展示档案通过 `save_display_profile` 追加。
- [ ] 展示档案引用本目标实体 ID，未知人员状态不计为确认在职，入离职日期没有从工资月份推断。
- [ ] 原时点事实、录入修订、后来新业务与后补管理资料分别有来源；未用最新值假装恢复完整原审计。
- [ ] 经营结论先读本目标 `preview_period_commentary` 的核算摘要，再使用当前 context_digest / revision 保存。
- [ ] 原时点已知说明在关账前保存；最新才补齐的名称、用途与经营解读保持后补，未放入原时点关账封存。
- [ ] 资料或上下文变化后重新复核经营说明，没有把旧库正文和旧 context_digest 原样提交。

## 关账与看板核对

- [ ] 本期正式业务、逐项资料处置、实际对账及完整性确认均已完成，未用空库或空清单证明无业务。
- [ ] 已知管理资料和有效经营结论先完成，再预览关账；管理缺项未变成额外核算门禁。
- [ ] `preview_close` / `preview_close_range`、原生密码批准及 `close` / `close_range` 使用同一公司、范围和预览。
- [ ] `closed_report` 中原时点说明保持冻结；关账后经营说明显示为后补，未改变原关账摘要。
- [ ] 五页看板按实际业务范围核对：摘要金额、往来/账户名称、原件名、日期精度、工资扣税付款、资产与业务说明。
- [ ] 长明细按游标完整核对，沿用版本信息；未把第一页或前 500 条当全量。
- [ ] 原始凭证借贷平衡，冲正关系与入账期间正确；新核算与旧错误结果的差异已说明，未为对齐旧数修改事实。
- [ ] 若执行 `rebuild`，其前后已验证汇总一致且凭证不变；未把它当作缺失资料恢复或重新核算。

## 备份与完整恢复

- [ ] 每家公司分别核对 `company_settings`，用 `configure_backup` 保存本机明确选择的备份目录。
- [ ] `backup` 返回的任务已用精确 job_id 查询；只有 succeeded 且指向已验证 ZIP 的结果交付。
- [ ] 初始包独立命名为 `<统一社会信用代码>.finance-company.zip`；pending、SQLite 中间文件不算初始备份。
- [ ] 完整恢复使用独立目标根目录及目标负责人会话，由 `restore_company` 验证并恢复，不覆盖已有公司。
- [ ] 恢复后身份、事实/凭证、原件、看板摘要、名称、公司说明、经营说明及实际关账范围均已核对。
- [ ] 恢复目标重新核对备份目录；旧外部导出文件不能访问时重新生成，不把已恢复任务记录当作已恢复文件。

## 交付记录

- [ ] 分别记录资料整理、隔离验证、真实写入核对和便携恢复的完成状态，不以合成测试代替真实业务验收。
- [ ] 记录本次实际运行的测试、复核范围和未覆盖事项；不要求执行退役工具的门禁。
- [ ] 私有补充清单、断点及真实回执继续保留在忽略目录；源码与公开说明不含真实公司凭据或业务明细。

失败时保留请求、证据与可复核结果；不手工 SQL 改账、不提交任意借贷分录、不改冻结结构绕过问题。
