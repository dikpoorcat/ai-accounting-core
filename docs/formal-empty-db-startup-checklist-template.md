# 新公司库隔离验证与恢复检查单

本模板用于新建合成公司、格式 2 便携包恢复和当前接口联调。复制到私有验证目录填写实际结果；空白勾选项不表示真实公司已重录、关账或恢复。本轮不处理真实资料重录、旧库升级、旧备份导入或正式换库。历史事实与原件索引见[历史流程记录](empty-database-replay.md)。

## 目标与结构

- [ ] 目标是新建合成公司或恢复同结构格式 2 公司包；目标资料根目录与公司身份已明确。
- [ ] 旧数据库、原件、负责人确认和备份继续保全，不覆盖已存在文件，不把空业务行文件视为可新建目标。
- [ ] `finance_local_schema` 显示 `ai-accounting-kernel/2`，目录库及公司库各自为 `draft / 0`，实际结构指纹与包内合同一致。
- [ ] 服务、MCP 和负责人本机登录均已验证；页面可打开本身不代替 MCP 与身份检查。
- [ ] 每家公司有独立业务库；命令使用目标 `company_id`，切换公司后重新读取上下文。

## 工作清单与事实

- [ ] 泛化起点调用 `workflow(company_id, as_of, period?)`；自动月份有真实依据，空公司不补造月份。
- [ ] 银行、工资、普通业务、税务、资产、融资六类资料状态和核算状态分别核对；关账、实际办理和文件交付单列。
- [ ] 原件保存真实字节及定位；资料接收、逐项处置、归属期间、事实登记和正式发布分别完成。
- [ ] 使用运行时 Schema 的类型化事实或指定专用入口；金额为整数分，实际日期与允许的月份精度不互相代填。
- [ ] `needs_information.fact_issues` 已先对照现有证据及来源；管理缺项没有被误当作核算缺项，技术故障没有变为负责人问题。
- [ ] 登记后的正式核算经过同版 `preview` 和 `confirm`；强重复候选、依赖及余额有明确处理。
- [ ] 实际外部办理与账务核对分别保存；申报、扣税、缴款及文件生成不互相推定。

## 中断、关账与文件

- [ ] 每次写入保存原请求键与载荷；响应丢失时原样重试，或用 `request_result` 查询 `committed` 原结果。
- [ ] `unknown` 只表示当前公司库没有相符记录；原载荷不能可靠恢复时先查真实状态，不据此另记一笔。
- [ ] 预览过期或内容改变后重新核对并使用新键；旧公司预览、批准和回答范围不跨公司沿用。
- [ ] 关账采用 `preview_close`、同版页面核对、本机密码批准和 `close`，按公司逐月执行。
- [ ] 已关账历史保持冻结；开放月承接真实更正，外部办理和文件待办可继续未完成。
- [ ] `jobs(job_id=...)` 的备份／导出任务成功且产物验证后才交付；失败看安全 `error_code`／`error_message`，处理原因后再 `retry_job`。
- [ ] 每家初始备份在已配置目录独立生成 `<统一社会信用代码>.finance-company.zip`，不把 pending 或中间 SQLite 文件作为交付。

## 恢复与验收记录

- [ ] `restore_company` 只使用同结构格式 2 便携包，目标文件不存在，目录 `operations` 显示恢复成功。
- [ ] 恢复后核对公司与数据库身份、证据、事实、凭证、关账、看板和备份配置；原外部导出文件如不可用则重新生成。
- [ ] 验证记录区分合成测试、隔离包验证和任何未来真实业务验收；合成通过不替代负责人确认。
- [ ] 私有补充清单和回执不进入源码，源码不含真实公司凭据或金额。

故障时保留请求、证据和可复核状态，不手工 SQL 改账、不提交自由分录、不修改冻结结构绕过检查。
