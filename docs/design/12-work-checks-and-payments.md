# 内部核对清单与银行代发表

## 1. 完成的含义

老板看到的八项清单保持简短，账务已算好、外部申报已办完、文件已交付分别核验。第3项取得并采用足够实际社保公积金反馈后才完成，政策估算不替代申报；第4项检查当前核算及文件交付，不能反过来成为第3项计算的唯一入口。已有正式结果足够就复用，缺项才批量读取和定向办理；保存工资、调用过生成或旧文件成功，都不替代本次有效文件。

共用核对项与八阶段的条件、依据和未满足动作只维护在 [work-checklist.json](work-checklist.json)，由程序生成运行指南。每个内部项目分别核为满足、有据不适用或尚未满足，适用项目全部满足才给外层阶段打勾。先确定公司、work_period及本次交付覆盖范围，再判断当前动作的必要事实；工作月不替代业务所属月、申报覆盖期或实际付款月。本轮当前项未完成而拟先办后续时，AI先说明范围和依据、问老板选择；未答复或选择等待时不提前推进。明确同意后按范围继续，每次更新清单仍提醒本轮范围内所有未完成项，保留真实状态和返回位置，不重复请求同一次接续。其他月份独立事项保留原范围，不催问、不阻断本轮，也不冒充完成。第1项只核本步骤资料，第5项末核全月业务资料覆盖，第8项复用依据并检查后来变化；流水读完、报表ready和旧完成文字均不能代替。普通接续许可不等于同意先关账。正常顺序和必要跨月查证直接进行；work:月份办理说明与当前待办承接未完工作，不新增阶段状态或检查日记。

## 2. 公司长期代发安排

内核通过work_defaults.payment_export声明默认需要文件。新公司首次建立安排且没有明确选择或用途明确的本公司模板时，简短问一次，需要才索模板。已有明确交办、模板或有效代发安排直接沿用，不能每月停在待明确是否需要。明确长期不用优先于旧模板；本月不用只影响本月。核实本次没有待付金额时不生成空表，也不把长期安排改成不用。

长期选择、模板名称保存在公司说明并引用模板来源，本月例外放在对应work:月份办理说明。已有模板但说明漏记时，AI先定向查现有资料并恢复安排；历史任务只作发现线索，不当永久配置或每月扫描。当前明确选用模板优先，老板明确更换后更新当前安排；多个有效候选无选择依据时只问选哪个，不重问是否需要文件，也不自动挑最新文件。

模板是本公司的已登记来源，可有不同工作表、起始行及列顺序。请求未指定模板返回payment_template_not_selected，由AI先复用已有来源；确无模板、损坏、布局不支持分别说明。程序保留模板样式，AI按原件识别必要布局，不让老板填写技术参数，不填假值或套用他公司模板。公司说明对来源的引用沿现有保全、标准文档和备份机制接续，不新增配置表或程序解析正文。

## 3. 职责与触发

| 模块 | 负责什么 |
| --- | --- |
| agent | 按内部清单核对，未满足时调用接口，核实实际成果后向老板交付。 |
| application | 协调 `accounting_payment_export`，不计算工资、税或余额。 |
| payments | 没有业务私表的付款文件适配模块；发现合格来源、组织当前付款指令、解释模板、生成与核验计划。 |
| people / ledger | 分别提供报酬当前可付额及其他精确应付余额。 |
| identity / records | 提供当前收款资料、模板来源及有效租约，按公司隔离。 |
| files / host | 保存当前任务，后台生成、重试、核验并提供文件；重启接续已接纳任务。host复用财报的桌面保存能力交付指定任务。 |

内部清单引导 AI 调用接口；生成请求一经接纳，确定的文件工作交给现有后台。程序不因保存一笔工资就推断本次资料齐全，不另建交付意向平台或整月流程状态机。

## 4. 办理接口与范围

`accounting_payment_export` 通过现有 CLI/MCP 使用 [payment-export.schema.json](contracts/payment-export.schema.json)：

- `inspect`：读取合格候选、当前可付额和必要缺项；可省略模板，没有模板不妨碍核算或候选读取。
- `generate`：对明确范围和本公司模板形成当前计划，创建或复用持久任务。AI 不提交最终付款金额或账号覆盖，不另加预览批准。
- `status`：核对当前范围、任务和实际文件，默认沿用任务中的模板；本次改用其他模板时，带上当前模板来源检查。pending、running、failed、expired 均不等于成果可用。
- `save`：仅指定company_id、精确task_id及destination=desktop，将该任务的已核快照保存到真实桌面，返回copied/reused、path、sha256、byte_size及公司、数据库和任务身份。生成后先按原范围用status核验，再保存指定任务；save不接收period、business_ids、任意源路径或目标目录，也不自动换任务。

省略 `business_ids` 时范围是文件组织月目前已登记的合格来源；明确提供时是选定来源，可以包含以前月份未付的款项。文件period按本次明确安排选择，不改写原业务所属期，也不改变会话工作月份。计划下月发放的本月工资可以准备文件，文件自身的必要组成和收款资料仍须齐全，不索取未来实际付款结果。AI 将候选与已有资料核对，空查询不证明现实没有业务，选定文件不声称整月完整。

当前余额采用程序已知的最新正式账务；文件组织月与余额截止月分别说明，不推定实际付款月份。同范围新增报销、扣税、付款、账号或模板变化使旧计划失效；无关收入和其他公司变化不使它失效。

## 5. 金额、模板与可靠交付

工资、奖金和劳务采用 people 当前可付额，扣税、有效暂留和实际付款只减一次。付款组成状态与扣税申报状态分别读取：有明确税依据、有效申报暂留，或有来源的本次付款安排时，可以准备代发。付款安排通过原报酬的 `disbursement_basis.current_payable` 表达“按当前可付余额发放、无额外未明暂扣”，不表示零税、免税、已申报或已经付款，也不要求税期。它不固定毛额，后续实际税款或付款仍改变当前可付额。只有毛额或笼统的未报税说明时，不能自动确认本次发放；已有具体确认则直接采用，不重复追问。必要组成确实未明时只阻塞对应文件，不阻塞计提或不相关的选定报销。

报销、代收代付的转付或退回，以及期初明确的净工资、员工或负责人报销欠款，都采用公开义务及其当前余额。每项款项按真实义务区分，同一份期初包可以有多个收款人；不把期初净工资重新推算成毛额或强索原扣税资料。普通供应商、税款、社保和借款不因同属应付而自动纳入。

同一收款人同一用途合并，不同用途分行。姓名、账号和用途按文本写入，账号保留前导零；金额由整数分精确转为元。四类模板语义为姓名、账号、金额、用途，位置可变。生成后逐格回读，核对行范围和总额，不把模板示例或公式作为付款数据。

计划保存范围、必要来源摘要、收款资料、模板定位与布局、付款行，绑定相关语义头。失败不回滚正确账务；生成、下载或交付不创建实际付款、流水或凭证。没有未付余额不生成空文件。

未完成计划保护模板来源不被清理，生产读取时取得有效原件租约；缺失、损坏或过期的文件不作为有效成果。同计划重复办理复用任务，失败可以接续；回复丢失不重复创建当前交付。

代发表与财报共用桌面保存能力和回执，经各自已核下载取得独立字节及同计划绑定的身份和文件名，再校验并原子发布桌面副本。同内容复用、同名不同内容另名保留；保存失败不改变源任务，可以接续同一任务。桌面副本不随内部任务失效或清理删除，也不代表以后仍是最新内容。AI只在save返回copied或reused后，提供回执path的桌面文件链接并完成交付；内部task.path只用于任务定位，不另用脚本复制或作为桌面交付链接。

## 6. 开发与集成

负责人统一规则、合同和下面的预期，再并行开发清单指引、付款适配与文件任务，集成只用公开端口。payment_export 是当前完整结构中的独立文件种类，不伪装成财报。

在合成库验证完整结构、事务回滚、当前备份恢复和任务接续，不自动调整真实库。老板五页主要内容、样式及默认读取保持。

## 7. 审核清单

| 编号 | 达成条件 |
| --- | --- |
| WP01 | 共用核对项与八阶段条件只有一份真源；先确定公司、工作月份与交付范围，第3项实际反馈与工资采用齐全才完成。本轮未完成而先办后续由老板选择，未答复不推进；同意后每次清单提醒本轮未完项，不重复请求同一次接续，其他月份独立事项不混入。 |
| WP02 | 工资已保存但无代发表时，第4项保持未完成，AI调用生成接口、按原范围status核实文件，再save指定任务到桌面并交付回执path的链接；调用成功、内部任务链接或旧成功标记不能代替桌面交付。 |
| WP03 | 默认需要，新公司首次无安排才问一次；已有用途明确的模板或代发安排直接复用，跨月、重启和恢复后不重问。本月例外不覆盖长期安排，明确不用不被旧模板推翻，无待付额不生成空表。 |
| WP04 | 两公司不同模板、列顺序、起始行正确输出，保留样式和固定说明，不跨公司混用。 |
| WP05 | 工资、奖金、劳务、员工费用报销、报销归集、代收代付及期初净工资和报销欠款选对义务；同一业务可含多个真实义务，同人同用途合并、不同用途分开。 |
| WP06 | 三类报酬的有来源付款安排可独立于税期确认；税务状态保持真实，后续扣税、暂留和部分付款只减一次，跨月选款采用当前余额和原业务用途；生成前后账务、资金和应付不变。 |
| WP07 | 后加同范围油费、金额/账号/模板变化使旧文件失效；政策估算改为实际申报金额时，工资明确采用后更新可付额及文件，实际付款仍独立。无关收入、公司和历史增加不触发无关重算。 |
| WP08 | 重复请求幂等，失败和进程中断可接续；缺失或篡改文件不返回可用，实际单元格和总额核验。 |
| WP09 | 卡号及本次付款组成等真实缺项先查已有来源；已经明确的付款安排不重复问，不强索税期、申报回执、身份证、手机号、可选票据或员工收款后的去向。 |
| WP10 | 公开CLI/MCP接真实合成模块完成读取、生成、后台、状态核验及精确任务桌面保存；核对身份、同内容复用、冲突保留、失效拒绝和失败接续。独立AI按规则补做并提供实际桌面文件链接，不写死台词。 |
| WP11 | 当前完整结构可创建、核验和准确恢复；备份恢复保留身份账务，重置本机文件任务并按需要重新生成，失败不覆盖既有目标。 |
| WP12 | 补充或撤去付款安排只改变有来源的采用及文件就绪判断，不制造扣税或付款；闭期沿既有无金额影响的更正接续，原凭证、原金额和历史读取保持，当前读取采用新依据。 |

程序测试核对固定金额与实际文件，独立 AI 对话核对行动和解释。分别说明覆盖范围，不用提示词代替核算，也不用固定 JSON 调用代替 AI 行为验收。
