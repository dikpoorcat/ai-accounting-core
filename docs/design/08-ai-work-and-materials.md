# 会计 AI 如何带老板把工作做完

AI是老板的会计和知识外挂，主动查清业务、作专业判断并办理。老板提供现有资料之外无法得知的现实事实及必要的办理选择，程序负责确定性计算、保存和接续。本节规定工作方法；具体核算条件以[业务规则](05-business-rules.md)和[接口合同](03-contracts.md)为准。

## 开始与接续

开始读 `accounting://guides/work`，取得实际连接的支持目录和公司上下文。只有公司名也要先定位工作：综合当前交办、有效安排、未完成事项、来源及正式业务，确定本轮月份、交付范围和当前动作。依据明确就说明并继续；确有多个独立工作、无法定序时，才把具体选择交给老板。

`work_period=null`只表示尚未选择，不证明老板缺少信息。最早开放月、系统日期、最新来源月份和最近work说明都只是线索，不能单独定月。最近work可能已完成或属于未来准备；不适用时继续查已有资料，不停在泛问“记几月”。确定后传入`work_period`；跨月查证、阶段切换、中断恢复和本月关账不暗中换月。

`accounting_schema({})`取得实际command/kind目录。用`accounting_schema(command="accounting_apply",kinds=[本单种类])`取得提交外壳及完整事实条件，待办`known_fact`的种类也须选入。纯说明、来源、对象、普通待办或撤回且无事实时传`kinds:[]`。其他命令按command读取合同，不读整套业务大Schema；已有有效规则直接复用。原kinds-only查询仍可独立查看事实合同。

首次需要业务规则时读取`accounting://guides/business`共同规则，再按当前kind读取专项规则。专项指南只交付该种类及其真实type/method分支；采用当前分支的条件，不能把同页其他分支或后续事项都当必需资料。更正时读`accounting://guides/corrections`。阶段条件按当前步骤读取，已读且仍适用的内容直接复用，不每轮重读全部。实际工具调用和安装见[运行说明](09-runtime-and-ai.md)。

## 先查清当前动作，再办理

先明确老板交办的完整成果，再确定当前动作、必需事实、可复用来源、成功结果，以及以后另办什么。工资计提、实际扣税、代发表和发薪分别判断，不能把后来结果全部变成当前计提的前置要求；也不能为了少问，将“把本月账做好”缩成“能保存这一条”。现实业务覆盖、已发生的付款关系和当前成果所需核算仍须查清。

AI先结合当前业务分支判断某项信息是否必要，再综合对话、有效说明、已读原件及正式结果自行回答。资料分散不等于缺失；多份来源可以共同支持判断，不要求某张原件逐字写出最终结论。已有依据足以分类时由AI负责，不让老板解释会计枚举。核对实际存在的其他候选和冲突，不穷举无依据假设让老板排除。

准备提问时，AI须能指出：这一事实或选择尚不明确，不同答案会怎样改变当前金额、期间、真实权利义务、付款关系或交付；现有来源为什么仍不能解决；老板能提供哪项现实信息或办理选择。仅仅“专业上可能有关”“合同有这个字段”或“为了记账准确”不能成为提问理由。已有线索要查清，但不能先假设一套特殊情形，再要求老板逐项证明不存在。这个判断由AI完成，不新增提问审批、记录表或向老板展示内部核查表。

| 当前情况 | 应怎样处理 |
| --- | --- |
| 尚未读取或串联资料 | AI定向读取、综合，不转成老板待办。 |
| 真实候选或来源冲突 | AI查版本、身份和关联；仍不能区分且影响当前结果时，只问现实差异。 |
| 输入、引用或程序交接错误 | AI修正或排查，不让老板解释内部编号。 |
| 所选计算方式不支持 | 查已有支持路线并说明能力边界，不手算替代，不让老板先申报来补算法；也不反复索取与能力缺口无关的资料。 |
| 必要现实事实确无来源 | 说明已有信息、剩余缺口、为什么影响本轮和答案用途，再请老板补充。 |

`null`、必填字段、空查询、未匹配或`needs_information`首先描述程序所知，不直接等于老板缺资料。Schema说明怎样提交，不独自证明老板必须回答；试提交报错也不能替AI决定该问什么。未匹配不证明付款没登记，无申报记录不证明现实未申报。输入格式、未登记引用、失效政策和上游计算问题先由AI处理；真实必要事实仍无来源时才向老板提问。

必要事实有有效来源、需要区分的候选范围已查清、没有影响金额、期间或归属的已知冲突，就结束核查并办理。未知不填零，有据不适用与未核验分开。可选票据、未来结果和无证据的假设不延长核查。

例如，取得投资不统一索取未来赎回或税务优惠的全部资料；但本次真实收款人与投资交易方不同，且现有资料不能证明代转关系时，需要问清这笔钱是否清偿该投资义务。不能把这个当前缺口忽略，也不能由此扩大成基金底层经营、管理人或持有人的整套问卷。工资当前可承担个人缴费时不先问承担不足的处理；实际出现不足且没有既定安排时，才明确该项选择。

工作月、业务所属月、报送覆盖期和付款月分别处理。当前事项需要的跨月依赖主动查证，但不接办相关月份全部工作；其他月份独立事项不加入本轮提问或反复提醒。查询范围按实际业务确定，不以电脑日期推断报送季度。

义务、清偿、资金和原行关系用`accounting_review`：身份已知直接inspect，确需找候选才find，按业务范围、经济截止月及版本接续。义务原月未知先查，不先索取月份；已结义务及已登记未匹配资金也可检查。工资当前可付额用薪酬接口，不从凭证手算。原件和完整事实由来源、业务读取入口按需取得。

## 内部核对与老板看到的进度

内部条件、依据及动作只有[work-checklist.json](work-checklist.json)一份真源。读`accounting://guides/work/checklist`取得共用条件和阶段目录，需要时读`accounting://guides/work/stages/{1..8}`。每项分别判断“条件已满足”“有据不适用”或“尚未满足”；适用内部项全部满足，外层阶段才打勾。保存成功、技术ready和旧勾选不代替核验。

第1项只核本步骤流水、账户渠道和款项处置，不提前索要全部后阶段资料。收付款对象按所在步骤的本批结果核对；已有有效结果复用，必要时批量查证，不逐笔另起问答，也不拖到第5项集中处理。

第5项末核全月业务覆盖：已收材料处理完，不等于现实全部业务资料交齐。结合实际经营、最终交接材料和既有答复判断，银行流水不能独自证明工资、报销等全部资料齐全。充分且适用的覆盖依据直接采用；仍不明确时说明已核范围，只问剩余必要覆盖，不列每月特殊事项否定问卷，不另造“全部通过”确认文件。

第8项复用有效覆盖判断，核查后来新增或改变的事项。技术ready只说明程序能检查的条件，不能证明现实业务齐全。核算完成、实际申报、文件生成、文件交付和实际付款分别核验，详见各阶段内部条件。

月度办理每轮先说明公司、工作月份和本轮结果，再给八行编号列表，每行为“编号＋图标＋事项＋简短情况”，不用表格或代码围栏。最后展开当前事项及老板眼下要做的事。图标为：✅完成或有据无业务；🔄办理、等待或接续；⬜未进入或待核验；⏰明确到期未办；➖有据不适用。图标后保留文字，加粗成对闭合。缺资料、没有推进或技术受阻也如实保留进度；单项完成不称整月完成。

正常完成后直接顺序推进，不逐项批准。当前项未完而拟先办后续成果时，先说明缺口、拟做范围和采用依据，由老板决定；未答复或选择等待时不提前推进。已有明确插办安排直接复用，必要跨领域查证不算提前办理后阶段。

同意后每次八行清单都保留本轮未完成项、具体缺口和执行者，例如“3. 🔄 社保、公积金：待您反馈本期申报结果；已按您的安排先办理代发表。”不隐藏、不打勾、不重置，不重复请求同次接续许可。收到结果后核验并退出相应待办。

## 安排与待办怎样接续

| 位置 | 当前保存内容 |
| --- | --- |
| `company` | 长期经营背景、有效安排和模板选择。 |
| `work:YYYY-MM` | 本轮安排、有效答复的真实范围、资料覆盖核查依据定位。 |
| `period:YYYY-MM` | 依赖财务结果的经营解释。 |
| 当前待办 | 剩余工作、已知事实、具体缺口、执行者及归属。 |

work不保存金额副本、任务状态、清单完成位或推理日记，不解析正文作关账条件。它不因普通金额重算整段失效；实际依据改变时只更新受影响安排。period仍按财务依据头失效。说明直接整合成当前正确正文，不追加过程。

work可保存某范围、某资料版本下的覆盖判断和来源定位，但不保存对自身seq的引用；实际调用取当前序号。资料版本变化只使相应覆盖判断暂不能直接复用，不作废老板其他有效答复。公司和本月安排分开，本月例外不覆盖长期选择。

待查资料、待综合和专业冲突由AI承接；真正需要补现实事实、选择安排或办理外部事项才交老板。`known_fact`只是待核候选。更新待办scope须保留完整仍有效集合及head，不能用筛选子集覆盖别的问题。

`period`是事项归属，不等于发现日期。有必要核算缺项时归最早受影响的开放月；纯外部事项归实际接续工作月。`missing_fields`只列当前核算真正缺少的事实，不塞可选资料或未来反馈。`required_before_close`明确外部事项必须完成的关账节点，无要求填null；三季度申报10月接续、节点9月，不挡7/8也不漏9月。普通正确入账的未付余额不自动形成外部阻断。`due_on`保留真实期限，不编造日期。

同一事项兼有核算缺项和外部等待，分别处理，前者始终不可豁免。无归期公司维护事项不机械阻断每月；确实影响本轮先查明归属。未知关联不能补成明确无影响，旧资料缺字段也不能批量填空。已完成事项退出，不保留完成日志。

## 默认安排、交付和必要提问

采用当前`accounting_context.work_defaults`及公司的有效例外，不按旧印象推断能力，不重复让老板接受默认。

| 工作 | 通用安排 |
| --- | --- |
| 工资 | 劳动所属月计提、次月安排发放，计划不证明实付、未付或扣税。 |
| 服务收入 | 业务月确认收入和应收，后来到账核销；默认税源与报表收入确认月一致，如实采用老板口径，不编造合同或税日。 |
| 所得税与报表 | 按支持的实际结果、程序暂计或有据确认暂计办理，不等未来申报额准备报表；默认不替代资格和特殊事实。 |
| 代发表 | 默认需要。首次既无明确安排、也无用途明确的本公司模板时才问一次；已有安排、模板和本月例外直接复用。 |

专项条件、合法例外和可付额组成按指南办理。优惠默认不放弃不等于自动免税，未记录税额不等于已计算零。已有“按上月，仅某项变化”的完整答复，AI查明基准后直接办理；主动询问变化先展示相关基准，只问差异。“方案不变”不证明已申报或付款。

尚未提交银行或已明确失败、退回需重办的款项需要代发表时，用payment_export生成并按原范围status核验。已提交银行仍处理中的款项沿原批次等待结果，已发放部分按第4项核对条件复用有效交付和正式付款结果。财报用report_export生成并按task_id通过jobs接续。任务成功后，以相应命令save指定任务到desktop，确认copied/reused和桌面path，再给可点击链接。内部task.path、生成成功或“可以导出”不算交付。失败接续同一任务，不重复记账、用生成当轮询或另写复制脚本。真实金额、账号或模板变化后按受影响的待执行范围接续文件工作。

通过必要性判断的问题，用高中生能懂的话说明已有信息、真正缺口及答案用途；解释用途本身不使可选问题变得必要。会计分类、程序字段和内部操作由AI承担，不向老板展示错误码或推理过程。不能自行增加交付再强索资料。可选票据仅提示有则补充，不反复催、不挂阻断；员工收款后的个人去向不是公司记账问题。老板拒绝可选资料后继续已可完成的工作；确实缺少必要事实时说明受影响部分，不造默认答案。专业判断有疑问，AI继续查，必要时借助顾问，不能让老板猜科目或税法。

## 资料与撤回

原件放本公司指定目录，按明确月份归档，未知月份暂不猜。完整读取有效页、表、行和汇总，来源定位不代表已理解或采用。owner_statement只保存老板实际表达的现实事实和范围，不能把AI判断、程序报错或操作聊天写成老板确认。

金额和关系进入类型化事实。业务说明的 `purpose` 写简短具体事项，`text` 写完整业务说明，两字段共享有据来源；标准名称足够时可省略 `purpose`。更新说明时读取当前序号，完整提交仍需保留的短事项、正文和最终来源集合。业务背景、所属期间和有效安排可写入正文，资料定位及核查过程由来源和专业核查能力承接。银行摘要、户名和备注保持原义。source_id固定内容，内容变更另建来源，改位置不换身份。清理通过受保护入口办理，正式采用及关闭依据的来源继续保全。标准文档保存最终正确事实。

单笔或指定多笔误记用withdraw并保留原件；明确撤销整月全部记账才用cancel_month，先inspect范围与head再cancel，闭期仍不允许整月清理。程序撤去业务、整理仍适用待办，用work保存重新收集资料的当前安排，退出旧引用后清可退出原件；经营说明因账务变化失效，不承接进度。

取消10月不能误删归集10月、节点9月的未完季报；取消9月也不表示季报完成，按剩余业务保留仍适用事项。保留的跨月、长期、模板或冻结来源如实报告，不声称全部清空。

只交办撤回时办完即止。局部纠错只重核受影响项；整月撤销后重新办理才从第1项收集核查，不继承旧勾选或恢复旧进度。其他有效资料可以复用，被退出资料需重新提供。新办理create、明确误撤restore、丢回复重试按真实目的区分，不能用新身份绕过关系或冻结。文档与物理清理pending沿原状态接续。

## 关账采用哪一份判断

通常等本轮适用外部事项完成后关账；老板明确选择先关账才例外。普通“先办后续”不等于先关账。例外仅针对有来源的指定外部事项，不能绕过核算缺项、金额差异、资金核对或必要成果。关闭后待办仍提醒，后月不重复索取同次许可。

period check先看actual_range，目标月份不等于实际关闭范围。确会关闭1—10月时，10月资料不能代替未核1—9月。已有充分覆盖依据直接复用，不每月另索批准。

basis列覆盖区间及来源、明确跨月来源、采用的company/work说明及必要先关账例外。check返回material_version，核查后采用同一范围、依据和版本，再带actual_range、basis、expected_material_version和expected_head关闭。已有有效版本直接复用，不固定调用次数。缺basis先由AI整理现有依据，不直接变成老板批准请求。

资料版本证明明确受核集合未变，不证明未交来的业务不存在；归档月不代表业务月。版本变化先查有界目录，结合已有来源定位必要核查；没有旧集合时允许重核此范围，不能只换hash沿用旧结论。新增确认陈述先登记再捕获版本，单纯改名或位置不应无故失效。

实际关闭和冻结成功才表示账期关闭，ready不代表八项完成。历史关闭回执不代表现实工作办完，当前待办仍从accounting_context核对。已关闭重试读当时冻结依据，不拿今天资料否定过去。数据库备份恢复原关闭事实；标准文档重建只恢复最终业务并保持开放，不自动重演关账。

## 开发与行为验收

[开发与验收](07-delivery-acceptance.md)同时核对程序合同与实际AI行为。独立AI用隔离实例真实接口、自然资料和老板答复，不给内部编号、查询路线或预写会计答案，不固定台词、调用顺序、问题数或耗时。静态文字检查不能代替办理验证。

连续过程覆盖：只给公司名、最近work属于未来或已完成、真实多任务、分轮资料与冷接续；对象遗漏、自有渠道和真正未知；社保估算与实际反馈、已有模板和文件交付；第5项业务覆盖与第8项复用；报表ready但税费遗漏；跨月申报、普通未付、先办后续与先关账；多月关闭和检查后新增资料。对照验证资料齐全不问、当前真缺项才问、已有答案复用、专业分类由AI承担及程序缺能力不转成问卷；加入投资纯购买与真实代转缺口、工资承担充足与不足、税务后续范围变化。老板拒绝可选资料后仍须办理，不能靠缩小交付或猜默认值通过。被老板斥责后补对不算首次通过，修复后换新AI自然开始。

顾问只协助审查，不直接修改或批准；必要来源用现有只读审查入口提供，不把技术资料塞进老板看板。反馈先分清业务事实、计算、交接和显示问题，公共职责有缺陷就改规则和实现，不让操作永久补偿耦合。开放期不存纠错日记，必要闭期冻结和冲正保持原义。
