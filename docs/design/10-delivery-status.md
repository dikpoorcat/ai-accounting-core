# 当前 3.0 体系交付状态

当前实现使用模块化体系 `ai-accounting-modular/1`，唯一 CLI 为 `finance-modular`。项目 MCP、记账 Skill 和看板使用同一目录库，各公司分别保存业务数据库。这里维护稳定能力与结果入口，不保存开发过程、历史测试数量或已经过期的公司业务数量。

## 正式资料保存在哪里

| 内容 | 正式位置及作用 |
| --- | --- |
| 负责人和公司目录 | `data/accounting/catalog.sqlite3`，保存负责人身份及公司位置。 |
| 公司资料根 | `data/accounting/companies/<信用代码>/`，每家公司独立。 |
| 公司账本 | 公司资料根的 `runtime/company.sqlite3`。 |
| 原件 | `originals/`，按归档月份保存原字节；仍有效的负责人陈述、模板及业务依据按来源合同承接。 |
| 标准业务文档 | `standard/current.json`、其引用的 `parts/` 和 `README.md`，表达当前最终事实。 |
| 公司备份 | `backups/<信用代码>.finance-company.zip`；当前版及按滚动规则保留的上一版均须完整验证。 |

公司清单、工作月份、关闭范围和当前待办通过 `accounting_context` 读取；标准文档通过 `accounting_documents` 核对就绪状态。当前公司状态以这些入口和实际资料为准，不在源码文档复制真实公司身份、数量或金额。

## 功能与使用边界

合同、存储、身份、业务领域、账务、完整办理、档案、文件任务、读取、看板和运行装配各有公开边界。支持类型明确的业务核算、整单原子保存、防重、开放期保号更正、闭期冲正及后台接续。具体业务范围以[业务规则](05-business-rules.md)及运行时 `accounting_schema` 为准。

- 会计AI按[工作指南](08-ai-work-and-materials.md)围绕当前动作主动定位月份、复用有效答复和来源，缺口才定向读取；先判断缺项是否真正影响当前交付，程序问题不转为老板问卷。普通命令与本次Apply种类的完整合同按需取得，专项按精确业务种类及实际分支交付，阶段内部条件和更正规则分别读取。
- 八项月度清单共用[内部规则](work-checklist.json)，AI逐项核对适用条件后才打勾。第1项核本步骤资料，第5项核全月业务覆盖，第8项复用有效依据并检查变化；实际文件、申报、付款和核算分别判断，不保存检查日记或全部通过字段。
- [银行代发表](12-work-checks-and-payments.md)使用当前正式可付金额、真实收款资料及本公司模板；生成文件不登记付款，不需要代发时不索取模板。
- 单笔或指定多笔撤回保留原件；整月撤销通过 `accounting_cancel_month` 办理，保护跨月、长期安排、模板及冻结所需来源，明确报告不能清除的保留项。
- [公司说明](11-company-note.md)保存长期安排，work:月份保存仍有效的办理安排、答复范围和核查定位；period:月份经营说明依财务结果失效，具体业务用途按业务身份维护。当前正文随标准文档保存，普通金额变化不清掉有效办理答复，不保存编辑日记。
- 关账明确采用实际起止范围、资料版本、来源和检查头。核算缺项与外部事项关闭节点分别检查；普通先办后续不等于先关账，明确例外只对应指定外部待办。关闭依据与来源随备份保全，历史重试核对原请求，标准文档重建保持开放。
- 三表和税费共用正式核算及取数结果。缺少细分的字段明确未知，不能把部分报表称为完整定稿；实际申报、实际扣款和账务核差独立接续。
- 投资理财覆盖货币基金、银行理财、其他基金、债券、对外股权和合同范围内的合作项目。产品管理类别、真实权利、持有安排和受控成本方法分别保存，沿通用accounting_apply办理取得、收益、实际收付、退出、实际损失、期初和更正。债券按合同确认票息；长期债券按剩余合同付息期直线摊销折溢价，短期债券保持成本。市场估值独立保存，不改变成本。
- 投资按明确份额和固定选批方法核算，零成本仍有份额的持仓保留；返本、拆分和债券摊销建立新成本区间，保留原取得顺序和已经发生的退出成本。候选共享有序回放和必要正式月末接续，普通收益不回放库存。资金页保留清仓后当月仍有收付款的投资；总览收益采用正式5111净额，产品未扣投资增值税的确认收益、公司税费调整及实际投资损失分别列示。
- 投资会计权利与税务资格分别保存。纯购买不提前要求税务资格；当前税务处理按有源适用区间采用taxes.investment_basis，补充资格不反向重算会计成本。投资正式量贯通独立VAT买入价及所得税批次税基、公司方法采用、月度金融VAT和完整税期核对。均价数量按有源转换统一单位，真实金融商品或权益类别分别建池，同一商品不同账户共池；实际申报组成独立于参考计算采用。负差、旧欠税、已缴款及有据多缴分别接续。季度所得税仅扣当前表单允许的投资优惠，国债按实际持有期间及对应VAT计算净免税收入；合伙年度及以前年度已税分回有独立来源关系，不提前制造季度收入。

## 数据结构与接续

目录结构为1，公司结构为7，均由当前完整合同一次定义。系统只读取、创建和恢复这一基线，不携带开发期结构升级链。数据库、标准业务文档和备份分别核对自己的完整格式、结构与来源；业务历史中的必要冻结和冲正仍是正式账务，不因技术结构整理删除。

准确恢复保持备份的一致状态；简化重建只使用标准业务文档和必要来源重新核算。两者都不覆盖已有目标。普通启动不创建新库、不自行重放，也不把开发中的合成验证当作真实账套已切换。旧投资条款的格式拆分使用[独立离线转换](04-data-model.md#投资条款旧格式的显式转换)，原输入保全；源码开发不代表真实账套已经转换或服务已经启用新版。

## 验证与运行结果

可执行验证要求见[开发与验收](07-delivery-acceptance.md)，运行方法见[安装与接入](09-runtime-and-ai.md)。源码合同检查、合成业务测试、真实页面、文件恢复和正式环境核验分别说明，不能彼此替代。

薪酬正式结果支持独立的计提与代扣凭证，当前公司结构保存稳定凭证阶段键；标准业务事实格式保持独立。按业务以“薪酬计提”和“个人代扣”为阶段主项，展开成员显示报酬、单位缴费或个人扣项组成；后补扣税只展示该次差额。组成、进展和精确凭证共用采用结果，历史合并凭证保持完整。读取展示不改变正式核算或业务事实，标准业务文档无需因此改写或重放。源码验证与正式环境接入分别核实，正式实例支持范围以其实际版本和accounting_schema为准。

看板保持流畅，后台状态明确且失败可接续。性能验证按实际工作范围检查扫描、解析、计算及改写量，不因无关历史增长增加工作，不追逐未经确认的耗时数字。
