# 会计 AI 专业核查与办理

本设计解决两件事：已有资料能回答时，AI自行查清并办理；尚未发生的申报、付款等结果，留到对应事项，不倒过来阻塞当前核算和报表。以完成当前动作所需的事实为中心，统一业务规则、程序反馈、账务读取和清单含义。

## 1. 谁负责什么

| 责任方 | 应做的工作 |
| --- | --- |
| 会计AI | 明确当前动作，综合已有对话、有效资料、长期安排与正式结果；完成专业判断、定向查证、类型化提交和结果核验。 |
| 业务模块 | 定义本次办理什么、必需事实、可复用来源、成功结果，以及后续另行办理的事项；维护确定性计算。 |
| Ledger、Money | 分别维护正式义务/余额/清偿，以及实际资金/原行/确定匹配；通过公开读取交付真实关系。 |
| Application | 在同一个只读快照组合当前事项所需结果，维护共同依据版本；不重算余额、工资可付额或税费。 |
| 老板 | 补充已有资料无法回答的必要现实事实，办理实际付款、报送和申报。专业疑问由AI继续核查，必要时请教顾问。 |

现有说明和待办继续承接未完成工作。标准文档保留最终事实及真实来源，不新增动作引擎、提问审批、核查记录表或推理日记。

## 2. 怎样结束核查并开始办理

先确定当前要完成什么，再综合已有依据；具体缺口才定向读取。反向核对实际存在的其他合理候选和冲突，不凭同额自动认定关系，也不把想象中的所有可能性变成问卷。

当前必要事实有有效来源、需要区分的候选范围已经查全、没有会改变金额/期间/归属的已知未解冲突，就办理。可选票据、无证据假设及未来结果不延长核查。特殊事项根据实际经营、适用依据和具体线索判断；有相关线索尚未解决时，也不能填零或填“无”。

老板明确的安排和答复按真实范围持续复用；阶段切换不要求重复确认。相关业务、来源或适用安排变化才重新核查受影响部分。“按上月”不自动证明本月已经付款或申报。提问时说明已有资料仍缺什么，以及答案用来完成哪项处理，用高中生能理解的语言。

统一操作说明在[工作指南](08-ai-work-and-materials.md)，领域所需事实在[业务规则](05-business-rules.md)，清单完成条件只维护于[内部清单](work-checklist.json)。

## 3. 程序反馈如何交接

| 原因 | 反馈与责任 |
| --- | --- |
| 当前核算事实尚缺 | needs_information和真实fact_issues；AI先查可复用来源，仍缺才问老板。 |
| 已提供的输入、身份或引用错误 | invalid_input；AI修正输入。引用未登记不等于现实资料不存在。 |
| 上游正式结果未就绪、事实或采用依据冲突 | dependency_conflict，保留真实字段和来源；AI核查并办理依赖。 |
| 所选计算路线不支持 | unsupported_business，fact_issues.code=unsupported_calculation；说明具体能力边界和已有替代路线。 |
| 有依据表明外部事项尚未发生 | 留给对应事项，不包装成当前准备工作的缺资料错误。系统没有记录不证明现实未发生。 |

类型化错误从领域到应用、MCP保留含义，不在汇总时重包成needs_information。字段定位实际输入；不存在可补字段的依赖用根路径`/`，不造`/data/profit_before_tax`让老板补程序利润。

特殊所得税事项不再以“实际累计额”填算法缺口；亏损扣除超过利润、小微采用口径与金额冲突按冲突处理。实际结果已采用后，参考算法不支持只保留真实非阻断提示，不反过来否定已采用实际税额。公式和既有业务保存、更正规则保持各自归属。

## 4. 有范围的账务核查

新增只读`accounting_review`，唯一合同及完整字段见[公开合同](03-contracts.md#事项核查accounting_review)和[Schema](contracts/accounting-review.schema.json)。

- find在明确类别/对象或账户/实际期间内发现义务、真实资金和已登记原行，支持已结及未结义务。
- inspect以业务、义务、真实资金或原行的明确身份为主体，分别分页交付本事项的义务、清偿、资金、原行和确定关联。原业务月、义务所属期及实际清偿时间分别表达。
- 义务返回自身清偿及对应资金；混合付款同时表达整笔资金额和本项清偿额。资金主体返回真实分配及所涉及义务的必要信息，其他义务的所有历史不继续递归展开。
- 原行的确定关联与已登记候选分别表达。没有匹配不等于没有记付款；实际资金ID由程序返回，AI不推导。工资当前可付额继续从accounting_remuneration取得。
- 每个请求只返回所选集合的正文和必要来源，完整数量/下一页明确说明；未请求、空集合、尚有下一页各有含义。

一个inspect的主体、related_scope和经济截止月共用basis_version。后续读取采用expected_version或集合游标，版本覆盖范围内完整成员、正式结果、清偿和转移、资金及确定关联，不能只覆盖当前页。若判断依赖“没有其他候选”，related_scope保留原发现条件，不能只保留已挑中的几个编号。

相关新增、替换、撤去和候选变化返回snapshot_changed；无关账户和范围外历史不使它失效。一次响应共用一个ReadContext，跨调用不保持连接或核查会话。独立查询不声称处于同一历史快照，需要组合采用的范围纳入同一个inspect。正式写入仍由原事务核对真实依赖，查询版本不是另一道审批。

Ledger和Money先限定范围、读取轻量目录，再加载本页正文。复用正式引用、关系及现有索引，不借用看板整月模型、不增影子匹配表或第二份余额库。

## 5. 税费、报表与清单

```mermaid
flowchart LR
    A[完整业务核算] --> B[共享税前利润及税源]
    B --> C[采用实际结果或有据暂计]
    C --> D[核验并交付报表]
    D --> E[实际报送和申报]
    E --> F[取得结果后处理差异]
```

各税种按实际依赖办理，不机械串成同一条链。所得税使用共享税前利润，不等待包含所得税自身的完整税后报表。项目默认按实际利润计算季度暂计，方式及项目默认来源由`accounting_context.work_defaults.income_tax`提供，不为采用默认向老板另索方式确认或税务证明。已有实际方式来源继续核查，默认不替代税务认定、优惠资格、亏损及特殊事项的必要事实。实际付款独立登记，不由申报或暂计自动生成。

| 当前依据 | 采用路线 |
| --- | --- |
| 已有完整实际结果 | 核查并采用实际结果。 |
| 尚无实际结果，季度默认或实际利润方式适用，其他必要依据齐全且程序支持 | 调用确定性程序计算并采用computed_provision；输入可省略method，预缴依据可各自省略collection_method和basis_source，程序保存明确采用方式及必要的项目默认标记。 |
| 已有来源充分的申报前确认暂计额 | 采用confirmed_provision，保留暂计性质。 |
| 年度汇算已有有据累计税额 | 明确采用annual_settlement，不自动套用季度计算默认。 |
| 算法不支持且无可采用金额 | 明确受影响的能力缺口，继续准备已知业务和取数；不猜零、不手算替代、不要求老板先申报。 |

有效暂计已采用、必要业务覆盖已核对、报表就绪，可以交付完整财报。ready只证明已记录数据可完整取数，不证明现实业务和必要税费没有遗漏；未记录而显示零，也不等于程序计算并采用了零额。不要求每月每个税种强建一笔计提。

八项清单继续展示真实进度。第5项处理本期核算和报表准备；第6项区分报表交付与实际报送；第7项接续适用申报和实际差异；第8项按真实账务、来源和关账结果核验。为完成当前事项而跨月、跨领域查证不等于提前打勾后续阶段。

## 6. 验收与交付边界

程序验收覆盖金额、身份、来源、错误类别及原子失败；包括部分/合并付款、已结义务、未匹配但已登记付款，分页期间新增清偿，相关替换/撤去/候选变化失效，无关范围继续复用。检查读取范围和查询计划，不用未经约定的耗时数字代替架构判断。

连续行为验收由独立AI通过隔离实例办理自然资料：分轮收到资料，主动关联跨月义务，复用一次明确答复，中断后继续未完成事项；发现技术ready下必要税费遗漏，采用受支持暂计并交付报表；晚到实际申报后处理差异，付款保持独立。同时覆盖真实缺事实、同额多候选及不支持计算的反例。测试老板不提供内部编号、查询路线或会计答案，不固定台词和调用顺序。

每组修改经过测试、完整复读、反向质疑和简化后集中复验。合成公司用于实施验收；真实账务、换库、重放及现有服务启用按明确任务另行执行。部署状态见[交付结果](10-delivery-status.md)。
