# 字段来源与去重复用

本说明记录当前 `ai-accounting-kernel/2`、`draft / 0` 的字段来源和保留边界。规范字段取实际模型与结构，接口复用已有合同；本轮精简来源检查和重复实现，保持公共业务输入、返回结构与核算语义。现有公司库及保全资料原样保留，不迁移、不执行真实重放、不启动或切换服务。

下面的来源表是字段审查依据。[检查工具](../scripts/export_field_inventory.py)按需从实际模型和两个内存 SQLite 结构生成字段索引，不读取真实公司库、目录库、工作稿、回放事实或备份。派生索引写入忽略的临时目录，不再将完整生成清单入库。

## 当前唯一来源

| 字段或字段族 | 唯一来源及写入入口 | 读取与复用方式 | 保留边界 |
| --- | --- | --- | --- |
| 对象名称、独立管理编号、外部标识、对象备注 | 按实际对象类别校验的 `entity_profile_revision.content`；`register_entity`、`update_entity_profile` | 对象查询、工作上下文、看板和导出按对象引用读取明确版本 | 资金账户只保留名称、备注及停用状态；其他类别有实际用途的独立编号和外部标识保留，不按同名或同值合并 |
| 人员任职起止、在册状态、当前管理状态 | 人员管理档案的明确登记；任职资料或负责人确认 | 看板和对象上下文复用；当前 `employment_state` 不从工资、备注或在册状态推断 | 任职管理日期不替代工资核算所属月；历史工资事实不由当前档案回写 |
| 银行与平台资金身份 | `fund_account_definition.identity` 的原始定义及 `fund_account_identity_revision` 的显式更正链；账户注册和资金身份更正入口 | `require_fund_account` 验证身份链；按对象引用读取，账户管理档案不再复制银行或平台身份字段 | 原始身份、明细科目和更正链保留；账户持有人不自动等于公司名称 |
| 现金账户身份与名称 | 稳定身份是 `entity.id`，正式资金身份为空对象；名称只写资金账户管理档案 `display_name` | 登记后按实体 ID 查找和引用；名称从同一档案用于展示和搜索 | 改名不建立另一份名称或身份，不改变实体、明细科目及已登记业务 |
| 自定义业务标题、业务用途、业务备注、来源定位 | `BusinessProfile.display_name`、`purpose`、`note`，保存于 `display_profile_revision` 的 `business` 记录；`save_display_profile` | 当前业务展示复用对象档案和结构化事实；用途与备注只写补充信息，文件及位置写入 `source` | `management_revision` 不再保存备注；业务说明不代替核算事实与证据 |
| 公司说明 | `company_note_revision`；`update_company_note` | `company_context`、工作上下文复用版本 | 自由文字不代替正式事实；保全原始说明仍是来源资料 |
| 业务事实及明细 | `fact_revision` 和相应生成的 `fact_*` 表；现有类型化登记、修改与专属确认入口 | 注册的领域计算器、准备流程、查询及完整性核验 | 金额使用整数分；缺少会影响核算的事实阻断，不能从管理资料猜填 |
| 工资方案与无变化确认引用 | `PayrollPlan.payroll_revision` 精确引用已登记工资版本，并以 `change_notice_revisions` 承接通知；`PayrollNoChange.employees[*].prior_payroll_revision` 引用上期已采用工资。通过 `save_fact`、`amend_fact` 或 `save_facts` 保存确认事实 | 员工、工资正文及精确政策引用从工资事实解析；准备和正式发布共用完整人员范围、精确版本、当前采用、政策及通知失效检查 | 确认不复制员工编号或工资正文。`confirm_payroll_preparation` 在有效无变化确认下原子登记本期候选工资，不创建方案或发布核算；历史采用依据及缺项阻断保留 |
| 借款利息协议与借款来源 | `LoanInterest.drawdown_id` 指向借款支用或期初借款，协议从该来源解析 | 利息计算和工作上下文按实际借款来源复用协议与政策 | 利息实际区间及所属月仍独立保存；不再输入可从借款来源确定的 `agreement_id` |
| 资料关联的业务、事实、种类、核算月 | `MaterialLink.calculation_id` 指向精确正式计算，再解析其原始事实 | `resolve_material_links` 批量校验计算与事实身份、封签、事实内容、明细顺序、期间和完整结果摘要 | 关联只输入 `calculation_id`、`amount_field`、`amount_fen`；不得用当前计算替换精确历史来源 |
| 资料金额字段和分配金额 | `MaterialLink.amount_field`、`amount_fen` 是负责人对原资料的分配选择 | 完整性检查比对精确来源金额及经济金额别名；联合组和重复选择复用同一解析器 | 分配金额不是业务原金额的冗余副本；同一业务重算后旧分配仍占用对应金额容量，并另报失效 |
| 资料原行所属期、原行处理、转期及联合组依据 | 资料规格、逐行处置版本和联合组确认 | 同一检查器供关账及完整代发使用；分开核验原行月份与关联业务月份 | 原行期、收件期、处置期和计算期各有责任边界，不按字段名称机械合并 |
| 收款人付款指令 | `payee_revision`；`save_payee` | 代发准备采用明确版本；姓名、收款账号不能从对象显示名称或资金账户猜填 | 付款指令与员工管理档案、公司资金身份不是同一事实；历史代发计划保留采用版本 |
| 工资税导入身份和映射 | `tax_import_identity`、`tax_import_details`、`tax_import_mapping` 类型化事实；相应登记入口 | 导入准备按采用工资事实、身份与映射生成计划 | 报税专用必填字段只阻断相应导出，不扩大为普通核算必填；不生成缺失证件等事实 |
| 正式计算、采用与凭证 | 精确 `calculation.outcome`、依赖版本、发布链、凭证版本 | 后续核算、清偿、报表、审计、关账及备份复用完整封存内容 | 必要计算解释、无影响复核、无凭证结果、开放期替换和闭期冲正保留 |
| 冻结关账、审核与报表依据 | 关账逻辑清单、安全批准、采用版本及各冻结根 | 按当时实际采用来源核验；读取目录可以重建 | 当前档案、当前计算或当前政策不能覆盖冻结依据；必要历史引用不因与当前字段同名删除 |
| 当前指针、作用域、查找与引用目录 | 不可变事实、发布链、源中实际引用及明确领域作用域 | 用于定位候选；实际采用、完成及正确性仍由源核验 | 可重建投影不能制造采用结论；材料派生作用域保留精确计算作用域入口 |
| 余额、清偿、报表贡献与看板读取模型 | 已验证来源、发布链与关账根 | 相应投影模块按原始采用来源重建，当前查询复用 | 可重建表示与其冻结根分开；不能为了少存字段删除源摘要或完整性核验 |
| 工作稿候选、未决请求和结果引用 | `WorkDraftStore` 的身份绑定私有工作文件；工作稿命令 | 候选复用现有类型化命令合同；恢复时验证目标和持久请求回执 | 工作稿不建立第二套业务输入模型；未确认候选和结果引用不等于正式采用 |
| 请求、审计及导出任务 | 幂等请求记录、追加审计、持久任务冻结负载与任务结果 | 幂等重试、查找、后台导出、完整性和恢复核验 | 任务计划保留实际采用及输出核验依据；生成导出文件不自动登记实际付款 |

## 按需检查与字段索引

工具枚举实际注册事实及嵌套模型、对象与资金登记档案、业务档案、计算合同和工作稿；每个规范字段只记录一次。公共输入和响应引用已有合同，不再复制完整 schema、DDL、指纹或源码扫描结果。数据库字段从 `schema_sql(default_registry())` 和 `catalog_sql()` 的两个 `:memory:` 连接取得。

字段语义优先读取该字段的正式 `description` 或 `x-accounting-fact`。必要的[精确语义补充](../scripts/field_meanings.py)按完整模型身份与字段绑定，不重复模型结构或源码路径，不覆盖正式说明，不按同名字段或模型级说明推断子字段含义。来源缺项、失效引用和未声明语义都明确报告并返回失败；类型约束不冒充业务含义。公司非事实表和目录表按已审查的精确表名绑定来源，新增同前缀表不能自动通过。

唯一来源、登记入口和消费责任按上表核对。源码词频、字典键扫描和有限静态 SQL 分析不作为来源证明；新增字段或结构应先审查其核算与管理语义，再更新必要的来源绑定。结构和公共响应的一致性继续由原有合同导出检查负责。

使用仓库虚拟环境，默认和 `--check` 都不写文件：

```powershell
.tmp-kernel-venv/Scripts/python.exe -X utf8 scripts/export_field_inventory.py --check
.tmp-kernel-venv/Scripts/python.exe -X utf8 scripts/export_field_inventory.py --output .tmp/field-inventory.md
.tmp-kernel-venv/Scripts/python.exe -X utf8 scripts/export_kernel_schema_contracts.py --check
```

按需索引用于审查，不成为第二套合同或业务数据。本轮精简仍保留账户单次登记、现金改名、备注复用，工资、资料和贷款精确引用的失效与原子失败，以及冻结来源、备份与独立恢复核验。后续真实重放只使用原重放文档，企业、对象、事实和计算身份由新目标产生；旧编号或旧回执不能作为执行结果。
