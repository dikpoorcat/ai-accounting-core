# 历史来源与内容版本

## 核算、展示与时间

已关账核算继续按 `period_close` 中的精确凭证、计算、事实读取；原 manifest、摘要和经营说明不回写。
未关账核算采用当前正式发布版本。保存事实不等于发布，来源过期与待复核状态仍独立存在。

`display_profiles(period)` 返回当月精确冻结档案。看板可补充当前已知管理资料，
但冻结非缺项字段优先，最终字段值与 `field_sources` 一起选择。来源包含类型、精确 ID／revision、
原说明／证据、`frozen`／`current`／`current_supplement` 分类及系统记录时间。
姓名、编号、备注等空字符串允许回退；日期以 null 表示缺项。`False`、`0`、`unknown` 不作为缺项。
混合入离职区间只有在允许精度下能确定倒置时才报冲突并显示未知在册状态；
例如 `2026-03-31` 与 `2026-03` 不构成可确定的倒置。

收款档案、税务身份、业务管理备注等回退同样保留最终实际采用来源。
`management.version` 为兼容保留基础档案版本，`version_scope=base_profile` 明确其含义；
混合内容的字段来源以 `field_sources` 为准，派生字段可列多个来源。
看板响应 `read_semantics` 说明当前知识下的核算和后补展示口径。

实际申报继续按人员、税期及工资身份回挂历史工资，代发采用的旧精确申报引用不被当前申报替换。
`tax_period`、业务 `recording_period`、实际 `date` 分别保留；`recorded_later` 仅比较业务月份。
`recorded_at`／`confirmation_recorded_at` 是该精确版本成功确认的系统审计时间，
不表示负责人最早知悉日。只解析受支持 action 的明确结果结构和精确 ID；多重匹配、
无时区或无法可信关联时为空，不选最早／最晚值，不借用实际日、月份或后续发布时间。
旧 `management` 审计没有足以唯一关联版本的身份，因此其时间保持未知。
同一响应收集来源后批量读取并复用时间，幂等重放不会创建新确认时间。

`Workflow.as_of` 是中国自然日：用当前已知资料判断该业务日的期限与完成可证明性。
`as_of_semantics=current_knowledge` 明确它不是历史知识回放。实际完成日已知时优先采用；
否则使用唯一确认时间的 UTC+08 自然日作保守上界，缺失时保持无法建立。
`completion_time_basis` 分别为 `actual_date`、`confirmation_recorded_at`、`unestablished`。
当前关账状态和当前完成版本集合不按 `as_of` 还原历史。时间元数据不进入 outcome 或核算签名。

## 提交版本与内容依据

`preview_period_commentary` 提供两种独立摘要：

- `context_digest`：提交令牌，绑定完整预览内容、公司／数据库、月份／闭期及三类 epochs。
  保存仍须携带 `expected_revision`，在同一写事务内核验；内容相同也不能绕过过期预览。
  升级前未提交的预览需刷新；已有请求的同参数幂等重放保留原结果。
- `content_digest`：`commentary-content-v1` 的精确采用内容摘要，`content_basis` 给出可追溯依据，
  原 `basis` 字段兼容保留相同内容。它不含全局 epochs、查询时间或说明自身。

内容依据采用确定排序、去重的精确引用及原结果摘要，不调用核算等价签名，也不复制全部 outcome：

- 目标月份的既有核算汇总、冻结／当前正式凭证、计算和必要依赖，包括无分录但有核算状态的结果。
- 本月及以前的当前非材料事实、相关主体当前事实／计算对应关系及 pending；跨月原因不截断。
- 当月最新资料清单、原件引用及现有 `check_completeness` 的覆盖摘要、精确来源和状态。
  跨期分配、联合组与归属未知沿用同一检查器，不能用内容摘要绕过它。
- 全公司共享 profiles、management、payees、company_note 仍保守纳入，管理 typed facts 维持既有期间覆盖。
- 按已涉及工资身份／人员／工资月的现有 scopes 选择后来记录的实际申报和代发依据，
  连同精确当前计算和待复核状态；无关未来工资来源排除。

承诺仅排除没有进入上述依据的未来写入。共享档案或仍影响本月的未来材料变化仍可使内容失效；
同额、同文字的新精确来源也可能需要复核。本轮不引入档案有效期或任意时点回放系统。
分页 `snapshot_version` 保持自身 epochs 并发语义，不替换成内容摘要。
没有经营说明的普通读取不构造整份内容依据。

## 不可变采用关系与旧版读取

公司库 v9 追加 `period_commentary_basis`，目录库保持 v3，冻结 v1—v8 结构合同不改动。
新说明先写含 `content` 和 `adoption` 的依据，再写说明本身；延迟外键及插入触发器保证两者原子创建。
依据保存合同和内容摘要；采用关系绑定说明 ID、revision、原 context_digest 及说明摘要。
两表不能更新／删除，已存在说明不能事后补绑依据。

升级事务仅给此前已有说明写入不可变 `legacy-context-v8` 标记，其依据及内容摘要为空。
这不是补建旧采用内容。运行时不能再创建该标记，不能把新说明缺依据降级成旧版。
旧说明按独立保留的 v8 算法执行 `legacy_strict`；无法证明则返回 `unverifiable`，保留原文。
新保存的复核说明使用新 ID／revision 及 v1 依据，旧标记始终不变。

两种合同均按原说明摘要算法核验正文及原采用信息，再判断当前或冻结有效性。
读取同时核对合同、内容摘要、公司／期间和说明采用关联。缺依据、未知合同、损坏内容或错绑仅使对应说明
`content_validity` 不可验证，不阻断普通账务或要求负责人补造事实。
新说明内容相同时为 `current`，采用内容变化为 `stale`。

已冻结原说明通过 manifest 的精确 ID／摘要及原采用关联验证，显示 `frozen`，
不拿后来补充资料将原文标成过期。通过校验时 `current/frozen` 保留这份原文；
说明自身摘要或采用关联校验失败时，原文留在 `frozen/latest` 供查验，不作为有效 `current` 展示。
每条闭期 `supplements` 独立比较“冻结核算＋当次当前补充资料”，返回自己的有效性；
后补原文即使失效也继续可查，不冒充关账时已知内容。

## 保持的边界

材料逐行／联合处置、导出预览及冻结任务、实际申报、代发采用确认和工资准备依据继续精确绑定。
`TaxImportDetails.payroll_result_digest` 仍是完整结果摘要，不能替换为内容或核算签名。
[核算无影响复核](accounting-equivalence.md)仍须正式发布；说明有效不代表付款、申报或复核完成。
