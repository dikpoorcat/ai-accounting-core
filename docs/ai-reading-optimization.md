# 会计AI读取链

本轮只优化已有资料的发现和阅读，不改数据库结构、业务登记规则、工作清单推进顺序或负责人确认要求。资料陆续收到时先查已有来源，再询问会改变处理的剩余事实。未保存草稿的持久恢复仍未实现。

## 接口合同

MCP `finance_local_schema` 和 CLI `call schema --input <请求.json>` 共用发现入口：

| 视图 | 请求 | 返回 |
|---|---|---|
| 概要 | `{}` 或 `{"view":"overview"}` | 协议、程序及数据库合同版本、事实和命令目录、错误处理与发现说明 |
| 所选合同 | `{"view":"selected","fact_kinds":["expense"],"commands":["save_fact","preview","confirm"]}` | 所选事实与命令的自足合同及必要引用定义 |
| 完整合同 | `{"view":"full"}` | 完整事实、命令、响应和安全／发布／关账合同，供诊断与检查 |

`response_types` 按响应目录中的命令名选择，例如 `{"view":"selected","commands":["work_context"],"response_types":["work_context"]}`。选择通用 `save_fact`、`amend_fact`、`save_facts` 时必须提供 `fact_kinds`；返回登记联合模型只含所选普通事实，运行校验器仍覆盖全部注册事实。专用事实自动包含其指定登记入口，不伪装成通用登记。无效视图组合或不存在的选择明确拒绝。

## 当前事项资料

`work_context` 要求明确 `company_id`、`period`、`work_area`，事项沿用银行、工资、普通业务、税务、资产和融资。可用 `subject_ids`、`source_ids` 定位工作清单中的明确业务或来源，每种最多500个。默认页100条，上限500条。

一次只读快照返回公司身份、说明与版本；本页事实及证据、正式采用和待重算状态；资料原件索引、映射与归期／处置引用；本页事实直接引用的对象及档案。事实正文复用既有发现查询的封签、摘要与正式采用核验，动态状态不跨请求缓存。不重新运行工作清单、完整性检查或全文件解析。

主集合按月份、事实编号倒序分页，游标绑定公司、数据库、筛选、业务版本与读取修复版本。资料来源和处置也参与主集合分页，只额外展开本页的精确来源引用；同摘要关联很多来源不会放大一页正文。`has_more` 和 `page_semantics` 明确提示续读。本页没有不等于资料缺失；解析映射可能在续页。历史计算和事实以精确依赖编号继续读取，不自动展开全部历史。

跨月资料按实际归期作用域、未知归期标记或明确来源编号定位，接收月不代替核算月。`received_period` 只报告接收月。公司切换、数据版本变化或修复后旧游标失效，重新读首页。

明确 `source_ids` 可引用其他类别的共用原件，保留原类别及期间，不因当前事项类别将其排除。工资方案、变更通知、无变化确认和个税导入来源按既有工资准备／导出用途加入工资资料范围；实际工资申报及代发依据按其明确 `tax_period` 定位，恒定个税身份按事项人员的当前精确对象引用定位。来源被发现不等于已采用；报告等没有明确六类归属的资料继续通过工作清单的精确引用查询。

## 纯解析缓存

常驻服务在现资料根 `.inspection-cache` 管理独立私有JSON文件；仅 `inspect_material` 使用。身份包含公司、数据库、原件摘要、规范化解析映射、程序构建身份和缓存格式。每次先从当前公司库取原件并核对实际摘要，随后优先复用最近一份内存结果，再校验持久文件；缓存不存在或损坏才重新解析并原子保存。原件损坏报来源错误，不能通过重建缓存掩盖。

文件保存完整解析明细、原位置、隐藏内容、诊断、覆盖与控制合计，不保存正式采用、批准或业务完成。公开响应继续有界分页，并复制本页以隔离调用方修改；无需每页复制完整原件解析对象。服务内存只保留最近一份完整解析结果。

全公司磁盘总额度512MiB，包含结果和使用记录；显式保存最后使用时间，最久未用先淘汰，不设置时间过期。私有目录、权限和文件锁复用现有机制，独立JSON读写不放大安全凭据文件的大小限制。只删除专用目录内本缓存命名的文件和中断写入临时文件。写入失败、单份超额、并发锁不可用或结果被淘汰均不阻断本次正常阅读。

接收资料、归期预览与确认、发布、资料完整性和关账继续执行自身正式检查；阅读缓存的命中或 `ready` 不代表业务已完成。服务重启可重用解析文件并重读事实与正式进度，不能恢复未保存草稿。

## 会计操作

1. 先读概要，按当前事项取合同。
2. 沿既有流程绑定公司、读取工作清单，明确当前事项。
3. 获取 `work_context` 并按需续页，优先复用明确事实、负责人确认与来源。
4. 需要原文细节时读对应 `inspect_material` 页；有歧义才追溯具体原位置。
5. 查清来源后只询问剩余核算缺项，新资料到达后更新相关读取范围。
6. 登记、预览、发布继续使用现有入口；事项完成后重读清单并反馈进度。

## 合成验证与比较方法

隔离资料使用真实 `LocalService → HTTP ServiceClient → MCP → SDK` 链路。验证设施为 `tests/kernel/reading_agent_harness.py`；复现基准使用 `scripts/benchmark_ai_reading.py compare --output <新目录> --baseline-archive <基线ZIP> --current-source src --phase both --repeats 3`。基线为实现前Git源码归档；每个版本分别新建合成根，重启仅恢复该根。

工具次数、紧凑UTF-8返回字节数、解析调用数和SQL执行条数分别记录。纯计时与SQL／解析插桩分开运行；SQL条数是执行语句数量，不等同于扫描行数或虚拟机指令。冷读、热读、重启后读取和正式检查分列。模型令牌用量未由此链路提供，不估算为已测结果。

## 2026-10-08测量结果

实现前源码为 `457fefa17f393baceb06a62d52d15c37bf2bec1e`。最终集中回归286项通过（323.92秒），另先完成205项接口回归（119.16秒，和集中回归有交集，不能相加为独立测试数）；原生接线与响应合同另4项通过。Ruff与差异空白检查通过。验证期间未修改公司库／目录库结构、看板或AGENTS约定，未写真实业务、重启现有服务或提交Git。隔离验证服务均已停止。

两版均读完250行，只询问第250笔债权人类别；负责人补充后只新保存该笔，前两笔事实身份及版本保留，三笔预览借贷平衡且未发布。重启后事实和请求回执恢复，乙公司的空范围未被当作无业务确认。优化版第一阶段主动预览两笔，增加2次正式路径解析；正式工作数量受AI决策影响，单独记录，不将其混入缓存命中数。

完整工作清单仍执行原检查，本样本甲公司workflow的紧凑响应两版都为210,173字节。聚合没有消除这一既有成本。JSON中的对话耗时只为插桩工具诊断，未包含模型思考、负责人等待或为隔离测时而暂停的时间，不能当作完整AI对话耗时。纯计时的最小／最大值及每次样本也保留在JSON；冷读和重启单样本不代表稳定分布。

AI对话使用定版源码快照；优化版快照后补齐了显式跨类别 `source_ids` 筛选。对话样本未使用该条件，该边界由最终专用回归验证。独立基准使用最终源码，双方构建身份均已记录。
