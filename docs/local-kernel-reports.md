# 本地内核季度三表

新 SQLite 内核提供小企业会计准则季度资产负债表、利润表及直接法现金流量表。
金额按整数分计算；XLSX 复用仓库已固定 SHA-256 的税务模板、行次及纯 XML 渲染器。
共享模块 `financial_statement_template.py` 不导入 ORM、旧服务或数据库；旧报表模块继续重导出原模板接口。
这是经营核对与材料准备能力，生成文件不表示已经实际申报。

## 准备与办理

希望使用三表的公司，应通过 `save_fact` 确认适用的报表口径：新设企业使用 `report_profile`，
明确公司名称、小企业会计准则、建账月份及零期初依据；接续企业使用 `continuation_report_profile`
引用有来源的期初包，必要时明确选择 `report_carry_forward` 的前期三表结转。不接受自由分录式期初导入。
已有建账月份之前的凭证时，不能用零期初声明隐藏它们。
没有配置报表口径的公司可以使用记账和关账，但不能据此导出季度三表。

`report_classification` 只引用已经存在的不可变凭证版本与行次，不接收科目或借贷方向。
它可以保存三类具有依据的报表明细：

- 普通管理、销售、财务费用的利润表明细。分类金额必须完整覆盖原行金额；明确银行手续费、利息、工资等沿用业务来源的确定分类。
- 无法从核算依赖唯一确定的往来交易方。资产负债表按账户和交易方分别重分类，不在不同交易方之间抵销。
- 无法确定类别的现金流分配。可将一条实际现金行分配到多个受控报表行次，分配合计须等于原现金行金额。员工或负责人偿还混合代垫、退抵税明细等不靠猜测归类。

`report_income_tax_confirmation` 是季度末的**内部计税口径确认**：
明确 `not_applicable`、`zero` 或 `assessed`，提供说明与证据，金额与当年累计所得税费用核对。
`assessed` 必须引用该季度有效的 `income_tax_assessment` 不可变计算版本。
此事实不会自行生成所得税分录，也不代表实际完成纳税申报；真实办理用 `external_completion` 保存，办理后的账务核对用 `external_basis_review`。

这些报表来源通过 `save_fact` 确认即可，不需再调用 `preview/confirm` 发布零分录。
已配置报表口径时，每月关账在同一只读快照中调用同一报表计算，检查本月及累计范围的分类。
季末还要求上述内部 CIT 确认。缺项会给出 `fact_issues`，补齐后重新预览关账。
`Registry.register_snapshot_readiness` 只负责查询适配，不在通用关账器中硬编码报表业务。
财务报表报送在覆盖期核算与报表检查通过后可使用开放期报表，默认先核对、报送，再收尾关账。
银行开始收集完整原行并识别业务，收尾再核对完整覆盖、匹配与余额。办理、复核和关账分别留痕，
默认工作顺序不新增外部办理或核对的关账硬门槛；完整安排见[八步会计流程](local-kernel.md#工作清单外部办理与恢复)。

## 查询和导出

公共命令均明确绑定 `company_id`：

| 命令 | 主要参数 | 行为 |
| --- | --- | --- |
| `report` | `year`, `quarter`, `source=open/closed` | 返回三表、勾稽结果、结构化缺项、来源关账摘要和模板版本 |
| `preview_report_export` | `year`, `quarter`, 可选 `carry_forward_fact_id` | 根据期末是否已关账自动选择开放或闭期来源，检查三表及资料、核算就绪情况 |
| `confirm_report_export` | 上述期间、`preview_digest`, `epochs`, `request_id`，可选 `output_directory` 父目录 | 原子写入冻结文件任务，不在 SQLite 写锁内渲染文件 |
| `run_report_jobs` | 可选 `limit` | 渲染、核对并原子发布冻结文件；`run_jobs` 也包含报表任务 |

开放查询使用当前开放凭证与已闭月份的冻结凭证；闭期查询只通过 `period_close.manifest.vouchers` 选择不可变版本。
报表口径和分类取 `readiness.financial_reports.facts` 中冻结的事实版本，不能用后来的名称或分类覆盖历史。
闭期冲正使用 `reverses_id` 指向的原核算与原行分类；替换凭证使用新的分类。
当前投影被重建、未来期间发生业务或后补管理资料，都不会改变已冻结报表的金额及内容摘要。
导出入口按期末是否已关账自动选择 `open` 或 `closed`；开放期复用资料与核算就绪检查，
不等待关账批准、外部办理或复核完成。报表自身的分类、内部所得税口径、期初及勾稽检查仍须通过。
预览和确认核对同一 `digest` 与三条 lane 的 `epochs`，确认事务还检查准备时的读取修复版本；
发生变化须重新预览，不直接使用过期计划。内容摘要本身不含实时 epochs。

`confirm_report_export` 可省略 `output_directory`，默认使用公司内部 `exports`；提供时只表示导出父目录，新任务的独立成果目录由程序分配。页面的 `confirm_browser_report_export` 不接收此参数，程序按请求编号管理公司内部下载目录，成果以任务返回路径为准。旧任务继续使用原保存的精确输出路径，重试不改写原载荷。按任务结果定位成果目录，其中包含：

- `财务报表报送与信息采集（小企业会计准则）月季报_YYYYQn.xlsx`。
- `manifest.json`：完整冻结报表、公司/数据库身份、关账来源摘要、模板版本、文件摘要和任务 ID。

文件生成后按同一冻结数据重新渲染逐字节核对；原子目录发布前逐文件刷新到磁盘。
只有 `jobs` 成功且产物核验通过后，才用会计 Skill 的桌面复制脚本交付报表和 manifest；相同内容复用，不同内容自动另名保留。
任务在发布文件后崩溃，可以识别同一任务成果继续完成，不能覆盖其他任务或损坏的已有目录。
后台按任务原保存的 `plan` 输出，不重新读取后来的账务替换计划；改变账或公司名称不会改变
已经排队任务的内容。任务 payload 不可修改，失败记录与重试次数独立更新。

## 实际报送与复核

文件生成只表示交付准备完成。实际提交后，用 `evidence` 保全真正提交的系统导出任务
`manifest.json` 与原 XLSX，再由 `external_completion.adopted_evidence_digests` 引用其不可变摘要。
办理回执独立保全并作为该事实的证据，不能用提交文件自身冒充回执。
实际日期、记录月份与申报覆盖期分别保存；精确采用计算及真实补报接续仍遵守外部办理合同。

完整财报复核需要真实提交的 manifest 与 XLSX，以及本次核对所用的经验证 manifest。
核对公司、数据库、季度、文件摘要、模板及冻结计划，并验证原 XLSX 与原计划一致；
本次依据未变时复用已保全的原 manifest，变化后重新导出，保全并核对新 manifest。
通过 `external_basis_review` 的既有证据和精确引用保存核对依据，不为继续、结果确认或重复阅读另造来源。

原报送资料可以先保存；人工形成且没有结构化可核验依据的资料，只说明复核依据尚未建立，
不能凭文件名、人工文字或空计算集合猜测 `matched`。实际报送仍保留完成状态，等待补齐可核验的复核依据。

复核过期判断覆盖报表口径、分类、期初、全年累计、规则与模板及核算源。
原提交快照、XLSX、采用依据与回执保持不可变；后续变化使核对待复核，不覆盖实际报送。
版本变化没有影响报表时，可用精确的新依据重新核对为 `matched`；存在实际差异时记录差异，
不能把复核当成已经补报。相关快照元数据存于既有 JSON 与计算上下文，不新增物理数据库结构。

## 验证及性能边界

`tests/kernel/test_reports.py` 覆盖真实现金出资、费用、现金付款生成三表及模板缓存数值；
内部 CIT 确认、缺分类关账阻断、跨季度冲正、不同交易方余额重分类、现金分配完整性、
附加税退抵明细、闭期来源隔离、预览过期以及文件发布后的崩溃重试。
旧 `test_tax_template_preserves_structure_and_cached_values` 继续验证提取前后原模板接口兼容。

季度三表属于按需查询，不在普通入账路径重算；启用三表的关账会执行其完整性检查。
当前读取相关历史凭证及依赖并在内存中计算，成本随报告包含的账和往来明细增长。
已按凭证索引组织分类，避免每个分类再扫描全部行；核算结果复用批量主查询，常见报表属性取冻结计算输出。
未映射的非零账户、现金流或必要明细一律返回缺项，不用科目前缀猜测含义或生成看似完整的报表。
