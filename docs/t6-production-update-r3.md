## 问题与最小修复

原 production-v11-r1 浏览器检查没有将每页成功响应与当前公司明确绑定，也未覆盖资金页实际的 `error-state` 类。按架构要求追加的 r2 严格检查发现：员工请求返回 HTTP 200，但页面显示读取错误。失败结果保留，没有覆盖或淡化。

只读诊断确认，公司与期间匹配、共同查询合同有效；错误是 `LOCAL_MONEY_FORMAT`。员工 `field_sources.social_insurance_base_fen` 和 `field_sources.housing_fund_base_fen` 是合法来源证明对象，前端金额检查却只根据字段名将它们当作金额字符串。诊断只保存字段路径和类型，没有保存业务值、身份或金额。

本次仅修改 `frontend/src/api/localKernel.ts` 与 `frontend/tests/local-kernel.test.mjs`：`field_sources` 映射的直接键名不再解释为金额字段，仍递归检查来源内容。真实业务金额的整数分字符串校验保持，普通位置的金额数字或对象仍被拒绝，来源内部的非法实际金额也被拒绝；大额字符串、null 和来源证明内容原样保留。不修改后端、业务事实、共同查询合同或错误面板。
