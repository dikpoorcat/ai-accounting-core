# 银行批量代发

当前内核从已正式确认的未付工资、奖金、劳务、员工及负责人报销、个人代垫、期初报销应付款和期初净工资，以及代收代付的转付、退回义务生成银行付款指令。真实报销使用“报销”用途，转付最终收款人使用“代付款”，退回原付款人使用“代收款退回”；已有明确自定义用途继续采用，代收债权不能当作付款金额。金额与剩余应付来自公司库，不接受请求方临时覆盖金额或提交自由分录。代发文件生成、重试、下载均不代表实际付款；银行扣款发生后仍要依据实际流水登记付款及核销。完整的读取和任务规则见[新内核的银行代发文件](kernel-payment-exports.md)。

## 当前办理顺序

第2步确认工资方案、适用劳务和个税并登记必要输入，第3步办理社保、公积金，第4步统一办理银行代发。第2步确认不因尚未办理第3步而阻止，第4步复用仍有效的确认，不重复要求确认同一方案。进入第4步，先核对本次工资、奖金、劳务、报销及代付款事项和已收资料，在本步补齐相关事实、核算净额并正式发布，再完整读取候选、核对本次范围、预览确认并核验文件交付，跟踪真实银行代发。后续账务、报表及税费与银行代发无关，不作为前置条件，不等待后续核算回补代发。缺项保留第四步具体待办，继续本步其他可办工作并等待，每轮同一事项最多3个独立问题。正式计算、发布门槛不变，不自动执行银行付款，没有未付余额不生成空文件。

1. 按运行时 `finance_local_schema` 查 `export_sources`、`save_payee`、`preview_export`、`confirm_export` 的字段合同。用 `export_sources(period, limit=100, cursor=None)` 按归集月份读取全部分页；每页最多500条，版本变化时重新读取。核对来源身份、业务类型、核算月、归集月、用途、未结义务和核算状态；未发布和待重算来源可被发现，未发布金额不猜测。候选读取不要求模板、账号和整月资料齐备，也不证明正式导出条件通过或已经付款。先核对尚未登记的拟付款事项，再留存银行模板原件及收款姓名、文本账号与证据；`save_payee` 为收款资料追加版本，不把收款账号当作公司资金账户。
2. `preview_export` 从当前正式来源、未结余额及其采用依据生成核对内容。显式 `source_ids` 统一使用 `selected` 范围，工资、奖金、劳务、报销、代付款和混合范围均核验所选业务及直接、传递依据，并按精确义务关联核验实际付款、代垫、抵销、退回等影响余额的处理；已结清但明确选择的来源也参加核验。相关原件整份检查未处理行、隐藏内容、控制合计、人员、金额、期间、重复或竞争来源及失效结果，相关范围内、闭期承接及未知归期的问题仍阻断；其他明确未来期行只在所属期处理。报销月份不额外扩大工资原件检查范围，无关联的整月资料、税费及普通账务不阻挡选定付款。省略来源 ID 的完整导出和关账保持整月核验。选定文件不代表全月完整代发，不能以裁切原件或缩小来源掩盖相关问题。
3. `confirm_export` 核对同一预览摘要和核算、资料、管理版本，保存冻结计划与持久文件任务。`output_directory` 是可选父目录，省略时使用公司内部 `exports`，新任务成果目录由程序分配；旧任务保留原精确路径。用 `jobs` 查看结果；需要处理文件任务时走 `run_export_jobs`。只有任务成功且文件内容已核验，才用会计 Skill 的桌面复制脚本交付银行工作簿和核对报告；相同内容复用，不同内容自动另名保留。
4. 已有任务须核对是否覆盖本次来源、金额和收款资料，仍有效时复用；新增来源、付款、更正或收款资料变化时，重新预览、核对并生成新任务，旧任务保留原金额和用途。候选为空、范围已保存或旧任务成功都不能代替本次交付核验结果；实际付款另行入账。

收款资料和公司业务说明分别承担收款指令与管理说明的职责，不能代替正式账务来源。账号保留前导零，不从金额、名称或用途猜测身份。生成的四列 XLSX 仍须以银行实际接收结果核对。

## 历史边界

旧 `finance-mybank`、`python -m ai_accounting.mybank_export`、`finance_preview_mybank_export`、`finance_generate_mybank_export`、`finance_import_mybank_payment_source` 和 `0008_mybank_payment_metadata` 属于退役体系，不是当前运行、迁移或恢复指令。旧的 `org_id`、`template_path`、`recipients_path` 请求文件及 `source_hash` 生成流程不能传给当前内核。原设计和命令样本由 Git 历史保留；当前只使用 `finance-local` 的类型化命令和运行时 Schema。本阶段仍是 `ai-accounting-kernel/2` 的开发合同，不宣称已发布正式 v1。
