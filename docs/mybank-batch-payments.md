# 网商银行批量代发

`finance-mybank` 和 MCP 工具从当前公司已过账的内核数据生成导入文件。
生成请求只接受公司、期间、范围和文件路径，不接受临时金额覆盖。实际个税等补充事实先从留存原件导入。
CLI 经过已注册 MCP 工具的负责人认证、公司路由和数据库版本检查，不直接打开指定业务库。

## 公司规则与原始依据

公司规则保存在业务数据目录的 `<统一社会信用代码>/业务说明.md`，不保存于源码。
AI 读取负责人说明，保存具体适用范围；导出支持以下受控金额来源：

| 导出类别/用途 | 内核金额来源 |
| --- | --- |
| 薪资 | 已过账工资明细的实发工资，或报税工资－税务局实际个税－个人社保－个人公积金 |
| 劳务 | 已核定代发类别、人员和期间的劳务应付款剩余金额；已有原表时同时核对原额 |
| 报销 | 回扣报销1＋回扣报销2＋发票报销，或内核已合并的剩余报销应付款 |

MD 中可由 AI 维护单个 `mybank-export` 配置块，内核仅接受上述固定规则。
没有公司专用配置时使用内核实发工资；选用税局实际个税时，缺失实际个税不能退回计算个税或零。
普通导出请求不能覆盖规则，其他公司不继承本公司的说明。修改文件会使旧导出预览失效，不改写工资凭证。

`finance_import_mybank_payment_source` 使用证据 ID、公司、月份、来源类型、预期版本和幂等键导入原件。
`actual_tax` 读取本期收入及“应补(退)税额”，不把累计“已缴税额”当作本期个税；
`payment_register` 读取报税工资、未报税劳务及三项报销，用于额外核对。
支持 XLS、XLSX、CSV 及 Markdown 表格，未知金额阻断。最新来源和证据引用随回放包保留，目标库重新解析。
原表的货币会计格式 `¥ -` / `￥ -` 识别为明确的零；普通横杠、空白和待定内容仍不补零。

三项已经在内核合并为一笔应付款时，只读取该笔剩余应付总额一次；核对报告标为“内核合并报销”，
不重新相加，不臆造三项拆分。分别记录时按员工汇总三项。
归类只影响导出展示，不改写任何会计事实或原凭证。

## 选择数据

- 默认 `scope=complete`，按公司和月份读取全部有效工资及已知劳务、报销来源，并执行月度清单完整性检查。
  清单已核对通过时不要求另换固定代发表。不能用员工或应付款 ID 筛选来缩小完整范围；缺来源或账号时列出缺项。
  只有明确的部分付款才使用 `scope=selected` 和人员/应付款 ID，报告保留部分范围标记。
- 工资应付款原额是应发工资，**不能直接作为实发金额**。已结清工资排除；工资已有部分核销时
  返回 `needs_information`，当前版本要求先核对剩余实发金额，不猜测已支付部分的扣缴组成。
- 报销自动复用清单关联及本期已核定范围，部分导出可选择 `reimbursement_open_item_ids`。支持代收代付和个人垫付费用的已过账应付款；
  读取原额减已核销金额，已结清项只列在核对报告。收款员工必须能从内核确定，重名或缺受益人阻止导出。
- 会计确认月份与实际代发月份分别表达；可选管理资料 `payment_period` 只用于代发范围，不能证明本月应付已经计提。
  本月应确认却在下月才入账，仍不能完成本月资料清单。未入账金额不能当作零应付。
- 负责人已明确报销人员时填写 `reimbursement_employee_ids`，逐人检查内核来源覆盖。
  其中任何一人缺少本次未结清报销来源都阻止整个批次生成，不能缩减人数后交付。
- 历史“应付款结算”凭证表示已经支付；应追溯其核销来源及剩余余额，不能把结算额重新导出。
  例如屋舍心声 `202608-0008` 对应已全额核销的合并款，不会再次计入待付。

## 模板与收款资料

使用负责人提供的 `网商银行批量代发模板.xltx`，银行文件前四列为：
收款方名称、收款方账号、金额、附言/用途。保留表头、样式及右侧填写说明，
转换为普通 `.xlsx` 工作簿。四列都按文本写入，金额固定两位小数，单文件最多 2000 条。

`recipients_path` 提供姓名和账号，支持：

- “姓名、账号”两列表；
- 同款四列银行模板；
- 原“编号(*)、账户名称(*)、账号(*)、交易金额(*)……”六列收款表。

账号必须为文本，公式、数字型账号、科学计数法、重复姓名/账号会被拒绝。
收款资料中的金额、公式、旧备注一律不用于付款计算。当前内核未登记收款账号，
所以账号仍由这份收款资料提供；所有业务金额和收款员工身份来自内核。

## 使用

创建完整代发请求 JSON（UUID 换为当前公司）：

```json
{
  "org_id": "74299243-c333-43d9-9807-4f2336cd984c",
  "payroll_period": "2026-08",
  "template_path": "C:/Users/MD01/Desktop/网商银行批量代发模板.xltx",
  "recipients_path": "D:/资料/收款账号.xlsx",
  "scope": "complete"
}
```

先预览，不产生银行文件：

```powershell
.\.venv\Scripts\python.exe -m ai_accounting.mybank_export `
  --request 'D:\资料\代发请求.json' --report 'D:\资料\代发核对.json'
```

核对人员、金额及来源后，用刚返回的 `source_hash` 生成：

```powershell
.\.venv\Scripts\python.exe -m ai_accounting.mybank_export `
  --request 'D:\资料\代发请求.json' --generate `
  --expected-source-hash '<预览返回的64位哈希>' `
  --output-dir 'D:\资料\网商代发202608'
```

也可调用 `finance_preview_mybank_export` / `finance_generate_mybank_export`。
生成工具比预览多接受 `expected_source_hash` 和 `output_dir`，不接受金额。
CLI 使用本地安装环境与已登录负责人会话。更新运行中的 MCP 后需重新连接才能发现新增工具；
本地 CLI 可直接调用当前代码。

数据库须升级到 `0008_mybank_payment_metadata`，以使管理资料中的代发月份、类别与数据库校验一致。
该前向迁移保留管理历史的追加保护、负责人归属与版本校验，不改写凭证或核算期间。

## 输出与边界

输出目录必须不存在。缺项、来源变更或校验失败不发布部分文件。准备完工作簿后再次读取内核
核对来源快照；金额、核销状态、员工范围、账号、公司规则或模板变化均使旧预览失效。
全部成功后发布目录，包含单个 `网商银行_月份_代发.xlsx` 以及 `代发核对.json`。
XLSX 只有一个工作表，各笔用途分别为薪资、劳务、报销。
核对报告保存内核来源 ID、工资计算哈希、金额组成、已结清排除项、公司配置及文件哈希，不保存账号。

导出只准备文件，不连接银行，不改凭证或登记付款。文件不是付款锁：导出后如又有付款或更正，
应重新生成；同一付款不得重复上传。实际核销仍须依据银行回单入账。
银行端能否接受文件，以实际上传校验结果为准。
