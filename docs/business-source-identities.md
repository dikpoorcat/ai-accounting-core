# 业务来源主体标识

类型化事实中用于引用另一业务事实的字段采用 `kernel.types.SubjectId`，与登记入口的 `subject_id` 使用同一合同：非空字符串，最多 200 个字符。引用必须原样复用登记结果中的主体标识，包括内核生成的 `payroll:employee-example:2026-02`；不能截断、去掉冒号或另建别名。

该合同适用于付款与非现金抵销的 `Allocation.source_id`、超付追收的 `source_id`、银行对账的 `Match.source_id` 和 `statement_id`，以及项目／基金成本、费用退回、预付退款、销售税点、资产验收与借款、期初包成员、工资政策与税务来源等实际业务主体引用。现金付款和工资备用金付款复用相同的核销来源类型。

业务种类、义务名称、交易方、员工、账户、资产等实体标识保留各自的类型约束。例如交易领域的普通 `Identifier` 仍限制为最多 150 个字符，以字母或数字开头，其后只允许字母、数字、下划线、点和连字符。来源引用不能因此被当成实体身份。

接受合法主体字符串不代表采用该来源。预览与发布仍核对业务种类、当前正式结果、期间、交易方、金额和核销边界；来源缺失或不满足处理条件继续阻断。空字符串、超过 200 个字符或非字符串的来源引用在登记阶段拒绝，且不产生正式写入。

此接口修复不改变 SQL 结构、已保存业务事实、冻结记录或任意分录边界。合成验证使用新建公司库，覆盖工资准备生成主体后发布，再通过银行／现金付款、工资备用金付款、非现金抵销与银行对账引用该主体。
