# 本地会计工作台启动

Windows 的默认入口是本地 SQLite 内核。每个资料根目录运行一个后台服务，CLI、MCP 和工作台连接同一服务；每家公司仍使用独立数据库。启动只连接服务并打开工作台，公司登记需要另行明确执行。

## 已分发的运行包

解压运行包，在包目录执行：

```powershell
.\finance-local.ps1 --root D:\会计资料 serve
```

运行包自带 Python、SQLite、前端发布文件及所需依赖。运行包可以移动，账务目录由 `--root` 明确指定。不要把正在使用的账务目录放到网络盘或云同步目录。

## 仓库开发环境

首次安装受控运行时和工作台：

```powershell
.\scripts\kernel-runtime.ps1
Set-Location frontend
npm ci
npm run build:release
Set-Location ..
```

日常启动：

```powershell
.\deploy\windows\start_accounting.ps1 -DataRoot D:\会计资料
```

未指定 `DataRoot` 时，先使用 `FINANCE_DATA_ROOT`，否则使用仓库 `data/kernel-released`；指定 `-PackageRoot` 时默认使用该包内的 `data/kernel-released`。原开发目录不移动、转换或删除，也不导入原凭据；CLI 直接运行需要 `--root` 或环境变量，不按当前工作目录选择裸 `data`。`-NoBrowser` 只连接服务并返回身份状态，默认打开页面。第 9 阶段本轮按用户决定保持开发库draft／0及现有5173、资料根和身份，不进行正式冻结、正式包交付或运行入口切换；目录名称不代表已经发布。已有released隔离验证不转换当前开发库。

服务在本机回环地址自动选择端口；再次启动会复用同一资料根目录的服务。启动脚本不需要 Docker、PostgreSQL 或系统 Python，也不会替换旧 `.venv`。旧数据目录不会被转换或删除；遇到未知库或不支持的版本，应按诊断处理，不能绕过数据库检查。

当前先在已有的本体系公司库试用并补齐缺口；结构变化不另设负责人、不自动建立空库重放。普通启动只接受匹配的结构，不隐式迁移。包内已声明的开发结构变化通过显式 `upgrade-development` 处理：先停止服务，完成已验证备份，再按精确来源与目标逐公司原子调整，追加 `schema_draft_history`，保留原版本 0 安装记录、全部原行、目录和负责人身份及冻结历史。入口已通过合成验证，真实执行与核验分别记入私有回执；完整操作及失败接续见[开发库前向升级](development-database-upgrades.md)。旧体系不作为来源，已发布的 `released` 合同不可回写；只有用户明确指定时才建立空库重放。

## 负责人登录与安全操作

请通过启动命令打开看板。首次使用，在登录面板填写登录名，点击“设置负责人”。密码与恢复码只在弹出的本机安全窗口输入。已有身份使用“负责人登录”；登录后从侧栏底部进入负责人安全操作，修改密码、恢复访问、更换恢复码仍由本机安全窗口处理。

页面会轮询该安全操作的状态，登录成功后自动读取公司目录。启动器用一次性 `#ticket` 打开页面；页面立即清除票据片段，并通过同源 POST 换取 HttpOnly、SameSite Cookie。该 Cookie 证明页面来自本机启动器；已登录时同时建立负责人会话。刷新页面继续使用 Cookie，页面不保存负责人令牌，不把密码放入网页表单。

看到“请通过本机安全窗口完成负责人登录”时，点击登录按钮；关闭或超时后可以重试。直接输入地址且没有启动器 Cookie 时，请重新执行启动命令。没有已登记公司的空目录是有效状态，启动不会自动建立业务公司。

## 开发验证

```powershell
Set-Location frontend
npm test
npm run type-check
npm run build
npm run build:release
```

两个 HTML 文件 `index.html`、`local.html` 和默认首页加载同一套 Vue 看板，包含经营简报、资金、员工、资产和财务报表；五页均可直接访问和刷新。主题、侧栏和月份选择继续沿用原界面，数据来自新 SQLite 内核。页面展示业务金额、对象、时间和本人待办；侧栏显示文件处理状态，季度报表成功生成并验证后才可下载。

当前五页以经营情况为默认阅读层：简报显示本月收入、费用、赚亏及资金、待收待付，员工和资产显示成本、付款及生命周期。默认每集合20条，汇总覆盖完整范围；精确业务定位不受首屏限制。核算来源、技术详情及完整准备检查由 AI 通过 CLI/MCP 读取，不进入默认看板或折叠区；必要金额和内容核验仍在服务端执行。已有管理资料按精确身份复用，报表来源由 AI 核对；页面只展示报表是否可用及本人需处理的事项。刷新同时更新月份和关账状态，账户筛选覆盖整月，版本变化后整体重载。详见[老板看板阅读边界](dashboard-owner-experience.md)。

浏览器身份交换从本地服务的同源页面发起。开发时先启动同一资料根的服务，再运行 `npm run dev`；Vite 通过只读 `service-info` 核验目录库、数据库合同及在线服务身份，从同一目录受保护的 `.service.json` 取得私有连接能力，仅在开发进程内代理 API、换取一次性浏览器票据。请求发现服务状态变化或连接失败时，会重新核验并更新端口和私有能力；并发发现合并执行，资料目录身份必须与 Vite 启动时一致。后台暂时离线时 API 返回明确连接错误，开发页面仍可访问；后台重启后刷新页面即可重新建立浏览器会话，无需重启 `npm run dev`。失败请求不自动重发；主动切换 `FINANCE_DATA_ROOT` 时重启 Vite。私有能力不进入浏览器。公司选择参数为 `company_id`。

当前开发结构直接包含管理档案和月度经营说明。管理资料通过类型化 CLI/MCP 维护，页面只读；缺资料显示未提供，不推断入职日期或成本拆分，也不影响正式凭证。已关账的后补说明作为附录，冻结摘要保持原样。旧系统数据库及备份均不能作为当前启动或恢复来源。
