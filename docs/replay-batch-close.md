# 持久重放执行流程

空库重放只在用户明确指定后执行，全部从头，只使用重放文档及其索引的原件和负责人确认。新目录、负责人和公司使用本次实际创建的身份；旧库的对象编号、余额、凭证、冻结、完成标记和回执不作为输入。本轮按全新空库落地，不处理现库迁移或旧包转换。普通记账继续逐月核对和本机密码批准。

## 运行范围与固定构建

先建立目标目录与公司，登记本次负责人范围确认原件。通过私有范围文件指定目录身份、公司与数据库身份、连续起止月份和确认摘要，再显式启动：

```text
finance-local --root <新资料根> daemon --replay-scope <私有范围文件>
```

范围文件沿用 `ai-accounting-kernel/2/replay-close-scope/1`，每家公司一个连续范围，最多120个月。服务要求有效负责人登录；普通服务不自动取得重放权限。通过 `service-info` 和 Schema 核对实际模式、范围摘要与开发合同。

服务从私有、按内容摘要命名的运行副本加载代码、规则、合同和看板资源，并记录活动构建。工作区变化不切换已运行服务；重启读取同一活动副本。更换构建在明确检查点执行，恢复同时核对原构建、范围、身份、凭据、实际业务版本和连续关账前缀。页面可打开不能代替这些核对。

## 准备、确认和恢复

1. 从单份最终事实清单整理实体、账户、来源摘要、核算事实、允许精度、依赖引用和未决事项。删除已授权旧库之前，先用合成目标身份完成来源字节与目标合同的离线模板检查，不创建活动数据库。新事实按当前 `registry.input_models` 及 Schema 校验；历史计税类型虽可解码，也不能进入新登记计划。材料 `fact.*` 金额引用核对目标类型的当前整数分字段，旧原表字段和别名不能复活已退出字段；未知或冲突目标返回结构化问题及实际路径、允许字段。`result.*` 保留正式结果核验，不能凭合成金额宣称接口通过。材料原件按真实字节登记，负责人确认保留原话和出处。新目标建立后使用 `ai_accounting.kernel.replay_document.compile_replay_document`，明确提供本轮 `company_id`、`database_id`、`owner_confirmation` 和稳定 `request_id`；最终输入只编译一次，将 `request`、新身份映射及 `preservation_requirements` 保存于本轮单份私有执行索引。纯编译不读取数据库、不执行业务，也不使用清单中的历史运行编号和回执。额外确认按返回的原字节保全后才能提交，编译问题先与已有来源核对，再处理实际缺项。
2. 调用 `prepare_replay`，外层提供 `company_id`，`request` 使用 Schema 发布的 `ReplayPrepare` 合同。准备绑定公司及数据库、月份范围、来源清单摘要、负责人确认、运行构建和结构指纹，返回计划摘要及阻断项。事实不齐先补原始事实，不猜金额、核算日期、科目、角色或凭证行。
3. 核对计划后调用 `confirm_replay`，`request` 提供 `plan_id`、`plan_digest` 和稳定 `request_id`。确认持久化运行与节点后立即返回 `run_id`，后台逐步推进。
4. 调用 `replay_status`，`request` 提供 `run_id`，先查询只读进度摘要，需要精确回执时另提供 `step_id`，或用 `step_ids` 一次查询最多200个不同节点；二者不能同时提供。批量回执在同一读快照中按请求顺序返回，任何节点不存在时整体拒绝，不逐节点反复读取完整响应。摘要的节点列表限前100项，耗时限前600行；后段 `current_phase` 可能为空，实际阶段用 `current_step` 与保存计划映射解释，截断不能当作未提交。连续关账前缀、阻断信息与最终交付任务分别核对。
5. 连接中断或服务重启后，用 `resume_replay(company_id, run_id)` 接续原任务。先恢复稳定请求键对应的实际回执；已提交节点不再执行。不得因一次响应丢失改用新键重记业务。

节点保存完整原载荷、依赖、稳定请求键和真实响应。业务节点的完成记录及输出绑定与事实、正式采用、凭证、审计和原请求回执在同一事务保存；无凭证结果也保留完整输出。按真实依赖使用现有 `save_facts`、`inventory_batch` 与专用批量入口，保持原子失败及各项实际输出绑定。每家公司每轮推进一个节点，节点明确提交后短暂让出并连续调度；没有重放进展时，闲置、阻断、失败及普通后台任务按原间隔等待。固定构建中的命令 Schema 可复用，实时权限、结构和提交边界仍逐次核对。

构建变化后不能直接恢复绑定旧构建的运行。首次关账前，可使用纯函数 `prepare_replay_continuation`，提供本轮保存的原请求、通过 `replay_status` 取得的全部已提交回执和实际 `parent_run_id`，移除已完成业务节点，并把其声明输出替换成本轮实际身份；未完成业务保持原事实和身份。原请求已声明 `continuation_from` 时，`ancestor_checkpoints` 只提供该显式链上各运行的原请求和真实回执，不能加入未连接的历史。仍被剩余节点使用的只读预览或准备在新构建重新生成，不携带旧预览直接确认。

接续请求的 `continuation_from` 指向本轮实际父运行。服务核对目录、公司、数据库、范围、权限、实际提交回执及当前边界，准备和确认均复核；已提交父节点仅参与顺序验证，实际执行图只含剩余节点，不重复接收材料、不改写父运行。原运行的恢复仍要求原会话；新的显式接续计划允许同目录、同负责人、同凭据版本的当前有效会话，原权限记录不变。已有关账前缀、未明的执行结果和仍能推进的同构建父运行均拒绝。原请求、原运行和回执保留在同一私有执行索引，剩余计划重新准备、核对和确认；缺少祖先实际上下文时停止，不能从历史编号推导已完成结论。

已关账后，业务接续入口仍受闭期保护，不能直接把原运行的剩余业务和关账节点重新合成接续请求。先保留原运行及全部关账回执，核对实际冻结链，通过正常类型化入口处理未关月份的问题，再用普通 `prepare_replay`／`confirm_replay` 准备只含剩余 `preview_close`／`close` 的新关账子范围。子范围必须在原负责人范围内，从真实前缀的下一月连续推进，不再次执行已关月份、不重新登记业务。首个预览的前月与摘要须同时匹配运行检查点中的实际前缀；没有前缀时仍必须由建账首月真实采用期初。材料修复先独立完成并取得真实回执，不混入新关账计划；材料处置的顺序检查要求真实接收祖先，不能添加虚假的接收节点或祖先关系使计划通过。

编译结果及新身份映射保存于本轮单份私有执行索引；恢复使用已保存的同一请求，不能重新编译出另一组身份后重发原请求键。批量回执的成员通过声明的 `output_selectors` 选择：`array_path` 指向真实回执数组，`match_field` 和 `match_value` 唯一匹配本轮业务身份，`field` 读取该成员的实际输出。引用依赖进入同一计划；没有匹配、出现多项匹配或字段缺失时拒绝，业务写入、节点回执和绑定一并回滚。报告分类重新读取本轮当前正式采用和完整凭证，按业务来源、分类及精确金额唯一定位；旧行号与旧凭证版本不作为输入。

原 `preview_replay_close_range / confirm_replay_close_range` 仅作为关账计划适配入口。确认同样返回持久运行编号，由正式执行器推进，不另执行同步月循环。

## 内核保证的顺序

实体与完整资金账户先于使用它们的事实。材料接收先于材料处置；主组确认先于复制成员，复制成员先于复制组。编译器完整消费材料清单与专用步骤中声明的归期预览和确认；同一来源及相同归期只执行一次，冲突或不完整声明明确阻断。归期确认的摘要、时期版本和预期修订号来自本轮真实预览；材料处置与关账等待归期确认，不沿用模板中的旧修订号。工资、奖金和 `labor` 先保存报酬，再以本轮实际 `subject_id`、`fact_id` 登记唯一 `remuneration_tax_basis`，工资准备及报酬预览等待税依据后才发布。税依据只等待报酬保存，合并税源的所有个人报酬也先保存，不能等待发布形成循环。核算期与税期独立，未知管理扣税日可省略；应计劳务和资本化劳务保持尚未记录扣缴及申报的真实性质。历史个税政策、累计期初、首次工资处理及旧实际扣税事实只读，不登记到新库。专用资产与义务入口产生的成员从真实预览及完整回执绑定。

报酬税额按 `lookup_first` 联合核对最终方案、原件、个人贡献与实际税额分配，明确零税也保存来源。只接受唯一且有据的关系：核算毛额等于完整个人社保公积金、确认最终净额为零且无其他扣减时，可据此确定税额为零，不要求来源再单独填写同一个结论。未付款、应付余额或单条银行合并总额不能证明个人税额，旧理论计税也不替代当前来源。仍有歧义或缺少会改变核算的事实时，只阻断受影响事项并核对原件，不机械转成负责人追问。工资无变化确认只复用正文依据，不复用上月税额；已有工资准备返回 `ready`、无缺项、无候选且版本精确匹配时，直接普通批量 `preview`／`confirm`，不重复登记。

期初包及其完整成员必须先正式采用，随后才能首次发布普通核算业务。期初来源不完整或尚未采用时，内核返回结构化事实问题，普通发布整体回滚；零期初也需要明确、可追溯的负责人事实，不能由执行器默认创建。

业务发布、银行对账、材料关联、逐项处置和月度清单按实际依赖完成。同一银行账户首月对账等待明确账面起点正式采用，后月等待前月对账正式采用；纯函数 `add_bank_reconciliation_dependencies` 只补计划依赖边，缺月份或账面起点时拒绝，不补造事实。每个月重新核对资料、核算、报表和冻结依据，再连续关账，不跳过阻断月份。报告分类准备入口根据原业务、义务及付款分配的类型化身份解析准确凭证行；非唯一定位返回问题，不接受调用者猜测的科目或行号。

有精确原件位置的独立业务可通过 `add_replay_registration_preparations` 为尚未提交的登记增加只读重复准备，业务身份、金额和原件不变。独立意图只用于要求核验不同原行；当前强候选都须有真实位置并经准备核验，登记事务再次核对候选摘要和依据，不能自动把无法证明的候选判为独立。

后续付款或其他跨月业务可能让此前结果产生 `review_no_impact`，即使事实、核算结果摘要和凭证都不变，也会生成新的正式计算身份。材料不能继续使用首次发布时的计算编号。关账前统一检查未关月份的资料；发现失效关联时，通过本轮 `business_status` 核对当前正式采用、事实版本、待处理原因和凭证来源，并逐项比较旧与新计算。确认同一事实、同一结果摘要和同一凭证后，用正常 `resolve_material`／`resolve_material_group` 追加处置修订，保持原资料身份、期间、其余数据及证据，只更新计算引用，采用当前预期修订号并保存真实回执。结果或凭证改变时转对应业务更正，不能当作无影响引用更新；已关月份的冻结资料不改写。

## 看板与提交

公司写入锁、业务事务、提交前身份锁按固定顺序取得。业务事务保存权威事实、正式采用、凭证、必要账务投影、冻结、审计、原请求和变更记录；共享身份锁只包住最终授权复核与提交。提交前撤权必须回滚。

看板由独立派生库在一致读快照中生成。内容先持久化，再用短事务核对来源版本并发布引用。来源在发布前改变则放弃本次发布，合并新任务。实际读取的对象、期间、范围及空命中共同决定依赖；跨月累计、后续清偿、展示资料、公司说明、关账、日期、修复版本和构建均参与有效性判断。

默认五页摘要与首屏一起生成；筛选、续页和详情按需读取。回放阶段合并历史月份的连续变更，明确浏览的月份可优先生产。仅公司全局版本增加不触发全部月份重建。

看板首页统一返回版本6的 `ready / preparing / failed` 合同。只有 `ready` 含业务响应；`preparing` 清空旧内容并显示“正在更新”，页面按服务端间隔只读重试；内容损坏与尚未生成分别处理。分页和迟到响应继续核对公司、期间与内容版本。

## 冻结、备份与交付

普通月结继续逐月生成备份任务。重放中间月份只保存正式冻结与独立关账回执，`backup_job` 为空；末月创建该轮唯一完整公司备份任务。回放核算完成、看板准备完成、备份交付完成分别记录，不能互相替代。

公司保持交付边界，直到目标 SQLite 快照已持久固化并核对关闭摘要。随后释放业务写入；压缩、核验和发布只使用该固定快照。重试同一任务不会重新抓取活动库。任务保存租约、心跳、不可变尝试事件、阶段耗时和失败原因；ZIP已发布而状态回写失败时，按任务身份与快照摘要恢复成功结果。

各公司分别在配置目录生成 `<统一社会信用代码>.finance-company.zip`。只有任务成功且指向已核验ZIP才算交付，最后月份已冻结而任务仍待处理时分别记录两个状态，不提前宣称整轮交付完成。完整包保留必要业务历史，派生看板在同结构恢复后通过明确的重建边界重新生成。恢复不覆盖已有目标。

恢复普通运行使用本轮活动固定副本：先通过该副本核验 `service-info` 并执行受保护停止，等待原进程退出，随后隐藏启动同一副本的 `daemon`，省略 `--replay-scope`。保留 `.runtime-snapshots/active`，核对新服务目录、结构及构建身份不变、模式为普通、范围摘要为空；MCP与看板按同目录身份重新连接。仓库 `.codex/config.toml` 的记账 MCP 启动器先选择已有活动副本，再导入运行入口；缺少活动副本时拒绝启动，不借连接创建目标。该启动配置已通过前台隔离的工具发现及真实 Schema 请求，测试进程随即退出，不代替宿主重连。重建前已经连接旧目录的会话仍须重新打开项目会话。工作区源码或合同的后续变化不进入这次恢复，不利用自动启动隐式更新构建。

工作区合同已变化时，开发看板代理的默认CLI发现会拒绝固定库结构。可使用私有Vite覆盖配置，复用原 `localApiProxy`，只把发现回调改为从活动固定副本读取：核对受保护服务状态、目录精确结构、实时健康及固定构建，再返回进程内连接信息。保留原目录身份锁定、能力请求头处理、同源会话及禁止自动重放请求的规则，连接信息不进入日志或页面。Vue源码仍来自当前开发目录，必须另验接口兼容，不能把该配置称为固定页面代理；固定包内置页面是独立的操作入口。更换目录身份后，宿主MCP必须实际重新连接；旧会话仍缓存原身份时，说明需重新打开会话，新宿主连接成功不代表旧会话也已恢复。

## 验证范围
