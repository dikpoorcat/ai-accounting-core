# 持久重放执行流程

空库重放只在用户明确指定后执行，全部从头，只使用重放文档及其索引的原件和负责人确认。新目录、负责人和公司使用本次实际创建的身份；旧库的对象编号、余额、凭证、冻结、完成标记和回执不作为输入。本轮按全新空库落地，不处理现库迁移或旧包转换。普通记账继续逐月核对和本机密码批准。

## 运行范围与固定构建

先建立目标目录与公司，登记本次负责人范围确认原件。通过私有范围文件指定目录身份、公司与数据库身份、连续起止月份和确认摘要，再显式启动：

```text
finance-local --root <新资料根> daemon --replay-scope <私有范围文件>
```

范围文件沿用 `ai-accounting-kernel/2/replay-close-scope/1`，每家公司一个连续范围，最多120个月。服务要求有效负责人登录；普通服务不自动取得重放权限。通过 `service-info` 和 Schema 核对实际模式、范围摘要与开发合同。

服务从私有、按内容摘要命名的运行副本加载代码、规则、合同和看板资源，并记录活动构建。工作区变化不切换已运行服务；重启读取同一活动副本。更换构建在明确检查点执行，恢复同时核对原构建、范围、身份、凭据、实际业务版本和连续关账前缀。页面可打开不能代替这些核对。

## 准备、确认和恢复

1. 从单份最终事实清单整理实体、账户、来源摘要、核算事实、允许精度、依赖引用和未决事项。材料原件按真实字节登记；负责人确认保留原话和出处。使用 `ai_accounting.kernel.replay_document.compile_replay_document`，明确提供本轮 `company_id`、`database_id`、`owner_confirmation` 和稳定 `request_id`，取得 `request`、新身份映射及 `preservation_requirements`；纯编译不读取数据库、不执行业务，也不使用清单中的历史运行编号和回执。额外确认按返回的原字节保全后才能提交，存在编译问题时先处理实际缺项。
2. 调用 `prepare_replay`，外层提供 `company_id`，`request` 使用 Schema 发布的 `ReplayPrepare` 合同。准备绑定公司及数据库、月份范围、来源清单摘要、负责人确认、运行构建和结构指纹，返回计划摘要及阻断项。事实不齐先补原始事实，不猜金额、核算日期、科目、角色或凭证行。
3. 核对计划后调用 `confirm_replay`，`request` 提供 `plan_id`、`plan_digest` 和稳定 `request_id`。确认持久化运行与节点后立即返回 `run_id`，后台逐步推进。
4. 调用 `replay_status`，`request` 提供 `run_id`，需要精确回执时另提供 `step_id`，或用 `step_ids` 一次查询最多200个不同节点；二者不能同时提供。批量回执在同一读快照中按请求顺序返回，任何节点不存在时整体拒绝。状态只读，返回提交进度、当前阶段、连续关账前缀、阻断信息、节点耗时和最终交付任务。
5. 连接中断或服务重启后，用 `resume_replay(company_id, run_id)` 接续原任务。先恢复稳定请求键对应的实际回执；已提交节点不再执行。不得因一次响应丢失改用新键重记业务。

节点保存完整原载荷、依赖、稳定请求键和真实响应。业务节点的完成记录及输出绑定与事实、正式采用、凭证、审计和原请求回执在同一事务保存；无凭证结果也保留完整输出。每家公司每轮推进一个节点，节点明确提交后连续调度；没有重放进展时，闲置、阻断、失败及普通后台任务按原间隔等待。

构建变化后不能直接恢复绑定旧构建的运行。首次关账前，可使用纯函数 `prepare_replay_continuation`，提供本轮保存的原请求、通过 `replay_status` 取得的全部已提交回执和实际 `parent_run_id`，移除已完成业务节点，并把其声明输出替换成本轮实际身份；未完成业务保持原事实和身份。原请求已声明 `continuation_from` 时，`ancestor_checkpoints` 只提供该显式链上各运行的原请求和真实回执，不能加入未连接的历史。仍被剩余节点使用的只读预览或准备在新构建重新生成，不携带旧预览直接确认。

接续请求的 `continuation_from` 指向本轮实际父运行。服务核对目录、公司、数据库、范围、权限、实际提交回执及当前边界，准备和确认均复核；已提交父节点仅参与顺序验证，实际执行图只含剩余节点，不重复接收材料、不改写父运行。原运行的恢复仍要求原会话；新的显式接续计划允许同目录、同负责人、同凭据版本的当前有效会话，原权限记录不变。已有关账前缀、未明的执行结果和仍能推进的同构建父运行均拒绝。原请求、原运行和回执保留在同一私有执行索引，剩余计划重新准备、核对和确认；缺少祖先实际上下文时停止，不能从历史编号推导已完成结论。

已关账后，先保留原运行及全部关账回执，核对实际冻结链并处理未关月份的问题，再为已核验前缀之后的月份准备新关账计划。子范围必须在原负责人范围内，从真实前缀的下一月连续推进，不再次执行已关月份。首个预览的前月与摘要须同时匹配运行检查点中的实际前缀；没有前缀时仍必须由建账首月真实采用期初。

编译结果及新身份映射保存于本轮单份私有执行索引；恢复使用已保存的同一请求，不能重新编译出另一组身份后重发原请求键。批量回执的成员通过声明的 `output_selectors` 选择：`array_path` 指向真实回执数组，`match_field` 和 `match_value` 唯一匹配本轮业务身份，`field` 读取该成员的实际输出。引用依赖进入同一计划；没有匹配、出现多项匹配或字段缺失时拒绝，业务写入、节点回执和绑定一并回滚。报告分类重新读取本轮当前正式采用和完整凭证，按业务来源、分类及精确金额唯一定位；旧行号与旧凭证版本不作为输入。

原 `preview_replay_close_range / confirm_replay_close_range` 仅作为关账计划适配入口。确认同样返回持久运行编号，由正式执行器推进，不另执行同步月循环。

## 内核保证的顺序

实体与完整资金账户先于使用它们的事实。材料接收先于材料处置；主组确认先于复制成员，复制成员先于复制组。编译器完整消费材料清单与专用步骤中声明的归期预览和确认；同一来源及相同归期只执行一次，冲突或不完整声明明确阻断。归期确认的摘要、时期版本和预期修订号来自本轮真实预览；材料处置与关账等待归期确认，不沿用模板中的旧修订号。工资使用本次实际采用的事实路径；专用资产与义务入口产生的成员从真实预览及完整回执绑定。

期初包及其完整成员必须先正式采用，随后才能首次发布普通核算业务。期初来源不完整或尚未采用时，内核返回结构化事实问题，普通发布整体回滚；零期初也需要明确、可追溯的负责人事实，不能由执行器默认创建。

业务发布、银行对账、材料关联、逐项处置和月度清单按实际依赖完成。同一银行账户首月对账等待明确账面起点正式采用，后月等待前月对账正式采用；纯函数 `add_bank_reconciliation_dependencies` 只补计划依赖边，缺月份或账面起点时拒绝，不补造事实。每个月重新核对资料、核算、报表和冻结依据，再连续关账，不跳过阻断月份。报告分类准备入口根据原业务、义务及付款分配的类型化身份解析准确凭证行；非唯一定位返回问题，不接受调用者猜测的科目或行号。

有精确原件位置的独立业务可通过 `add_replay_registration_preparations` 为尚未提交的登记增加只读重复准备，业务身份、金额和原件不变。独立意图只用于要求核验不同原行；当前强候选都须有真实位置并经准备核验，登记事务再次核对候选摘要和依据，不能自动把无法证明的候选判为独立。

后续业务可能让此前结果产生无影响复核，材料不能继续使用首次发布时的计算编号。关账前统一检查未关月份的资料；发现失效关联时，通过本轮 `business_status` 核对当前正式采用、事实版本、待处理原因和凭证来源，再用类型化材料入口追加处置修订，保存真实依据和回执。无法证明关联业务或版本时停止；无影响复核不免除当前结果核验，已关月份的冻结资料不改写。

## 看板与提交

公司写入锁、业务事务、提交前身份锁按固定顺序取得。业务事务保存权威事实、正式采用、凭证、必要账务投影、冻结、审计、原请求和变更记录；共享身份锁只包住最终授权复核与提交。提交前撤权必须回滚。

看板由独立派生库在一致读快照中生成。内容先持久化，再用短事务核对来源版本并发布引用。来源在发布前改变则放弃本次发布，合并新任务。实际读取的对象、期间、范围及空命中共同决定依赖；跨月累计、后续清偿、展示资料、公司说明、关账、日期、修复版本和构建均参与有效性判断。

默认五页摘要与首屏一起生成；筛选、续页和详情按需读取。回放阶段合并历史月份的连续变更，明确浏览的月份可优先生产。仅公司全局版本增加不触发全部月份重建。

看板首页统一返回版本6的 `ready / preparing / failed` 合同。只有 `ready` 含业务响应；`preparing` 清空旧内容并显示“正在更新”，页面按服务端间隔只读重试；内容损坏与尚未生成分别处理。分页和迟到响应继续核对公司、期间与内容版本。

## 冻结、备份与交付

普通月结继续逐月生成备份任务。重放中间月份只保存正式冻结与独立关账回执，`backup_job` 为空；末月创建该轮唯一完整公司备份任务。回放核算完成、看板准备完成、备份交付完成分别记录，不能互相替代。

公司保持交付边界，直到目标 SQLite 快照已持久固化并核对关闭摘要。随后释放业务写入；压缩、核验和发布只使用该固定快照。重试同一任务不会重新抓取活动库。任务保存租约、心跳、不可变尝试事件、阶段耗时和失败原因；ZIP已发布而状态回写失败时，按任务身份与快照摘要恢复成功结果。

各公司分别在配置目录生成 `<统一社会信用代码>.finance-company.zip`。只有任务成功且指向已核验ZIP才算交付。完整包保留必要业务历史，派生看板在同结构恢复后通过明确的重建边界重新生成。恢复不覆盖已有目标。

## 验证范围

节点核对其实际效果，失败后只重新检查失效项；整轮结束独立核对业务完整性和最终ZIP。验证依据来自原件、具体事实版本、冻结摘要和检查器版本，不复用其他快照中的成功标记。

日常开发只运行改动相关的定向验证。隔离探针记录1、12、49个月的工作量，并检查无关变化零重建、连续变更合并生产。57个月代表基准及一小时目标属于单独的整轮规模验证；未完成该基准时不能声称目标已达成，不把整轮验收作为每次修改门禁。

`scripts/benchmark_replay_runner.py` 只生成隔离合成样本并记录性能，不处理真实资料、不读取旧公司库，也不是日常重放入口。正式重放使用当前类型化CLI/MCP与持久执行器。
