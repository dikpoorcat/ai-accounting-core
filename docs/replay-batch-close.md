# 重放专用批量关账

## 需求与边界

按重放文档恢复已保全资料时，默认使用批量关账，负责人不再逐月输入密码。普通记账继续使用同版单月核对、密码批准和关账。

重放必须由本机 CLI 显式启动，携带私有范围文件，限定目录身份、公司数据库、起止月份及已登记的负责人范围确认原件。仅支持开发合同的 `draft` 公司库，不能用于已发布正式合同的公司库。默认常驻服务拒绝重放批量命令；自动启动或重启不会隐式继承重放权限。批量命令仍要求有效负责人登录。

## 准备与启动

先完成目标月份的资料登记、核算和逐项处置。范围文件使用受保护的本机私有 JSON，格式如下；示例中的身份和摘要均需换成当前目录及目标公司实际返回值：

```json
{
  "format": "ai-accounting-kernel/2/replay-close-scope/1",
  "catalog_instance_id": "实际目录身份",
  "targets": [
    {
      "company_id": "实际公司身份",
      "database_id": "实际公司库身份",
      "first_period": "2026-01",
      "last_period": "2026-07",
      "owner_confirmation": "已登记负责人范围确认原件的64位SHA-256"
    }
  ]
}
```

每家公司只配置一个连续范围，单个范围最多 120 个月；一个文件最多 100 家公司。确认原件必须已登记到对应公司库，不能用其他确认或未登记摘要替代。文件加载后固定到服务进程，修改文件不会扩大正在运行的范围。

停止同资料根已有的服务后，显式执行 `finance-local --root <资料根> daemon --replay-scope <私有范围文件>`。已有服务运行时显式启动重放会报错，不会静默沿用普通模式。通过 `service-info` 的 `execution_mode=replay` 和 Schema 的 `replay_close_contract.enabled=true` 核对实际模式及范围摘要；服务信息不输出访问凭据。

## 接口与执行

`preview_replay_close_range` 接收扁平字段 `company_id`、`first_period`、`last_period`、`owner_confirmation`，核对限定范围、起始版本和已关账前缀，返回 `digest`、`epochs` 及 `first_month_review`。无关账前缀时从范围首月开始，已有前缀时从已关账后的首月连续执行；可以只选择范围内一段连续剩余月份。

范围文件保持原授权起止月，命令的 `first_period` 使用实际尚未关闭的首月。例如范围为1月至7月、已关至3月，新的预览及确认均传4月至7月；重新传1月会被拒绝，不能重关已完成前缀。

`confirm_replay_close_range` 携带同一四项字段、将预览的 `digest` 传为 `preview_digest`，另带相同 `epochs` 和稳定 `request_id`。首月摘要必须仍与已核对内容一致；后续月份在前月实际关账之后重新准备真实预览，逐月调用现有 `Periods.preview_close` 和 `Periods.close`。全部资料、核算、报表和完整性门槛继续生效，不将范围授权当作无业务确认。

每月保持独立事务、冻结链和便携备份任务。重放不创建密码批准记录，冻结内容的 `approval` 为 `null`；现有审计明确记录重放范围、负责人及稳定的批量和逐月请求身份。

中间月失败时返回 `blocked` 或 `partial`，列出 `closed_through`、`blocked_period`、实际逐月回执及阻断原因；全部完成才返回 `completed`。不跳过失败月，不把部分完成写为全部完成。同一请求重试先验证已提交子请求的审计身份、范围确认、读取版本及实际冻结链，再继续剩余月份。事实、资料、管理版本、读取修复、程序版本或会话凭据发生变化时，原批量停止，重新核对剩余范围并使用新请求键。

已全部完成的请求重试仍核验实际逐月提交和冻结链，不再写入关账或备份任务；有效重新登录后可以读取该完成结果。尚未完成的批量继续绑定原程序、会话和凭据。

每次保存原载荷与请求键。服务中断或响应丢失后原样重试；未完成批量的主请求可能显示 `unknown`，不能由此推定其中月份没有提交。持久计划和逐月请求保存在现有请求、审计表中，不新增业务版本通道，也不改变数据库结构或关账合同。
