# 看板读取合同

本文约束老板看板的有界读取、分页和版本关联。老板可见信息按[老板看板与内核边界](dashboard-kernel-alignment.md)裁剪；完整核算、资料来源、关账依据和 AI 会计工作流仍由服务端及 CLI/MCP 查询。

## 读取与筛选

看板默认每个明细集合返回 20 条，汇总与数量始终覆盖完整业务范围。筛选由后端先应用于完整集合，再分页；全量汇总、筛选结果和当前返回页分别保持清楚的范围语义。资金账户过滤不得只作用于已加载页。

精确业务直跳按稳定业务身份查询，可定位不在默认前 20 条中的记录。定位结果使用与页面相同的公司、期间及快照上下文，不扫描或串接分页来寻找目标。筛选、分页或快照变化后，游标和定位结果按合同失效并重新读取。

分页游标绑定公司、数据库、期间、查询入口、集合、实体、筛选条件及 `snapshot_version`。任务集合还关联其结果版本。服务端在同一读取快照中生成汇总、筛选和明细；版本或范围不符时返回结构化失效状态，页面不拼接不同版本的数据。HTTP 金额保持十进制整数分字符串，浏览器按整数精确处理，不使用浮点数重算金额。

wire 层继续验证请求与响应合同、最终请求 URL 与公司／期间／筛选／快照的精准关联，以及分页和业务身份关联。失效、未知、空值和零值保留各自含义。验证信息用于保证页面读取正确，不渲染为老板可见的技术说明。

## 页面与合同版本

现有五页共用公司和期间上下文，不增加趋势页、其他页面或业务写入能力。合同版本如下：

| 合同 | 版本 |
| --- | ---: |
| `context` | 3 |
| `brief` | 11 |
| `funds`、`assets` | 9 |
| `employees` | 9 |
| `business-status` | 6 |
| `quarterly-report` | 5 |
| `close-review` | 2 |
| 关账核对存储 | 4 |
| `OwnerReview` | 1 |

关账页面和原生密码窗口显示同一版核对内容，并固定同一个 `preview_digest`。预览失效后停止使用旧内容，不自动切到新摘要。关账核对内容服务于老板判断关账结论，不把凭证、借贷、试算、来源引用或采用证明、原始 JSON、内部编号及技术细节带入页面。

老板看板默认不运行完整 readiness。AI workflow、完整 `period_readiness` 和 corebusiness trace 仍保留其完整查询与核对能力，不能因老板展示裁剪而缩减。`business-status` 的看板投影不代替完整业务状态查询。员工集合仅保留 `employees`、`labor_sources`；人员展开只显示已返回的本月薪酬，不再请求工资历史页或保留人员历史页缓存。月末未付仍按真实历史义务及截至所选月的清偿汇总，不以本月应付减本月付款代替。

## 业务待办边界

“AI 会计核对中”表示暂不需要老板介入的工作。正常未付款、未申报、未关账及正常往来不会仅因状态未完成而生成老板待办或付款提示。确需老板确认、补充资料、付款或决定的事项，才作为本人待办展示，并说明对象、金额、期限、影响和下一步。正式业务事实、外部办理回执和关账检查不因展示边界而改变。

这些读取与展示边界已接入当前实现，并有定向合同、业务及损坏回归记录。r61 固定主12月完整核验通过，五页150次请求成功，但简报2／30次不低于500毫秒，整体仍未达标；48／120月最终规模、正式v1和独立运行包尚未验收。实际版本和原始证据见第9阶段文档，不以局部测试替代阶段完成。
