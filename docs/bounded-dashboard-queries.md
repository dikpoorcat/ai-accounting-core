# 看板读取合同

本文约束老板看板的有界读取、分页和版本关联。老板可见信息以 [FRONTEND.md](../FRONTEND.md) 和[老板看板与内核边界](dashboard-kernel-alignment.md)为准；完整核算、资料来源、关账依据和 AI 会计工作流仍由服务端及 CLI/MCP 查询。实际同类排查、工作量与前后测量按[性能优化方法](performance-optimization.md)执行。

## 读取与筛选

看板默认每个明细集合返回20条，汇总与数量始终覆盖完整业务范围。本月发生和待收待付默认返回20组，服务端在完整范围按相同正式对象身份及相同业务事项归并，再分页；组金额和笔数不随已加载页变化。工资、奖金计提及税期确认保留完整确认业务，沿用原业务金额口径，不按凭证分录或应付义务拆分计提金额；实际缴付和应付义务按工资、奖金、个税、社保、公积金及各税种分别列项。本月发生的混合实际收付款按原采用事项拆分，同一大类内的不同事项分别列示，收入与代收分别列示，代收与代付各有分类。分项保留原单用途备注并标明“整单说明”，不将整单说明当成本事项专属用途，也不据此改变分项金额或范围。同一正式对象且同一事项的业务才归组；单类多人银行批次限定精确原批次，不能因对象集合或姓名相同而跨批次合并，缺少明确身份保留单项。工资、奖金及劳务个税归入税费事项，税费分类独立展示为待缴税费，关账时为应付税费；待收与待付及不同款项分类分别汇总，跨月款项可以归组，异常不能被合计掩盖。组数、活动分项笔数及去重完整凭证数保持独立口径，不能把各类别凭证数相加代替全月凭证总数。筛选由后端先应用于完整集合，再分页；全量汇总、筛选结果和当前返回页分别保持清楚的范围语义。资金账户过滤不得只作用于已加载页。

资金按业务和本月发生组内记录先按实际日期升序、再按完整对象名称排序；当月按月确认排在实际日之后，缺日期最后。本月发生组按最早成员的同一排序规则排列，时间展示真实日期范围并保留按月确认。待收待付按对象、事项及稳定身份排序，不用未显示的所属月份排序；社保和公积金顶层按正式员工身份分别跨月归组，组内保留正式工资月及本事项的个人、单位两项拆解。对象采用固定字符顺序，同名身份不合并。排序基于已核完整范围的窄日期、对象及身份信息；实际收款人已明确的非批量付款不再推导原债权人，没有余额关系的候选不遍历祖先，其余候选从精确余额义务确定递归根。只对返回成员页装载正文及分录，冻结余额仍读取固定历史来源。前端只沿游标追加，不以局部重排替代全范围顺序。

精确业务直跳按稳定业务身份查询，可定位不在默认前 20 条中的记录。定位结果使用与页面相同的公司、期间及快照上下文，不扫描或串接分页来寻找目标。公司、期间、实体、筛选或快照范围变化后，游标和定位结果按合同失效并重新读取；同范围续页沿返回游标增量追加，不清空重读。

分页游标绑定公司、数据库、期间、查询入口、集合、实体、筛选条件、排序模式及 `snapshot_version`。旧排序游标失效；配对业务凭证与独立凭证号列表不能混用进度。首次手动切入按凭证以 `section=vouchers`、无游标读取独立首屏20张，后续按凭证号游标读取；组摘要不返回成员凭证；展开通过专用 `/api/dashboard/brief-group` 读取本组20笔成员及对应精确凭证，响应不重复组装整页简报。组成员游标还绑定集合和组键，原始凭证分页游标不能混用。成员页凭证只供精确预览、定位，已加载凭证操作不增加请求。刷新仅在上下文和新主响应均通过校验、公司／月份／快照一致后复用独立凭证清单、游标、页码及分页／全部模式，凭证预览索引仍重建；范围变化或失败丢弃旧集合。切回本月发生模块恢复待到达页，初始化或续页中刷新也只在校验成功后恢复读取，取消后的迟到响应不得追加。凭证直链同版本的刷新不重置人工选择的分页模式，不同精确目标仍优先定位。服务端在同一读取快照中生成汇总、筛选和明细；版本或范围不符时返回结构化失效状态，页面不拼接不同版本的数据。HTTP 金额保持十进制整数分字符串，浏览器按整数精确处理，不使用浮点数重算金额。

模块自动续页、详情允许后台续读、响应式列表及凭证索引增量更新按 [FRONTEND.md](../FRONTEND.md) 执行。简报必需布尔字段 `has_business_progress` 准确决定独立凭证的进展入口；无进展显示“—”，没有悬停、聚焦或详情请求。字段来自当前有界页元数据及窄关系查询，不逐行调用完整业务详情，不预加载进展。普通成员主动打开进展后按详情10合同读取；多人批次由 `is_batch` 明确控制，在用户首次展开组并取得成员后自动打开该成员详情，直接展示每人的用途和准确金额，默认刷新仍不读取成员或进展。分类成员的 `detail_scope_key` 与现有 `voucher_version_id` 共同约束精确成员事项详情；响应 `detail_scope` 回显成员范围键、类别、精确凭证及本次金额，首读、续页、游标、URL校验、读取身份与缓存均绑定公司、月份、快照、业务、凭证、成员事项范围及 `settlement_view`。服务端先裁剪本项义务、对象、用途和事件，再计算数量并每页返回20条；当前整笔结果及其他事项不能混入事项详情，事件用途直接使用准确的 `purpose_label`。完整凭证详情使用无分类范围，不复用分类响应。相关收付自动续页，成功内容、游标及失败状态只在相同读取范围复用。本月发生刷新、切组、收起及范围变化取消旧详情的首读和续页；凭证进展刷新时收起浮窗，范围变化清空缓存，关闭、切换或卸载取消未完成请求，迟到响应不能保存或追加。不新增原业务余额查询，不加入默认刷新等待链路。看板不读取全公司任务列表；报表仅按精确任务读取状态，下载时完整核验文件，核心 CLI/MCP 后台任务保留。

wire 层继续验证请求与响应合同、最终请求 URL 与公司／期间／筛选／快照的精准关联，以及分页、业务身份、精确凭证、分类及收付视图关联。失效、未知、空值和零值保留各自含义。成员页完整凭证按精确版本及成员首现顺序去重；多类别凭证的精确定位只返回完整凭证，活动定位为空。验证信息用于保证页面读取正确，不渲染为老板可见的技术说明。

## 页面与合同来源

现有五页共用公司和期间上下文，不增加趋势页、其他页面或业务写入能力。实际响应形状和版本以[后端响应模型](../src/ai_accounting/kernel/response_contracts.py)及[生成HTTP Schema](../frontend/src/api/generated/dashboardResponseSchemas.json)为准，本文不维护第二份版本表。模型、生成类型、校验器和消费者在同次接口修改中接通，生成检查不能暗中改写文件。

经营简报仅在返回有效 `owner_review_request` 时提示老板确认，点击后才按精确 `preview_digest` 读取核对内容；已关账或被后续关账覆盖的月份不默认读取独立核对区块。核对内容和原生密码窗口使用同一版预览或冻结内容；失效后停止使用旧内容，不自动切到新摘要。页面不提供准备、批准或关账操作，不展示来源证明、原始 JSON、内部版本和技术摘要。简报的会计凭证列表、业务凭证浮窗及借贷分录仍按 [FRONTEND.md](../FRONTEND.md) 保留。

老板看板默认不运行完整 readiness。AI workflow、完整 `period_readiness` 和 corebusiness trace 仍保留其完整查询与核对能力，不能因老板展示裁剪而缩减。`business-status` 的看板投影不代替完整业务状态查询。员工集合仅保留 `employees`、`labor_sources`；人员展开只显示已返回的本月薪酬，不再请求工资历史页或保留人员历史页缓存。月末未付仍按真实历史义务及截至所选月的清偿汇总，不以本月应付减本月付款代替。

## 业务待办边界

“AI 会计核对中”表示暂不需要老板介入的工作。正常未付款、未申报、未关账及正常往来不会仅因状态未完成而生成老板待办或付款提示。确需老板确认、补充资料、付款或决定的事项，才作为本人待办展示，并说明对象、金额、期限、影响和下一步。正式业务事实、外部办理回执和关账检查不因展示边界而改变。

## 验证与证据边界

各轮合同、业务、损坏回归、性能及开发运行包结果见[第9阶段记录](kernel-refactor-stages/09-performance-and-release.md)。历史 c063 窗口完成主规模和独立分布五页热刷新验收；后续改动的小型回归与现有开发库对比只证明各自已测范围，不能继承历史规模通过。正式版本冻结、正式交付及运行入口切换仍延期，保持开发库；性能检查不自动授权换库、重建大型样本或重启现有服务。
