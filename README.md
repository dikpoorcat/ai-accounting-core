# AI Accounting Core

本地、单负责人、多公司的确定性会计内核。采用 **Python 模块化单体 + SQLite**：保存有依据的事实版本，纯函数计算，通过统一事务发布会计结果，并保留可解释的历史。

每家公司一个数据库，证据正文与账务共享事务和备份快照；目录库保存公司位置、负责人身份和本地设置。它不是法定账簿或报税系统。

## 当前实现与已批准目标

当前代码已采用新系统 `ai-accounting-kernel/2`：目录库、公司库均为严格核验的 `draft / 0`，公司备份格式为 2。旧系统数据库和备份明确拒绝，不能通过改版本、补标识或重建文件绕过。

本轮按全新开发、全新库推进，不安排真实换库或重录。未来正式版本的迁移能力已建立，正常事实历史和更正能力保留；开发库只接受当前精确结构，不跨开发基线升级，第 9 阶段才冻结正式 v1。期间、身份、备用金等业务改造仍按[整体架构](docs/kernel-refactor-architecture.md)和[路线图](docs/kernel-refactor-roadmap.md)推进。

## 开发页面手动重启

你现在用的是开发页面，按下面做最稳妥：

1. 在运行 `npm run dev` 的终端按 `Ctrl+C`。

2. 在仓库根目录依次执行：

```powershell
.\.tmp-kernel-venv\Scripts\python.exe -I -X utf8 -m ai_accounting.kernel.cli --root .\data\kernel-draft stop
.\deploy\windows\start_accounting.ps1 -NoBrowser
Set-Location .\frontend
npm run dev
```

3. 刷新 `http://127.0.0.1:5173`。

后台重启后端口可能变化，重启 Vite 会重新核验同一开发资料根的目录身份和服务协议。开发启动器默认使用仓库 `data/kernel-draft`，不连接原来的裸 `data`；旧目录必须单独保全，不执行转换或清理。

## 运行

独立 Windows 包自带 Python 3.12.13、SQLite 3.53.1、Argon2id 和 Tcl/Tk，无需 Docker、PostgreSQL、系统 Python 或旧虚拟环境。

```powershell
# 在解压后的运行包内
.\finance-local.ps1 --root D:\会计资料 serve
```

每个资料根目录只有一个常驻服务，承载页面、鉴权、命令和后台任务。负责人在原生安全窗口输入独立密码；Windows 凭据管理器保存会话。密码不通过聊天、命令行或业务 MCP 提交。

连续历史关账支持一次密码批准多个明确的公司与月份范围：先分别 `preview_close_range`，再通过原生 `approve_close_batches` 确认，按公司执行 `close_range`。每家公司整段月份原子提交并生成一次备份；中断和部分成功按原批准与幂等请求继续，已关月份保持冻结。

仓库环境可说“启动”，或运行 `deploy/windows/start_accounting.ps1`。详见 [运行入口](docs/local-kernel-startup.md) 与 [独立打包](docs/local-kernel-packaging.md)。

## 公共接口

唯一业务命令体系为 `finance-local`，MCP 是同一服务的薄适配：

- `finance_local_schema`：共享类型模型生成的事实、命令及安全窗口 Schema，以及 `database_formats` 中的目录库和公司库合同。
- `finance_local_command(command, payload)`：公司查询、资料登记、事实版本、预览确认、报表及后台任务。
- `finance_local_security(action, payload)`：请求、查询、取消原生窗口及查询登录状态；不接收密码。

公司命令必须绑定 `company_id`。先登记实际采用的证据与类型化事实，再预览、核对摘要和版本、确认发布。公共接口不接受任意科目或借贷分录；金额使用整数分，规则小数使用 Decimal。

## 看板

保留经营简报、资金、员工、资产、财务报表五页及原有主题和导航，栏目按现有内核事实调整。负责人登录、后台任务和报表下载都在同一界面。

- 经营简报区分业务确认金额、凭证合计和实际资金，按来源展示交易方及冲正依据。
- 资金页区分公司对外收付与账户互转，明确银行流水覆盖情况；货币基金成本、申赎确认与实际收付分别列示。
- 员工页按工资所属期查看计提、清偿、实际申报及代发差额，另列费用化和资本化劳务；人员在册资料不决定工资核算。
- 资产页覆盖在用、待启用固定及无形资产和项目成本，付款按已有资产、批次或项目来源关联；财务报表页复用内核准备事项、三表和持久导出任务。

历史页面缺少姓名时，复用数据库已有的对应档案、收款人或个税导入身份，并保留资料来源。按月确认的资料明确显示月份；没有依据的旧栏目移除，不要求为适配界面补造资料。刷新会更新月份列表，分页遇到数据变化会重新加载，避免混合不同版本的明细。

展示口径与回归入口见 [看板与内核对齐说明](docs/dashboard-kernel-alignment.md)。运行包的构建和使用见 [独立打包](docs/local-kernel-packaging.md)。

## 已实现机制

- 新系统标识、数据库类别、开发/正式状态、独立结构版本及完整 SQL 指纹；明确步骤的事务迁移、失败回滚和实际安装历史。开发库不升级，已发布正式版本才允许沿可信路径前向演进。
- 事实、规则、计算和凭证版本；具体版本与空范围依赖；待更正传播；开放期保号替代、闭期关联冲正、无影响复核和受控误记删除。
- 凭证封存、借贷平衡、期间保护、幂等和失败回滚。读取与计算在写事务外完成，提交时再次验证状态和负责人权限。
- 公司创建、恢复的持久操作记录；启动中断恢复。备份、代发、个税和报表导出由常驻服务自动执行，失败最多自动尝试三次，保留可查询结果。
- CSV/XLS/XLSX 逐项原始资料核对，包含隐藏数据、金额、期间、控制合计和拆分；PDF、图片与文本保存页码或位置依据。关账和完整代发共用完整性检查。
- 公司说明防覆盖更新，按业务类型、人员、期间、状态找回事实和来源。工资方案复用要求明确无变化并核验来源；BIFF8 个税文件复用已验证的格式。
- 实际工资扣税单独保存核算事实，工资采用有依据的实际额，保留规则计算值和差异解释。实际申报、扣税及缴款各自追溯，重算不改写真实银行付款。
- 收入费用、往来核销、预收预付、代收代付、真实银行现金收付、工资劳务、社保公积金、累计个税和奖金、固定无形资产、借款利息与税期处理。
- 资产启用按确认批次发布一张凭证，固定资产折旧和无形资产摊销按月发布一张凭证；逐卡计算、累计额、账面价值及分录归属保持可追溯。
- 类型化期初接续：银行现金、往来、资产、借款、税费、薪酬累计和权益明细统一校验。期初不制造当期收入、费用或现金流。详见 [期初接续](docs/local-kernel-opening.md)。
- 关账冻结有效结果、分类及依据。外部申报和缴款进度形成独立待办，不能仅因办理未完成阻断关账；季度、年度义务由明确适用范围及版本化规则生成。
- 月度发生额、现金流、往来与期初汇总同步更新且可重建。SQLite Online Backup API 生成完整公司快照，验证结构、身份、外键、证据摘要和关账记录。

具体可用字段和边界以运行时 Schema 为准。缺少影响核算的事实返回 `needs_information`，管理资料后补不重新计算会计结果。

核算等价、内容有效性和提交并发版本分别判断；完整结果及精确来源始终保留。共同业务查询统一财务位置、清偿、期间准备和来源追溯，每次看板响应在同一公司库快照中读取汇总与明细。简报和季度报表先返回主数据，再按公司、数据库、数据版本及日期匹配后续月度准备结果。未证明的冻结采用保持未知，历史核算与当前相关后来事项分别展示。具体边界见[核算等价](docs/accounting-equivalence.md)、[历史内容](docs/history-content-versions.md)、[统一业务查询](docs/unified-business-queries.md)和[有界读取](docs/bounded-dashboard-queries.md)。

## 开发与验证

准备 uv 0.12.3，再运行 `scripts/kernel-runtime.ps1 -UvPath <uv.exe路径>`。受控虚拟环境为 `.tmp-kernel-venv`，不要使用本机默认 Python。

```powershell
.tmp-kernel-venv/Scripts/python.exe -m pytest
.tmp-kernel-venv/Scripts/python.exe -m ruff check src/ai_accounting/kernel tests/kernel tests/pure
```

默认测试仅运行新内核及保留的纯计算/解析/模板测试，不需要数据库服务或特殊隔离参数。前端执行 `npm test` 和 `npm run build:release`。运行包执行 `scripts/package-local-kernel.ps1`，实际验证移目录、原生窗口、Windows 凭据、CLI/MCP、记账及备份恢复。

按当次风险选择必要检查，以上入口不构成每次修改的统一门禁。复用仍有效的验证，跨阶段检查在收口时集中执行。本轮只在合成资料根验证运行包，不包含真实资料重录、公司迁移或正式换库。

容量边界为 20 MiB 单文件、10 万行银行文件和 5,000 条事实批次，不将合成测量当作更高容量承诺。

## 当前维护能力与历史记录

当前开发基线支持 `restore_company` 恢复相同结构的格式 2 公司包，`verify_integrity` 核验保存内容、投影和引用目录；`rebuild` 维修四张金额投影，`repair_read_indexes` 从冻结原文维修引用目录。两类维修先核验权威来源，实际变化才增加读取修复版本，不改历史事实与关账。领域层仍有待第 3 阶段整理的旧关账表示及有限覆盖分支，不代表正式首版允许缺少采用依据。

此前旧 ORM、业务服务、MCP、身份接续桥、Alembic 及本项目专属 PostgreSQL 容器和卷已退役，运行包和默认入口已经独立。此前恢复与重录方法保存在[历史流程记录](docs/empty-database-replay.md)，仅作资料和实现索引，不是本轮的后续任务。原件、负责人确认、现有数据库及备份继续保全，本轮不执行重录、身份接续或旧资源清理。

原 Vue 五页看板已经接入当前 SQLite 内核，负责人登录与后台任务使用同一界面。看板不提供按计算逐层展开的凭证核算追溯，`trace` 保留为 CLI/MCP 读取能力。当前结构沿革和分页边界见[有界看板查询](docs/bounded-dashboard-queries.md)，内容有效性及历史后补见[历史来源与内容版本](docs/history-content-versions.md)，运行入口见[启动说明](docs/local-kernel-startup.md)。业务原件、公司说明及正式回执保存在资料目录，不进入源码。
