# AI Accounting Core

本地、单负责人、多公司的确定性会计内核。采用 **Python 模块化单体 + SQLite**：保存有依据的事实版本，纯函数计算，通过统一事务发布会计结果，并保留可解释的历史。

每家公司一个数据库，证据正文与账务共享事务和备份快照；目录库保存公司位置、负责人身份和本地设置。它不是法定账簿或报税系统。

## 当前实现与已批准目标

当前代码已采用新系统 `ai-accounting-kernel/2`：目录库、公司库均为严格核验的 `draft / 0`，公司备份格式为 2。旧系统数据库和备份明确拒绝，不能通过改版本、补标识或重建文件绕过。

当前按已确认的全局字段去重方案清理代码、数据库结构及回放文档，以新建合成公司验证；现库、原件和备份保全，现库退出后续使用，本轮不迁移、不保留退出字段别名、不执行真实重放。银行与平台账号只登记于正式账户身份，实体档案按类别限制字段，业务备注、工资正文及资料计算引用各有唯一来源，详见[字段来源清单](docs/field-sources.md)。目录库与公司库仍为 draft／0，现有5173及身份原样，正式冻结、正式交付和运行切换延期。历史性能结果按原时点保留，不代替本轮字段清理验收；阶段边界见[整体架构](docs/kernel-refactor-architecture.md)及[路线图](docs/kernel-refactor-roadmap.md)，未来执行见[空库重建](docs/empty-database-replay.md)。

## 5173 开发页面

在仓库根目录运行：

```powershell
$env:FINANCE_DATA_ROOT = Join-Path $PWD 'data/kernel-released'
.\deploy\windows\start_accounting.ps1 -DataRoot $env:FINANCE_DATA_ROOT -NoBrowser
npm run dev
```

打开 `http://127.0.0.1:5173/`。若 5173 已在运行，直接使用现有开发页面；后台服务会按资料根目录复用。开发页面显示连接错误时，先确认同一资料目录的后台已启动，再刷新页面，无需重启 `npm run dev`。

Vite 在服务状态变化或连接失败时重新发现后台，核验同一资料根的目录身份、数据库合同和服务协议，再更新端口与连接凭据；失败请求不会自动重发。后台重启后刷新页面会重新建立浏览器会话。资料目录身份改变时拒绝连接；主动切换 `FINANCE_DATA_ROOT` 才需重启 Vite。启动器、仓库 MCP 和 Vite 默认使用仓库 `data/kernel-released`；原开发目录保留，不移动或转换。当前合同仍为 draft，目录名称不表示正式 v1 已经交付；第 9 阶段验收状态见路线图。

## 运行

独立 Windows 包自带 Python 3.12.13、SQLite 3.53.1、Argon2id 和 Tcl/Tk，无需 Docker、PostgreSQL、系统 Python 或旧虚拟环境。

```powershell
# 在解压后的运行包内
.\finance-local.ps1 --root D:\会计资料 serve
```

每个资料根目录只有一个常驻服务，承载页面、鉴权、命令和后台任务。负责人在原生安全窗口输入独立密码；Windows 凭据管理器保存会话。密码不通过聊天、命令行或业务 MCP 提交。

关账按公司逐月完成：AI 先 `preview_close`，负责人在经营简报核对内核提供的同版内容，再通过本机 `approve_period_close` 密码窗口批准，由 AI 执行 `close`。页面只读，整月统一批准；预览变化须重新核对。已关月份保留原核对内容及实际采用依据，自动备份按任务状态确认完成。

仓库环境可说“启动”，或运行 `deploy/windows/start_accounting.ps1`。详见 [运行入口](docs/local-kernel-startup.md) 与 [独立打包](docs/local-kernel-packaging.md)。

## 公共接口

唯一业务命令体系为 `finance-local`，MCP 是同一服务的薄适配：

- `finance_local_schema`：无参返回通用操作协议、专项规则目录、版本和事实／命令目录；`view="selected"` 按 `fact_kinds`、`commands`、`response_types` 获取当前事项合同及相关专项规则，也可通过 `protocol_topics` 单独选择规则。同一会话、同一程序版本复用已读内容；旧MCP连接未传选择参数时用通用 `schema` 命令。`view="full"` 显式读取完整合同与全部规则，CLI 使用相同载荷。会计执行规则统一维护于 `kernel/operating_protocol.py`，记账 Skill 只提供任务入口。
- `finance_local_command(command, payload)`：公司查询、资料登记、事实版本、预览确认、报表及后台任务。
- `finance_local_security(action, payload)`：请求、查询、取消原生窗口及查询登录状态；不接收密码。

公司命令必须绑定 `company_id`。登记业务前用 `find_entities` 查找人员、机构、资金账户、资产、项目或基金产品，明确复用已有对象或用 `register_entity` 新建；对象编号由内核生成，业务另有编号。再登记实际证据与类型化事实，预览、核对摘要和版本、确认发布。公共接口不接受任意科目或借贷分录；金额使用整数分，规则小数使用 Decimal。

受管资金账户使用按类型区分的专用登记合同，完整身份及已登记来源必填，内核原子分配独立明细科目。银行须完整文本账号、开户名及银行名称，平台须实际账户标识及归属，现金须明确受管账户名称；显示同名不合并，改名停用不释放科目。普通档案更新不改身份，有来源的开户资料纠错追加身份修订。正式资金分录保存唯一明细归属，新关账冻结当时定义和明细核验；父级汇总及报表金额不变。详见[资金账户合同](docs/fund-account-contract.md)。

确定工作清单的当前事项后，用 `work_context(company_id, period, work_area, include_work_draft=true, ...)` 一次取得工作稿和公司说明、已有事实、精确采用与依赖引用、资料索引及本页直接引用对象。工作稿文件和内核快照分别核验。后续资料查询和翻页省略该参数，不再返回整份稿；默认100条、最多500条。本页没有不等于资料缺失，接收月不代替所属月。需要原文时再调用 `inspect_material`。其纯解析结果在资料根 `.inspection-cache` 内复用，所有公司合计最多512MiB、按最后使用时间淘汰，服务内存只保留最近一份；原件摘要每次核对，正式核验独立执行。接口用法及测量见[会计AI读取链](docs/ai-reading-optimization.md)。

`workflow` 版本2在顶层 `issues` 保存一份完整问题正文，各事项用本次响应的整数引用保留原范围、顺序及重复次数。检查与状态判断保持原规则，共用正文不表示不同事项可以合并追问。实现与比较见[读取和工作稿优化](docs/ai-reading-work-draft-optimization.md)。

未提交事项工作稿通过 `list_work_drafts`、`read_work_draft`、`save_work_draft`、`delete_work_draft` 管理：每公司、月份、事项一份独立私有文件，最多8MiB，原子保存并按版本防止覆盖，只保留最新版直到明确删除。关键节点保存的候选输入、回答、来源和原请求可在同根重启后恢复；问题明确区分待答、已收到回答、已解决、撤回及后阶段待办，并保留实际业务范围和处置原因。提问前复用有效依据，有现成入口的技术阻塞先处理，实际范围变化仅核对变化部分；草稿不构成登记或批准。公司备份ZIP不包含工作稿，未成功保存的内容不能恢复。用法见[工作稿恢复](docs/work-draft-recovery.md)，实现及实际对话验证见[信息复用与追问机制](docs/ai-question-reuse.md)。

泛化“开始记账”调用 `workflow(as_of=实际查询日)`，默认选最早真实待处理月，在聊天开场说明公司、月份和当前事项，展示银行、工资、普通业务、税务、资产、融资六类完整清单，另列关账、实际办理和文件交付；明确交办某件事时直接处理。`period_readiness` 查看指定月份。没有可靠月份的空公司返回空状态；未办理申报和文件任务独立保留，不把核算月份拉回闭月。

每个清单事项完成后重读 `workflow`，展示本次结果、完整清单及下一项或待确认。默认严格按展示清单顺序推进，从最早未完成或待确认事项开始；当前缺资料、依赖未满足或待确认时停止，不跳过阻断项或因到期插队。已有明确确认覆盖同公司、期间、事项和事实范围且仍有效时，可连续完成相邻事项；没有该确认时，完成当前事项后等待确认才能进入下一项，这不是逐笔入账审批。先查资料再问；后项已有结果如实保留，不撤回结果或补造前项完成。只有老板明确交办先处理后项才可改序，回答当前项、泛化继续或提供资料本身不授权改序。普通重算不一律重新询问，关键事实或范围变化才重新确认。资料、事实、正式发布、实际办理和交付分别判断；有明确确认的无业务结论不误作未完成，也不推定外办不适用。中断恢复时重读真实状态和可查确认，缺少依据显示待确认。

`external_completion` 保存真实办理及原依据，`external_basis_review` 单独保存与正式账务的核对。可以先登记报税、社保办理，再核对账务；季度税务与季度财报分开，财报须等待对应期间关闭。已申报、账务待核对、文件未生成可以同时成立。

响应丢失时重发原请求和原请求键；只知道请求编号时用 `request_result` 读取原回执。`unknown` 只表示尚未观察到提交，不能当作失败另记一笔。任务返回稳定的 `error_code` 和直白说明，先处理失败原因，再重试原任务。切公司或中断后重新读取公司上下文和工作状态。

`save_fact`、`amend_fact` 和批量登记自动检查强重复候选；AI 先查原件，仍不能判断才问负责人。复用既有业务或确认另建都留下绑定版本的核对依据。弱线索不打断登记，原有唯一性和防重复核销不能被核对绕过。

对象名称与档案通过 `update_entity_profile` 部分更新，省略字段保留。员工和劳务通过 `register_worker` 原子登记或复用同一人员身份；入职、停薪、复薪、离职、劳务开始结束、互转及更正通过 `change_workforce_relationship` 保存有来源的生效事件。程序从唯一时间线推导六种用工状态和月度名册，没有工资或劳务费也能入册；月份不补造日期，入职前不自动归劳务。`workforce_relationship_history` 提供事件版本绑定的分页历史，可指定月份读取归属及结构化缺项。闭期名册显示最新确认历史，工资与凭证保持冻结。详见[用工关系与月度名册](docs/workforce-relationships.md)。指错对象使用 `preview_identity_correction`／`confirm_identity_correction`，一次提交完成受影响事实及账务更正；闭期明确指定开放入账月，原冻结内容保留。`find_facts` 使用 `entity_id`、角色、`identity_match=current|recorded` 和不透明 `cursor`，默认按月份及事实编号倒序，每页最多 500 条。

备用金用 `managed_reserve_expense` 登记实际支出、`managed_reserve_refund` 登记实际退回公司，支持银行、现金和公司平台账户，沿用通用预览和发布流程。平台收付必须引用核验过的原行。备用金本身不建账户、不管余额或退款额度，退款不要求原支出编号；内部消费、退款权利和债务结清不能当成公司实际退款。

工资混合付款用 `payroll_reserve_payment`：净薪分配加 `reserve_expense_fen` 必须等于真实银行全额，同时保留完整工资组及实际退入备用金的确认。差额不能证明钱已经退入；具体日期未知时不补造。实际退入备用金与实际退回公司分开处理，不使用旧范围或专用结清命令。

## 看板

保留经营简报、资金、员工、资产、财务报表五页及原有主题和导航，栏目按现有内核事实调整。负责人登录和报表生成下载使用同一界面；后台任务清单由 AI 会计读取，不在老板看板展示。

- 经营简报集中展示收入、费用、赚亏、资金、本月发生、用工成本和待收待付；本月发生与待收待付仅按相同正式对象身份且相同业务事项汇总，社保与公积金分别归组，工资、奖金及劳务个税归入税费分类，展开查看逐笔记录及凭证，跨月未结款项保留所属月；老板待办只列明确需要本人确认、补资料或执行付款的事项。
- 资金页区分公司对外收付与账户互转，明确银行流水覆盖情况；货币基金成本、申赎确认与实际收付分别列示。
- 员工页展示本月公司成本、本月实际支付和截至月末未付，分别标明期间；人员清单和工资、劳务详情按需展开。
- 资产页展示原值、折旧、账面价值及新增、启用、退出、项目成本，付款说明实际范围；财务报表页保留季度关键金额、三张报表和生成、下载。

姓名复用数据库已核验的对应档案、收款人或个税导入身份，来源仍供 AI 会计追溯。未知金额显示待确定，无需老板参与的核对显示“AI 会计核对中”，读取失败明确报错。手机报表按项目纵向排列。刷新会更新月份列表，分页遇到数据变化会重新加载，避免混合不同版本的明细。

展示口径与回归入口见 [看板与内核对齐说明](docs/dashboard-kernel-alignment.md)。运行包的构建和使用见 [独立打包](docs/local-kernel-packaging.md)。

## 已实现机制

- 新系统标识、数据库类别、开发/正式状态、独立结构版本及完整 SQL 指纹；保留显式合同的事务升级、失败回滚和历史核验机制。当前生产包不声明此前开发结构到本轮结构的升级路径，未知结构和旧体系拒绝，已发布的 `released` 合同不可回写。
- 事实、规则、计算和凭证版本；具体版本与空范围依赖；待更正传播；开放期保号替代、闭期关联冲正、无影响复核和受控误记删除。
- 凭证封存、借贷平衡、期间保护、幂等和失败回滚。读取与计算在写事务外完成，提交时再次验证状态和负责人权限。
- 公司创建、恢复的持久操作记录；启动中断恢复。备份、代发、个税和报表导出由常驻服务自动执行，失败最多自动尝试三次，保留可查询结果。
- CSV/XLS/XLSX 逐项原始资料核对，包含隐藏数据、金额、期间、控制合计和拆分；PDF、图片与文本保存页码或位置依据。关账、期间准备及默认完整代发保持整月检查；显式工资、奖金、劳务 `source_ids` 的薪资代发，按本次来源及直接、传递采用依据核验，相关原件仍整份解析并核验隐藏内容、控制合计，重复、竞争来源和失效结果不豁免；本次核验期、闭期承接及未知归期的问题继续阻断，其他明确未来期行只在所属期处理，文件不代表全月完整代发。闭期资料问题由后续开放月持续承接，未来行到所属月才阻断，未知期间必须补足依据。清单计数不能代替逐项处置，范围说明见[银行代发文件](docs/kernel-payment-exports.md)。
- 公司说明防覆盖更新；统一对象登记与版本档案，按业务类型、对象、期间、状态分页找回原始事实和来源。身份纠错、业务替代及重复核对保留不可变依据，当前归属与当时冻结分别读取。
- 普通和 bounded 工资正式发布都核对本月确认：采用附证据的明确方案，或完整人员范围的明确无变化确认。确认绑定工资输入、档案、实际采用的政策修订及变更通知。`confirm_payroll_preparation` 只登记工资事实，发布仍走统一入口；累计或实际扣税变化不因重算本身要求重复确认。日常按[八阶段流程](docs/local-kernel.md#工作清单外部办理与恢复)：第2步确认工资劳务与个税输入，第3步办理社保公积金，第4步依据实际扣税及个人承担额核算工资净额、正式发布和办理代发；不因尚未完成社保而阻止第2步确认，也不在第4步重复有效确认。文件交付及真实银行代发分别跟踪，AI不自动银行付款，正式计算门槛保持不变。
- 工资准备和期间待办提前检查个税文件的月度扣款映射。映射缺失、错误或模板不能表达只影响个税文件，不阻断合法工资、付款、关账或真实外部申报完成。个税输入文件引用已确认工资修订及有源申报明细，在取得税额、正式发布工资前即可生成，不猜测险种或扣除。
- 工资、奖金、劳务、税务与申报日历共用政策来源校验：仅接受合法 HTTPS 官方 `gov.cn` 域名及子域，不接受凭据或伪装主机；保存来源原文，不在计算时联网，不改变税率及生效期。
- 工资、奖金和劳务统一采用 `remuneration_tax_basis` 保存的最终报酬表应扣额或实际扣税额，内核不计算个税。零税也需明确依据；缺税可保存报酬事实，正式发布及净额代发等待税依据。实际申报、扣税及缴款各自追溯，重算不改写真实银行付款。见[报酬与确认税额](docs/kernel-remuneration-tax.md)。
- 收入费用、往来核销、预收预付、代收代付、真实银行现金收付、工资劳务、社保公积金、确认个税和奖金、固定无形资产、借款利息与税期处理。
- 资产启用按确认批次发布一张凭证，固定资产折旧和无形资产摊销按月发布一张凭证；逐卡计算、累计额、账面价值及分录归属保持可追溯。
- 类型化期初接续：银行现金、往来、资产、借款、税费、薪酬累计和权益明细统一校验。期初不制造当期收入、费用或现金流。详见 [期初接续](docs/local-kernel-opening.md)。
- 关账冻结有效结果、分类及依据。外部申报和缴款进度形成独立待办，不能仅因办理未完成阻断关账；季度、年度义务由明确适用范围及版本化规则生成。
- 月度发生额、现金流、往来与期初汇总同步更新且可重建。SQLite Online Backup API 生成完整公司快照，验证结构、身份、外键、证据摘要和关账记录。

具体可用字段和边界以运行时 Schema 为准。缺少影响核算的事实返回 `needs_information`；名称等展示资料后补不重算。工资确认依据变化须重新核对，金额不变时使用无影响复核，不重写冻结内容。

核算等价、内容有效性和提交并发版本分别判断；完整结果及精确来源始终保留。共同业务查询统一财务位置、清偿、期间准备和来源追溯，每次看板响应在同一公司库快照中读取汇总与明细。看板默认每集合 20 条明细，汇总覆盖完整范围，业务详情按需读取。核算过程、来源证明及完整准备检查由 AI 会计通过专用入口读取。已关账月份不显示独立月度核对；开放月有有效预览时，在老板待办点击读取与密码窗口同版的内容，默认刷新不请求核对正文。冻结读取保留精确采用，缺少必需依据按内容错误处理；尚未建立的业务金额保持未知。历史账面与当前业务结果分别说明。此前c063轮次规定主规模及独立分布的整页热刷新全部低于500毫秒；压力仅诊断，不承诺500毫秒。该历史轮次主120按需功能和1de新开发包、两档资源诊断及独立只读补证完成，提交记录按其来源保留。固定SOURCE24主12／主48五页默认各150正式样本全部低于500ms；凭证全部交互仍有600ms超线。主120计时准备已停止，没有成绩。本次进度提交的固定SOURCE27规模验收尚未完成，不能继承旧来源成绩。五页默认刷新500ms与其他交互暂定600ms分别验收；普通规模只main12／main48／main120，独立三档及stress12按需辅助、不设每轮门禁，历史失败、污染窗口及原始样本保留。本次按用户要求提交阶段性成果，正式版冻结、交付及运行切换延期；各源码及窗口结果见[阶段9](docs/kernel-refactor-stages/09-performance-and-release.md)。具体边界见[核算等价](docs/accounting-equivalence.md)、[历史内容](docs/history-content-versions.md)、[统一业务查询](docs/unified-business-queries.md)和[有界读取](docs/bounded-dashboard-queries.md)。

## 开发与验证

准备 uv 0.12.3，再运行 `scripts/kernel-runtime.ps1 -UvPath <uv.exe路径>`。受控虚拟环境为 `.tmp-kernel-venv`，不要使用本机默认 Python。

```powershell
.tmp-kernel-venv/Scripts/python.exe -m pytest
.tmp-kernel-venv/Scripts/python.exe -m ruff check src/ai_accounting/kernel tests/kernel tests/pure
```

默认测试仅运行新内核及保留的纯计算/解析/模板测试，不需要数据库服务或特殊隔离参数。前端执行 `npm test` 和 `npm run build:release`。运行包执行 `scripts/package-local-kernel.ps1`，实际验证移目录、原生窗口、Windows 凭据、CLI/MCP、记账及备份恢复。

按当次风险选择必要检查，以上入口不构成每次修改的统一门禁。复用仍有效的验证，相关改动收敛后集中执行。本轮使用新建合成公司完整验证，不操作现库，不把模板校验当作真实重放；后续真实重放仍需明确执行授权。

容量边界为 20 MiB 单文件、10 万行银行文件和 5,000 条事实批次，不将合成测量当作更高容量承诺。

## 当前维护能力与历史记录

当前开发基线支持 `restore_company` 恢复相同结构的格式 2 公司包，`verify_integrity` 只读核验保存内容、正式发布链、关账采用及派生数据。两个显式维修入口 `rebuild`、`repair_read_indexes` 先核对权威源，在同一事务内恢复所有必要派生目录、金额／冻结派生与已登记读取模型，再完整核验；实际变化才推进读取修复版本一次，失败一起回滚。不修原始源，不在普通只读连接自动维修，不更改业务 epochs 或冻结源。关账直接记录实际采用的版本与依据，缺失依据明确拒绝，不提供旧格式推断或有限核验。

此前旧 ORM、业务服务、MCP、身份接续桥、Alembic 及本项目专属 PostgreSQL 容器和卷已退役，运行包和默认入口已经独立。历史恢复与重录记录继续作为资料和实现索引，[空库重放说明](docs/empty-database-replay.md)仅在用户明确指定该流程时适用。原件、负责人确认、现有数据库及备份继续保全；当前本体系库的结构接续不重新设置负责人，也不授权旧资源清理或旧体系导入。

原 Vue 五页看板已经接入当前 SQLite 内核，负责人登录和报表生成下载使用同一界面。看板不提供后台任务清单或按计算逐层展开的凭证核算追溯，`jobs`、`trace` 保留为 CLI/MCP 读取能力。当前结构沿革和分页边界见[有界看板查询](docs/bounded-dashboard-queries.md)，内容有效性及历史后补见[历史来源与内容版本](docs/history-content-versions.md)，运行入口见[启动说明](docs/local-kernel-startup.md)。业务原件、公司说明及正式回执保存在资料目录，不进入源码。
