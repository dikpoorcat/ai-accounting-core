# 撤回记账

在会计操作模式中执行老板已明确交办的撤回。先读取当前 MCP 的 `accounting://guides/work`、`accounting://guides/commands` 和 `accounting://contracts`，沿工作指南说明公司、月份、实际结果和办理进度；本 Skill 只补充撤回指令的办理方式，业务规则仍以当前合同和所选业务指南为准。不修改仓库实现，不直接删数据库或标准文档文件。

通过 `accounting_context` 核对当前公司、数据库身份、开放和关闭月份及现有说明、待办，不沿用上次会话的公司编号。结合当前对话定位老板指定的业务；公司或范围已经明确时直接接续，只澄清仍会影响撤回对象的歧义，不要求老板提供内部编号或重复批准同一范围。

## 单笔与批量共用现有入口

单笔先用 `accounting_get` 读取原业务当前身份、序号、事实及结果。多笔按老板指定范围用 `accounting_find` 查询并完整接续分页，再读取所选业务及必要关联，核对跨月清偿、依赖和冻结结果。

**老板说“撤回某公司某月的记账”时，按业务所属月逐类查齐该公司该月的有效业务，通过现有批量接口撤回，不调用或假设存在专门的当月撤回接口。** 查询范围以当前 `BusinessQuery` 的领域枚举为准；不能只处理一个领域或第一页，也不能按原件归档月、录入时间或凭证月份误撤其他月份的源业务。既有业务自动延续到本月的结果须另行核对，不把它们当作本月新建业务删除。

整月撤回前，通过 `accounting_backup` 保全当前公司，以 `accounting_jobs` 核实备份已成功并指向经过验证的 ZIP；备份未完成时不执行该整批撤回。保留公司、数据库、负责人身份、其他月份及原件资料。

用 `accounting_new_ids` 分配本次 `command_id`，调用 `accounting_command(command="accounting_apply", payload=完整请求)`；`mutations` 中每笔只提交 `op="withdraw"`、原 `business_id` 和当前 `expected_seq`。单笔为一项，批量为多项；同一业务身份只出现一次。相互依赖且均在已授权范围内的撤回放在同一原子单中，交由内核统一核验。超过当前合同上限时，仅按真正独立的单元拆分，并逐单报告结果，不把部分成功称为整批完成。

不能为通过依赖检查自行扩大撤回范围、撤掉其他月份源业务或拆散原子关系。冲突时重新读取实际状态；仍有范围外依赖时说明具体关联及尚未撤回的范围。闭期按业务指南通过开放更正期形成必要关联冲正，保留冻结历史，不能当作未关账业务直接清空。

## 完成与接续

提交结果不明时，按原业务身份查询，确认已撤回后接续，不换身份重复办理。账务已撤回但标准文档待完成时，通过 `accounting_documents` 查询并接续发布；文档未就绪不能报告整项完成。只更新撤回实际影响的月份说明和待办，保留其他仍未解决事项，不清空长期公司说明。

核对所选业务的实际撤回状态、标准文档和实际影响范围。整月撤回后，按同一公司、月份和领域再次完整分页查询，确认没有漏撤的有效业务，并核对其他月份原业务及冻结结果保持正确；仍有未处理项时如实说明，不提前报告整月完成。本月仍由既有资产等产生的自动核算结果须单独说明，数据库会保留必要撤回身份，工作月份也不会自动倒退，不能宣称数据库已无本月任何痕迹。

仅要求撤回时，到核验和文档接续完成为止，不自行重记业务；重新办理同一事项时，用原业务身份、撤回后的当前序号和完整正确事实执行 `restore`，不另建重复业务。

撤回默认保留原件和来源登记。老板另行要求替换错误原件时，按工作指南导入新来源并更正当前引用，不覆盖旧来源内容；原件退出沿独立的 `accounting_sources(action="discard")` 保护检查办理，不能把业务撤回当作已删除原件。
